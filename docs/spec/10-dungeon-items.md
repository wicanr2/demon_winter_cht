> 狀態：**`T`／`D`／`E`／`M`／`U` 已實作**（含 `MAPn.MAP` 的寫回路徑）；
> 只剩 `I` 探查周圍（掃描範圍未讀）與 `S` 的劇情段文字；
> 證據來源：`docs/re/94`（位置表與載入端）、`docs/re/95`（50 件 × 6 欄、
> 動作碼分派、道具槽 union、位置表是存檔、§3.6 `Take:` 全流程、
> §3.7 `Drop` 靠名字回推）、`docs/re/69` §1（三個提示詞）、
> `docs/re/27` §2（字串切表）、`docs/re/25`（一般道具的槽位布局）
> 最後複核：2026-07-27（`Take:`／`Drop` 兩支逐指令讀完並實跑驗過）

手冊「物品」一節那六個指令（`I`／`E`／`T`／`D`／`M`／`U`）。
**地城解謎的全部內容在這裡** —— 主線的線索（Qoorik、Asaht、魔晶、
冥河擺渡人、光之環）都是從地城道具的敘述裡給出來的。

---

## 行為

地城道具與一般道具是**兩種東西**，手冊講得很清楚：

| | 一般道具 | 地城道具 |
|---|---|---|
| 性質 | 通用（劍、鎖子甲、火把）| **獨一無二、有特定用途**（鐵砧、花朵、金鑰匙）|
| 清單顯示 | 無前綴 | 前面加 `/` |
| 什麼時候用 | **紮營時** | **移動途中** |
| 丟掉之後 | 再也拿不回來 | **一定撿得回來**（原地）|
| 價值 | 可賣 | 沒有價值、不能賣 |

## 資料

### 位置：`ITEMLOCB.DAT`（50 筆 × 3 bytes）

```
[X, Y, 子地圖]      子地圖 0 ＝ 這一筆已經被拿走
```

**這個檔是存檔的一部分**：拿走一件時原版就地把子地圖寫 0（`0x18397`）。
`ITEMLOCX.DAT` 是出廠母本 —— 與 `nSS.DAT` vs `ALL_SS.DAT` 同一個模式
（`docs/re/78`），**存回沿用那條路，不要新設計**。

載入走通用資源迴圈（`0x11fc2`）：六筆檔名表 `ds:0x14c9` 索引 2 → arena 槽 2。

### 內容：`FILES.DTT` 索引 164–463（50 件 × 6 條）

索引與位置表**同一個 `i`** 對齊。

| 欄 | 語意 | 非空 |
|---|---|---|
| `+0` | 名稱 | 50 |
| `+1` | 拿不走的理由（`*` ＝ 拿不走但沒話說）| 25 |
| `+2` | 檢視敘述 | 48 |
| `+3` | 推開之後改哪一格 tile（`*` ＝ 沒事）| 19 |
| `+4` | 要搭配哪一件道具（存的是**名字**）| 18 |
| `+5` | 用對之後的動作，**首字元是動作碼** | 18 |

`50 × 6 = 300`，用完 `docs/re/27` 第 6 張表 303 條裡的前 300 條。

### 拿在手上：角色道具槽的第二種解讀

17-byte 的槽對地城道具是：

```
[0]      型別 ＝ 0xfe          ← 不是 0xff，那是空槽
[1..16]  名字，NUL 結尾
```

與一般道具（`docs/re/25` 的效果／強度欄）是**同一塊記憶體的 union**。
`0xfe` 有三條證據，最直接的是 `Take:` 的寫入端
（`0x1996f  mov es:[bx+si+0xc], 0xfe`）；另外兩條在 `docs/re/33`
（§3 的「不能在營地丟」判定 `> 0xfd`、§4 找空格用 `== 0xff`）。
手冊說清單裡前面加 `/`，那個記號就是這個型別值 —— **記號加在譯名外面**，
不進翻譯檔。

> **判定要分開寫。** 原版把「地城道具」與「空格」用 `> 0xfd` 一起擋掉，
> 那是隨手複用；本專案對空格另外說「這一格是空的」（`docs/re/33` §3）。

## 演算法

### 列出腳下這一格有什麼（`222f:2da5`）

```
found = 0
for i = 0; i < 50 && found < 9; i++:
    if itemloc[i] == (隊伍X, 隊伍Y, 隊伍子地圖):
        清單[found] = i
        found++
return found
```

**上限 9**（原版 `cmp [bp-2],9`）。手冊說「每個位置最多只能放 10 件」，
兩個數字都留著，以 9 實作。

### 六個指令

| 鍵 | 行為 |
|---|---|
| `I` 探查周圍 | 掃視野內所有格，把有道具的位置畫出圖示。**動作碼未定**（見未解表）|
| **地圖改動要存回** | `M` 與 `U` 的 `P` 都改地圖 tile，原版改完立刻把整張圖寫回 `MAPn.MAP`（`docs/re/95` §3.9）。本專案寫存檔目錄，載入走 `world.LoadByID` 的三段優先序。**只對 1／3／5 存**（其餘在 `SUM.MAP` 裡，原版寫了也讀不回來）|
| `E` 檢視 | 選**身上**一件 → 顯示 `+2`；`+2` 空著就印 `You see nothing special about the %s`（50 件裡只有 `Iron key`、`Bag/red dust` 兩件）|
| `T` 拾取 | 選一件 →（1）`+1` 是 `*` 印 `You can't`；（2）`+1` 非空印那句話；（3）**再問哪個角色**；（4）找第一個空槽，沒有就印 `No more room.`；（5）槽寫 `0xfe` ＋ 名字，位置表那一筆**三個 byte 全清** |
| `D` 丟棄 | 選一個槽 → 清空槽（只寫 `0xff`），**靠名字掃字串表回推索引**，把那一筆改寫成目前座標 |
| `M` 移動 | 選**腳下**一件 →（1）`+3` 是 `*` → `You can't`；（2）`+3` 空著 → `Nothing happens.`；（3）三組 2 位數 `atoi` 得 X／Y／tile；（4）那一格已經是這個 tile → `Nothing happens.`；（5）改 tile、印 `Something happened...`、**把整張地圖寫回 `MAPn.MAP`** |
| `U` 使用 | 選一個**隨身道具** → 三選一（`Use on: Character／Room／Quit`）→ 選目標 → 目標的 `+4` 要等於手上那件的名字（或 `+4` 是 `=`）；對了跑 `+5`，錯了印 `Nothing happens`（**什麼都不消耗**）|

`U` 是兩段式的（手冊：「用手上持有的物品對另一件物品使用。從選單中依序選取物品」）。

**六個指令分成兩組**（`docs/re/95` §3.8）：`T`／`M` 選**腳下這一格**的
（`222f:2da5`），`E`／`D`／`U` 選**哪個角色的第幾格**（`122f:1d23`）。
規格原本把 `E` 寫成「選一件腳下的」，那是推的。

### 動作碼（`+5` 的第一個字元，內容從第二個字元起算）

| 碼 | 動作 |
|---|---|
| `D` | 印一段敘述 |
| `N` | 目標**變成另一件**（參數是新名字）。`Use on: Room`：手上那件用掉、目標從地圖上消失、**新道具放在腳下**；`Use on: Character`：目標那一格變成新道具（型別 `0xfe`）|
| `T` | 傳送：參數 `XXYYMM` → 隊伍的 X／Y／子地圖 |
| `P` | 改地圖 tile：`map[YY×64 + XX] = MM`，並把整張圖寫回 `MAPn.MAP` |

`T`／`P`／`+3` 的參數**共用一套解析**：前兩組固定兩位，第三組讀到結尾。
（原版三段程式碼寫法不同但結果相同 —— 五個字元的 `T07203`／`P04480`
第二個字元讀到的是結尾的 NUL。**別寫成「三組兩位數」**。）
| `S` | 主線（見下）|

`+3` 與 `P` 是同一種動作，共用參數格式。

### `S` 的兩條

```
S1   if (劇情階段 +0xb9 == 0)  播第 2 段劇情，結束
     if (+0xc1 != 0)           已經做過了，結束
     播第 3 段劇情 → 「Who wishes to become a god?」→ 選一名角色
S2   播第 7 段劇情 → 隊伍傳送到 (11, 27)
```

**`S1` 就是結局的不朽／凡人抉擇**（`docs/re/82`、`ending.go` 已實作），
觸發點是冰之祭壇 ＋ 祈禱卷軸。`+0xc1` 是它的一次性閂鎖。

**`S2` 是光之環**（`Circle light` ＋ `Facet mirror`），
接到 `docs/re/59`–`61` 的破關路徑上。

## 邊界條件

| 情況 | 行為 |
|---|---|
| 同一格超過 9 件 | 只列前 9 件 |
| `+1` 非空 | 拿不走。有話就印那句（`tr.Event`，索引 `164 + i×6 + 1`），只有 `*` 就印 `You can't` |
| 角色道具欄滿了 | 拿不起來，印 `No more room.`（ds:0x27b6）。**這一步在選完角色之後才發生** |
| 拿不走的東西 | 清單裡**只列名字**，理由等選了才說 —— 接在名字後面會被 21 格的欄寬裁掉半句 |
| 丟棄時名字對不上 | 拒絕。原版沒有這道檢查，會拿 `i = 51` 去寫有效區之外 |
| 位置表子地圖 ＝ 0 | 那一筆等於不存在，不參與任何比對 |
| `U` 用錯東西 | 印失敗訊息，**不消耗任何東西** |
| 新遊戲 | 從 `ITEMLOCX.DAT` 重建 `ITEMLOCB.DAT` |

## 驗收

1. **資料層**（已完成）：`gamedata.ParseItemLoc` 50 筆、`LoadDungeonItems`
   50 件 × 6 欄，18 個 `+4` 全部命中清單、`N` 的參數全部命中。
2. **拿與丟的往返**（已完成）：地圖 1 (14,22) 拿 `Iron key` → 丟 → 撿回來；
   (13,22) 的 `Bed` 印 `It is too heavy` 且留在原地；(13,26) 同一格兩件血清
   各自拿得到。存檔逐位元組比對：`ITEMLOCB.DAT` 只有那一筆的三個 byte 變 0，
   `PARTY.DAT` 往返 0 差異，重讀後 `0xfe`／`Red serum` 都還在。
3. **`M` 的地圖寫回**（已完成）：地圖 3 (46,12) 推 `Old bookcase` → (46,11)
   的牆開了；再推一次說「什麼也沒發生」；`MAP3.MAP` 只有 offset 751
   一個 byte 從 `0x31` 變 0；**關掉重開之後還是推不動**。
4. **一條完整的解謎鏈實跑**：`Cage` ＋ `Mallet` → `Iron key`，
   而且西牆的密門真的開了。
5. **`S2` 接到主線**：`Circle light` ＋ `Facet mirror` → 傳送 (11,27)。

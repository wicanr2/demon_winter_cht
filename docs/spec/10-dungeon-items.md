**地城解謎的全部內容在這裡** —— 主線的線索（Qoorik、Asaht、魔晶、
冥河擺渡人、光之環）都是從地城道具的敘述裡給出來的。

---

## 行為

地城道具與一般道具是**兩種東西**，手冊講得很清楚：

| | 一般道具 | 地城道具 |
|---|---|---|
| 性質 | 通用（劍、鎖子甲、火把）| **獨一無二、有特定用途**（鐵砧、花朵、金鑰匙）|
| 清單顯示 | 無前綴 | 前面加 `/` |
| 什麼時候用 | **紮營時** | **移動途中** |
| 丟掉之後 | 再也拿不回來 | **一定撿得回來**（原地）|
| 價值 | 可賣 | 沒有價值、不能賣 |

## 資料

### 位置：`ITEMLOCB.DAT`（50 筆 × 3 bytes）

```
[X, Y, 子地圖]      子地圖 0 ＝ 這一筆已經被拿走
```

**這個檔是存檔的一部分**：拿走一件時原版就地把子地圖寫 0（`0x18397`）。
`ITEMLOCX.DAT` 是出廠母本 —— 與 `nSS.DAT` vs `ALL_SS.DAT` 同一個模式
（`docs/re/78`），**存回沿用那條路，不要新設計**。

載入走通用資源迴圈（`0x11fc2`）：六筆檔名表 `ds:0x14c9` 索引 2 → arena 槽 2。

### 內容：`FILES.DTT` 索引 164–463（50 件 × 6 條）

索引與位置表**同一個 `i`** 對齊。

| 欄 | 語意 | 非空 |
|---|---|---|
| `+0` | 名稱 | 50 |
| `+1` | 拿不走的理由（`*` ＝ 拿不走但沒話說）| 25 |
| `+2` | 檢視敘述 | 48 |
| `+3` | 推開之後改哪一格 tile（`*` ＝ 沒事）| 19 |
| `+4` | 要搭配哪一件道具（存的是**名字**）| 18 |
| `+5` | 用對之後的動作，**首字元是動作碼** | 18 |

`50 × 6 = 300`，用完 `docs/re/27` 第 6 張表 303 條裡的前 300 條。

### ⚠ 拿在手上時放哪裡 —— **未定案，擋住 `T` 與 `U` 的實作**

原本這裡寫「17-byte 的槽，型別 `0xff` ＋ 16 字名字」。
**那個讀法與既有的 `slotEmpty = 0xff` 直接衝突**，已在 `docs/re/95` §3.1 降級。

`0xfe` 可能才是地城道具的型別（`0xff` 是清空來源槽），但**沒有追完**。

**這一節定案之前，`T` 拾取與 `U` 使用不要實作** ——
它們都要把東西放進道具欄。`E` 檢視與 `M` 移動不碰道具欄，可以先做。

## 演算法

### 列出腳下這一格有什麼（`222f:2da5`）

```
found = 0
for i = 0; i < 50 && found < 9; i++:
    if itemloc[i] == (隊伍X, 隊伍Y, 隊伍子地圖):
        清單[found] = i
        found++
return found
```

**上限 9**（原版 `cmp [bp-2],9`）。手冊說「每個位置最多只能放 10 件」，
兩個數字都留著，以 9 實作。

### 六個指令

| 鍵 | 行為 |
|---|---|
| `I` 探查周圍 | 掃視野內所有格，把有道具的位置畫出圖示。**掃描範圍未讀**，先比照 `L` 用光源強度 |
| `E` 檢視 | 選一件 → 顯示 `+2` |
| `T` 拾取 | 選一件 → `+1` 非空就印那句話並拒絕；否則放進第一個空槽，位置表那一筆的子地圖清 0。**擋在「槽的型別」定案之前** |
| `D` 丟棄 | 選一個槽 → 清空槽，在**目前座標**新增一筆位置表記錄 |
| `M` 移動 | 選一件 → `+3` 是 `*` 就沒事；是數字就照 §動作碼的 `P` 改 tile |
| `U` 使用 | 選一個**隨身道具** → 再選一件**腳下的地城道具** → 名字比對 `+4`；對了跑 `+5` 的動作，錯了印失敗 |

`U` 是兩段式的（手冊：「用手上持有的物品對另一件物品使用。從選單中依序選取物品」）。

### 動作碼（`+5` 的第一個字元，內容從第二個字元起算）

| 碼 | 動作 |
|---|---|
| `D` | 印一段敘述 |
| `N` | 這一格的道具**變成另一件**（參數是新名字）；同時把原本那一筆的位置清 0 |
| `T` | 傳送：參數 `XXYYMM`，**逐 2 位數 `atoi`** → 隊伍的 X／Y／子地圖 |
| `P` | 改地圖 tile：參數同樣三組 2 位數 → `map[YY×64 + XX] = MM` |
| `S` | 主線（見下）|

`+3` 與 `P` 是同一種動作，共用參數格式。

### `S` 的兩條

```
S1   if (劇情階段 +0xb9 == 0)  播第 2 段劇情，結束
     if (+0xc1 != 0)           已經做過了，結束
     播第 3 段劇情 → 「Who wishes to become a god?」→ 選一名角色
S2   播第 7 段劇情 → 隊伍傳送到 (11, 27)
```

**`S1` 就是結局的不朽／凡人抉擇**（`docs/re/82`、`ending.go` 已實作），
觸發點是冰之祭壇 ＋ 祈禱卷軸。`+0xc1` 是它的一次性閂鎖。

**`S2` 是光之環**（`Circle light` ＋ `Facet mirror`），
接到 `docs/re/59`–`61` 的破關路徑上。

## 邊界條件

| 情況 | 行為 |
|---|---|
| 同一格超過 9 件 | 只列前 9 件 |
| `+1` 非空 | 拿不走。有話就印那句，只有 `*` 就印通用的拒絕訊息 |
| 角色道具欄滿了 | 拿不起來（沿用 Trade 的 `%s is full`，`docs/re/33` §4）|
| 位置表子地圖 ＝ 0 | 那一筆等於不存在，不參與任何比對 |
| `U` 用錯東西 | 印失敗訊息，**不消耗任何東西** |
| 新遊戲 | 從 `ITEMLOCX.DAT` 重建 `ITEMLOCB.DAT` |

## 驗收

1. **資料層**（已完成）：`gamedata.ParseItemLoc` 50 筆、`LoadDungeonItems`
   50 件 × 6 欄，18 個 `+4` 全部命中清單、`N` 的參數全部命中。
2. **拿與丟的往返**：拿走 → 存檔 → 重讀 → 那一格空的；
   丟下 → 存檔 → 重讀 → 撿得回來。**逐位元組對 `ITEMLOCB.DAT`**。
3. **一條完整的解謎鏈實跑**：`Cage` ＋ `Mallet` → `Iron key`，
   而且西牆的密門真的開了。
4. **`S2` 接到主線**：`Circle light` ＋ `Facet mirror` → 傳送 (11,27)。

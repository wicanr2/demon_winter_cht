# 戰鬥系統

> 狀態：**DRAFT**（框架、普通攻擊、一般法術為 READY；
> 即死／束縛／召喚三類與 `Use` 效果套用仍缺，見文末「仍未解」）
> 證據來源：`docs/re/06-combat-system.md`、`docs/re/09-spells-and-actions.md`
> 最後複核：2026-07-25（協調者複核武器骰表與動作跳表）

---

## 行為

戰鬥在一個網格戰場上進行，最多 15 個單位同場。
每回合開始時，全部單位（玩家與怪物混在一起）**依速度屬性降冪重排**，
然後依序行動——**不是**「玩家全體行動完再換敵人」的兩段式。

每個單位輪到時，從選單挑一個動作。動作消耗行動點；點數耗盡就換下一個單位。
全部單位行動完畢即為一回合結束（顯示 `End of round`）。

勝負：怪物全滅顯示 `All monsters dead`；隊伍全滅為戰敗。

## 演算法

### 單位行動順序

```
回合開始：
  將 15 個槽位（0-6 = 怪物，7-14 = 玩家）依速度屬性降冪排序
  依排序後的順序，每個存活單位輪流行動
```

### 動作分派

動作編號由 `138d:258f` 的跳表索引（19 → 實為 15 項，`CMP AX,0xf` 邊界檢查）：

| case | 動作 | 狀態 |
|---|---|---|
| 5 | Attack 攻擊 | READY |
| 6 | Cast 施法 | DRAFT（見下） |
| 7 | Use 使用道具 | 未解 |
| 8 | Turn Undead 驅散不死 | READY |
| 9 | Dodge 閃避 | READY |
| 10 (0xa) | Examine 檢視 | READY（純顯示，不耗行動點） |
| 11 | Sound 音效開關 | READY（非戰鬥行為） |
| 12 | Pray 祈禱 | READY |
| 13 | Leech 汲取 | READY |

> **警告**：`docs/re/06` 舊版曾把 case 0xa 標為 Attack 並註記「已驗證」，那是錯的
> （反編譯誤判）。正確編號如上表，來源是原始跳表。
> 協調者複核：case 5 進入點先檢查行動點 `[0x5190] >= 3` 再索引戰鬥單位陣列（有成本）；
> case 0xa 只做一次 far call 後返回（純顯示）。

### 普通攻擊（case 5）— READY

```
命中判定：
    命中率 = 攻擊者技巧 × 4 + 各項修正
    若 Roll(100) <= 命中率 → 命中，否則落空（顯示 misses.）

傷害計算（命中時）：
    傷害 = Roll(武器最大傷害)
         + (力量 − 7) / 2        ← 力量加成
         + 附魔加成
    若爆擊 → 傷害 << 1（乘二）
    傷害 −= 目標護甲值
    最終傷害套用到目標 HP
```

**全程整數運算，不使用浮點**（PLAN V7 已結案）。

玩家與怪物的普通攻擊**共用同一套核心邏輯**（`FUN_1990_0002` → `FUN_138d_25da`），
Go 引擎不必分兩份實作。

### Turn Undead（case 8）— READY

```
成功率 = (18 × (智力 − 等級) + 18) / 5
若 Roll(100) <= 成功率 → 目標 HP 歸零（即死）
```

### Dodge（case 9）— READY

```
狀態計數 = [0x5190] / 3
效果：對命中率的修正為 ×(−4)
```

### Pray（case 12）— READY

```
若 Roll(100) <= chance → 成功，且 chance −= 5（永久遞減）
```

初始 `chance` 值與手冊記載的 20% 一致，但**初始化位置未逐指令確認**。

### Leech（case 13）— READY

```
若 Roll(100) <= 2 × 智力 → 成功，目標損失當前 SP 的一半
```

### 法術參數表 — READY（2026-07-25 找到）

**位置：`DEM_DATA/FILES.DAT`，offset `0x45e`–`0x60c`，43 筆 × 10 bytes。**

不在 `DEMON.INT` 裡 —— 這是先前一直找不到的原因。
（附帶意義：`FILES.DAT` 曾被判定「不是資源索引」，那個否證仍然成立，
但它確實裝著結構化的遊戲資料表，不是雜項。）

每筆 5 個 signed 16-bit word：

| 欄位 | 位移 | 意義 |
|---|---|---|
| `school_id` | 0 | 所屬符文系 |
| `effect_type` | 2 | 效果類型（決定套用到哪個屬性欄位） |
| `K` | 4 | 效果強度係數（正負決定增益/傷害方向） |
| `M` | 6 | **最低施法 SP**（= 通式裡的 M） |
| `w4` | 8 | 未解 |

索引 `0..42` 與 `FILES.DTT` 裡的「名稱 + 訊息」字串對順序 1:1，
也就是 `FUN_1000_114f` / `FUN_1000_293d` 已在用的 `spell_index`。

**`M` 就是最低施法成本**，這點有程式碼直證：`FUN_1000_11e5` 裡有
`if (SP < M) → 失敗並顯示 "not enough points"`。

**驗證**：35 個法術全數找到，34 個與手冊記載的最低 SP 完全吻合。
唯一例外是魔法火炬（Magic Torch）：手冊與攻略記 3，表記 2 ——
研判手冊描述的是某個效果基準而非硬性下限。
`Resurrect` 的 `K = M = 25` 正好重現手冊「25 點、25% 機率」的說法。

> 協調者獨立複核：以多重集合比對，glossary 的 35 個最低 SP 值在 `M` 欄中
> **只缺一個 `3`**，與上述唯一例外完全一致。35 個任意數值對上特定欄位、
> 只差一個，不是巧合。（順序未獨立驗證，只驗了集合。）

**修正 `docs/re/09` 兩處猜測**：`effect_type 8` 是復活（不是幻術）、
`effect_type 0x11`(17) 是御風而行/傳送（不是復活）。

### 法術效果通式 — 現已可實作

兩個獨立函式（`FUN_1000_11e5`、`FUN_138d_10bc`）給出同一個骨架：

```
magnitude = Roll(K × SP / M)
若 magnitude < 上限的 1/3 → 重擲
K 的正負決定「增益」或「傷害」方向
效果類型 ID 決定套用到 HP / 技巧 / 力量 / 速度 / 護甲 哪個欄位
非 HP 屬性鉗制於 [3, 255]
```

> 屬性下限 3 這一條**恰好對上攻略記載的「屬性不會低於 3」**，是強力交叉驗證。

`K` / `M` 常數已找到（見上方「法術參數表」），**這條通式現在可以實作**。

仍缺的是幾類特殊法術的**判定邏輯**（不是常數）：即死（`effect_type 2`）、
束縛的施加與解除（`10`/`11`）、枯萎（`14`）。這些法術的 K/M 有了，
但「豁免怎麼判、束縛狀態怎麼儲存」還沒解，所以那幾個法術仍不可實作。

## 邊界條件

| 情況 | 行為 |
|---|---|
| `Roll(n)` 的 n ≤ 1 | 回傳 1 且不推進 RNG（見 `01-rng.md`） |
| 傷害減護甲後為負 | **未確認**是否鉗制為 0 或允許負值 |
| 屬性增減 | 非 HP 屬性鉗制 `[3, 255]`（已驗證） |
| Pray 的 chance 遞減至 ≤ 0 | **未確認**是否有下限 |
| 單位死亡時的排序 | **未確認**已死單位是否仍佔排序槽位 |

## 驗收

1. **武器傷害範圍**：對每種武器擲 1 萬次，觀測值必須落在 `[1, 表中最大值]` 且涵蓋端點。
2. **命中率**：固定技巧值，統計命中比例，應趨近 `技巧 × 4 / 100`。
3. **與 DOSBox 原版對拍**（尚未做，最終驗收）：固定種子、固定隊伍與敵人，
   逐回合比對傷害數值序列。

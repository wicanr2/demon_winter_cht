## 行為

踏上特定格子會觸發事件：顯示敘述文字、進入戰鬥、或被傳送到別處。

事件文字存在 `DATA*.TXT`（NUL 分隔的變長記錄，只能從頭 parse）。
座標與事件的對應存在 **`nSS.DAT`**（每張子地圖一份；下文所有寫
`EXITS.DAT` 的地方都指這個，見上方訂正）。切換地城時緩衝區的內容會被**整份覆寫**。

## 資料

| 來源 | 用途 |
|---|---|
| `EXITS.DAT` → 遠指標 `0x5514`/`0x5516` | 3-byte 記錄 `[X, Y, type]`，以 `[0,…]` 結尾。**緩衝區 511 bytes**（比 330 bytes 的檔案大，尾端留給傳送目標）|
| `DATA%d.TXT` | 事件文字與戰鬥定義，記錄變長、NUL 分隔 |
| `0x4c94` | 當前地圖 tile 陣列（64×64）|
| `0x52f4` / `0x52f6` | **共用的輸入／輸出參數對**（見下）|
| `0x5c62` | 上一次查詢得到的事件類別 |

### `type` 位元組的拆法

```
類別 = type >> 5        （0–7）
子值 = type % 32
```

真實 `EXITS.DAT` 只用到類別 0、1、2、4。

## 演算法

### `0x52f4` / `0x52f6` 是雙用途的

這對全域**先當輸入、再被覆寫成輸出**。實作時要照這個語意，
否則會誤以為 `0x52f4` 恆為「記錄索引」：

```
呼叫前：  0x52f4 = 查詢 X，  0x52f6 = 查詢 Y
呼叫後：  0x52f4 = 事件索引，0x52f6 = 子值（傳送類則為目標座標）
```

### 主路徑：座標 → 事件索引

```
事件計數 = 0
傳送計數 = 0
掃 EXITS.DAT 的 3-byte 記錄:
    若 record[0] == 0            → 回傳 0xff（此座標無事件）
    若 record[0]==X 且 record[1]==Y → 命中，跳出
    cat = record[2] & 0xe0
    若 cat ∈ {0x20, 0x40}        → 事件計數 += 1     （類別 1、2）
    若 cat == 0x80               → 傳送計數 += 1     （類別 4）
    下一筆

命中後:
    [0x52f8/0x52fa] = 該記錄的遠指標
    [0x52f4] = 事件計數
    [0x52f6] = record[2] % 32
    類別    = record[2] / 32
    [0x5c62] = 類別
    若 類別 ∈ {1, 2} → [0x52f4] += 1
    若 類別 != 4     → 回傳 類別

    // 類別 4 = 傳送
    idx = 0x1ff − (傳送計數 × 2 + 2)
    [0x52f4] = 表[idx]        ← 目標 X
    [0x52f6] = 表[idx + 1]    ← 目標 Y
    回傳 目標 Y
```

> **傳送目標存在同一張表的尾端、反向成長**：記錄從表頭往後排，
> 傳送目標座標對從 `0x1ff` 往前排。第 n 個傳送點的目標在 `0x1ff − (2n + 2)`。

**事件索引的語意**：`DATA*.TXT` 是變長記錄，無法隨機定位，
所以這個索引是「從頭 parse 到第幾筆」的計數，由讀取函式當迴圈上限用。

### 觸發閘門：不是每步都查

移動後讀新座標的 tile 值：

```
tile（遮罩後）== 0x11 或 0x53  → 呼叫事件檢查（走上面的主路徑）
tile == 0x35                   → 回傳動作碼 0x11，完全不查特殊格清單
```

> ⚠ 這裡原本寫「`0x35` ＝ 寫死的阻擋」，**那是 `docs/re/05` 當年的推測，已推翻**
> （`docs/re/90`）。`0x35` 是一口**治療用的水池**：隊伍不會走上去，但要選一名角色
> 喝水回 1–4 HP，額度是隊伍共用、一天七次（trailer `+0xaa`，睡覺補回 7）；
> 用完印 `The pool is empty`。「不移動」這半對，「什麼都不發生」是錯的。

### 第二路徑：五個特殊 tile 直接當索引

**這條路徑完全不經過 `EXITS.DAT`**：

```
若 tile ∈ {0x25, 0x26, 0x2e, 0x5b, 0x64}:
    [0x52f4] = tile 值本身        ← tile 值直接就是 DATA*.TXT 的記錄索引
    [0x50f0] = X, [0x50ee] = Y
    回傳 0x13
```

> 這五個值是逐位元組解出來的 —— Ghidra 在此處失步，把
> `CMP AX,0x64 / JZ` 整組漏掉了，只讀反組譯輸出會少一個 tile。

### 事件分派與讀取文字

拿到類別（`0x5c62`）與事件索引（`0x52f4`）後，由事件處理器依類別分派：

```
若 類別 ∈ {3, 6}  → 走各自的特殊處理
若 類別 == 5      → 走另一條（顯示鑑定相關訊息）
否則（含 0、1、2、4、7）:
    若 類別 == 1 且 struct[+0xa5] != 0:
        改寫該 EXITS 記錄的 type byte = (類別 << 5) + 1
        若 struct[+0xa5] != 3 → 歸零該旗標並返回
    從頭 parse DATA%d.TXT，消耗到第 [0x52f4] 筆記錄，顯示文字
    若該記錄的 count != 0 → 進入戰鬥（見 02-combat.md）
```

> **判定條件是「類別 != 5」，不是「類別 ∈ {1, 2}」。**
> 佔 94/110 的類別 0 會正常顯示事件文字。
> 早期文件曾說「類別 0 不觸發任何事」，那是看錯了函式
> （看的是座標查表的閘門，不是事件消費者）。

**這條路徑不會重新查座標** —— 它直接消費已經設好的 `0x52f4`／`0x5c62`。

### 一次性遭遇的消費

戰鬥結束後：

```
0x52f4 = 隊伍 X;  0x52f6 = 隊伍 Y
重新查一次座標（取得該記錄的遠指標 0x52f8）
*(byte *)(0x52f8 + 2) = 0        ← 把該筆 EXITS 記錄的 type byte 清零
```

清零後該座標的類別變成 0，也不再被計入事件計數 —— **打完就不再重複觸發**。

## 邊界條件

| 情況 | 行為 |
|---|---|
| 座標不在 `EXITS.DAT` 裡 | 掃到 `record[0] == 0` 的結尾標記，回傳 `0xff` |
| 類別 1 / 2 | 事件索引額外 `+1` |
| 類別 2 | 另外武裝一個「防止同格重複觸發」的倒數計時器（`0x4e2e`）|
| 切換地城 | `EXITS.DAT` 內容整份被覆寫；快取要跟著失效 |

## 驗收

1. **表格掃描**：用真實 `EXITS.DAT`（110 筆 3-byte 記錄）跑一次完整掃描，
   結尾標記必須在第 110 筆之後被命中。
2. **類別分布**：解出的類別統計必須是類別 0 佔 94 筆、其餘為 1/2/4。
3. **傳送目標**：對每個類別 4 的記錄，`0x1ff − (2n+2)` 算出的索引必須落在表內
   且指向合理的 64×64 座標。
4. **與 DOSBox 原版對拍**（尚未做，最終驗收）：
   走進一個已知的「純文字房間」，比對顯示的文字與本規格算出的記錄索引。

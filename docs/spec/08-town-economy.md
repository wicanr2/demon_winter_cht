> 狀態：**READY**

---

## 行為

城鎮是遊戲的補給與成長中心。隊伍進城後可以造訪六類設施：

| 設施 | 提供什麼 |
|---|---|
| 神殿／教堂 | 捐獻換經驗、祈禱恢復神祇好感度、改宗 |
| 學院 | 花智力點數學技能（每間只教一種）|
| 公會 | 升級（免費）|
| 酒館 | 買糧、打聽消息（與公會共用同一個選單函式）|
| 碼頭 | 買船、修船 |
| 治療所 | 治療、解毒、解除束縛、復活 |
| 市集 | 購買、議價、出售、鑑定 |

**幾乎所有價格都由單一的「城鎮經濟係數」推導**（見下）。這是本系統最重要的結構特徵：
不是每個設施各有一張價目表，而是一個城鎮一個物價指數。

---

## 資料

| 來源 | 用途 |
|---|---|
| 城鎮資料表（執行期指標 `0x5534`）→ **就是 `TOWN<n>.DAT` 檔案本身**（512 bytes）| `+0x1ed` = **經濟係數 E**；`+0x1f5` = 船價基礎值 |
| `FILES.DAT` `0x158` | **技能學費表** 31 技能 × 10 職業，1 byte／格，值域 1–10 |
| `ITEMS.DAT` 欄位 0 | 商品基礎價（全遊戲共用一份）|
| 角色記錄 | `+0xeb` 神祇好感度、`+0xec` 束縛等級、`+0xf0` 信仰、`+0xf4` 等級、`+0xf5` 種族、`+0xf6` 職業、`+0xc8`–`+0xe6` 技能旗標 |
| 全域狀態 `0x4c76` | `+0xa`/`+0xc` = 隊伍金幣（32-bit）、`+0x9a` = 隊伍人數、`+0xa8` = 當地學院教的技能 id |

隊伍金幣與角色經驗值都是 **4 bytes 儲存、數值封頂 `0x00FFFFFF`**。

## 演算法

### 城鎮表就是 TOWN<n>.DAT（2026-07-26 確認）

反組譯看到的是遠指標 `0x5534` 指向「當前城鎮資料表」。那個緩衝區
**就是載入的 `TOWN<n>.DAT`** —— 檔案剛好 512 bytes，兩個已知位移都落在檔內。

兩個獨立證據：

1. **值域**：`+0x1ed` 在 25 座城鎮的值落在 8–25，正好是物價指數該有的分佈。
   隨便挑一個位移不會剛好給出這麼窄又這麼合理的範圍。
2. **稀疏性 + 攻略佐證**：`+0x1f5` 只有 5 座非零（Janthrin、New Gleon、
   Dragontooth、Asaht、Land's Edge），其餘 20 座為 0 —— 只有碼頭城鎮賣船。
   攻略明寫「前往東北方很遠的**新格里昂**，買一艘船」，
   New Gleon（第 8 座）正是那 5 座之一，船價 61 × 10 = 610 金。

| 城鎮 | E | 船價 |
|---|---|---|
| Janthrin(7) | 10 | 570 |
| New Gleon(8) | 13 | 610 |
| Dragontooth(11) | 20 | 670 |
| Asaht(14) | 9 | 680 |
| Land's Edge(24) | 12 | 600 |

實作：`internal/assets/gamedata/town.go`，驗收條件寫成測試。

### 城鎮經濟係數 E — 一切價格的基礎

`E = 城鎮資料表[+0x1ed]`（1 byte）。八個地方用到它：

| 用途 | 公式 |
|---|---|
| 市集買價 | `商品基礎價 × E / 10` |
| 市集鑑定 | `E × 5`（與道具無關）|
| 酒館糧食單價 | `E / 5`，**下限 1** |
| 碼頭修船 | `(75 − 目前船體值) × E / 2` |
| 治療所・治療 | `E / 5` 每點傷害 |
| 治療所・解毒 | `E × 4`（固定，不乘任何欄位）|
| 治療所・解除束縛 | `47 × E / 5` 每級 |
| 治療所・復活 | `E × 10` 每級 |

**全部整數除法。** 兩個例外不看 E：碼頭買船 `= 城鎮表[+0x1f5] × 10`、
市集**賣價**（見下）。

### 神殿

> 神祇編號 1–10 奇偶交錯（奇數薩滿、偶數司祭），11 是 Ancient One。
> 改宗學會的技能是 `0x10 − (神祇編號 mod 2)`，祈禱**要求先改宗到這座神殿**
> （既要有該教派技能、信的也要是同一位神）。見 `docs/re/29`。

```
捐獻:  輸入金額 N（需 1 ≤ N ≤ 隊伍金幣）
       隊伍金幣 −= N
       該角色.EXP += N                      ← 1:1，無倍率
       EXP 封頂 0x00FFFFFF

祈禱:  若角色.信仰 != 本神殿的神 → 失敗訊息
       若角色.好感度(+0xeb) == 20 → 「已經處於良好關係」
       費用 = 角色.等級 × 50
       付費後 角色.好感度 = 20

改宗:  若角色.信仰 == 目標神 → 失敗
       需要的智力點數 = 技能學費表[司祭或薩滿][角色職業]
       若 剩餘可用智力點數 < 需要點數 → 失敗
       不扣金幣，設定信仰與對應技能旗標，好感度 = 20
```

> 改宗**不花金幣但花智力點數**，對應手冊「牧師會免費為你辦理，
> 但司祭／薩滿技能仍然需要花費智力點數」。

### 學院

每間學院只教一種技能。技能 id 來源：
先讀 `全域[+0xa8]`，若為 `0xFF` 則以隊伍座標查程式段內嵌的
`[X, Y, skill_id]` 三位元組表（最多 35 筆，`278d:342d`）。

```
若 角色已學過該技能 → 顯示已學過訊息
points   = 技能學費表[skill_id][角色職業]        （1–10）
金幣費用 = points × (5 × points + 25)
若 角色剩餘可用智力點數 < points → 「點數不足」
若 隊伍金幣 < 金幣費用 → 失敗
成功: 隊伍金幣 −= 金幣費用；技能旗標[skill_id] = 1
```

費用表（`points` 1→10）：30、70、120、180、250、330、420、520、630、750。

### 酒館

```
單價 = max(1, E / 5)
數量必須在 [1, 200]
總價 = 單價 × 數量
```

### 碼頭

```
買船: 價格 = 城鎮表[+0x1f5] × 10
      付費後在船塢四個相鄰方向格找一格放船；四格全滿 → 「碼頭滿了」

修船: 找一艘座標在隊伍位置 ±1 格內的船，找不到 → 失敗
      費用 = (75 − 船體值) × E / 2
      費用為 0（滿血）→ 「你的船看起來很好」
      付費後 船體值 = 75
```

船體滿值固定 75。

### 治療所

四項服務的費率先從 E 算出，再依角色狀態選一項：

```
費率: 治療 = E/5   解毒 = E×4   解束縛 = 47E/5   復活 = E×10

依 角色.狀態(+0x102):
  5（死亡）    → 費用 = 角色.等級 × 復活費率
  2/3/4（束縛）→ 費用 = 角色.束縛等級(+0xec) × 解束縛費率
  1（中毒）    → 費用 = 解毒費率            （固定，不乘）
  0（正常）    → 費用 = (最大HP − 目前HP) × 治療費率

付費後（四種情況共通）: 角色.狀態 = 0
  原為死亡 → 目前HP = 1；束縛等級 = 0
  原為正常 → 目前HP = 最大HP
```

> **城鎮復活必定成功**（沒有任何機率判定，只有金幣夠不夠），且只恢復 1 點生命 ——
> 與手冊一致。
>
> ⚠ **解束縛乘的是束縛等級（`+0xec`），不是角色等級。** 畫面標籤印
> `Unbind %3d/lvl`，那個 lvl 指的是束縛法術的等級。本專案一度拿角色等級去乘，
> 已訂正（`game.HealerQuote` 現在多收一個 bindLevel 參數）。

### 市集

#### 購買

```
標價 = ITEMS.DAT[商品].價格 × E / 10
```

商品基礎價全遊戲共用一份；城鎮只決定**賣哪些商品**與 E。

#### 議價

每件商品有一個議價狀態 `s`（30 件商品各一個 word）。

```
初始化（進入市集時）:
    s = 1
    若 隊伍中任一角色已學「說服」(技能 id 9) → s = 0
    30 件商品全部設為這個初始值

每次議價:
    1) 若 Roll(100) < s × 10:
           「你冒犯了商人」；s = 1000；此商品從此拒賣
    2) 否則若 Roll(100) < s × 15:
           「商人不為所動」；議價失敗，價格不變
           若 s < 100 → s += 100
    3) 否則:
           議價成功；s += 1

顯示價格:
    n = s
    若 n == −1 → n = 0
    若 n > 99  → n −= 100
    價格 = max(2, 標價 − 標價 × n × 0.06)
```

**每次成功議價打掉標價的 6%，下限 2 金幣。**

> 第 2 步的 `s += 100` 是關鍵設計：失敗一次後 `s ≥ 100`，
> 第 1 步的 `s × 10 ≥ 1000` 必定大於 `Roll(100)` 的上限 →
> **「商人不為所動」之後再議價，一定會觸怒對方並永久拒賣。**

風險曲線（有說服技能時）。**這張表是名目值** —— `Roll(100)` 回傳 `1..100`，
所以 `Roll(100) < s×10` 實際命中 `1..(s×10−1)`，機率是 `(s×10−1)%` 不是 `s×10%`。
`s = 2` 的實際分佈是觸怒 19%、談不攏 `81% × 29% = 23.5%`、成功 `81% × 71% = 57.5%`：

| 議價次數 | s | 觸怒 | 談不攏 | 成功 | 累計折扣 |
|---|---|---|---|---|---|
| 1 | 0 | 0% | 0% | 100% | 6% |
| 2 | 1 | 10% | 15% | 75% | 12% |
| 3 | 2 | 20% | 30% | 50% | 18% |
| 4 | 3 | 30% | 45% | 25% | 24% |
| 5 | 4 | 40% | 60% | 0% | — |

無說服技能時整條往前挪一格（第一次議價就是 `s = 1` 那一列）。

#### 出售

```
售價 = ITEMS.DAT[商品].價格 / 2        ← 不套用 E
道具槽型別欄設為 0xFF（清空）
隊伍金幣 += 售價，封頂 0x00FFFFFF
```

**買價套 E、賣價不套** —— 這是原版的不對稱設計，要照做。

#### 鑑定

```
若 道具槽[+0x10] != 0 → 「已經鑑定過了」
道具槽[+0x10] = 1
隊伍金幣 −= E × 5
```

## 邊界條件

| 情況 | 行為 |
|---|---|
| 金幣不足 | 各設施都先做 32-bit 比較，不足即中止，**不扣款** |
| 金幣／EXP 超過 `0x00FFFFFF` | 封頂在 `0x00FFFFFF`，不環繞 |
| 糧食單價算出 < 1 | 強制為 1 |
| 糧食數量 | 必須在 `[1, 200]`，超出即拒絕 |
| 議價價格算出 < 2 | 鉗制為 2 |
| 修船費用為 0 | 顯示「船況良好」並中止，不進入付費流程 |
| 碼頭四格全滿 | 顯示訊息，**不扣款** |
| 祈禱時好感度已是 20 | 顯示訊息，**不扣款** |
| 改宗時已信奉該神 | 顯示訊息中止 |
| 鑑定已鑑定過的道具 | 顯示訊息，**不扣款** |

## 驗收

1. **學費公式**：對每個 `points` 值 1–10 檢查金幣費用等於
   30/70/120/180/250/330/420/520/630/750。
2. **議價收斂**：模擬「有說服技能、連續議價到觸怒」1 萬次，
   統計第一次議價成功率必須是 100%、第二次 75%。
3. **價格一致性**：同一件商品在 E 不同的兩個城鎮，標價比例應等於 E 的比例
   （整數除法造成的誤差在 ±1 以內）。
4. **與 DOSBox 原版對拍**（尚未做，最終驗收）：在同一座城鎮買同一件商品，
   比對顯示的標價；反覆議價比對每次的顯示價格。

## 進城：世界座標 → 城鎮編號（READY）

原版沒有「城鎮編號」欄位存在地圖裡。判斷分兩步：

**第一步：這格是不是城鎮。** 剛踩到的 tile 值放在 `DS:0x52f4`，
只有 `0x2e` 或 `0x64` 才算城鎮（`DEMON.INT` 檔位移 `0x19192`）。
全世界 26 張子地圖總共只有 27 格這種 tile。

**第二步：是哪一座。** 拿隊伍座標去比對一張 25 筆的 `(X, Y)` 常數表
（`DS:0x2f86` = 檔位移 `0x28a86`），命中的那一筆的序號（1-based）就是城鎮編號，
拿去組 `town%d.dat`：

```
1b5d2  loop: inc  word [bp-0x5c]      ; 索引 += 2
1b5d5        inc  word [bp-0x5c]
1b5d8        inc  word [bp-0x58]      ; 城鎮編號++
1b5db  chk:  mov  bx,[bp-0x5c]
1b5de        mov  cl,[bx+0x2f86]      ; 表內 X
1b5e2        les  bx,[0x4c76]         ; 隊伍狀態
1b5e6        mov  al,es:[bx+0xa1]     ; 隊伍 X
1b5eb        cmp  al,cl / jne loop
1b5f2        mov  al,[bx+0x2f87]      ; 表內 Y，與 es:[bx+0xa2] 比
1b601        push [bp-0x58]           ; 命中 → 城鎮編號
1b605        mov  ax,0x3055           ; "town%d.dat"
```

`town%d.dat` 這個字串在整個執行檔只有這一處引用，所以是從字串反推函式找到的。
表的結尾不用猜：第 25 筆 `(1,3)` 之後緊接著一張遠指標表。

反方向，全世界 27 格城鎮 tile 只有 2 格不在表上（都在子地圖 54，語意未解）。

**兩個要注意的地方：**

1. 原版的查表迴圈**沒有上界**。它預設「呼叫進來就一定找得到」，
   座標不在表上會一路讀過頭。本專案的 `TownAt` 回 `ok=false`，不重現這個。
2. 比對只看 `(X, Y)`，**不看在哪張子地圖上**。25 組座標剛好兩兩相異所以夠用，
   但這是原版設計上的隱性約束，不是保證 —— `TestTownSites_AllDistinct` 守著它。

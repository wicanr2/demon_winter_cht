# 素材格式與渲染

> 狀態：**READY**（`OPEN.PIE` 未解，但有 CGA 版可替代，不擋開工）
> 證據來源：`docs/formats/graphics.md`（全部格式與肉眼比對）、
> `docs/re/07-sprite-blit.md`（EGA blit 與載入鏈的指令級證據）
> 最後複核：2026-07-25（**sprite frame 尺寸全面訂正**：CGA 16×16、EGA 16×28；
> 原本的 16×32／32×28 已推翻）

---

## 行為

遊戲有 CGA 與 EGA 兩套完整素材，開機時以 `INT 10h` 偵測顯示卡後擇一載入
（判別旗標 `DAT_31f0_19fb`：`0` = CGA、非 `0` = EGA）。

兩套素材內容相同、佈局不同。**兩套都要支援** —— 這是文化保存的完整性要求，
不是二選一。

---

## 資料

| 副檔名 | 類別 | 尺寸 | 狀態 |
|---|---|---|---|
| `.PIC` | CGA 全螢幕圖 | 320×200，2bpp | ✅ |
| `.PIC` | CGA 人像框（5,184 B）| 144×144 | ✅ |
| `.SHP` | CGA 精靈圖 | frame **16×16**，64 B | ✅ |
| `.PIE` | EGA 全螢幕圖／人像框 | 檔內 144×252，**顯示時 288×252** | ✅ |
| `.SHE` | EGA 精靈圖 | 檔內 frame **16×28**，224 B；載入加倍後記憶體內 32×28、448 B | ✅ |

## 演算法

### CGA 全螢幕圖 `.PIC`

```
320 × 200，2bpp，**線性排列**
每列 320/4 = 80 bytes，每 byte 4 個像素，MSB-first
調色盤 = CGA palette 1 高亮度：{黑, 亮青, 亮洋紅, 白}
```

> **不是** IBM CGA 硬體 framebuffer 的偶／奇掃描線交錯佈局。
> 這點只有肉眼比對抓得到 —— 兩種佈局的位元組數完全相同。

### CGA 精靈圖 `.SHP`

```
frame 16 寬 × 16 高，64 bytes/frame，2bpp，線性排列（同 .PIC）
每列 16/4 = 4 bytes
```

指令級證據：CGA 分支的視訊初始化寫入 `1d9f:018d MOV word ptr [0x5226],0x40`
（64 = 每個 frame 的檔內位元組數），並用同一個變數乘出各素材檔大小
（`× 0x66` = 102 → 6,528 = `DEMON.SHP`；`× 0x1b` = 27 → 1,728 = `CYPHER.SHP`）。
`CYPHER.SHP` 沒有特例，跟其他五個檔一樣是 16×16。

### EGA 全螢幕圖／人像框 `.PIE`

```
檔頭 16 bytes = 內嵌調色盤
之後 4 個 plane 依序排列（sequential，不是列內交錯）
MSB-first
檔內解碼尺寸 144×252（高度是 CGA 版的 1.75 倍）
```

**畫到畫面上是 288×252**：`FUN_217b_0884` 每列呼叫 `FUN_217b_0a95` 九次，
每次吃 2 個來源 byte 吐出 4 個 byte，等於 blit 當下做水平像素加倍
（18 bytes/列 → 36 bytes/列）。所以解碼器解出的 144 寬是**檔案內的半寬圖**，
不是最終顯示寬度。

### EGA 精靈圖 `.SHE`

```
檔內 frame 16 寬 × 28 高，224 bytes/frame，4-plane，無壓縮
frame 內位移 = row × 8 + plane × 2 + col   （col ∈ [0,2)）
```

指令級證據：EGA 分支的視訊初始化寫入 `1d9f:00bf MOV word ptr [0x5226],0xe0`
（224 = 檔內 frame 大小），並用它乘出檔案大小
（`× 0x66` = 102 → 22,848 = `DEMON.SHE`；`× 0x1b` = 27 → 6,048 = `CYPHER.SHE`）。
`CYPHER.SHE` 的 224 B 不是特例，是**所有** `.SHE` 的常態。

**載入時做水平像素加倍**（`1d9f:0101 SHL AX,0x1` → `[0x521a]` = 448）：
素材載入器 `FUN_1d9f_0a8b` 在 EGA 模式把副檔名 `.SHP` 改成 `.SHE`，讀檔後
比對副檔名字串（`DEMON.INT` 檔案位移 `0x27592`/`0x27596` 的 `"shE\0SHE\0"`），
命中就呼叫 `FUN_217b_0adf(size)` 就地把緩衝區 N bytes 展開成 2N bytes。
所以記憶體內的 frame 是 **32×28、448 bytes**，`FUN_217b_07cf` 寫死的
stride `0x1c0` 指的是這個，不是磁碟格式。

```
記憶體內位移 = row × 16 + plane × 4 + col   （col ∈ [0,4)）
```

兩者是**同一張圖**：檔案每列 8 bytes（4 個 plane 各 2 B），逐 byte 加倍後
每列 16 bytes（4 個 plane 各 4 B），plane 佈局結構同構，只有 rowBytes 從 2 變 4。
解碼器直接讀檔案時用 16×28，不需要模擬加倍。

EGA 寫入走 sequencer map mask（port `0x3c4`/`0x3c5`），目標畫面 640×350 十六色。

### EGA 素材的統一縮放規則

EGA 素材一律「**檔案存半寬、顯示時寬度 ×2、高度 ×1.75**」，差別只在
加倍發生的時機：`.SHE` 在**載入時**加倍（`FUN_217b_0adf`），
`.PIE` 在 **blit 時**加倍（`FUN_217b_0884` → `0a95`）。

### 3.5 倍規律的正確用法

`3.5 = 2（2bpp→4bpp）× 1.75（高度）`。這個分解**只約束總位元數**，
`.PIE` 人像框與 `.SHE` 精靈圖的檔案大小都符合。

**但它推不出佈局，也推不出尺寸。** sprite 這一項本專案連續猜錯兩輪
（16×32 → 32×28 → 實際 16×28，見 `CONTEXT.md` §5），
每一輪的錯誤版本都整除、都通過全部自動測試。

> **硬性驗收條件：任何視覺產物一律 dump 成 PNG，肉眼比對 DOSBox 原版截圖。**
> 不接受「解碼器沒報錯」或「測試綠」當作正確的證據。

## 邊界條件

| 情況 | 行為 |
|---|---|
| CGA/EGA 判別 | `DAT_31f0_19fb == 0` → CGA；非 0 → EGA。開機時以 `INT 10h` 決定 |
| `.PIE` 調色盤 | 每個檔自帶 16 bytes，不共用全域調色盤 |
| `.SHE` 載入 | 讀檔後就地水平加倍（`FUN_217b_0adf`）。重寫版直接以 16×28 解檔即可，不必複製這步 |
| `.FNE` 字型 | **不受加倍影響** —— 載入器只比對 `"SHE"` 字串。16×14 的結論見 `09-fonts.md` |
| 怪物素材分組 | `MONSTER` 的載入單位是 `[0x5226] << 3` = 8 個 frame（一隻怪物 8 個動作），240/8 = 30 隻 |

## 驗收

1. **逐檔 dump 比對**：每個素材檔解碼成 PNG，與 `workplace/dosbox/shots/` 的
   原版截圖肉眼比對。**這是硬性條件，不可用測試綠替代。**
2. **CGA/EGA 交叉一致性**：同一張人像框的兩個版本解碼後，圖案內容必須一致
   （只有色深與高度不同）。
3. **sprite 逐格自成一體**：每個 frame 必須是一個完整、自成一體的圖形。
   若看到「一格裡有 2 個或 4 個小圖左右／上下並排」，那是尺寸解錯把相鄰
   frame 疊起來的徵狀，不是美術打包慣例。
4. **sprite 兩套素材逐格對齊**：`.SHP` 與 `.SHE` 同索引必須是同一張圖，
   frame 數、順序、空白格位置全部一致（六個檔都已如此驗過）。
   `MONSTER` frame 0–7 必須是同一個戰士的 8 個姿勢。
5. **`OPEN.PIC`**：解出的畫面必須能看出魔鬼臉孔、`DEMON'S WINTER` 標題、
   `NOVOTRADE` 與 `STRATEGIC SIMULATIONS INC` 商標、下方製作人員名單。

## 未解 / 風險

| 項目 | 影響 |
|---|---|
| `OPEN.PIE`（102,160 B）| 唯一未解的素材。不符 3.5× 規律，六種候選尺寸全是雜訊。**不擋開工** —— 開場畫面可先用已驗證的 CGA `OPEN.PIC`。但依完整性原則，這項必須補上，不得以「只是開場畫面」為由跳過。可再試的方向：若它也走「檔案存半寬、顯示時加倍」的規則，實際顯示寬度會是解碼寬度的兩倍，候選尺寸表要照這個重算 |
| `DEMON`/`WINTER` 的第 102 格 | 這兩個檔的 102 格是地形圖塊集，對應 `FILES.DAT` offset `0x040` 可通行性表的 tile 0–100（101 項）；索引 101 未被該表涵蓋，用途未定 |
| 中文化的畫布尺寸 | 規劃拉到 640×400（中文需 16×16 點陣才可讀，英文 8×8 放大兩倍後同高）。見 `09-fonts.md` |

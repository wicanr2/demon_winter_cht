# 角色建立與升級

> 狀態：**READY**（全部有指令級或實測證據；擲點分佈與重擲次數已於 2026-07-26 由反組譯定案）

> `docs/re/21-skills-races-and-files-dat.md`（技能 id 表、種族表、種族修正公式）、

> 最後複核：2026-07-25（協調者以 `PARTY.DAT` 五名角色端到端解碼驗證整條鏈）

---

## 行為

建角流程：**選種族 → 擲屬性 → 選職業 → 選技能**。

角色的五項屬性是速度、力量、智力、耐力、技巧。種族決定屬性修正與上限，
職業決定各技能的學習成本，智力決定可用來買技能的點數。

升級在城鎮公會進行，**免費**。經驗值達門檻後等級 +1，
獲得 HP／SP 成長與 3 點屬性分配。

## 演算法

### 建角：屬性擲點

```
種族修正(race, attr) = (種族上限[race][attr] − 種族上限[0][attr]) / 4
                        整數除法，向零捨去，保留正負號

每一項屬性:
    屬性 = 2d6 + 種族修正(race, attr) + 1
    若 屬性 < 3 → 屬性 = 3
    若 race == 0（人類）→ 屬性 += 2
```

**擲點公式已從原版反組譯定案**（`DEMON.INT` 0x13bba–0x13c0d）：

```asm
13bba  mov ax,6 / call rnd     ; 第一顆 d6
13bc5  mov ax,6 / call rnd     ; 第二顆 d6
13bd2  add ax,cx               ; 兩顆相加
13bdb  call 106a:026c          ; 取種族修正
13be6  add ax,cx               ; + 種族修正
13be8  inc ax                  ; +1
13bec  cmp ax,3 / jge          ; 下限 3
13c02  cmp es:[bx+si+0xf5],0   ; 種族 == 人類？
13c0a  inc / inc               ; 人類 +2
```

> **原本推定的 `Roll(15)` 是錯的，已訂正。** 兩者的期望值剛好都是 8
> （2d6 期望 7 加上固定的 +1），所以「該種族平均」那一欄一直是對的，
> 從畫面上完全看不出問題 —— 錯的是**分布**：均勻 1–15 會擲出原版
> 不可能出現的 1、2、14、15，也沒有 2d6 往中間集中的手感。
> 期望值對不代表分布對。釘在 `TestRollTraits_MatchesOriginalDistribution`。

範圍：不含種族修正時 3–13（下限 3 剛好等於 2d6+1 的最小值，兩者在此重合）。

種族修正表（由上式算出）：

| 屬性 | 人類 | 精靈 | 矮人 | 黑暗精靈 | 巨魔 |
|---|---|---|---|---|---|
| 速度 | 0 | 0 | −1 | 0 | −1 |
| 力量 | 0 | −2 | +1 | −2 | 0 |
| 智力 | 0 | +2 | −2 | +2 | −3 |
| 耐力 | 0 | −1 | 0 | −1 | +2 |
| 技巧 | 0 | 0 | 0 | −1 | 0 |

> ⚠ **手冊附錄的巨魔那一列有誤。** 手冊記「力量 −1、智力 −3、耐力 +2」且無速度修正；
> 實際是「速度 −1、力量 0」。DOSBox 截圖與本公式獨立吻合，見 `docs/re/21` §3.3。

> **人類的 +2 是手冊沒寫的。** 手冊記人類「優缺點：無」，但程式碼給每項 +2、
> 五項共 +10。這解釋了攻略作者「不知道為什麼人類擲骰就是比較好」的觀察。

### 建角：初始值

```
初始最大 HP  = 耐力（種族修正後的最終值），1:1
初始技能點   = 智力，1:1
初始 SP      = 依職業而異（巫師 = 智力、遊俠 = 0；其餘職業未逐一測試）
初始等級     = 1
```

### 剩餘可用智力點數

學院教技能與神殿改宗都要用到：

```
剩餘 = 角色.智力(+0xf9)
for skill in 0..30:
    若 角色.技能旗標[skill] == 1:
        剩餘 −= 技能學費表[skill][角色職業]
```

也就是**智力就是技能點總量**，已學技能各自扣掉自己的成本。

### 升級：門檻檢查

```
若 角色.EXP(32-bit) < 門檻表[角色.等級] → 顯示「還需要 N 點經驗」，不升級
```

門檻表以浮點方式存取，本專案尚未從程式碼逐一解碼，但**英文原版手冊第 6 頁列出完整 20 級表**：

| 級 | 經驗 | 級 | 經驗 | 級 | 經驗 | 級 | 經驗 |
|---|---|---|---|---|---|---|---|
| 1 | 300 | 6 | 4,600 | 11 | 66,400 | 16 | 1,217,500 |
| 2 | 700 | 7 | 7,500 | 12 | 118,000 | 17 | 2,189,300 |
| 3 | 1,100 | 8 | 12,600 | 13 | 210,800 | 18 | 3,938,200 |
| 4 | 1,800 | 9 | 21,600 | 14 | 377,600 | 19 | 7,086,100 |
| 5 | 2,800 | 10 | 37,700 | 15 | 677,600 | 20 | 12,752,200 |

> 表值取自手冊掃描（`demons_winter_rulebook.pdf` p.6），未與程式碼的浮點查表逐一核對。
> 攻略 `docs/walkthrough/part-1.md` 的經驗值表與此一致。

### 升級：等級與成長

```
角色.等級(+0xf4) += 1

HP:
    N    = 耐力(+0xfa) × 10 / 17 + 1          整數除法
    gain = max(Roll(N), Roll(N))               ← 擲兩次取較大
    最大HP(+0xfc) = min(255, 最大HP + gain)

SP:
    N    = 智力(+0xf9) / 2 + 1                 整數除法
    gain = max(Roll(N), Roll(N))               ← 同樣擲兩次取較大
    SP天生(+0xea) = min(200, SP天生 + gain)
    SP含加成(+0xfe) = min(200, SP含加成 + gain)   ← 同一個 gain 寫兩個欄位
```

> **升級不回血也不回魔**：`目前HP(+0xfd)`／`目前SP(+0xff)` 完全不被觸碰。
> 這與一般 CRPG 直覺不同，但要照做。
>
> HP 封頂 255、SP 封頂 200，**兩者不同**。

### 升級：3 點屬性分配

```
若 五項屬性總和 >= 該種族五項上限總和 → 跳過分配

重複 3 次:
    do {
        idx = Roll(5) − 1                      // 0..4 = 速/力/智/耐/技
    } while (該屬性目前值 == 種族上限[race][idx])   ← 已滿則重骰
    該屬性 += 1
    若 idx ∈ {速度, 力量, 技巧} → 對應的「含加成」欄位也 += 1
```

## 邊界條件

| 情況 | 行為 |
|---|---|
| 建角屬性算出 < 3 | 鉗制為 3（**在人類 +2 之前**套用）|
| 升級 HP 超過 255 | 封頂 255 |
| 升級 SP 超過 200 | 封頂 200 |
| 屬性已達種族上限 | 分配時重骰換一項；**總和已達上限總和則整個分配跳過** |
| 經驗值超過 `0x00FFFFFF` | 封頂（神殿捐獻與戰鬥獎勵共用同一個封頂檢查）|
| 剩餘智力點數不足 | 學院與改宗都會拒絕，不扣款 |

> **鉗制順序要注意**：`if (屬性 < 3) 屬性 = 3` 在人類 `+2` 之前執行，
> 所以人類的實際下限是 5 不是 3。

## 驗收

1. **種族修正**：對五個種族算出的 25 個修正值，必須等於本文的表
   （亦即與手冊附錄 B 的上限表推導一致）。
2. **端到端解碼**：用本規格解析 `workplace/orig/demwin/DEM_DATA/PARTY.DAT`，
   五名角色的種族／職業／技能／裝備必須與 `docs/formats/game-data-tables.md` §1.6
   的表完全一致（該表已驗證與手冊的職業裝備限制相容）。
3. **剩餘點數**：對同一份存檔算出的剩餘智力點數必須是
   Wopple 7、Stumpy 5、Podgom 9、Norman 9、Menhir 8。
4. **升級成長分佈**：耐力 17 的角色，`N = 11`，`max(Roll(11), Roll(11))` 的
   期望值應趨近 **7.818**；跑 10 萬次驗證。

   > 這裡原本寫 7.7，數字算錯了。`Roll(n)` 回傳 `1..n`，兩次取大的期望值是
   > `Σ k·(k²−(k−1)²) / n²`；`n = 11` 代入得 `946/121 = 7.8182`。
   > 實作量到 7.804（10 萬次）與此相符。
5. **與 DOSBox 原版對拍**（尚未做，最終驗收）：固定種子建角，
   比對五項屬性與初始 HP／SP。

### 建角：重擲（已由程式碼複核）

```
初次擲點算第一次「生成」，之後還能重擲 2 次，合計 3 次
一次重擲操作可指定「一項或多項」屬性，只算一次機會
沒有「低於 6 才能重擲」的門檻
```

**兩本手冊對這段的描述不一致**，以英文原版為準（中譯本是譯本，不是獨立來源）：

| 差異 | 英文原版 | 軟體世界 1990 中譯 | 裁決 |
|---|---|---|---|
| 一次能重擲幾項 | 「該屬性（**或多項屬性**）」 | 一次一項 | 取英文。**程式碼佐證**：`DEMON.INT` 的提示字串是 `Enter #s to be rerolled!`，`#s` 是複數 |
| 次數 | 「三次機會」但又說「最多只能做兩次」 | 「三次機會」 | 初次擲點算第一次生成 → 可重擲 2 次 |
| 「低於 6」 | 「**建議**凡是低於 6 的數值都應該重骰」 | 「若覺得某項屬性點數低於 6，可按…」 | 是建議不是門檻，不加 gate |

> 英文原版那句「你有三次機會……這個動作最多只能做兩次」**自己前後不一**。
> 合理解讀是把初次擲點算進「三次生成」，實作照這個解讀。
>
> **✅ 2026-07-26 已在程式碼裡找到這段，三個裁決全部成立**
> （`DEMON.INT` 0x13b80–0x13d69，從提示字串 `Enter #s to be rerolled!`
> 在 `DS:0x1ca1` 的唯一引用 0x13ce2 反推）：
>
> - **一次可勾多項**：按鍵 1–5 各自切換一個旗標（`ax = 1 - flags[i]`，
>   0x13d21–0x13d36），按終止鍵才一起重擲。與「取英文版」的裁決一致。
> - **三次 = 初擲 + 兩次重擲**：0x13b9d 把計數器設 0，0x13b80 起先把五項
>   旗標全設成 1（所以第一輪就是「全部擲一次」＝初擲），每輪玩家選完後
>   `inc` 計數器、`cmp 3` 沒到就再擲一輪（0x13d60–0x13d69）。共三輪。
> - **沒有「低於 6」的門檻**：選擇迴圈只檢查按鍵是否落在 1–5，
>   完全沒有讀屬性值（0x13d09–0x13d19）。確認是建議不是 gate。
>
> 尚未解出的一點：終止鍵的碼是 `0x25`，對應哪個實體按鍵沒追出來
> （中譯手冊寫「按號碼再按 ENTER」）。本專案用 `R`，理由見
> `cmd/demonwinter/createui.go`。

平均值方框顯示 `擲點期望值(8) + 種族修正`，人類再 +2。
**要照程式碼的人類 +2 走**，不能照手冊寫的「人類優缺點：無」——
不然玩家拿手冊的印象去比會覺得數字對不上。

## 行為

世界地圖與地城都是 64×64 的方格。隊伍有座標與**面向**（四方向）。
按方向鍵會先轉向再前進；`Walk` 指令沿目前面向前進。

移動的每一步都可能推進遊戲時間、觸發隨機遭遇、或踏上會觸發事件的格子。

---

## 資料

| 位址 | 內容 | 說明 |
|---|---|---|
| `struct(0x4c76)+0xa1` / `+0xa2` | 隊伍 X / Y | 進入移動函式時刷新到全域 |
| `struct+0xa4` | 面向 | 刷新到 `0x4e32` |
| `struct+0xa0` | **步數計數器** | 每步 +1（某些 tile +2），達 11 時小時 +1 |
| `0x2107` | 面向 → 線性位移表 | `−64, 1, 64, −1` |
| `0x15da` | 面向 → ΔX 表 | `0, 1, 0, −1` |
| `0x15d2` | 面向 → ΔY 表 | `−1, 0, 1, 0` |
| `0x5500` | 遠指標 → **可通行性對照表** | tile 值 → 可否通行 |
| `0x4c94` | 遠指標 → 當前地圖 tile 陣列 | 64×64，索引 `y*0x40 + x` |

### 面向編碼

| 值 | 方向 | ΔX | ΔY |
|---|---|---|---|
| 0 | 北 | 0 | −1 |
| 1 | 東 | +1 | 0 |
| 2 | 南 | 0 | +1 |
| 3 | 西 | −1 | 0 |

順時針。線性位移 `= ΔY × 64 + ΔX`，與 `0x2107` 表逐項吻合。

## 演算法

### 一步移動的完整順序

```
1. 從 struct 刷新 X / Y / 面向 / mode 到全域
2. 推進遊戲時間 → 若回傳非 0（例如隨機遭遇碼 0x17）→ 直接返回，本步中止
3. 繪製 viewport
4. 讀取玩家指令
5. 指令 0–3（方向鍵）→ 面向 = 指令值，續 6
   指令 4（Walk）    → 沿用目前面向，續 6
   其他指令          → 走各自的處理，不移動
6. 目標座標 = 目前座標 + (ΔX, ΔY)[面向]
7. 目標 tile = 地圖[目標Y × 64 + 目標X]
8. 查可通行性表 [0x5500][目標 tile]
      不可通行 → 撞牆訊息，座標不變
      可通行   → 座標更新為目標座標
9. 步數計數器 += 1（某些 tile += 2）
   若 步數計數器 >= 11 → 小時 += 1，計數器歸零
10. 依目標 tile 值判斷是否觸發事件（見 `03-events.md`）
```

### 可通行性

**不要硬寫死 tile 值。** 原版查的是 `[0x5500]` 指向的對照表，
以 tile 值為索引。早期文件只找到少數硬寫死的判斷（例如 tile `0x35` 直接阻擋），
那些是特例分支，主判定走表。

> 對照表的**來源檔案尚未追出**（與 `EXITS.DAT` 是同一套「執行期指標分發」模式）。
> 實作時需先 dump 這張表；在那之前可用已知的特例值當暫時替代。

### 子地圖／城鎮進出

一張 10 筆的「入口對照表」，每筆含座標、dataset 差值、面向。
玩家新座標命中某筆入口 → 切換 `mode`（`0x52d4` / `struct+0xb0`），
並把舊的座標／dataset／面向壓進一個 6 bytes/層的歷史堆疊
（`struct+0x22`..`+0x26`，以 `mode` 值當堆疊指標）。

## 邊界條件

| 情況 | 行為 |
|---|---|
| 目標座標超出 64×64 | **未確認**是否有邊界檢查，或靠可通行性表擋住 |
| 方向鍵按向已面對的方向 | 仍會執行完整移動流程（轉向是無操作）|
| 時間推進回傳非 0 | 本步**不移動**，直接返回（隨機遭遇會吃掉這一步）|
| 步數計數器 | 達 11 進位，不是 10 —— 這個數字要照抄 |

---

## 驗收

1. **面向位移表**：四個方向的 `(ΔX, ΔY)` 必須等於 `(0,−1) (1,0) (0,1) (−1,0)`，
   且 `ΔY×64 + ΔX` 等於 `−64, 1, 64, −1`。
2. **步數→時間**：連續移動 11 步，遊戲時間的小時數必須恰好 +1。
3. **與 DOSBox 原版對拍**（尚未做）：從已知座標往固定方向走 N 步，
   比對最終座標與時間。

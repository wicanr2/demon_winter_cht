# 86 — 世界地圖上的 19 座神殿與 35 座學院：兩張內嵌座標表

`docs/re/74` 把學院那張表（`ds:0x342d`）解完了，但神殿那一支（`278d:0932`）
只記了「有這條分派」。這一篇把神殿補完，並把兩張表都抄進引擎。

順帶記一個結構性的觀察：**這兩張表跟 `EXITS.DAT` 是同一個設計**——
座標表不帶「哪張地圖」，靠腳下的 tile 分辨。

---

## 1. 神殿的表：`ds:0x310d`，19 筆 × 4 bytes

`278d:0932`（＝檔位移 `0x1be02`）的迴圈：

```c
if (party[+0xa8] != 0xff) {            // 城鎮入口：直接用給定的值
    idx  = party[+0xa8];
    flag = idx % 2;
} else {                                // 走地圖：用座標查表
    for (i = 0; i < 0x4c; i += 4) {
        if (tbl[i] != party[+0xa1]) continue;   // X
        if (tbl[i+1] != party[+0xa2]) continue; // Y
        flag = tbl[i+3];
        idx  = tbl[i+2] * 2 - tbl[i+3];         // ← 兩欄壓成一個索引
        i = 0x64;                                // 找到就跳出
    }
}
```

步長 4、上限 `0x4c`（76）→ **76 ÷ 4 ＝ 19 筆**。

### `idx = a*2 − b` 是把兩欄壓回一個索引

資料裡 `a ∈ 1..5`、`b ∈ {0,1}`，所以：

| b | idx |
|---|---|
| 1 | 1, 3, 5, 7, 9 |
| 0 | 2, 4, 6, 8, 10 |

**`idx ∈ 1..10`，每一組 `(a,b)` 對到唯一值。** 那就是神祇編號。

三條互相獨立的旁證：

1. **城鎮入口把城鎮記錄的值直接當 `idx`**（`!= 0xff` 那條路徑）——
   兩個入口餵的是同一個索引空間。
2. `FILES.DTT` 的神祇名表有 **11 筆**（`[153:164)`，`docs/re/27` §4），
   容得下 1–10。
3. 實跑進去，`(55,8)` 那座顯示的是 **Gamur**（idx 3）—— 名字出得來，
   不是「神祇 13」那種越界的樣子。

九筆 `b=1`、十筆 `b=0`，剛好把 1–10 用滿。

## 2. 學院那張表重抄一次（驗證 `docs/re/74`）

從 `DEMON.INT` 的 `ds:0x342d` 直接讀 105 bytes，逐筆與 `docs/re/74` §3
的表對照 —— **35 筆座標全部相同**。那張表可以信。

兩個要照抄的怪處：

- **#19 的技能欄是 `0`，那是劍擊（技能 id 0），不是表結束標記。**
  `docs/re/74` 記過它自己踩過這個雷（一度寫成「20 座」）。
  表長度看迴圈邊界（`cmp [bp-4], 0x69`），不猜哨兵。
- **#20 與 #1 三個欄位完全相同。** 迴圈找到第一筆就跳出，
  所以 #20 永遠選不到。移植時**不要去重** —— 去重會改變「第一筆」是哪一筆。

兩條都釘成測試了（`internal/game/worldsites_test.go`）。

## 3. 座標表不帶地圖編號 —— 又一次

`EXITS.DAT` 沒有 FromMap，靠可通行表值 `0xfd` 分辨（`docs/re/85`）。
這兩張表也沒有，靠的是**腳下的 tile**：只有踩在 `0x25`（神殿）／
`0x26`（學院）上才會查表，所以同一組座標在別的地圖上不會誤中。

可以被資料打死的檢查：35 筆學院座標，各落在幾個地圖段的 `0x26` 上？

| 情況 | 筆數 |
|---|---|
| 恰好一個地圖段 | **34** |
| 沒有任何段 | 1（#6 的 (54,57)）|
| **兩個以上** | **0** |

**零次碰撞**（26 張 64×64 的圖）。跟 `docs/re/85` 的出口表、
`docs/re/83` 的類別 5 普查是同一個手法與同一個結果形狀。

> 三張互不相干的表（出口、神殿、學院）都用「座標 + tile 當判別式」，
> 而不是多存一個 byte 的地圖編號。1988 年省的是磁片空間，
> 但這也是為什麼這些表單看資料時完全解不出來 ——
> **判別式不在表裡，在地圖裡。**

## 4. 引擎接上之後

`internal/game/worldsites.go`（兩張表 + 查表）、
`cmd/demonwinter/worldsiteui.go`（入口）。

照原版的分工做：**同一支函式、兩個入口**（`docs/re/74` §5）。
查完表之後造一份只有那一項設施的臨時城鎮記錄，再開一般的城鎮畫面 ——
祈禱、捐獻、改宗、學技能全部是現成的程式碼，
而且行為與城鎮裡那份**保證一致，因為就是同一份**。

實跑驗證（`docs/playtest/04`）：

- 零捷徑走出地城 → 落在 (55,8) → 那一格就是 **Gamur 的神殿**，
  五名隊員、祈禱／捐獻／改宗都出得來。
- (46,7) 的 **觀地學院**，10 點 750 金 ——
  `CollegeGoldCost(10) = 10*(5*10+25) = 750`，公式對得上。

### 未解

- **世界地圖設施的經濟係數 E 從哪來。** 城鎮的 E 在 `TOWN<n>.DAT`，
  地圖上的設施沒有那份記錄。引擎先用 1。
  學費公式不吃 E（所以學院價格與原版一致），受影響的只有捐獻換經驗。
- `party+0xa8` 在「tile 是神殿／學院但表裡查不到」時留在 `0xff`，
  之後的行為沒追。引擎目前顯示一則明確的訊息，不靜默。
- `docs/re/74` §4 記的三種沒有學院的技能（戰術、說服、藥劑學識）
  只能在城鎮學，仍然成立。

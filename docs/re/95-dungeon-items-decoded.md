# 95 — 地城道具：50 件、每件 6 條字串，整套解謎鏈都在裡面

A2 卡了好幾輪的「是什麼東西」解開了。**而且不是猜出來的** ——
件數與每件的欄位數都是原版明寫的常數。

## 1. 列出腳下道具的那支常式（`222f:2da5` ＝ `0x18c95`）

`Take:`／`Move:`／鑑物三個動作都轉呼叫它。讀完之後整個資料層就通了：

```
18c9c  found = 0            ; [bp-2] 輸出件數
       i = 0                ; [bp-4] 位置表索引
       j = 0                ; [bp-6] 字串表索引
loop:
18cb7  名稱遠指標 = ds:0x55b8[j]                  ; 場景文字表（docs/re/27 第 6 張）
18cce  ds:0x5c7c[found] = 名稱遠指標              ; 輸出：這一格第 found 件的名字
18cd6  j += 6                                     ; ← **每件佔 6 條**
18ce1  把那條字串複製進 ds:0x514e                 ; 顯示緩衝
18d0b  si = i × 3                                 ; ← **位置表是 3 bytes 一筆**
18d16  if (itemloc[si+0] != party[+0xa1]) 下一筆   ; X
18d2a  if (itemloc[si+1] != party[+0xa2]) 下一筆   ; Y
18d3d  if (itemloc[si+2] != party[+0xa3]) 下一筆   ; 子地圖
18d5d  ds:0x5c68[found] = i;  found++             ; 輸出：它在位置表的索引
18d61  i++
18d64  until (i == 0x32) || (found >= 9)
18d73  return found
```

三個常數一次落地：

| 常數 | 值 | 意義 |
|---|---|---|
| `add [bp-6], 6` | **6** | 每件道具佔 6 條字串 |
| `cmp [bp-4], 0x32` | **50** | 道具總數 |
| `cmp [bp-2], 9` | **9** | 同一格最多列 9 件 |

**`50 × 6 = 300`**，而 `docs/re/27` §2 宣告第 6 張表有 303 條
（`FILES.DTT` 索引 164–466）—— 前 300 條剛好用完，剩下 3 條是殘留
（`CICLE` / `T031704` / `ICICLE`，看得出是 `ICICLE` 被切過的碎片）。

而 `ds:0x54e4` 就是 `ITEMLOCB.DAT` 的緩衝區遠指標，比對的三個欄位是
隊伍的 `+0xa1`(X)／`+0xa2`(Y)／`+0xa3`(子地圖) ——
**`docs/re/94` 的 3-byte `(X, Y, 子地圖)` 格式，程式碼這一側確認完成**
（在這之前只是「檢視資料推出來的」）。

**位置表 50 筆與道具 50 件靠同一個索引 `i` 對齊。**

## 3. 動作碼（**已確認**，分派表在 `0x186fd`）

`+5` 的第一個字元是動作碼，指標 `+1` 之後才是內容（`0x18285` 的 `inc`）。
分派在函式尾端（Turbo C 的慣例，`docs/re/50` §1.1）：

```
18288  cmp al, 0x44   ('D') → 0x1828c   ; 直接在前面比，沒進表
186fd  cmp ax, 0x4e   ('N') → 0x182e3
18705  cmp ax, 0x50   ('P') → 0x1849d
1870d  cmp ax, 0x53   ('S') → 0x185b2
18715  cmp ax, 0x54   ('T') → 0x183f1
1871d  其他            → 0x18732
```

| 碼 | 處理 | 內容 |
|---|---|---|
| `D` | `call 15be:158e` | 印一段敘述 |
| `N` | `0x182e3` | 把新名字寫進角色的道具槽（見 §3.1）|
| `T` | `0x183f1` | **逐 2 位數 `atoi`** → `+0xa1`(X)／`+0xa2`(Y)／`+0xa3`(子地圖) |
| `P` | `0x1849d` | 同樣三組 2 位數 → **就地改寫地圖 tile**（見 §3.4）|
| `S` | `0x185b2` | 主線劇情，`S1` 與 `S2` 兩條完全不同（見 §3.5）|

`T` 的解析逐指令看得很清楚（`0x183f8`–`0x18441`）：
取 `es:[bx]`／`es:[bx+1]` 兩個字元組成字串 → `1f16:000f`（`atoi`）→ 寫 `+0xa1`；
`+2`／`+3` → `+0xa2`；`+4`／`+5` → `+0xa3`。
**`T564603` ＝ 傳送到 (56,46) 子地圖 3，判讀完全正確。**

### 3.1 地城道具就放在角色的道具欄裡

`N` 的分支（`0x182f0`–`0x18382`）把新名字**一個 byte 一個 byte 複製**到：

```
角色記錄 + 0x0c + 槽位×17 + 1     ; 名字（NUL 結尾）
角色記錄 + 0x0c + 槽位×17 + 0     ; 型別 = 0xfe 或 0xff
```

也就是說 **17-byte 的道具槽對地城道具是另一種解讀**：
`[0]` 是型別、`[1..16]` 是 **16 個字的名字**。
一般道具那一套（`docs/re/25` 的 `+0x13` 效果、`+0x14` 強度…）是同一塊記憶體的
**另一種用法** —— 兩者是 union，靠型別 `0xfe`／`0xff` 分辨。

手冊：「角色物品清單中，**地城道具前面一律會加上 `/` 記號**」——
那個記號的來源就是這兩個型別值。

> `0xfe` 與 `0xff` 的差別是進來的參數：`param == 2` 寫 `0xfe`、而且**不清位置表**，
> 否則寫 `0xff`（`0x1834e`／`0x18386`）。
>
> **但 `param == 2` 是死碼。** `222f:2088` 全檔只有三個呼叫端，
> 傳的分別是 **0**（`0x16300`）、**1**（`0x1631a`）、**3**（`0x17b7f`）——
> 對上提示詞表的 `Use `／`Drop `／`Examine `（`docs/re/69` §1）。
> 中間那一格（空字串提示詞）沒有人用。
> 與 `docs/re/73` 的神殿樓梯、`docs/re/63` 的模式值 `1` 同一類
> 「資料在、路徑沒接」的遺留碼。**引擎只實作 `0xff`。**

### 3.2 位置表會被改寫 —— 所以 `ITEMLOCB` 是存檔

`N` 的分支在 `param != 2` 時做這件事（`0x18397`）：

```
les bx, ds:0x54e4                 ; ITEMLOCB 緩衝區
mov byte es:[bx+si+2], 0          ; ← 那一筆的子地圖清 0
```

子地圖 0 不是合法值，所以那一筆從此對不上任何座標 ＝ **那一格的東西被拿走了**。

**這解掉了 `docs/formats/town-and-map.md` §4.1 留的問題**（「`B`／`X` 的命名意圖未解」）：

| | 角色 |
|---|---|
| `ITEMLOCB.DAT` | 遊玩中會被改寫、要存回的那一份 |
| `ITEMLOCX.DAT` | **出廠母本**（新遊戲從它重建）|

與 `nSS.DAT` vs `ALL_SS.DAT` 是**同一個模式**（`docs/re/78`）。
兩檔現在逐 byte 相同，是因為那份資料還沒被玩過。

> 這一條直接決定實作：地城道具的狀態**不是另外設計的存檔格式**，
> 沿用 `nSS.DAT` 那條「母本 → 存檔目錄 → 寫回」的路子就對了。

### 3.4 `P` ＝ 就地改寫地圖 tile

```
1849d  三組 2 位數 atoi（與 T 同一套解析）
18518  les bx, ds:0x4c94        ; ← **當前地圖的 tile 陣列**
18530  mov es:[bx+si], al       ; ← 把那一格改成第三個數字
18537  cmp byte es:[bx+0xa3], 1 ; 子地圖 1 有特判
```

`ds:0x4c94` 是地圖 tile 陣列（`docs/re/05` §1.3）。所以
`P04480` ＝ 把 (04,48) 那一格的 tile 改成 `0` —— **開一條路**。

`+3`（推開的結果）那三筆數字是同一種形狀
（`Old bookcase 461100` ＝ (46,11) → tile `00`），
而它的檢視敘述正是「It has been moved to **reveal a passage**」。
**兩邊互相印證，`+3` 與 `P` 是同一種動作。**

### 3.5 `S` ＝ 主線，而 `S1` 就是結局的抉擇

```
185b5  if (參數[0] != '1') → S2 那條
       ; --- S1（Ice altar）---
185c2  if (trailer[+0xb9] == 0) { call 15be:1694(2); return }   ; 劇情階段還沒到
185de  if (trailer[+0xc1] != 0) return                          ; ← 一次性閂鎖
185ef  call 15be:1694(3)
185f6  印 "Who wishes to become a god?"
18603  印 "Character :"
18618  0x990:179b(0, 5, 2)                                      ; 選人清單
```

**「Who wishes to become a god?」就是結局的不朽／凡人抉擇**
（`docs/re/82`、`ending.go` 已實作的那一段）——
原來它的觸發點是**冰之祭壇 ＋ 祈禱卷軸**。

順帶給了 `+0xc1` 一個脈絡：`CONTEXT.md` §7 C9 把它列為「門檻未解」，
現在知道它是 **`S1` 的一次性閂鎖**（非 0 就直接返回）。

```
       ; --- S2（Circle light）---
186d9  call 15be:1694(7)
186e7  trailer[+0xa1] = 0x0b        ; X = 11
186f1  trailer[+0xa2] = 0x1b        ; Y = 27
```

**`S2` 是傳送到 (11,27)** ＋ 播第 7 段劇情。`Circle light` ＋ `Facet mirror`
——那正是 `docs/re/59`–`61` 破關路徑上的光之環。

### 3.3 掃描教訓：`cmp` 不只一種形式

我第一次掃「有沒有人比對 `D`／`N`／`T`／`P`／`S`」得到 **`N` 零命中**，
差點據此推翻整個動作碼的判讀。實際上它們都在，只是我漏了兩種編碼：

| 形式 | opcode | 這裡用在 |
|---|---|---|
| `cmp al, imm8` | `3c ii` | `'D'` |
| `cmp ax, imm16` | **`3d iiii`** | `'N'`／`'P'`／`'S'`／`'T'` 的分派表 |
| `cmp byte [bp+d8], imm` | `80 7e dd ii` | — |
| `cmp byte [bp+d16], imm` | **`80 be dddd ii`** | `'N'` 的前置檢查 |

**只掃一兩種等於沒掃。** 這與 `docs/re/89`（算出來的偏移搜不到字面值）、
`docs/re/94` §1（基底＋位移掃不到全域引用）是同一類 ——
**「搜尋落空」永遠先懷疑查法**。

## 4. 整套解謎鏈

`+4` 把 50 件串成一張圖。抄幾條看得出這是**地城玩法的全部內容**：

```
Cage        + Mallet          → Iron key（老鼠跑出去，露出西牆的密門）
Man in glass+ Mallet          → 變成 Man in trance
Man in trance + Blue serum    → 說出「Qoorik 的入口藏在 Idlewood 西北的森林」
Red dust    + Bag             → 變成 Bag/red dust
Censer      + Bag/red dust    → 惡魔現身：「只有持有魔晶的人能逃過他的注視」
Ancient tome+ Spectacles      → 讀得懂了：上古諸神的故事
Silver pen  + Unicorn blood   → 變成 Glowing pen
Papyrus     + Glowing pen     → 自動書寫：「Asaht 是上古諸神的聖城」
Ouiji board + Scryer          → 「沿冥河走，直到找到擺渡人」
Ferryman    + Black coins     → 傳送 (56,46) 子地圖 3
Ice altar   + Prayer scroll   → S1
Circle light+ Facet mirror    → S2
```

**這些敘述就是主線的線索鏈** —— Qoorik、Asaht、魔晶、冥河擺渡人，
全部從地城道具裡出來。`Circle light` 掛著 `S2`，那正是 `docs/re/59`–`61`
破關路徑上的光之環。

> 也就是說「地城解謎沒有它就是空的」這句話比我原本以為的更嚴重：
> **沒有這一套，玩家根本拿不到主線的提示。**

# 95 — 地城道具：50 件、每件 6 條字串，整套解謎鏈都在裡面

A2 卡了好幾輪的「是什麼東西」解開了。**而且不是猜出來的** ——
件數與每件的欄位數都是原版明寫的常數。

## 1. 列出腳下道具的那支常式（`222f:2da5` ＝ `0x18c95`）

`Take:`／`Move:`／鑑物三個動作都轉呼叫它。讀完之後整個資料層就通了：

```
18c9c  found = 0            ; [bp-2] 輸出件數
       i = 0                ; [bp-4] 位置表索引
       j = 0                ; [bp-6] 字串表索引
loop:
18cb7  名稱遠指標 = ds:0x55b8[j]                  ; 場景文字表（docs/re/27 第 6 張）
18cce  ds:0x5c7c[found] = 名稱遠指標              ; 輸出：這一格第 found 件的名字
18cd6  j += 6                                     ; ← **每件佔 6 條**
18ce1  把那條字串複製進 ds:0x514e                 ; 顯示緩衝
18d0b  si = i × 3                                 ; ← **位置表是 3 bytes 一筆**
18d16  if (itemloc[si+0] != party[+0xa1]) 下一筆   ; X
18d2a  if (itemloc[si+1] != party[+0xa2]) 下一筆   ; Y
18d3d  if (itemloc[si+2] != party[+0xa3]) 下一筆   ; 子地圖
18d5d  ds:0x5c68[found] = i;  found++             ; 輸出：它在位置表的索引
18d61  i++
18d64  until (i == 0x32) || (found >= 9)
18d73  return found
```

三個常數一次落地：

| 常數 | 值 | 意義 |
|---|---|---|
| `add [bp-6], 6` | **6** | 每件道具佔 6 條字串 |
| `cmp [bp-4], 0x32` | **50** | 道具總數 |
| `cmp [bp-2], 9` | **9** | 同一格最多列 9 件 |

**`50 × 6 = 300`**，而 `docs/re/27` §2 宣告第 6 張表有 303 條
（`FILES.DTT` 索引 164–466）—— 前 300 條剛好用完，剩下 3 條是殘留
（`CICLE` / `T031704` / `ICICLE`，看得出是 `ICICLE` 被切過的碎片）。

而 `ds:0x54e4` 就是 `ITEMLOCB.DAT` 的緩衝區遠指標，比對的三個欄位是
隊伍的 `+0xa1`(X)／`+0xa2`(Y)／`+0xa3`(子地圖) ——
**`docs/re/94` 的 3-byte `(X, Y, 子地圖)` 格式，程式碼這一側確認完成**
（在這之前只是「檢視資料推出來的」）。

**位置表 50 筆與道具 50 件靠同一個索引 `i` 對齊。**

## 2. 六個欄位

| 欄 | 語意 | 非空 |
|---|---|---|
| `+0` | **名稱** | 50 |
| `+1` | **拿不走的理由**（`*` ＝ 拿不走但沒話說）| 25 |
| `+2` | 檢視敘述 | 48 |
| `+3` | **推開之後**發生什麼 | 19 |
| `+4` | **要搭配哪一件道具**（存的是名字）| 18 |
| `+5` | 用對之後發生什麼，**首字元是動作碼** | 18 |

`+4` 對上了 `docs/re/93` §2：鑑物讀的 `[bx+0x55c8]` ＝ `0x55b8 + 4 筆` ＝ 這一欄。
手冊「**鑑物：可得知物品未來可能的用途**」—— 它讀的正是「要拿什麼來配」。

### 交叉驗證：18 個 `+4` 全部命中清單裡的其他成員

`UseWith` 存的是名字。18 個字串**每一個**都能在這 50 件裡找到同名的一件
（`TestUseWithAlwaysNamesAnotherItem`）。切割方式只要錯一格就不可能全中。

## 3. 動作碼（**已確認**，分派表在 `0x186fd`）

`+5` 的第一個字元是動作碼，指標 `+1` 之後才是內容（`0x18285` 的 `inc`）。
分派在函式尾端（Turbo C 的慣例，`docs/re/50` §1.1）：

```
18288  cmp al, 0x44   ('D') → 0x1828c   ; 直接在前面比，沒進表
186fd  cmp ax, 0x4e   ('N') → 0x182e3
18705  cmp ax, 0x50   ('P') → 0x1849d
1870d  cmp ax, 0x53   ('S') → 0x185b2
18715  cmp ax, 0x54   ('T') → 0x183f1
1871d  其他            → 0x18732
```

| 碼 | 處理 | 內容 |
|---|---|---|
| `D` | `call 15be:158e` | 印一段敘述 |
| `N` | `0x182e3` | 把新名字寫進角色的道具槽（見 §3.1）|
| `T` | `0x183f1` | **逐 2 位數 `atoi`** → `+0xa1`(X)／`+0xa2`(Y)／`+0xa3`(子地圖) |
| `P` | `0x1849d` | 同樣三組 2 位數 → **就地改寫地圖 tile**（見 §3.4）|
| `S` | `0x185b2` | 主線劇情，`S1` 與 `S2` 兩條完全不同（見 §3.5）|

`T` 的解析逐指令看得很清楚（`0x183f8`–`0x18441`）：
取 `es:[bx]`／`es:[bx+1]` 兩個字元組成字串 → `1f16:000f`（`atoi`）→ 寫 `+0xa1`；
`+2`／`+3` → `+0xa2`；`+4`／`+5` → `+0xa3`。
**`T564603` ＝ 傳送到 (56,46) 子地圖 3，判讀完全正確。**

### 3.1 拿在手上時放哪裡（**定案**，但走了一段冤枉路）

**型別 `0xfe` ＝ 地城道具，`0xff` ＝ 空槽。**

這一節先後錯過兩次，值得完整記下來：

1. 第一版寫「型別 `0xff` ＝ 地城道具」。**錯的**，`0xff` 是 `slotEmpty`。
2. 發現衝突之後把整節降級成「未定案」，列了三個要追的問題。
3. 追完寫入端，才發現**答案 `docs/re/33` §3 早就寫了**：
   > 「**型別 0xfe 是地城道具。** 判定寫成 `> 0xfd` 而不是 `== 0xfe`，
   > 所以空格（`0xff`）也會撞上同一句『地城道具不能在營地丟』。」
   >
   > 「找空格用的是 `== 0xff` 而不是 `> 0xfd`，所以 **0xfe 確實不是空格**，
   > 是一個真的型別值。」

第 3 步是這個 session 第八次「答案已經在自己的筆記裡」。
**降級那一步是對的**（避免蓋在錯前提上），但如果第一步就 grep 過 `0xfe`，
兩輪都省下來了。

#### 寫入端（逐指令追完的部分）

```
; 名字：複製到 NUL 為止（0x182ea–0x18327）
182f4  cx = 角色 × 0x104
182fc  ax = 槽位;  ax = ax×16 + 槽位          ; ＝ 槽位 × 17
1830d  cx = cx + ax + k
18316  角色記錄[cx + 0x0d] = 來源[k]
18349  角色記錄[… + 0x0d] = 0                 ; NUL 結尾

; 型別（0x1835e–0x18382）
18354  al = 0xfe   (param == 2)
1835a  al = 0xff   (否則)
18379  si = 角色×0x104 + 槽位×17               ; ← **沒有 + k，同一個槽**
18382  角色記錄[si + 0x0c] = al
```

`inventoryStart` 是 `0x0c`，所以：

| 槽內位移 | 內容 |
|---|---|
| `[0]` | 型別（`0xfe` ＝ 地城道具）|
| `[1..16]` | 名字，NUL 結尾（16 bytes） |

**兩處是同一個槽** —— `[bp-2]`（角色）與 `[bp-4]`（槽位）之間沒有被改。
這回答了降級時列的第 1 與第 3 個問題。

#### 還沒追完的：`N` 在可達路徑上到底做了什麼

實際會發生的 param（0／1／3）走的是 `0xff` 那一支 —— **也就是把槽清空**，
而名字留在 `[1..16]` 當殘值。「只改型別、不清其餘 bytes」是原版的既有行為
（`docs/re/33` 記過 Wopple 那一格留著殘值 2）。

所以 `N`（`Man in glass` → `Man in trance`）在可達路徑上做的是
「**消耗掉手上那件 ＋ 地圖上那一格清掉**」，而**新道具怎麼出現**還沒追到
（可能在 `0x183a0` 之後）。寫 `0xfe` 的那一支掛在 `param == 2` ——
已知是死碼，所以 `0xfe` 是誰寫進去的仍是開放問題。

> **對實作的影響**：`T` 拾取要寫的型別是 `0xfe`（`docs/re/33` 的獨立證據），
> 這一條夠明確，`T`／`D` 可以做。`U` 的 `N` 動作要等上面那個問題。

#### 補：`Take:` 那一支自己就寫了 `0xfe`

上面繞的那一大圈，其實只要去讀 `Take:`（§3.6）就結束了 ——
它的道具欄寫入端是一行明碼：

```
1996f  mov BYTE PTR es:[bx+si+0xc], 0xfe
```

**第三條證據，而且是最直接的一條。** 前兩條（`docs/re/33` §3／§4）
是從「營地丟棄怎麼擋」與「找空格用什麼判定」反推的；這一條是
「拿東西的時候寫什麼進去」，正面命中。

會繞路是因為我從 `N` 動作那一頭開始追（它在同一支函式裡，看起來更近），
而 `N` 在可達路徑上寫的是 `0xff`。**入口選錯，追得再仔細也只會確認錯的那一半。**

### 3.6 `Take:` 全流程（`25be:0077` ＝ 動作 `0x09` ＝ `0x19857`）

`docs/re/58` §5 說 `Take:` 與 `Move:` 「逐指令相同」—— 那只對前五行。
從 `222f:2e8b` 回來之後兩者就分家了，而 `Take:` 的後半段有 190 行。

```
1986e  call 222f:2da5                 ; 列出腳下有什麼（§1）
19876  call 222f:2e8b(件數)           ; 選一件，回傳 **字串索引 j = i×6**
1987f  j < 0 → return 2               ; 取消

; --- 拿不拿得走 ---
19891  strcmp(ds:0x2791, 表[j+1])     ; ds:0x2791 = "*"
198b1  相等 → 印 ds:0x2793 "You can't"，結束
198d0  表[j+1] 的第一個 byte == 0 → 拿得走
198e0  否則印 表[j+1] 那句話，結束     ; "It is too heavy"

; --- 選人 ---
198ed  印 ds:0x279d "Character to take"
19906  0x990:179b(0,5,1) / (2,5,1)    ; 選人清單，回傳 [bp-6]
19935  == party[+0x9a] → 取消

; --- 找空格 ---
19944  si = 角色×0x104 + 槽位×17
19961  型別 = 記錄[si+0x0c]
19967  != 0xff → 下一格（0x19a1d，掃到第 10 格）
19a23  十格都滿 → 印 ds:0x27b6 "No more room."

; --- 寫進去 ---
1996f  記錄[si+0x0c] = 0xfe           ; ← 型別
199be  逐 byte 複製 表[j] → 記錄[si+0x0d …]，到 NUL 為止
199d7  補一個 NUL
199db  印 ds:0x27af "Taken."

; --- 從地圖上清掉 ---
199ef  i = j / 2                      ; ← j = i×6，除以 2 得到 i×3 ＝ 位元組位移
199f9  itemloc[i×3 + 0..2] = 0        ; **連寫三個 0**
19a0d  until 寫了 3 次
```

兩個容易寫錯的地方：

**`222f:2e8b` 回傳的是字串索引，不是道具索引。** `[bp-2]` 全程拿去
`×4` 查 `ds:0x55b8[j]`／`ds:0x55bc[j+1]`，最後才 `/2` 換回位置表的位元組位移。
把它當成 `i` 會讓每一件都對到第 6 件之後去。

**`Take:` 清三個 byte，`N` 只清一個。** `N` 是 `mov es:[bx+si+2],0`
（§3.2），只把子地圖寫 0；`Take:` 把 X／Y／子地圖全部歸零。
查詢結果一樣（子地圖 0 對不上任何座標），但**寫回檔案的位元組不同** ——
逐位元組比對存檔時會抓到。

順帶一提：`0x19891` 對 `*` 做 `strcmp` 這件事證明**那個星號是佔位不是台詞**。
50 件裡有 25 件拿不走，其中 18 件的 `+1` 欄就只有一個 `*`。

### 3.7 `Drop` ＝ `222f:2088(1)`，而它**靠名字回推索引**

`docs/re/69` §1 認出 `ds:0x23e8` 那張提示詞表（`Use `／`Drop `／` `／`Examine `），
但當時說「參數 1 在分派表裡沒有對應的格子」。**有的**，就在同一支函式的尾端：

```
17fec  ax = [bp+6];  jmp 0x1871f      ; 分派尾（Turbo C 慣例）
1871f  cmp ax,1 → 0x17ff2             ; ← Drop
18727  cmp ax,3 → 0x18054             ; Examine
1872f  否則     → 0x180e7             ; Use
```

`0x17ff2`（Drop）本體只有三件事：

```
1800f  記錄[si+0x0c] = 0xff           ; 清空那一格（名字留著當殘值）
18025  sprintf(buf, ds:0x240e, 名字)  ; "%s Dropped."
18049  call 122f:2845(角色, 名字遠指標)
```

而 `122f:2845`（＝ `0x18735`）就是「放回地圖」：

```
18748  strcmp(名字, ds:0x55b8[j])     ; ← **逐 6 條掃字串表比對名字**
1876b  沒中 → j += 6; i++
18772  until j >= 0x12f               ; 303
1877e  i ×= 3
18785  itemloc[i×3+0] = ds:0x50f0     ; 目前 X
18795  itemloc[i×3+1] = ds:0x50ee     ; 目前 Y
187a5  itemloc[i×3+2] = party[+0xa3]  ; 目前子地圖
```

三件事值得記：

**手冊「丟棄之後一定能在原地撿回」的機制就是這個。** 改寫原本那一筆，
不是新增 —— 50 格是固定陣列，索引就是身分。`docs/spec/10` 原本寫
「在目前座標**新增**一筆」，那是推的，現在改掉。

**名字是原版自己選的主鍵，不是本專案的權宜。** 而它不是唯一的：
`Bed` 在第 1 與第 41 件各出現一次，原版取第一個命中的。
兩件都拿不走，所以實際遊玩碰不到 —— 但別因此把「名字可以當主鍵」
當成通則。

**沒有找不到的處理。** 掃完 303 條沒命中時 `i` 會停在 51，
接著往 `itemloc[153..155]` 寫三個 byte —— 有效區之外、看不出症狀。
本專案在這裡加了一道檢查並拒絕，屬於**明知原版有洞而不照抄**的那一類
（與 `docs/re/93` §3 觀室不遮罩 tile 同一個處理原則）。

### 3.8 六個指令分成兩組：看腳下的 vs 看身上的

規格原本把 `E` 檢視寫成「選一件**腳下的**」。**錯的。** 兩組的選取常式不同：

| 指令 | 進入點 | 選什麼 |
|---|---|---|
| `T` 拾取 | `25be:0077`（動作 `0x09`）| `222f:2da5` → **腳下這一格** |
| `M` 移動 | `222f:3621`（動作 `0x0b`）| 同上 |
| `E` 檢視 | `222f:1c74`（動作 `0x0a`）→ `222f:2088(3)` | `122f:1d23` → **哪個角色的第幾格** |
| `D` 丟棄 | `222f:2088(1)` | 同上 |
| `U` 使用 | `222f:2088(0)` | 同上 |

`222f:2088` 開頭那一段（`0x17fc3`–`0x17fe9`）算的是
`角色記錄 + 角色×0x104 + 槽位×17 + 0x0d` —— 也就是**槽裡的名字**，
三個指令共用這個指標。所以 `E` 檢視的是身上那件，`T` 拿的是腳下那件，
兩者剛好相反。

`E` 本體（`0x18054`–`0x180e4`）：

```
18054  j = 0
18066  while j < 0x12f:  if strcmp(表[j], 槽裡的名字) == 0 break;  j += 6
18092  look = 表[j+2]                     ; 0x55c0 − 0x55b8 = 8 ＝ 2 筆 ＝ +2 欄
180a4  if look[0] == 0:
180aa    sprintf(ds:0x241a, 名字)         ; "You see nothing special about the %s"
180d3  else 印 look
```

**又是靠名字 strcmp 掃回索引**（與 `Drop` 同一套，§3.7）。
50 件裡只有 2 件的 `+2` 是空的：`Iron key` 與 `Bag/red dust`。

### 3.9 `Move:`（`222f:3621` ＝ `0x19511`）—— 它會把地圖寫回檔案

```
1951e  印 ds:0x26bf "Move:"
1952a  222f:2da5 → 222f:2e8b              ; 選腳下的一件，回傳 j
19554  moveResult = 表[j+3]               ; 0x55c4 − 0x55b8 = 12 ＝ 3 筆 ＝ +3 欄
1956d  strcmp("*", moveResult) == 0 → 印 ds:0x26c7 "You can't"，結束
1958c  moveResult 是空字串 → 印 ds:0x26d1 "Nothing happens."，結束

; --- 三組 2 位數 atoi，與 T／P 同一套 ---
195bb  X    = atoi(s[0..1])
195e0  Y    = atoi(s[2..3])
195f5  tile = atoi(s[4..])
19600  si = (Y << 6) + X                  ; ＝ Y×64 + X
1960d  已經是這個 tile → 印 ds:0x26e2 "Nothing happens."，結束
19645  map[si] = tile
19649  印 ds:0x26f3 "Something happened..."
19665  call 122f:28d0(子地圖, 1)          ; ← **把地圖寫回 MAPn.MAP**
```

`122f:28d0`（＝ `0x187c0`）第二個參數非 0 時走 `0x18906`：
`sprintf("MAP%d.MAP", n)` 之後**寫 0x1001 bytes 回那個檔案**。

> **所以 `MAPn.MAP` 也是存檔的一部分。** 這是第三份就地改寫的資料
> （前兩份是 `nSS.DAT`、`ITEMLOCB.DAT`），而且原版是直接蓋回自己的資料目錄 ——
> 出貨的 `MAP1.MAP` 早就是玩過的狀態，與 `docs/re/87` 對 `PARTY.DAT` 的結論一樣。
>
> **本專案不可以照抄這一點**：`workplace/orig` 唯讀。改過的地圖要走
> 「母本 → 存檔目錄 → 寫回」那條路（`nSS.DAT` 的模式），
> 這是 `M` 實作前要先解決的事。

#### 順帶解掉 `docs/re/28` 的「固定 2、語意未解」

地圖 1 有一段特判（`0x19671`–`0x196a0`），在寫完檔案之後補一筆：

```
19671  if (party[+0xa3] != 1) 結束
19679  al = party[+0x5c] + 0x3f
19680  Y = party[+0x59];  X = party[+0x58]
1969b  map[Y×64 + X] = al
```

`+0x58` = `0x22 + 9×6`，所以那是**船隻陣列的第 9 格**（`docs/re/28` §1：
基底 `+0x22`、stride 6、10 格）。三個欄位對上 `docs/re/28` §2 的布局：
`+0` X、`+1` Y、`+4` 那個「固定 2、語意未解」的 byte。

**它是船的種類，而地圖 tile ＝ 種類 + 0x3f。** 種類 2 → tile `0x41`。
`Move:` 剛把整張地圖寫回檔案，所以要把船重新蓋回那一格 ——
不然船會在存檔裡消失。

還沒讀出來的：**為什麼只有第 9 格、只有地圖 1**。
（第 9 格是最後一格，可能是某艘固定的船；也可能這是原版的疏漏，
只補了一艘。）

### 3.2 位置表會被改寫 —— 所以 `ITEMLOCB` 是存檔

`N` 的分支在 `param != 2` 時做這件事（`0x18397`）：

```
les bx, ds:0x54e4                 ; ITEMLOCB 緩衝區
mov byte es:[bx+si+2], 0          ; ← 那一筆的子地圖清 0
```

子地圖 0 不是合法值，所以那一筆從此對不上任何座標 ＝ **那一格的東西被拿走了**。

**這解掉了 `docs/formats/town-and-map.md` §4.1 留的問題**（「`B`／`X` 的命名意圖未解」）：

| | 角色 |
|---|---|
| `ITEMLOCB.DAT` | 遊玩中會被改寫、要存回的那一份 |
| `ITEMLOCX.DAT` | **出廠母本**（新遊戲從它重建）|

與 `nSS.DAT` vs `ALL_SS.DAT` 是**同一個模式**（`docs/re/78`）。
兩檔現在逐 byte 相同，是因為那份資料還沒被玩過。

> 這一條直接決定實作：地城道具的狀態**不是另外設計的存檔格式**，
> 沿用 `nSS.DAT` 那條「母本 → 存檔目錄 → 寫回」的路子就對了。

### 3.4 `P` ＝ 就地改寫地圖 tile

```
1849d  三組 2 位數 atoi（與 T 同一套解析）
18518  les bx, ds:0x4c94        ; ← **當前地圖的 tile 陣列**
18530  mov es:[bx+si], al       ; ← 把那一格改成第三個數字
18537  cmp byte es:[bx+0xa3], 1 ; 子地圖 1 有特判
```

`ds:0x4c94` 是地圖 tile 陣列（`docs/re/05` §1.3）。所以
`P04480` ＝ 把 (04,48) 那一格的 tile 改成 `0` —— **開一條路**。

`+3`（推開的結果）那三筆數字是同一種形狀
（`Old bookcase 461100` ＝ (46,11) → tile `00`），
而它的檢視敘述正是「It has been moved to **reveal a passage**」。
**兩邊互相印證，`+3` 與 `P` 是同一種動作。**

### 3.5 `S` ＝ 主線，而 `S1` 就是結局的抉擇

```
185b5  if (參數[0] != '1') → S2 那條
       ; --- S1（Ice altar）---
185c2  if (trailer[+0xb9] == 0) { call 15be:1694(2); return }   ; 劇情階段還沒到
185de  if (trailer[+0xc1] != 0) return                          ; ← 一次性閂鎖
185ef  call 15be:1694(3)
185f6  印 "Who wishes to become a god?"
18603  印 "Character :"
18618  0x990:179b(0, 5, 2)                                      ; 選人清單
```

**「Who wishes to become a god?」就是結局的不朽／凡人抉擇**
（`docs/re/82`、`ending.go` 已實作的那一段）——
原來它的觸發點是**冰之祭壇 ＋ 祈禱卷軸**。

順帶給了 `+0xc1` 一個脈絡：`CONTEXT.md` §7 C9 把它列為「門檻未解」，
現在知道它是 **`S1` 的一次性閂鎖**（非 0 就直接返回）。

```
       ; --- S2（Circle light）---
186d9  call 15be:1694(7)
186e7  trailer[+0xa1] = 0x0b        ; X = 11
186f1  trailer[+0xa2] = 0x1b        ; Y = 27
```

**`S2` 是傳送到 (11,27)** ＋ 播第 7 段劇情。`Circle light` ＋ `Facet mirror`
——那正是 `docs/re/59`–`61` 破關路徑上的光之環。

### 3.3 掃描教訓：`cmp` 不只一種形式

我第一次掃「有沒有人比對 `D`／`N`／`T`／`P`／`S`」得到 **`N` 零命中**，
差點據此推翻整個動作碼的判讀。實際上它們都在，只是我漏了兩種編碼：

| 形式 | opcode | 這裡用在 |
|---|---|---|
| `cmp al, imm8` | `3c ii` | `'D'` |
| `cmp ax, imm16` | **`3d iiii`** | `'N'`／`'P'`／`'S'`／`'T'` 的分派表 |
| `cmp byte [bp+d8], imm` | `80 7e dd ii` | — |
| `cmp byte [bp+d16], imm` | **`80 be dddd ii`** | `'N'` 的前置檢查 |

**只掃一兩種等於沒掃。** 這與 `docs/re/89`（算出來的偏移搜不到字面值）、
`docs/re/94` §1（基底＋位移掃不到全域引用）是同一類 ——
**「搜尋落空」永遠先懷疑查法**。

## 4. 整套解謎鏈

`+4` 把 50 件串成一張圖。抄幾條看得出這是**地城玩法的全部內容**：

```
Cage        + Mallet          → Iron key（老鼠跑出去，露出西牆的密門）
Man in glass+ Mallet          → 變成 Man in trance
Man in trance + Blue serum    → 說出「Qoorik 的入口藏在 Idlewood 西北的森林」
Red dust    + Bag             → 變成 Bag/red dust
Censer      + Bag/red dust    → 惡魔現身：「只有持有魔晶的人能逃過他的注視」
Ancient tome+ Spectacles      → 讀得懂了：上古諸神的故事
Silver pen  + Unicorn blood   → 變成 Glowing pen
Papyrus     + Glowing pen     → 自動書寫：「Asaht 是上古諸神的聖城」
Ouiji board + Scryer          → 「沿冥河走，直到找到擺渡人」
Ferryman    + Black coins     → 傳送 (56,46) 子地圖 3
Ice altar   + Prayer scroll   → S1
Circle light+ Facet mirror    → S2
```

**這些敘述就是主線的線索鏈** —— Qoorik、Asaht、魔晶、冥河擺渡人，
全部從地城道具裡出來。`Circle light` 掛著 `S2`，那正是 `docs/re/59`–`61`
破關路徑上的光之環。

> 也就是說「地城解謎沒有它就是空的」這句話比我原本以為的更嚴重：
> **沒有這一套，玩家根本拿不到主線的提示。**

# 71 — `EREGORE.TXT`／`T.TXT` 沒有載入路徑，`CYPHER.SHP` 有

`docs/re/70` §4 把三筆檔名指標（`EREGORE.TXT`／`WIN.TXT`／`T.TXT`）
列為「用算出來的索引存取」。**再掃一輪之後，這個推測要收回。**

---

## 1. 掃了哪些模式

對 `ds:0x2f59`（表基底）、`0x2f6b`／`0x2f77`／`0x2f7f`（三個字串本體）
逐一掃這些形式：

| 形式 | 位元組 |
|---|---|
| `mov ax/bx/cx/dx/si/di, imm16` | `b8`／`bb`／`b9`／`ba`／`be`／`bf` |
| `les`／`lds reg,[bx+disp16]` | `c4`／`c5` + ModRM `0x80`–`0xBF` |
| `mov reg,[bx+disp16]` 與反向 | `8a`／`8b`／`88`／`89` + 同樣的 ModRM 範圍 |
| `lea reg,[bx+disp16]` | `8d` |
| `add ax,imm16` | `05` |

**四個位址全部零命中。**

`docs/re/70` 說「用算出來的索引存取」是為了解釋掃不到 ——
但索引式存取的**基底**還是要出現在某處（`mov bx,0x2f59` 或 `[bx+0x2f59]`），
而那也掃不到。所以更簡單的解釋是：

**這三個檔案在這份執行檔裡沒有載入路徑。**

---

## 2. 這不是第一次

同一份 dump 裡已經有兩個「資料在、程式沒接」的例子：

| 東西 | 情況 |
|---|---|
| `TITLE.PIC` | 引擎的檔名表列著它，但**檔案不在 dump 裡**（`cmd/demonwinter/title.go`）|
| `OPEN.PIE` | 檔案在，但 `OPEN.*` 這兩個檔名在兩個執行檔裡**零命中** |
| `EREGORE.TXT`／`T.TXT` | 檔名在資料段、指標表也在，但**沒有任何指令碰那張表** |

`WIN.TXT` 也在這一類，但已經不重要 —— `docs/re/61` §2 確認結局文字
寫死在 `ds:0x066a`，根本不從檔案讀。

> 三個檔名擺在資料段、還做了一張 far ptr 表，卻沒有讀取端 ——
> 最合理的解釋是**開發途中改過設計**：原本打算從檔案讀這些劇情文字，
> 後來改成寫死或改走別的路徑，表留在那裡沒清掉。
> 這是判讀，不是結論 —— 但「沒有載入路徑」這件事本身是掃出來的。

## 3. `CYPHER.SHP` 有一處，走同一個載入器

```
1b0da  push bp / mov bp,sp
1b0e0  push ds:0x53cc / ds:0x53ca      ; 第 4 參數
1b0e8  push ds:0x4c96 / ds:0x4c94      ; 第 3 參數：目的緩衝區
1b0f0  push ds / 0x2f4e                ; 第 2 參數："CYPHER.SHP"
1b0f5  push ds / 0x522a                ; 第 1 參數：模式
1b0fa  call 1d9f:0a8b                  ; 素材載入器
1b105  回傳 0 → 失敗處理
```

`ds:0x4c94` 是**地圖／通用緩衝區** —— 六篇筆記一致
（`docs/re/05` §126「目的緩衝區遠指標」、`docs/re/22` §90「地圖緩衝區」、
`docs/re/08`、`23`、`28`、`59`）。`docs/re/22` 把那一帶定性為資源 arena，
所以「載地圖也載別的東西」是預期的複用，不是矛盾。

`docs/re/65` 猜 `CYPHER.SHP` 與那兩道密碼（`VOID`／`JESRIC`）有關 ——
**仍未證實**：載入的位址知道了，但誰讀那份資料、拿它畫什麼還沒追。

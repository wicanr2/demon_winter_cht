# 79 — tile `0x5b` 是廢墟：冬之魔降臨的機制實作

`CONTEXT.md` §7 的 B13：tile `0x5b` 會讓 `222f:0b0e` 回傳 `0x13`，
但 `0x19192` 那四個 tile 比較全部落空 —— 記成「第五個資料在、路徑沒接」。

**那是看漏了。** `0x5b` 走的是**同一支函式更前面**的分支群，
而且順著它讀出了這款遊戲標題的機制實作。

---

## 1. 看漏的原因：分派有兩層

回傳碼 `0x13` 的處理函式是 `222f:3233`（`0x19123`）。
之前只讀了它後半段的四個比較，前半段被跳過了：

```
19123  ds:0x4c7a = 0x28
19129  ax = ds:0x52f4                    ; 剛踩到的 tile
1912c  if (ax == 0x2e) {                 ; 城鎮
19135      if (party[+0xbe] != 0) goto 1915a      ; ★ 城鎮已成廢墟
       }
1913d  if (ax == 0x25) {                 ; 神殿
19146      if (party[+0xba] == 0xff) goto 1915a   ; ★ 神殿已成廢墟
       }
19152  if (ds:0x52f4 == 0x5b) goto 1915a          ; ★ tile 0x5b 一律走這裡
19158  else goto 19188                            ; 其他 → 設施分派

; ── 廢墟 ──
1915a  FUN_222f_1813(0)
19164  call 1cdc:1727
19169  ds:0x4c7c++
1916d  FUN_1d9f_1361(ds:0x2635)          ; "You are walking through ruins"
1917a  FUN_222f_1813(2)
19184  return 2

; ── 設施分派（原本只讀了這一段）──
19188  party[+0xa8] = 0xff
19192  if (tile == 0x2e || tile == 0x64) call 178d:0098    ; 城鎮
191a7  if (tile == 0x25)                 call 178d:0932    ; 神殿
191b3  if (tile == 0x26)                 call 178d:11bd    ; 學院（docs/re/74）
191bf  return 0
```

**`0x5b` 不是沒接，是接在另一個出口。** 教訓很具體：
一支函式裡有兩組針對同一個變數的比較時，**只讀其中一組會得出「沒接」的錯誤結論**。
`docs/re/74` §1 引的正是後面那組。

---

## 2. `+0xba` ＝ 神殿已成廢墟，而且看得見

`+0xba` 只有四處存取（`tools/fieldscan.py 0xba`）：

| 位址 | 動作 |
|---|---|
| `0x03ec8` | `cmp 0` |
| `0x03ed0` | `= 0xff` |
| `0x1739a` | `cmp 0x7f` ← **繪製路徑** |
| `0x19147` | 讀（上面那段廢墟判斷）|

`0x1739a` 是關鍵，它在**畫地圖**的路徑上：

```
1738c  les bx, [0x4c94]                  ; 地圖 tile 陣列
17390  al = tile[si]
17393  [bp-0x14] = al
1739a  if (party[+0xba] > 0x7f) {
173a2      if (al == 0x25)               ; 神殿
173a6          [bp-0x14] = 0x5b          ; ★ 改成廢墟 tile
       }
173aa  al = [bp-0x14]
173ad  les bx, [0x514e]                  ; 繪製緩衝區
173b4  buf[si] = al
```

**旗標一立起來，畫面上所有神殿就變成廢墟。**
規則用的地圖陣列不動 —— 替換只發生在拷進繪製緩衝區的路上。
（與海面浪花 `0x14`／`0x62` 是同一種「純外觀替換」，`docs/formats/town-and-map.md` §212。）

所以 tile `0x5b` **不只是一個可以走的格子，它就是「毀掉的神殿」長什麼樣子**。

## 3. 神殿被毀，全隊永久失去薩滿與司祭

唯一的寫入端 `0x03ec0`：

```
3ec0  if (party[+0xb9] == 2 && party[+0xba] == 0) {
3ed0      party[+0xba] = 0xff                    ; 神殿全毀
3ed6      for (i = 0; i < 5; i++) {
3eea          char[i].+0xd7 = 0                  ; 薩滿
3efc          char[i].+0xd8 = 0                  ; 司祭
          }
      }
```

`char+0xd7`／`+0xd8` 是**薩滿（技能 15）與司祭（技能 16）的技能旗標**
（`docs/re/19` §683 已定案：`0xc8 + 15`／`0xc8 + 16`，就是技能旗標陣列裡那兩格）。

掃描把這件事釘死了 —— 這兩個欄位各有 6 處存取，
**寫入端只有這一處，而且寫的是 0**：

```
+0xd7  0x03eea 寫 0   ← 唯一的寫入
       0x04b55 / 0x055b8 / 0x0aff2 / 0x0d358 / 0x1c469  全部是 cmp 0
+0xd8  0x03efc 寫 0   ← 唯一的寫入
       其餘五處同樣全是 cmp 0
```

那五個 `cmp 0` 是驅散不死、祈禱、改宗的資格檢查（`docs/re/09` §103／§152、
`docs/re/29` §117）。**所以這兩個技能只能在建角時取得，
之後全遊戲唯一會動它們的事件就是神殿被毀 —— 而且是一次性剝奪。**

驅邪與祈禱從此永久失效。這不是推論，是「唯一寫入端」這個事實直接給的。

> 這是 `tools/fieldscan.py` 那種全欄位普查最有價值的用法：
> **「只有一處寫入，而且寫 0」比任何邏輯推理都強。**
> 光讀那一段程式碼只知道「這裡清了兩個 byte」，
> 掃完才知道「全遊戲只有這裡清它們」。

## 4. `+0xbe` 的劇情終於有名字了

`docs/re/78` §6 解出 `+0xbe` 是一次性劇情的單向閂鎖（11 處存取沒有一處寫 0），
但註明「事件本體 `25be:1ae2` 沒有字串，是哪一段劇情仍未定」。

現在 `0x19135` 給了答案的形狀：**`+0xbe != 0` 之後，tile `0x2e` 的城鎮走同一條
廢墟路徑，不再進得去**。所以 `25be:1ae2` 是**把城鎮變成廢墟**的那段劇情，
而 `+0x99` 的「兩趟才上鎖」是它的分段演出。

### ⚠ 兩個旗標的門檻不一樣，別統一

| 旗標 | 比較 | 位址 |
|---|---|---|
| 神殿 `+0xba` | `> 0x7f`（`cmp 0x7f / jbe`）| `0x1739a` |
| 神殿 `+0xba` | `== 0xff` | `0x19147` |
| 城鎮 `+0xbe` | `!= 0`（`cmp 0 / jne`）| `0x19135` |

同一個旗標在兩處用了兩種比較（`> 0x7f` 與 `== 0xff`），
而城鎮那個用第三種。實務上寫入值只有 `0xff` 與 `1`，三種比較結果一致，
**但照原版分開寫** —— 這與符印旗標「進門看 `!= 0`、傷害看 `< 0x80`」
是同一類陷阱（`docs/re/63`），統一之後只要有人寫進中間值行為就分歧。

### `0x64` 沒有廢墟覆寫

城鎮 tile 有兩個（`0x2e`／`0x64`），但**只有 `0x2e` 檢查 `+0xbe`**。
`0x64` 的城鎮不會變廢墟。原版就這樣，不補。

## 5. `+0xb9` 是階段機，但語意還沒定

觸發神殿全毀的條件是 `+0xb9 == 2`。這個 byte 有 **19 處存取**：

| 位址 | 轉移 |
|---|---|
| `0x03ea3/ab` | `== 1` → `2` |
| `0x0b875/7d` | `== 2` → `3` |
| `0x0dff7/ff` | `== 3` → `2` |
| `0x1072e/36` | `== 3` → `2`（海上遇船，`docs/re/78` §4）|
| `0x15f99/a1` | `== 4` → `2`（進大地圖時）|
| `0x161d0/d8` | `== 2` → `4` |
| 另外 8 處 | 只讀（`== 0`／`== 2`／`== 3` 的閘門）|

值域 0–4，`2` 是樞紐，`3` 與 `4` 都會回到 `2`。
**這個形狀更像「模式」而不是單向的劇情階段** ——
單向階段不會有 `2→3→2` 與 `2→4→2` 這種來回。

`docs/re/24` §188 記著「隨機遭遇加值路徑的觸發條件 `+0xb9 == 2` 語意未定」。
本篇沒有解開它，**只把轉移圖畫完**。下一步該讀 `0x0b875` 與 `0x161d0`
那兩處「離開 2」的上下文，而不是從 `cmp` 的用法猜。

## 6. 引擎那邊本來錯在哪

`internal/game/events.go` 原本把這五個 tile 註成
「tile 值本身就是 `DATA*.TXT` 記錄索引」，`checkEvent` 就照著
`idx = int(tile)` 去取敘述。

**那是錯的** —— 原版拿 tile 值當設施選擇器，不是文字索引。

錯得剛好沒人發現：`0x25` ＝ 37，而 `DATA1.TXT` 只有 35 筆記錄，
所以取不到、什麼都不顯示。**一個越界索引把 bug 藏成了「這格沒事」。**

已改成 `game.TriggerSite` + `game.SiteFor(tile, 神殿旗標, 城鎮旗標)`，
回傳城鎮／神殿／學院／廢墟。世界地圖上的神殿與學院**還沒接**，
但現在會明確顯示「還沒接」而不是靜默無反應。

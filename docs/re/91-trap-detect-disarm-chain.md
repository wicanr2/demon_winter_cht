# 91 — 陷阱的偵測、解除、與「已注意」的存放位置

`docs/re/68` 讀完了七種陷阱的擲點，但留下一句沒追：**技能「察覺陷阱／解除陷阱」
怎麼生效、「已注意」記在哪裡。** 手冊寫得很具體（25%／100%、沒技能只標記
noticed、離開地城再回來仍然保留），這一篇把那三句話對回機器碼。

結果是整條鏈閉合，而且**手冊的每一個數字都對得上**。

## 1. `L` 查看陷阱 ＝ 動作 `0x07`（`222f:1882` ＝ `0x17772`）

```
; 先掃全隊有沒有人會這兩個技能（而且還活著）
17796  hasDetect = 任一角色 [+0xd2] != 0 且 [+0x102] <= 1      ; 技能 10 察覺陷阱
177ab  hasDisarm = 任一角色 [+0xd3] != 0 且 [+0x102] <= 1      ; 技能 11 解除陷阱

177d8  x, y = 隊伍座標
       for step = 0; step <= ds:0x5c64; step++ {               ; ← 掃描距離 ＝ 光源強度
177f1      x += ΔX[facing]; y += ΔY[facing]                    ; 只往正前方
17817      tile = map[y*64 + x];  if (tile > 0x7f) tile −= 0x80
17829      if (tile != 0 && tile != 0x11) break                ; 不是走道 → 停
1783f      if (tile != 0x11) continue                          ; 走道但不是特殊格
17842      ds:0x52f4 = x; ds:0x52f6 = y; call 222f:1321        ; 查特殊格清單
17853      if (ds:0x5c62 != 3 && != 6) continue                ; 不是陷阱
17864      if (!hasDetect && Roll(4) != 4) continue            ; ← 25%
17879      if (!hasDisarm) {
1788e          if (attr < 0xc1) attr += 0x60                   ; ← 類別 3 → 6
17893          印 "Noticed."
           } else {
178a6          attr = 0                                        ; ← 整格清掉
178ab          印 "Disarmed."
           }
178b8      畫白框（ds:0x5192 = 0xff，畫在相對位置）
178e6      found++
       }
17902  found == 0 → "No traps found."  否則 "%d traps found."
```

`+0xd2`／`+0xd3` 相對技能旗標基底 `0xc8` 是 **10（察覺陷阱）與 11（解除陷阱）**，
與 `docs/re/21` §1 的 id 表一致。`ds:0x5c64` 是進地圖時填好的地城光源
（存檔 `+0xa7`，`docs/re/50` §旁證）。

### 手冊三句話的對應

| 手冊 | 機器碼 |
|---|---|
| 「檢查你正前方、**光源所能照到範圍內**」 | 迴圈上界 `ds:0x5c64`，只走 facing 方向 |
| 「找到陷阱的機率是 **25%**，有察覺陷阱技能提高到 **100%**」 | `Roll(4) != 4 → continue`；`hasDetect` 直接跳過那一擲 |
| 「找到的每個陷阱都會用**白色方框**標示」 | `ds:0x5192 = 0xff` 後畫框，畫完設回 0 |
| 「陷阱只會設置在**筆直的通道**上」 | 撞到 tile 不是 `0`／`0x11` 就 `break` |

## 2. 「已注意」就是把類別 3 改寫成 6

`attr += 0x60`。類別在 attr 的高 3 bit（`docs/re/78`），`3 << 5 = 0x60`，
所以這一加就是 **3 → 6**，低 5 bit 的值原封不動。
守衛 `attr < 0xc1` 是防止已經是類別 6 的格子再被加上去。

而類別 6 在陷阱本體（`25be:0263`）走的是這一條：

```
19a87  if (ds:0x5c62 == 6) {
19a92      if (Roll(2) == 1) { 印 "You carefully avoid the trap"; return 2 }
19ab4      印 "Even being extra careful" / "you set off the trap"
       }
19ace  ax = ds:0x52f6 → 分派到九格陷阱表
```

**類別 3 沒有這一段** —— 沒注意到的陷阱必定觸發。

於是手冊那句「沒有解除陷阱技巧的話，陷阱只會被標記為『已注意』，**經過時可能不會
觸發**」有了精確值：**50%**。而「解除」是把整個 attr 清成 0 —— 類別 0 是預設文字格，
值也歸零，等於這一格從陷阱清單上消失。

### 為什麼「離開地城再回來仍然保留」

因為 attr 寫的是 `nSS.DAT` 的那個 byte，而 **`nSS.DAT` 是存檔**（`docs/re/78`）。
引擎這一側已經有對應的寫回路徑（`scenario.WriteSpecialTileSet`），
`MarkVisited` 用的就是同一個機制 —— **Noticed／Disarmed 是它的第二、第三種改寫**。

> `docs/re/78` §3 當時只認出「已造訪」一種改寫。現在是三種：
> 造訪（值 ← 1）、已注意（類別 3 → 6）、已解除（整個 byte ← 0）。

## 3. 順帶修正 `docs/re/68` §3 的一處含糊

飛鏢／長矛那一段當時記成「`Roll(3)` → 扣血；`Roll(4)` → 第二條傷害路徑」，
沒說第二條什麼時候走。讀完是：

```
19c8b  count = Roll(5) + 1                      ; 2–6 支
       for i = 1..count {
19cc5      if (Roll(2) == 1) { 印 "%smisses"; continue }    ; 50% 落空
19d22      who = 隨機隊員
19d2e      dmg = Roll(3)
19d52      if (ds:0x52f6 == 4) dmg += Roll(4)   ; ← 只有 case 4
19d6c      套用 HP（25be:145c）；回 0 → 全隊死亡
       }
```

所以 **case 4 ＝ 長矛，傷害 `Roll(3)+Roll(4)` ＝ 2–7；case 5 ＝ 飛鏢，`Roll(3)` ＝ 1–3。**
手冊寫的是「飛鏢 1-3」「長矛是飛鏢的加強版，2-7」——**逐字對上**，
`docs/re/66` §3 的 case 4＝`Spear trap!`／case 5＝`Darts shoot from` 也對上。
兩個獨立來源指向同一組數字，這一格可以定案。

### 另一件事：「毒坑」名字唬人

坑那一段（`0x19bb3`–`0x19c42`）**沒有任何 `cmp ds:0x52f6`** ——
一般坑（case 2 `A Bungei pit!`）與毒坑（case 3 `Poison pit!`）
`Roll(2)` 安全、否則 `Roll(6)` 傷害，**數值一模一樣**，只有宣告的字串不同。

真正有毒的那個是毒針，而它特別的地方不是毒，是**沒有命中判定**（`docs/re/68` §1）。
`docs/re/68` §5 提到 `Bungei` 查不到出處 —— 仍然查不到，維持不譯。

| 0 | `Something you cannot`… | — | — | 未讀 |

## 5. 引擎缺什麼

只差接線，沒有未解的機制：

1. `L` 鍵（世界模式），照 §1 的順序：掃描距離 ＝ 光源、只往正前方、
   撞到非走道就停、25%／100%、Noticed／Disarmed 兩種改寫、白框、結尾計數訊息。
2. 類別 3／6 觸發時真的跑 §4 那張表並**扣血**（目前只印一行「有陷阱！」）。
3. 類別 6 的 50% 迴避。
4. 技能 10／11 的效果 —— 由 1、3 自動獲得。

`scenario.SpecialTile` 已經有 `Class()`／`Value()`／`Attr`，
`WriteSpecialTileSet` 也在，**兩種新改寫直接沿用 `MarkVisited` 的路子**。

# 69 — 移動分派表最後四格

`docs/re/58` 認出 21 格裡的 12 格，`CONTEXT.md` §7 的 A1 留下
`0x08`／`0x0f`／`0x10` 與「`0x0c`／`0x12` 的參數語意」。這一篇補完。

這四格**都沒有字串**，所以字串錨定失效，只能讀行為。

---

## 1. `0x0c` 與 `0x0a` — 參數選的是提示詞

`222f:2088` 開頭：

```
17f85  ax = [bp+6] × 4
17f8e  印 遠指標 ds:0x23e8[參數]
17f9e  call 122f:1d23(參數, &結果)
17fb1  結果 < 0 → return 2
```

`ds:0x23e8` 那張 4-bytes-per-entry 的遠指標表：

| 參數 | 字串 |
|---|---|
| 0 | `Use ` |
| 1 | `Drop ` |
| 2 | ` ` |
| 3 | `Examine ` |

（第 5 筆起 segment 值就亂掉了，表只有 4 筆。）

所以：

- **動作 `0x0c` ＝ `222f:2088(0)` ＝ Use（使用道具）**
- **動作 `0x0a` ＝ 轉呼叫 `222f:2088(3)` ＝ Examine（檢視）**

參數 1（`Drop `）在這張分派表裡沒有對應的格子 —— 同一支常式也被別處用。

> `docs/re/50` 說 `0x0c` 與 `0x12` 「成對，差在參數 0／1」——
> **那個判讀不成立**。`0x12` 是 `25be:0263`（`docs/re/65` 的地點劇情事件），
> 與 `222f:2088` 是兩支不同的函式，只是當時看到都帶參數 0 就配成一對。

## 2. `0x0f` 與 `0x10` — 兩個靈視技能

兩支結構完全相同，只差檢查的欄位：

```
18fdd  for (i = 0; i < 隊伍人數; i++)
18feb      if (角色[i][+0xe3] != 0) 有人會 = 1      ; 0x0f
193e1      if (角色[i][+0xe4] != 0) 有人會 = 1      ; 0x10
```

`+0xe3`／`+0xe4` 落在技能旗標陣列（`0xc8`–`0xe6`）裡：

```
0xe3 − 0xc8 = 27
0xe4 − 0xc8 = 28
```

對照 `docs/re/21` §1 的技能表：

| id | 技能 | 系 |
|---|---|---|
| 26 | 觀地 Sense Ground | 靈視 |
| **27** | **觀室 Sense Room** | 靈視 |
| **28** | **鑑物 Sense Object** | 靈視 |

- **動作 `0x0f` ＝ 觀室**
- **動作 `0x10` ＝ 鑑物**

兩者都是「掃全隊有沒有人會，有才繼續」。這與 `docs/re/38`（觀地，技能 26）
是同一組三個靈視技能 —— 觀地已解，另外兩個現在有了入口。

## 3. `0x08` — 載入地城的探索地圖

```
1798e  if (party[+0xa3] >= 10) 跳過        ; 戶外不做
1799d  索引 = 子地圖 − 1
179a1  push 0x1ff                          ; 511
179b2  push 遠指標 ds:0x551c[索引]          ; 來源
179ba  push ds:0x5514                      ; 目的
179c2  call 307c:0005                      ; memcpy 之類
179d1  ds:0x5c52[索引] = 1                 ; 標記已載入
```

**只在地城做**（`+0xa3 < 10`，依 `docs/re/24` 那是室內）。

`511` 這個長度是關鍵：`64 × 64 = 4096 bits = 512 bytes`。
地圖是 64×64 的格子，**每格 1 bit** —— 差的那 1 byte 大概是
邊界或 header。所以這是**「走過哪些格子」的探索記錄**。

`ds:0x5c52[索引] = 1` 是「這張地城的記錄已經初始化過」的旗標，
避免重複載入把玩家走過的痕跡蓋掉。

> 這條是**依長度與時機推的**，沒有追到讀取端（誰用那 511 bytes 畫圖）。
> 標為判讀，不是結論。

## 4. A1 收束

21 格現在的狀態：

| 已認出語意 | 16 格 |
|---|---|
| 子常式（被其他格呼叫，非獨立動作）| `0x0a`→`0x0c`、`0x09`／`0x0b`→`0x0d` |
| 仍未讀 | `0x07` 的內部細節（陷阱偵測，字串已知）、`0x13`／`0x14`／`0x16` 的內部 |

**A1 的原始問題「四格未解」已經解掉**：`0x08`（探索地圖）、
`0x0c`（Use）、`0x0f`（觀室）、`0x10`（鑑物），
外加更正了 `0x0c`／`0x12` 那個錯誤的「成對」判讀。

剩下的是各格**內部**的細節，那是另一個粒度的工作 ——
分派表本身已經沒有空格。

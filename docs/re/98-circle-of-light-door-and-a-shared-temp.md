# 98 — 光之環的門讀完了：它不是「不准走」，是走上去再推回來

`CONTEXT.md` §7 把 A7 的 case 15 列在「還沒接」那一堆裡。查下來不是沒接，
是**接得太寬**：引擎的閘門只看子地圖編號，沒有比對座標，
效果是符印沒解完就在整張地圖 5 一步都走不了。

順帶把 `docs/re/97` §5.2 那條「同一個 DS 位址在不同函式裡語意不同」的警告
實際用了一次 —— case 15 讀的 `ds:0x4e32` 在這裡是**面向**。

## 1. case 15 的全文（`25be:0d85` ＝ `0x1a565`）

```
1a565  LES BX,[0x4c76]                       ; 隊伍結構
1a569  if (party[+0x96] == 0) goto blocked   ; 符印 0
1a571  if (party[+0x97] == 0) goto blocked   ; 符印 1
1a579  if (party[+0x98] != 0) goto ret3      ; 符印 2 也解了 → 放行，**不印任何訊息**

blocked:
1a581  印 ds:0x2e40                          ; "A crimson forcefield bars your entry
                                             ;  to the Circle of Light"
1a58e  LES BX,[0x4c76]
1a592  if (party[+0xa1] != 0x0b) goto skipY  ; X == 11 才動 Y
1a59a  party[+0xa2] = 0x36 − ([0x4e32]×2 + 2)

skipY:
1a5ac  LES BX,[0x4c76]
1a5b0  if (party[+0xa2] != 0x32) goto ret3   ; Y == 50 才動 X
1a5b8  party[+0xa1] = [0x4e32]×2 + 7

ret3:
1a5c5  return 3
```

`+0xa1` ＝ X、`+0xa2` ＝ Y（`save.go` 的 `positionXOffset`／`positionYOffset`）。

### 1.1 四格十字：資料層對得上

`5SS.DAT` 裡類別 5、值 15 的記錄剛好四筆，位置與 `docs/re/83` §2 一致：

```
(11,49) attr=0xaf    (12,50) attr=0xaf
(11,51) attr=0xaf    (10,50) attr=0xaf
```

（同一張圖另有一筆 `(11,20)` case 10 ＝ 那道 `VOID` 密語。）

### 1.2 那兩條式子在算什麼

看起來像魔術。把四格連同「走進來時的面向」代進去就清楚了
（面向 0=北 1=東 2=南 3=西）：

| 觸發格 | 走進來的面向 | X==11？ | Y==50？ | 結果 |
|---|---|---|---|---|
| (11,49) | 南 (2) | ✓ → Y = 54−4−2 = **48** | 48≠50 | **(11,48)** |
| (11,51) | 北 (0) | ✓ → Y = 54−0−2 = **52** | 52≠50 | **(11,52)** |
| (10,50) | 東 (1) | ✗ | ✓ → X = 2+7 = **9** | **(9,50)** |
| (12,50) | 西 (3) | ✗ | ✓ → X = 6+7 = **13** | **(13,50)** |

四格全部回到**剛才那一格**。作者把「退一步」寫成兩條算式，
省掉查 ΔX／ΔY 表 —— 對這四格而言等價。

**但它不是通用的退一步。** 從 (10,49) 往東走進 (11,49) 的話，
第一條把 Y 設成 50，第二條接著生效把 X 設成 9，隊伍被丟到 (9,50)。
所以引擎照抄式子，不改寫成 `party.StepBack()` ——
把巧合當規則就會在別的入射角上分岔（同 `docs/re/62` §3.3 的紀律）。

### 1.3 引擎原本錯在哪

```go
// cmd/demonwinter/main.go（已移除）
if a.mapID == game.ImprisonSubMap && !game.CircleOfLightOpen(a.save.GlyphFlags) {
    a.message = "緋紅的力場擋住了通往光之環的路"
    return nil
}
```

`ImprisonSubMap` ＝ 5 是**禁錮的地點條件**，被借來當「這裡是光之環」。
少了座標比對，效果是**整張地圖 5 都不能走**。

`docs/re/62` §3.2 記過一條刻意的差異：「原版走進去才擋並推開，
本專案在移動前擋，玩家看到的結果一樣」。那句話**只涵蓋時序**，
沒涵蓋範圍 —— 而範圍才是出問題的那一維。

**為什麼實機驗收沒抓到**：主線那幾段截圖都帶 `-glyphs`
（把三個符印當成已解），閘門根本沒生效。
> 偵錯旗標把驗收路徑繞過去了，這和 `rulebook/63`「陳舊標記」是同一個形狀：
> 不是沒驗，是驗的那條路不經過待驗的判斷。

現在它掛回 `locationPlot` 的 case 15，和其他 case 走同一條路
（`cmd/demonwinter/circleoflight.go`）。

## 2. `ds:0x4e32` 這一支裡是面向 —— 而 `docs/re/97` 的警告正好用上了

`docs/re/97` §5.2 已經把這個位址定性成**共用暫存**（40 個寫入點、
跨 `138d`／`1990`／`17c5` 五個段，還有 `IDIV word ptr [0x4e32]` 這種
把它當除數的用法），並且明文寫著「同一個位址在不同函式裡語意相同」
是個錯誤假設。**這一輪是那條警告第一次派上用場。**

case 15 自己**沒有寫過** `[0x4e32]`，值是呼叫鏈上游留下的：

```
222f:0b15  LES BX,[0x4c76]
222f:0b19  [0x50f0] = party[+0xa1]        ; X
222f:0b2a  [0x50ee] = party[+0xa2]        ; Y
222f:0b34  [0x4e32] = party[+0xa4]        ; ← **面向**
222f:0b3e  [0x52d4] = party[+0xb0]        ; 船
```

`222f:0b0e` 是「走一步」的入口，動作 `0x12` 在它下游，所以 case 15 讀到的
就是這一步開頭的面向 —— 與 `docs/re/97` §3 那段畫隊伍圖示的程式碼同源
（那裡也是 `MOV BX,[0x4e32]  ; 面向`）。

要注意這**不是**「查了 `docs/re/97` 就知道答案」：同一份筆記裡
`FUN_222f_0003` 用它裝矮人旗標。真正的證據是 §1.2 那張表 ——
代進四格全部落回「剛才那一格」，一個巧合湊不出四個。
**讀共用暫存時，唯一可靠的做法是往上游找最近的那個寫入點**，
`docs/re/97` 只能告訴你「不要直接套用別處的名字」。

### 2.1 順帶補一條判別法

`docs/re/97` 的判準是「數寫入點」。這一輪多一條更快的：
**出現在 `IDIV`／`IMUL` 的運算元位置就是暫存。**
沒有人會拿一個 0/1 旗標當除數 —— 一眼就能否決，不必先數 40 個寫入點。

`tools/fieldscan.py` 的普查除了數「有幾處寫 0」（用來定單向閂鎖），
也可以數「寫進去的值域有多雜」：`0`／`1`／`2`／`3`／`0xffff` 混在一起
就不是欄位。

## 3. 實機驗收

四組 headless 實跑，全部用 `-trace` 對座標（`workplace/dump/circle/`）：

| 起點／按鍵 | 軌跡 | 判讀 |
|---|---|---|
| `-x=11 -y=47` `Down×3` | (11,47) → (11,48) → **(11,48) ＋ 訊息** | 走上 (11,49) 觸發、印訊息、推回 (11,48)。**與公式相符** |
| `-x=8 -y=50` `Right×3` | (8,50) → (9,50) → **(9,50) ＋ 訊息** | 西向那一格同理，推回 (9,50) |
| `-x=11 -y=43` `Down×4` | (11,43) → (11,44) → (11,45) → **(11,46)** | **地圖 5 其他地方走得動** —— 舊版在這裡四步全部被擋 |
| 同上 ＋ `-glyphs` | (11,48) → (11,49) → **(11,50)** ＋ 文字框 | 符印解完就穿過去，一句訊息都不印 |

第三列是這次修的東西的**反面證據**：舊版那四步會印四次「緋紅的力場」而原地不動。

> **順手修掉兩個會騙人的東西**：
>
> - `tools/screenshot.sh` 的 `xdotool search --sync` 沒有 timeout。程式參數打錯
>   （這次是 `-trace` 少了值，flag 套件印用法就退出）→ 視窗永遠不出現 →
>   **整個流程靜靜掛住 30 分鐘，沒有任何錯誤輸出**。現在包 `timeout 20`，
>   逾時就把 app log 印出來並以非零碼結束。
> - 狀態列那一格印的是**內縮量**（`4 − 光照`），標籤卻寫「光照」。
>   「光照 3」讀起來像很亮，實際是只剩中央 3×3。改標「內縮」。
>   上一輪把兩邊改成共用同一個值只解決了一半 —— **名字錯照樣會誤導下一個人**
>   （`docs/re/97` §5.3 同一個坑的第二層）。

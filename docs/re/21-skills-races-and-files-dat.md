## 1. 技能學費表與遊戲內部的技能 id

### 定位方法：用攻略數值當指紋

`docs/re/19` 找到學院教技能會查 `[0x5508] + skill_id × 10 + class_id`，
並指出數值範圍與 `docs/walkthrough/part-3.md` 的 31 × 10 成本表相符 ——
但**只驗了範圍，沒驗順序**。

把攻略每一列的 10 個位元組當成指紋去 `FILES.DAT` 搜尋，
**31 列全部唯一命中**，且偏移量全部落在 10 bytes 的整數倍上：

```
表基底 = FILES.DAT 0x158，31 筆 × 10 bytes，1 byte／格，值域 1–10
索引    = skill_id × 10 + class_id
```

### 攻略的排列不是遊戲的排列

直接假設攻略列序 = 遊戲 id 的話，31 列只有 2 列對得上。
用指紋反推出來的真實順序如下，而且**分組明顯有結構**
（武器 → 戰鬥 → 實用 → 吟唱 → 神職 → 符文 → 學識 → 靈視 → 被動），

## 2. 爆擊門檻：條件是「學過狂暴」

`decompiled_all.c:3685`：

```c
local_6 = 0x5a;                                    // 90
if (((攻擊者.陣營 == 2) || (攻擊者.陣營 == 0xb)) &&
    (*(char *)(隊伍指標 + slot * 0x104 + -0x64e) != '\0')) {
    local_6 = 0x4b;                                // 75
}
```

那個 `-0x64e` 看起來很怪，先前因此被標成「查表索引方式與已知 `PARTY.DAT` 定址不一致」。
**其實是對的**，只是要把「戰鬥槽位 → 角色索引」的偏移算進去。玩家佔槽位 7–14，
角色索引 = `slot − 7`：

```
slot × 0x104 − 0x64e
  = (slot − 7) × 0x104 + 7 × 0x104 − 0x64e
  = 角色記錄基底 + 0x71C − 0x64E
  = 角色記錄基底 + 0xCE
```

而 `0xCE = 0xC8 + 6` —— 技能旗標陣列的**第 6 項**，也就是上表的**狂暴**。

**手冊逐字吻合**（`docs/manual/part-2.md`）：

> 狂暴（Berserking）：戰鬥中進入狂暴狀態的能力，將造成致命傷害的機率
> 從一般的 **10%** 提升到 **25%**。

門檻 90 → `Roll(100) > 90` 有 91–100 共 10 個值 = **10%**；
門檻 75 → 76–100 共 25 個值 = **25%**。兩者都對。**假設標記可以移除。**

> 這也順帶說明：爆擊加成**只對玩家角色生效**（陣營 `2` 或 `11`），
> 怪物與召喚生物不會有狂暴。

## 3. 種族系統

### 3.1 種族屬性上限表：`FILES.DAT 0x422`

初始化鏈裡「長度 `0x3c` 的未知表」就是它（`0x3c = 60 = 5 × 12` ✓）。
全域指標 `0x5510`。5 筆 × 6 words：

| race id | 速度 | 力量 | 智力 | 耐力 | 技巧 | w5 |
|---|---|---|---|---|---|---|
| 0 | 20 | 24 | 32 | 22 | 21 | **0** |
| 1 | 20 | 15 | 40 | 15 | 20 | 32 |
| 2 | 15 | 30 | 24 | 25 | 22 | 33 |
| 3 | 22 | 14 | 40 | 15 | 17 | 34 |
| 4 | 14 | 24 | 20 | 30 | 18 | 31 |

前五個 word 與手冊附錄 B「種族屬性上限」**25/25 全對**，
因此 race id 的順序確定是：**0=人類、1=精靈、2=矮人、3=黑暗精靈、4=巨魔**。

#### 第 6 個 word ＝ 種族附贈技能 id（`[已解，高信心]`）

值是 `0, 32, 33, 34, 31`。技能 id 只到 30，所以 31–34 是**技能旗標陣列之外的
偽技能 id**，代表天生就有、不佔學習點數的能力。

手冊 `docs/manual/part-1.md` 的種族表正好列出四個「附贈技能」，人類是「無」：

| race id | 種族 | w5 | 手冊的附贈技能 |
|---|---|---|---|
| 0 | 人類 | **0** | **無** |
| 1 | 精靈 | 32 | 感知魔法 Sense magic（DOS 版稱察覺靈光 Detect aura）|
| 2 | 矮人 | 33 | 夜視 See in dark（DOS 版稱黑暗視覺 Dark vision）|
| 3 | 黑暗精靈 | 34 | 汲取法力 Power Leech |
| 4 | 巨魔 | 31 | 再生 Regeneration |

四個非零值對應四個有附贈技能的種族、人類為 0 對應「無」，數量與位置都吻合。
（id 與技能名的**逐一配對**尚未從程式碼獨立驗證，但 `0` = 無這一項是確定的。）

### 3.2 種族欄位在角色記錄 `+0xf5`

`2aed:0a9f`–`0ac5` 是決定性證據：

```asm
MOV AX,0x104
IMUL [BP-0x2]              ; × 角色索引
LES BX,[0x4c7e]            ; 隊伍陣列
MOV AL,ES:[BX+SI+0xf5]     ; ← 種族
SUB AH,AH
MOV DX,AX
SHL AX,0x1  / ADD AX,DX / SHL AX,0x1     ; × 6      ← 種族表 stride
ADD AX,[BP-0xe]                           ; + 屬性索引 (迴圈 0..4)
SHL AX,0x1                                ; × 2 (word)
LES BX,[0x5510]                           ; ← 種族上限表
MOV AX,ES:[BX+SI]
```

旁證：`+0xf5` 全檔被比較的值是 `1`/`2`/`3`/`4`（0–4 五個種族），
另一處 `2aed:1a38` 以 `race × 4` 索引 `0x18fa`/`0x18fc` 的遠指標陣列
（種族名字串），且先判 `race != 0` 才查 —— 人類沒有對應條目。

> **推翻既有斷言**：`docs/formats/game-data-tables.md` 曾記
> 「`PARTY.DAT` 的 `0x0c` 是種族」，後來改標「已推翻、位置未知」。
> 現在確定是 **`+0xf5`**。

### 3.3 種族屬性修正：`(該種族上限 − 人類上限) / 4`

`FUN_206a_026c(race, attr)`：

```c
diff = 表[race*6 + attr] − 表[0*6 + attr];      // 以人類為基準
result = abs(diff) / 4;
if (diff < 0) result = −result;                  // 向零捨去，保留正負號
return result;
```

算出來的修正值（整數除法向零捨去）：

| 屬性 | 人類 | 精靈 | 矮人 | 黑暗精靈 | 巨魔 |
|---|---|---|---|---|---|
| 速度 | 0 | 0 | −1 | 0 | **−1** |
| 力量 | 0 | −2 | +1 | −2 | **0** |
| 智力 | 0 | +2 | −2 | +2 | −3 |
| 耐力 | 0 | −1 | 0 | −1 | +2 |
| 技巧 | 0 | 0 | 0 | −1 | 0 |

#### 這修正了手冊的巨魔那一列

手冊 `docs/manual/part-1.md` 記巨魔是「力量 −1、智力 −3、耐力 +2」，**沒有速度修正**。
本公式算出的是「速度 −1、力量 0」。

`docs/re/10` §1.2 曾用 DOSBox 截下五個種族的「平均值方框」，巨魔那張讀到
`7, 8, 5, 10, 8`。該文為了讓它對上手冊，自行補了一個手冊沒寫的速度 −1，
又把力量那碼（`8`）判定成「8×8 點陣字型下 7/8 誤判」的讀圖雜訊。

**但 `7, 8, 5, 10, 8` 正好等於 `8 +` 本公式的修正值，一碼不差。**
截圖是對的，需要被修正的是手冊那一列 —— 依專案的 oracle 優先序
（DOSBox 實測 > 手冊），且此處還有程式碼公式獨立支持，判定：

> **巨魔的實際修正是「速度 −1、智力 −3、耐力 +2」，力量沒有修正。**
> 手冊的「力量 −1」應是誤植（或把速度那格寫到力量去了）。

### 3.4 人類的隱藏加成：每項 +2

建角擲點的骨架（`decompiled_all.c` 約 10135–10145，
該函式反編譯丟失框架指標，需搭配原始指令讀）：

```
屬性 = Roll(a) + Roll(b) + 種族修正 + 1
若 屬性 < 3 → 屬性 = 3
若 角色.種族(+0xf5) == 0 → 屬性 += 2        ← 只有人類
```

**手冊把人類的優缺點都記成「無」，但程式碼給了每項 +2、五項共 +10 的加成。**

這解答了攻略作者的一段觀察（`docs/walkthrough/part-2.md`）：

> 「iii) **不知道為什麼**，人類的擲骰結果整體就是比較好。五項屬性加起來
> 擲到 60 到 65 並不難，相較之下我玩其他種族從沒擲出超過 55 的總和。」

玩家觀察到的差距（60–65 對比 55，約 5–10 點）與 `+2 × 5 = +10` 的量級吻合。
這是一條**手冊沒寫、玩家只能推測、要反組譯才看得到**的機制。

## 4. `FILES.DAT` 完整布局（2,254 bytes）

合併本文與 `docs/re/15`、`docs/re/19`、`docs/re/20` 的結果：

| offset | 長度 | 全域指標 | 內容 | 來源 |
|---|---|---|---|---|
| `0x000`–`0x157` | 344 | — | **未解** | — |
| `0x158` | 310 | `0x5508` | **技能學費表** 31 skill × 10 class | 本文 §1 |
| `0x28e`–`0x421` | 404 | — | **未解** | — |
| `0x422` | 60 | `0x5510` | **種族屬性上限表** 5 × 6 words | 本文 §3.1 |
| `0x45e` | 430 | `0x4e28` | **法術參數表** 43 × 5 words | `docs/re/15` |
| `0x60c` | 420 | `0x5300` | **未解**（長度 `0x1a4`）| `docs/re/20` §1 |
| `0x7b0` | 22 | `0x4cc4` | **未解**（長度 `0x16`）| `docs/re/20` §1 |
| `0x7c6` | 264 | `0x51d4` | **召喚生物屬性表** 12 × 11 words | `docs/re/20` §2 |
| `0x8ce`–`0x8cd` | 968 | — | **未解** | — |

四張表的邊界由啟動時的指標推導鏈給出（見 `docs/re/20` §1），
其中三張已用內容比對獨立驗證（法術表 43×10、種族表對手冊 25/25、
召喚表對手冊 24/24），**布局推導本身可信**。

> `FILES.DAT` 曾被判定「不是資源索引」——那個否證仍然成立。
> 它是**遊戲數值常數表的容器**，六張以上的表擠在一個 2 KB 的檔案裡。

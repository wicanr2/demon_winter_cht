# 99 — 兵器庫的四座台座：呼叫端一出現，六個 param 的規格就全對上了

`docs/re/65` §3 把地點劇情 case 3 記成一句「接近詢問」，
字串只有 `%s%s%s` 與 `Do you approach?`；同一篇 §3.2 讀完「劇情送道具」
的共用常式之後留了一句：

> 其餘六個 param 的規格沒讀（param 0 → 型別 `0x0a` ＋ 材質 3、param 1 → 型別 3、
> param 3 → 型別 2…），因為對應的劇情 case 還沒接，
> **沒有呼叫端就確認不了誰是誰**。

**呼叫端就是 case 3。** 它用座標算出 0–3 丟給那支常式，
所以四座台座剛好吃掉跳表的前四個 param。

## 1. case 3 的全文（`25be:085c` ＝ `0x1a03c`）

```
1a03c  idx = 0
1a041  if (X == 0x17 && Y == 0x1b) idx = 1          ; (23,27)
1a054  if (X == 0x21) {                             ; X == 33
1a05b      idx = 2
1a060      if (Y == 0x1f) idx++                     ; (33,31) → 3
       }
1a06a  旗標 = party + 0xb3
1a083  if (旗標[idx] != 0) return 2                 ; 拿過了 → 整格沒反應

1a08f  sprintf(buf, "%s%s%s",                        ; ds:0x2b84
                  ds:0x27dc,                         ; 場景敘述（前綴）
                  ds:0x27cc[idx],                    ; ← 這件道具的名字
                  ds:0x27e0)                         ; 球體那句（後綴）
1a0be  印 buf
1a0cc  印 ds:0x2b8b                                  ; "Do you approach?"
1a0d9  ans = 1000:b566()                             ; 是非題
1a0e0  if (!ans) return 2                            ; 說不 → 旗標不動

1a0e8  清文字框
1a0ed  25be:11ff(idx)                                ; ← 送道具的共用常式
```

X／Y 讀的是 `ds:0x50f0`／`ds:0x50ee` —— `222f:0b15` 在這一步開頭
從 `party+0xa1`／`+0xa2` 抄過去的那一對（同 `docs/re/98` §2 的 `ds:0x4e32`）。

### 1.1 那條 if 鏈的形狀值得看一眼

它**不是查表**，而且**預設值本身就是一個有效編號**：

| 觸發格 | X==23 && Y==27 | X==33 | Y==31 | idx |
|---|---|---|---|---|
| (23,31) | ✗ | ✗ | — | **0** |
| (23,27) | ✓ → 1 | ✗ | — | **1** |
| (33,27) | ✗ | ✓ → 2 | ✗ | **2** |
| (33,31) | ✗ | ✓ → 2 | ✓ → ++ | **3** |

(23,31) 沒有任何一條敘述提到它，靠「什麼都不符」拿到 0。
引擎照抄這條鏈而不寫成查表 —— 查表會多出一條「查不到」的分支，
那是原版沒有的狀態（`internal/game/armory.go`）。

## 2. 跳表七個 param 的規格

送道具常式（`25be:11ff` ＝ `0x1a9df`）的共用前置段：

```
1aaa2  17 bytes 全部清 0
1aabc  [+0x0e] = 0x0a                 ; 附魔 ＝ 10 − 10 ＝ 0
1aac7  [+0x10] = 0x01                 ; 已鑑定
1aacc  party[0xb3 + param] = 1        ; ← 旗標在分派**之前**就設了
1aad9  跳 cs:[param×2 + 0x139a]
```

跳表在 `0x1ab7a`（14 bytes，夾在兩段分支中間 —— 所以 Ghidra 的線性
反組譯在那裡錯位，要自己讀位元組）：

| param | 目標 | 覆寫的欄位 |
|---|---|---|
| 0 | `0x1aadc` | `+0x00 = 0x0a`、`+0x0f = 0x03` |
| 1 | `0x1aaee` | `+0x00 = 0x03`、`+0x09 = 0x12`、`+0x0a = 0x0c` |
| 2 | `0x1ab08` | `+0x0f = 0x05`、`+0x0e = 0x0b` |
| 3 | `0x1ab1a` | `+0x00 = 0x02`、`+0x01 = 0x0f`、`+0x02 = 0x04` |
| 4 | `0x1ab33` | 鐵匠鋪那把闊劍（`docs/re/65` §3.2） |
| 5 | `0x1ab6c` | `+0x00 = param + 0x17` ＝ 28 |
| 6 | `0x1ab6c` | 同一段 ⇒ 型別 29 |

**沒被覆寫的欄位就是 0**，型別也一樣 —— param 2 的匕首正是靠這個
拿到 `ITEMS.DAT` 第 0 件。看到「型別 0」不要當成漏寫。

## 3. 名字自己招供：六處交叉印證，零誤差

`ds:0x27cc` 那四個遠指標的**段值在載入時會被重定位**，
所以直接讀 4 bytes 只會拿到垃圾。但 offset 那一半是 DS 相對的，
`0x25B00 + offset` 就落在字串區：

| 指標 | offset | 檔位移 | 字串 |
|---|---|---|---|
| `0x27dc` 前綴 | `0x283f` | `0x2833f` | `You have entered an armory filled with old weapons and armor. On a pedestal in the center of the room lies a special item: ` |
| `0x27cc[0]` | `0x27f5` | `0x282f5` | `Silver Suit of Chain Mail` |
| `0x27cc[1]` | `0x280f` | `0x2830f` | `a Mace` |
| `0x27cc[2]` | `0x2816` | `0x28316` | `a Crystal Dagger` |
| `0x27cc[3]` | `0x2827` | `0x28327` | `an Icy Blue Short Sword` |
| `0x27e0` 後綴 | `0x28bb` | `0x283bb` | `. Several glowing spheres of light hover above the pedestal and seem annoyed by your presence.` |

把 param 的位元組分別對回名字，**每一項都對上**：

| param | 型別 | ＝ `ITEMS.DAT` | 材質類別 | ＝ 前綴 | 附帶法術 | 名字 |
|---|---|---|---|---|---|---|
| 0 | 10 | chain | 3 | Silver | — | Silver Suit of Chain Mail |
| 1 | 3 | mace | 0 | （無） | — | a Mace |
| 2 | 0 | **dagger** | 5 | Crystal | — | a Crystal Dagger（附魔 +1）|
| 3 | 2 | short sword | 0 | （無） | 15 ＝ **寒顫（Ice）** | an **Icy** Blue Short Sword |

材質前綴表見 `docs/re/48` §3、法術表見 `docs/re/15`。
「Icy Blue」不是材質前綴，是那把劍的附帶法術本身。

### 3.1 第七個印證：攻略講的就是這個房間

`docs/walkthrough/part-4.md` §3.2（加穆爾神殿）：

> 這一段有兩間大型側室，各由**鬼火**守著，共守四樣道具：
> i) 一把釘頭鎚，附帶恆常效果：速度+2
> ii) 一條銀鏈
> iii) 一把水晶匕首+1
> iv) 一把附帶潛伏效果（4點寒顫）的短劍

四樣道具一一對上，連 **匕首 +1**（param 2 覆寫 `+0x0e = 0x0b`）
與 **4 點寒顫**（param 3 的法術 15、強度 4）都對上了。
「鬼火」就是後綴那句 glowing spheres of light。

> 兩個獨立來源、六個欄位、零誤差 —— 這個判讀不需要 DOSBox 複核。
> 對照 `docs/re/57` §4.1 的教訓（「分不出兩者的證據不是證據」）：
> 這裡的證據**分得出來**，因為四件道具的型別／材質／法術三組欄位
> 各自不同，隨便換一組配對就會有名字對不上。

### 3.2 後續已定案：釘頭鎚的「恆常效果」

param 1 寫的是 `+0x09 = 0x12`、`+0x0a = 0x0c`，而
後續找到 `sub_11CBF` 的完整消費端：`11h` MaxSP、`12h` 速度、`13h` 力量、
`14h` 技巧，原始值一律減 10；`15h` 才是建立戰鬥單位時另讀的武器特效。
因此這把鎚子確定是 `12h` 速度、`0Ch − 10 = +2`，與攻略逐字吻合。

證據、地址、重建順序與 remake 實作集中在 [`docs/re/109`](109-equipment-passive-effects.md)。

## 4. 實機驗收

`workplace/dump/armory/`，四組都用 `-trace` 對座標與旗標：

| 按鍵 | 結果 |
|---|---|
| `Return,Left`（從 (24,27) 往西）| 敘述框：「…台座上放著一件特別的東西：**一把釘頭鎚**。幾團發光的球體…」，trace 記「台座 1」|
| `…,space,y,Return` | 「球體的光亮了起來。」→ 選人 → **Wopple 第 2 格拿到 1 號** |
| 拿完再走回同一格 | **完全沒反應**（原版 `0x1a083` 的 `return 2`）|
| `…,space,n` 之後再走回來 | 敘述**再播一次** —— 答不不會燒掉旗標 |
| (33,31) 那一座 | trace 記「台座 3」→ **一把冰藍色的短劍**，與 (23,27) 那件不同 |

### 4.1 順手抓到一個一直都在的輸入 bug

選人游標用 ↑↓，而世界地圖的移動迴圈也吃方向鍵 ——
而 `a.plotGift` 那個 block 原本擺在**移動之後**。結果按一次 `Down`
**游標動了、隊伍也走了一步**（trace 抓到 (33,31) → (33,32)），
選完人隊伍已經離開台座。

**鐵匠鋪同一條路一直都有這個病。** 沒被發現是因為當初的實跑只按了
`Enter`（選第一個人），從來沒送過方向鍵 —— 而畫面上看不出來，
因為選人頁蓋掉了地圖。單元測試也看不到：它測的是規則層，不是輸入順序。

現在那個 block 夾在「文字框」與「移動」之間，兩邊都不能換：
排在文字框前面台詞會翻不完，排在移動後面就是上面那個 bug。
（同記憶 `screen-bugs-tests-cannot-see`。）

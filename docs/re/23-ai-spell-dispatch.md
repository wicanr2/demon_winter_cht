# 23 — 怪物 AI 的施法效果分派：AI 到底會打誰

本文解掉 `docs/spec/02-combat.md` 掛著的那個缺口：**怪物 AI 挑到增益法術時
要打誰**。實測症狀是怪物法師會對玩家施放「聖域」「力量術」之類的加持。

位址換算沿用 `docs/re/00`：`file_offset = (Ghidra 段 − 0x1000) × 16 + 0x3c00 + 位移`。
`138d` 段的檔位移基底是 `0x74d0`。

---

## 1. 分派表在哪裡

AI 施法的主體是 `FUN_138d_065e`（Ghidra `138d:065e` = 檔位移 `0x7b2e`）。
選完法術之後（見 `docs/re/22` 與 `internal/game/aispell.go`）它在 `138d:0865`
跳進一段 switch：

```
138d:0865  JMP 0x1000:4557          ; = 138d:0c87
...
138d:0c87  CMP AX,0x11              ; 索引上界 17
138d:0c8a  JNC  default
138d:0c8c  XCHG AX,BX
138d:0c8d  SHL  BX,0x1
138d:0c8f  JMP  word ptr CS:[BX + 0xc65]
```

索引是效果類型 `ds:0x4e2e`。跳表在 `138d:0c65`（檔位移 `0x8135`），17 個 word。
直接從 `DEMON.INT` 讀出來：

| 效果 | 目標 | 檔位移 | 做什麼 |
|---|---|---|---|
| 1 | `138d:0868` | `0x7d38` | 範圍：挑一個玩家當中心的 5×5 |
| 2 | `138d:09fd` | `0x7ecd` | 單體，玩家側 |
| 3–7 | `138d:0a4d` | `0x7f1d` | 單體，**依 K 的正負決定打哪一邊** |
| 0x0b | `138d:0b29` | `0x7ff9` | 單體，玩家側（先掃過一遍確認有人可打） |
| 0x0e | `138d:0adc` | `0x7fac` | 單體，玩家側 |
| 0x10 | `138d:0bef` | `0x80bf` | 單體，玩家側（挑一次就算，不重挑）|
| 0、8、9、10、12、13、15 | `138d:0c63` | `0x8133` | default：什麼都不做 |

效果 3–7 五個索引指向同一個位址，是同一支處理常式。

> 這張表與 `docs/re/18` §6.3 的 `FUN_138d_2e63` **不是同一張**。那張是玩家／
> 道具共用的「效果套用」分派；這張是 AI 專用的「挑目標」分派。兩張都以
> `0x4e2e` 為索引、都是 17 項，很容易看混。

## 2. K 的正負決定打自己人還是打玩家（本文重點）

效果 3–7 那一支是唯一會分流的：

```
138d:0a4d  CMP  [0x4e30],0x0
138d:0a52  JLE  0x0a8c                  ; K <= 0 → 走「打玩家」那一支
           ; ---- K > 0：增益，打自己人 ----
138d:0a54  rnd(15) − 1                  → 候選槽位
138d:0a75  CMP  [BX+0x4eb4],0x0 / JZ  重挑   ; X == 0：不在場上
138d:0a7c  CMP  [BX+0x4ec4],0x1 / JG  重挑   ; 狀態 > 1：已經倒下
138d:0a83  CMP  [BX+0x4ed4],0xa / JG  重挑   ; 陣營 > 10：那是玩家，跳過
           ; ---- K <= 0：傷害／減損，打玩家 ----
138d:0a8c  rnd(15) − 1                  → 候選槽位
138d:0aad  CMP  [BX+0x4eb4],0x0 / JZ  重挑
138d:0ab4  CMP  [BX+0x4ed4],0xa / JL  重挑   ; 陣營 < 10：那是自己人，跳過
```

`0x4e30` 就是法術記錄的 **K**（`docs/re/09` §4.1 已驗證：有號係數，正負決定
增益／減損方向）。其餘六支沒有這道分流，一律打玩家側 —— 也就是說**怪物只有
效果 3–7 的法術會拿來加持自己人**。

### 用真實資料交叉驗證

把 `FILES.DAT` 的法術表與 `FILES.DTT` 的名稱接起來，套上這條規則：

| id | Effect | K | 判定 | 名稱 |
|---|---|---|---|---|
| 3 | 7 | +1 | 自己人 | FLAME SHIELD |
| 7 | 4 | +1 | 自己人 | STRENGTH |
| 8 | 7 | +1 | 自己人 | ARMOR |
| 9 | 7 | −1 | 玩家 | RUST ARMOR |
| 12 | 3 | +1 | 自己人 | WINGS OF VICTORY |
| 13 | 6 | +3 | 自己人 | WINGS |
| 15 | 3 | −1 | 玩家 | CHILL |
| 16 | 6 | −3 | 玩家 | SLOW |
| 18 | 7 | +1 | 自己人 | ICE SHIELD |
| 20 | 4 | −1 | 玩家 | WEAKEN |
| 22 | 7 | +1 | 自己人 | SANCTUARY |

被判成「自己人」的七個全是護盾／強化，一個例外都沒有。而且出現四組**共用
效果類型、K 正負相反**的對照：

- 效果 7：ARMOR (+1) ↔ RUST ARMOR (−1)
- 效果 4：STRENGTH (+1) ↔ WEAKEN (−1)
- 效果 3：WINGS OF VICTORY (+1) ↔ CHILL (−1)
- 效果 6：WINGS (+3) ↔ SLOW (−3)

英文名稱從頭到尾沒有參與推導，是事後才接上去核對的。

### 實機確認

`tools/screenshot.sh` 加上 `-battle` 與 `DW_LOG=1` 跑測試戰鬥：

```
Lvl 1 mage 的烈焰之柱讓 Wopple 減少 4      ← 效果 5、K = −3 → 打玩家
Lvl 1 mage 的聖域讓 Rat 增加 3             ← 效果 7、K = +1 → 打同伴 Rat
```

兩條分支都在實機上走到了。

## 3. 效果 1（範圍）的中心點與否決

先隨機挑一個**玩家側**單位當中心（`0x0868`–`0x0895`），然後掃全部 15 個槽位，
用 `|Δx| < 3 && |Δy| < 3` 判定誰在範圍內 —— 5×5 的方框，中心那一格算在內。
施法者自己若落在框內，也算一個己方命中（`0x08c2`–`0x090e`，這一段獨立於
底下的迴圈）。

掃完之後：

```
138d:09ae  MOV AX,[BP-0xe]      ; 己方命中數
138d:09b1  SHL AX,0x1
138d:09b3  CMP AX,[BP-0x10]     ; 敵方命中數
138d:09b6  JG  0x09d9           ; 己方×2 > 敵方 → 放棄
138d:09d9  ADD [BX+0x4ec2],AX   ; 把投入的法力退回去
```

**己方命中數 × 2 > 敵方命中數就中止並退款。** 怪物不會為了炸一個人把三個
同伴一起燒掉。

己方命中的計數有一個例外（`0x097e`–`0x0996`）：法術的 School（`ds:0x4e2c`）
等於 4 時，己方單位裡種族／元素類型是 4、7、10 的**不算誤傷**。那組
`{4, 7, 10}` 與噴吐的免疫組（`docs/re/22`）是同一組值，但兩邊的觸發條件不同
（噴吐看施放者類型 10，這裡看法術 School 4），所以只照抄，不推廣成通則。

## 4. 順手解掉：附身術（效果 0x10）的成功率

效果 0x10 那一支在 `138d:0c58` 呼叫 `0x1000:4586`，換算過來是 `138d:0cb6`
—— 也就是 `docs/re/20` §9.5 講的「把單位在兩個陣營間對調」的函式。
所以 **效果 0x10 = POSSESSION（附身術）**，資料表也對得上（id 26、effect 16）。

```
138d:0cbc  ax = 投入量
138d:0cbf  bx = 0x12c / IMUL BX        ; × 300，32-bit
138d:0cdd  ax = 目標 HP（unit+0x06）× 2
138d:0ce3  ax += 目標法力（unit+0x0e）
138d:0cfe  CALLF 0x3000:016a           ; 32-bit 除法
138d:0d20  rnd(100)
138d:0d2d  JLE 成功
```

```
成功率 = 投入 × 300 / (2 × 目標HP + 目標法力)      （整數除法，不鉗制）
成功 ⟺ rnd(100) <= 成功率
```

成功後走 `0x0d6a`–`0x0dba` 的比對鏈把陣營值對翻：`1→12`、`2→11`、`4→14`、
`11→2`、`12→1`、`14→4`。與 `docs/re/20` §9.5 的配對表一致，**幻化生物（3／13）
不在鏈上**，所以幻影不能被附身。

> `docs/re/18` §6.3 把 `FUN_138d_0cb6` 標成「職業轉換」，那是錯的標籤 ——
> 它是附身／陣營對翻。已在該文更正。

## 5. 順手釐清：`unit+0x20 == 2` 那道閘

`FUN_138d_065e` 一開頭有一道閘（`138d:068a`），成立時去查施法者的符文系
技能旗標，旗標為 0 就不施法：

```
138d:068a  CMP  [BX+0x4ed4],0x2 / JNZ 主流程
138d:0691  MOV  AX,0x104 / IMUL [BP+0x6]   ; 0x104 × 施法者槽位
138d:0697  ADD  AX,[BP-0xa]                ;   + 符文系（1–5）
138d:069c  LES  BX,[0x4c7e]                ; 角色記錄陣列
138d:06a0  CMP  ES:[BX+SI+0xf9bc],0x0      ; 旗標 0 → 不施法
```

`0xf9bc` 當有號 16-bit 看是 `−0x644`，所以位移是 `0x104 × 槽位 − 0x644`。
槽位 7（隊伍第 0 人）→ `0x71c − 0x644 = 0xd8`，加上符文系 1–5 得 `0xd9`–`0xdd`；
角色記錄的技能旗標陣列在 `0xc8`，技能 id 17–21 正好落在 `0xd9`–`0xdd`
（`docs/re/21`）—— 五個符文系，分毫不差。

也就是說這一支只對**槽位 7–14** 成立。陣營值 2 = **被附身、現在替怪物打的
玩家角色**：人還在玩家槽位、PC 記錄還在，所以 AI 幫它施法前要查它自己的技能。
一般怪物（陣營 1）不走這一支。

這正是 `CONTEXT.md` 那條「`+0x20` 語意收回」的癥結。當時的推論「這條路徑只對
玩家側成立，所以 `== 2` 是玩家側」**前半對、後半錯** —— 它確實只對玩家槽位
成立，但那是因為 2 是「玩家角色被搶走了」，不是「2 代表玩家陣營」。

## 7. 噴吐（`FUN_138d_17b8`）的後半

同一輪把噴吐也讀完了。整個函式分成**兩趟掃描**，中間夾一道否決：

```
第一趟（0x1805–0x196a）  數出兩邊各命中幾個
否決  （0x196d–0x197b）  敵方 0、或己方×2 > 敵方 → 中止，回傳碼 3
第二趟（0x1a15–0x1c8b）  逐格往外掃、畫動畫、對命中的單位扣血
```

**否決條件與 §3 的範圍法術完全一樣** —— `己方命中數 × 2 > 敵方命中數`。
同一條規則在兩個獨立的地方各寫一次，是這個引擎的慣用手法。

### 7.1 兩趟掃描描述同一個錐形

第一趟以**面前那一格**為起點，`|Δ橫| <= Δ沿`、深度 4；
第二趟以**施放者自己**為原點，`a = 1…4`、`|c| <= a − 1`。
代入 `a = 沿距 + 1` 兩者等價。這是一組現成的交叉驗證 ——
四個方向各寫死一段的程式碼最容易某一段抄歪，兩趟互相對得上就表示沒歪。

### 7.2 傷害

```
138d:1b4b  AX = 施放者當前 HP（unit+0x06）
138d:1b4f  CX = 3 / IDIV CX
138d:1b56  CALLF rnd(AX)
138d:1c1f  SUB [BX+0x4eba],AX
```

```
傷害 = rnd(施放者當前HP ÷ 3)
```

**與投入、等級、目標護甲都無關** —— 只看噴吐者自己還剩多少血。受傷的龍噴得
比較弱。扣血前 `目標.HP > 傷害` 才活得下來（0x1bb5 的 `JG`），所以傷害等於
HP 就死。

### 7.3 元素與免疫，對照 `MONSTER.DAT`

施放者種族換成元素（0x1992–0x19e8）：`8→6`、`9→7`、`10→8`、`11→rnd(3)+5`。
種族 12 沒有分支 —— 但那打不到：`MONSTER.DAT` 裡落在 AI 噴吐區間 8–12 的
**只有四隻，全是龍**：

| 索引 | 種族 | 名稱 |
|---|---|---|
| 74 | 8 | Fire dragon |
| 75 | 9 | Wind dragon |
| 76 | 10 | Ice dragon |
| 53 | 11 | Great dragon |

巨龍擲 `rnd(3)+5` 代表牠三種吐息隨機來一種。AI 那道 `8 <= 種族 <= 12`
只是抓得寬一點。

免疫組 `{4, 7, 10}` 也對得上：種族 10 是**冰龍**，種族 7 是冰系生物
（Ice elemental／Ice demon／Arctic bear／Winter wolf／Yeti／Snow giant／Guardian）。
**冰的吐息傷不了冰。** 火龍與風龍沒有對應分支，這個不對稱是原版本來就有的。
種族 4 在 `MONSTER.DAT` 裡沒有人用。

這順帶把 `gamedata.Monster.Special` 從「語意未確認」升級為已確認 ——
它是**種族／元素類型**，載入戰鬥後就是單位記錄的 `+0x22`。舊註解疑惑
「元素系怪物的值不連續、對不上五大符文系」，那是把兩件事混在一起：
這一欄不是符文系索引，符文系另有其表（`docs/re/21`）。

## 8. 還沒讀完

- 效果 1 之後的實際套用：六個 far call（`0x4c1d`／`0x47dd`／`0x498c`／`0x4875`／
  `0x46d4`／`0x4586`）走的是與玩家共用的效果路徑，只有 `0x4586`（附身）本輪讀了。
- `0x7bef` 那道 `effect_type == 1 && ds:0x518e == 1` 的重挑條件，`0x518e` 語意未解。
- 噴吐第二趟掃描的地形阻擋（`ES:[0x4c94][y*64+x] <= 0x13` 就不找單位）
  還沒接。

  **動畫接上了。** `0x1a59` 的那一行是
  `draw(x + 5, y + 5, ds:0x4e2c)` —— 逐格畫一個圖塊，圖塊由**法術記錄的
  school**（`ds:0x4e2c`）決定，座標的 `+5` 是 22 寬緩衝的牆偏移
  （`docs/re/36`）。**畫在地形檢查之前**，所以整個錐形都會亮，
  不是只亮打得到的格子。

  掃描順序（先沿方向推進、每層再從側偏 −along 掃到 +along）決定了
  動畫看起來是**從嘴邊往外擴**。本專案照這個順序逐格點亮
  （`game.BreathCone` + `cmd/demonwinter` 的 `breathAnim`）；
  圖塊來源還沒解，先用單色方塊，每格的延遲也是本專案自己挑的
  （原版那個迴圈裡沒有延遲，速度取決於當年的機器）。

# 80 — 睡覺時的劇情推進：夢境三階段與 `+0xb9`

`docs/re/79` §5 把 `+0xb9` 的 19 處存取畫成轉移圖，但語意留白。
`docs/re/26` §51 更早就描出形狀：「依 `+0xbd`／`+0xb9`／`+0xba` 三個旗標
決定要不要播夢境（`0x1000:0339` 連放兩張圖），並清掉全隊的
`+0xd7`／`+0xd8`／`+0xf0`。**夢境內容與旗標語意未解**。」

這一篇把那三個旗標定案。**冬之魔是在玩家睡覺的時候降臨的。**

---

## 1. 完整的推進流程（`1000:0206` ＝ `0x03e06`）

```
3e06  ds:0x4c7a = 0x1d ; call 1cdc:1727
3e1c  if (時辰 < 0x0f || 時辰 > 0x18) {          ; 15–24 才睡得著
3e2d      印 "You are restless"  →  return 3     ; （docs/re/26 §36 已記）
      }
3e54  r = FUN_2aed_03e4(1, 1)                    ; 睡覺本體
3e6d  if (r == 0) return -1                      ; 這一晚被打斷

; ── 以下是劇情推進，每晚只走一段就 return ──

3e7c  if (月份 > 3 && party[+0xbd] == 0) {        ; ★ 第一場夢
3e8c      party[+0xbd] = 1
3e92      FUN_1000_0339(1)                        ; 播文字頁 0
3e9c      return
      }

3ea2  if (party[+0xb9] == 1) {                   ; ★ 第二場夢
3eaa      party[+0xb9] = 2                        ; 進入「冬之魔已降臨」
3eb0      FUN_1000_0339(2)                        ; 播文字頁 1
3eba      return
      }

3ec0  if (party[+0xb9] == 2 && party[+0xba] == 0) {   ; ★ 世界壞掉
3ed0      party[+0xba] = 0xff                     ; 神殿全毀（docs/re/79）
3ee0      for (i = 0; i < 5; i++) {
3eea          char[i].+0xd7 = 0                   ; 薩滿技能
3efc          char[i].+0xd8 = 0                   ; 司祭技能
3f0e          char[i].+0xf0 = 0                   ; 信奉的神祇
          }
      }
```

**三個旗標的語意**：

| 欄位 | 語意 | 證據 |
|---|---|---|
| `+0xbd` | 第一場夢已播 | 只有 2 處存取，`cmp 0` 與 `= 1`，**自己守衛自己**的一次性閂鎖 |
| `+0xb9` | 劇情階段（`1` → `2` 是冬之魔降臨）| 見 §3 |
| `+0xba` | 神殿已成廢墟 | `docs/re/79` §2 |

`FUN_1000_0339(n)` 只有 64 bytes，做的是
`FUN_25be_19d1(0xffff, 2); FUN_25be_19d1(n − 1, 2);` 然後等按鍵 ——
**顯示文字頁 `n − 1`**。同一支 `25be:19d1` 就是結局序列用的那支
（`docs/re/04` §5.1 拿 mode `1` 播頁 0–5），夢境用 mode `2`，
而城鎮變廢墟那段事件（`25be:1ae2`，`docs/re/78` §6）用 mode `0` 播頁 9。

## 2. 神殿被毀是「信仰整套歸零」

`docs/re/79` §3 已經證明薩滿與司祭技能旗標**全檔只有這一處寫入**。
補上 `+0xf0`（信奉的神祇）之後這一組是完整的：

| 角色欄位 | 存取數 | 寫入端 |
|---|---|---|
| `+0xd7` 薩滿技能 | 6 | **只有 `0x03eea`（寫 0）** |
| `+0xd8` 司祭技能 | 6 | **只有 `0x03efc`（寫 0）** |
| `+0xf0` 信奉的神祇 | 8 | `0x1c53f` 改宗（`docs/re/29`）、`0x21f9c`、**`0x03f0e`（寫 0）** |

所以那一晚醒來，全隊**同時**失去薩滿技能、司祭技能、與信仰。
驅散不死、祈禱、改宗的資格檢查（`docs/re/09` §103／§152、`docs/re/29` §117）
全部落空 —— 而且沒有任何路徑能還原前兩者。

> 這是很重的設計決定：**遊戲中段永久拿掉玩家的兩個職業能力**。
> 移植時不能「順手修掉」——那會改變遊戲的難度曲線與敘事。
> （`rulebook/82`：對齊原版，不是對齊常理。）

## 3. `+0xb9` 是劇情階段，`2` 是「冬之魔已降臨」

`docs/re/79` §5 的轉移圖加上本篇的 `1 → 2`：

| 位址 | 轉移 | 脈絡 |
|---|---|---|
| `0x03ea3/ab` | `1` → `2` | **睡覺的第二場夢**（本篇）|
| `0x03ec1` | `== 2` | 神殿全毀＋信仰歸零＋播第三場夢 |
| `0x0b875/7d` | `2` → `3` | 未讀 |
| `0x0dff7/ff` | `3` → `2` | 未讀 |
| `0x1072e/36` | `3` → `2` | 海上遇船（`docs/re/78` §4）|
| `0x15f99/a1` | `4` → `2` | 進大地圖時 |
| `0x161d0/d8` | `2` → `4` | 未讀 |
| `0x18a39`、`0x18c5e` | `== 2` | 隨機遭遇的加值路徑（`docs/re/24` §188）|
| `0x185c3`、`0x1a268` | `== 0` | 未讀 |
| `0x102f4` | `== 1` | 未讀 |
| `0x17300` | `== 2` | **效果是死的**（見 §4）|

**19 處全部用同一個基底 `ds:0x4c76`**（逐一往前找最近的 `les bx, ds:XXXX` 核對過）
—— 排除了「同一個位移在不同基底下是不同欄位」那個陷阱（`docs/re/76` §4）。

`2` 是樞紐：`3` 與 `4` 都會回到它，所以 `3`／`4` 不是更後面的階段，
是從 `2` 出發的暫態。而 `2` 一到就觸發世界性的惡化（神殿全毀、遭遇加值），
所以 `2` ＝ **冬之魔已降臨**。

### 起始值是 0，而且**找不到把它寫成 1 的地方**

先把便宜的做完（比再讀一段組語省事）—— dump 兩份原版存檔：

| | `+0xb9` | `+0xba` | `+0xbd` | `+0xbe` |
|---|---|---|---|---|
| `PARTY.DAT` | **0** | 0 | 0 | 0 |
| `PARTY.BAK` | **0** | 0 | 0 | 0 |

新遊戲初始化（`0x148cd`–`0x1494d`）也**沒有寫 `+0xb9`**
（它寫的是糧食 20、`(28,50)`、子地圖 34、朝向、光源、日 8、時 5、
遭遇倒數、商隊基準 1 —— 順帶交叉驗證了攻略說的「75 金幣、20 份糧食」）。

而 19 處存取裡**沒有一處寫 1**。這不是掃漏：改成「不看 opcode，
只要 `mod=10` 且 disp16 == `0x00b9` 就列出」重掃一次，結果仍然是
`0x80`（cmp）13 處 + `0xc6`（寫 imm8）6 處，就是那 19 處。
另外也排除了幾種常見的替代寫法：

- 無位移的間接寫（`mov byte es:[bx],1` 等）：0 次
- 對 `+0xb8`／`+0xb9` 的 16-bit 寫入（會順便寫到 `+0xb9`）：0 次
- `add bx, 0xb9` 這種先調基底再寫：0 次

**所以照程式碼看，`+0xb9` 從 0 出發永遠動不了** ——
每一處寫 2／3／4 都要求它先是非 0。整條劇情鏈會卡死。

### 但攻略說這段劇情確實會發生 → 是掃描器有盲點

`docs/walkthrough/part-4` §105：

> 離開後第一次睡眠時，你會收到馬利馮的警告。第二次發生同樣狀況時，
> 你會經歷第二段夢境，並發現依姆羅斯全境的神殿都已被摧毀。

對照程式碼，攻略講的兩次睡眠是**第二場夢**（`+0xb9 == 1` → `2`）與
**第三場夢**（`+0xb9 == 2 && +0xba == 0` → 神殿全毀）。
也就是說玩家走到那裡時 `+0xb9` **已經是 1** ——
攻略的上下文是「拿到恆世寶珠、回祭壇向遠古者回報」之後，
所以寫入端在那段任務事件裡。

依 `CONTEXT.md` 的 oracle 優先序（**攻略 > 反組譯推論**），
結論不能是「這段劇情到不了」，而是：

> **寫入端存在，只是不在常數位移的形式裡。**

而那種形式確實存在於這支執行檔：隊伍結構有 **20 處計算式寫入**
（`mov es:[bx+si], al` 12 處、`mov byte es:[bx+si], imm` 8 處，
基底都是 `ds:0x4c76`）—— 偏移放在 `si`，執行時才決定。
**常數位移掃描原理上看不到它們。**

這正好連上 A2：`docs/re/58` §4 列的事件動作裡若有「設定劇情旗標」，
那個寫入就是資料驅動的，偏移來自事件資料而不是指令。
**下一步**：追那 20 處的 `si` 從哪來，而不是再擴大常數位移掃描。

> `tools/fieldscan.py` 的限制要寫在這裡，因為它前幾輪太好用了
> （`+0xbe`「11 處沒一處寫 0」、`+0xd7`／`+0xd8`「只有一處寫入」都靠它定案）。
> **好用的工具最容易被當成完備的。** 它掃的是
> 「位移是常數」的存取；偏移放在暫存器的存取一個都掃不到。
> 前面那些結論仍然成立（那些欄位的語意由讀取端與既有筆記共同支撐），
> 但「**某欄位沒有寫入端**」這種**否定式斷言**，只有常數位移掃描是不夠的。

## 4. `ds:0x15c8` 是死變數：五處寫、零處讀

`+0xb9` 的 `2 ↔ 4` 轉移每次都伴隨寫 `ds:0x15c8`，看起來像重要的顯示狀態。
掃完之後**它從來沒有被讀過**：

```
0x0b86a  寫 0        0x15fa6  寫 1        0x161dd  寫 0
0x17307  寫 0xff     0x1730f  寫 0
```

絕對定址（ModRM `mod=00 rm=110`）的全部形式掃過，短式 `a0`–`a3` 也掃過，
**零個讀取端**；`mov ax, 0x15c8`（取位址）也出現 0 次，
所以不可能透過指標讀。

`0x17307`／`0x1730f` 那一對還在**繪製函式**（`0x172f4`，就是
`docs/re/79` §2 那支把神殿換成廢墟的）開頭 —— 所以當年應該是
「階段 2 時換一套畫面」，但那個讀取端被拿掉了，寫入留著。

**這一項的價值是防止下一輪去追它。** 與 `docs/re/78` 的
`+0xa9` 死讀（`0x0e20c`）、`docs/re/73` 的神殿樓梯遺留碼同一類。

> 判別「死變數」要掃**全部定址形式**。只掃 `[bx+disp16]` 會漏掉絕對定址，
> 只掃絕對定址會漏掉結構欄位 —— 兩者的 ModRM 編碼完全不同
> （`mod=00 rm=110` vs `mod=10 rm=7`）。`tools/fieldscan.py` 目前只做後者。

## 5. 對 worklist

- **`+0xb9` 語意定案**（`docs/re/79` §5 留的白）：劇情階段，`2` ＝ 冬之魔已降臨
- **新解**：`+0xbd` ＝ 第一場夢已播；夢境的觸發條件與順序（月份 > 3 起算）
- **新解**：`FUN_1000_0339(n)` ＝ 播文字頁 `n − 1`，與結局序列同一支常式
- **新解**：神殿全毀時**信仰整套歸零**（薩滿＋司祭＋神祇），前兩者不可還原
- **新解**：`ds:0x15c8` 是死變數（五處寫、零處讀）
- **新解**：新遊戲的起始狀態（子地圖 34 的 `(28,50)`、糧食 20、金幣 75）——
  與攻略 `part-4` 開頭一致
- **未解且重要**：`+0xb9 = 1` 的寫入端。常數位移掃描找不到，而攻略證明它存在
  → 追隊伍結構那 20 處計算式寫入的 `si` 來源（§3 末）
- **工具限制**：`tools/fieldscan.py` 只掃常數位移。
  **否定式斷言（「沒有寫入端」）不能只靠它**
- `docs/re/26` §51「夢境內容與旗標語意未解」可以結案（**內容**仍未看到 ——
  文字頁 0／1 的實際文字沒 dump，那是資源層的事）
- 仍未解：`+0xb9` 的 `3`／`4` 暫態語意、`0x0b875`／`0x161d0` 的脈絡

# 26 — 紮營選單與睡覺

追「旅店休息還沒接上」時翻出來的整個子系統。原本只想找旅店，結果發現
**紮營（Camp）是一個完整選單**，睡覺只是其中一項。
（當時數成 13 項，`docs/re/33` §1 訂正為 14 項。）

---

## 1. 紮營選單有哪些選項

> ⚠ **這一節已被 `docs/re/33` §1 訂正，內容留著只為了記錄當時怎麼判錯的。**
> 選單是 **14 項不是 13**（漏掉排在最前面的 `Party`），而且顯示順序與跳表索引
> **完全一致** —— 下面那句「選單顯示順序 ≠ 跳表索引順序」是誤判。
> 完整的 14 項對照表、快捷鍵與每一項的處理常式位址請看 `docs/re/33`。
>
> 判錯的原因：只從字串區 `DS:0x0106` 往下讀名字，沒有讀**用它的那張指標表**
> （`ds:0x94`，14 個遠指標）。表格類資料要從讀取端回頭定邊界。

字串在 `DS:0x0106` 起（檔位移 `0x25c06`）：

```
Sleep  Identify  Worship  Xorcise  View land
Trade  Drop  Equip  Use  Hunt  Cast  Quit
```

（`Party` 在 `DS:0x00f8`、`Reorder` 在 `DS:0x00fe`，排在這一段前面。）

分派表在 `1000:01c7`（檔位移 `0x3dc7`），14 個 word，`1000:01e3` 的
`CMP AX,0xe / JMP word CS:[BX+0x1c7]` 是入口。

## 2. 睡不睡得著（`1000:0206`）

```
1000:021c  CMP byte ES:[BX+0x9f],0xf  / JC  拒絕     ; 時辰 < 15
1000:0224  CMP byte ES:[BX+0x9f],0x18 / JBE 可以睡    ; 時辰 <= 24
1000:022c  印 DS:0x16d "You are restless"，回傳 3
```

**時辰 15–24 才睡得著。** 一天有 38 個時辰，這一段正好是入夜到深夜。
（`internal/game/clock.go` 的 `CanSleep` 早就有這條，本文只是補上出處。）

另外 `1000:018b` 在時辰 == 24 時印 `You are sleepy`（`DS:0x15e`）。
那不是獨立的一支 —— 它是選單 case 13（`Quit`）的一部分，離開紮營前
順手提醒你該睡了（見 `docs/re/33` §1）。

睡下去之後（`1000:0254`）呼叫 `0x2000:b2b4(1, 1)`；**回傳 0 代表這一晚被打斷**
（`1000:026d` 回 −1 直接離開紮營選單，看起來是遭遇），那條路徑還沒讀。

沒被打斷的話走 `1000:0278`–`0330` 的劇情推進：依 `party+0xbd`／`+0xb9`／`+0xba`
三個旗標決定要不要播夢境（`0x1000:0339` 連放兩張圖），並清掉全隊的
`+0xd7`／`+0xd8`／`+0xf0`。夢境內容與旗標語意未解。

## 3. 睡覺常式（`2aed:03e4` ＝ `0x2000:b2b4`，檔位移 `0x1eeb4`）

兩個參數：`param1` 是「野外紮營」旗標，`param2` 是睡幾晚。
紮營選單傳 `(1, 1)`；`param1 == 1` 的分支（`2aed:03f1`）會把 `param2` 強制成 1。

### 3.1 一晚的時間

```
2aed:04ba  rnd(6)                        → r
2aed:04c7  睡眠時數 = (27 − 目前時辰) + r − 1
2aed:06f0  時辰 ← r                      ; 醒在清晨 1–6 時
2aed:0700  日 +1（wrap 0x23 = 35）
2aed:071c  月 +1（wrap 0x17 = 23）
```

**時辰是直接設成 `rnd(6)`，不是加上睡眠時數。** 幾點躺下都在清晨醒來。
睡眠時數只有一個用途：算中毒扣血。

### 3.2 每名隊員

```
2aed:0554  hp = char[0xfd]   （目前 HP，上限在 +0xfc）
2aed:055e  sp = char[0xff]   （目前 SP，上限在 +0xfe）

2aed:0568  若 野外紮營:
2aed:0572      糧食(party+0x9b) > 0 → 糧食 −1
2aed:0581      否則 → hp −= 2
2aed:0593  若 狀態(char+0x102) == 1（中毒）:
2aed:059b      hp −= 睡眠時數
2aed:05a1      若 種族(char+0xf5) == 4 → hp += 睡眠時數   ; 抵銷 ＝ 免疫
2aed:05af  hp += 旅店 ? 2 : 1
           sp += 旅店 ? 10 : 5
2aed:05c8  hp 鉗到上限、sp 鉗到上限
2aed:05e6  hp <= 0 → 死亡訊息（DS:0x3b71）
```

回復量是**每晚一次的定額**，不隨睡眠時數增加。旅店（`param1 == 0`）比睡地上
好一倍。**讀到的常式沒有扣任何金錢** —— 旅店免費。

### 3.3 紮營專屬的三件事

```
2aed:040c  party+0xa7 = 1        ; 光源重設為 1（火把）
2aed:0416  party+0xaa = 7        ; 語意未解
2aed:0471  道具 +0x06 = 0        ; 使用次數歸零 ＝ 過夜充能
```

充能有兩個例外：`+0x05 >= 100` 的不充（`2aed:045f`）、`+0x06 == 0xff` 的不充
（`2aed:0466`）。

## 4. 副產品：抓到一個標反的欄位

`docs/re/25` 把道具槽的 `+0x05`／`+0x06` 標成「已用次數／總次數」。
**標反了。**

使用端只有一道 `CMP AL,[BX+6] / JZ 跳過`（`17c5:1981`），兩邊對調完全等價，
從那裡分不出來。寫入端才分得出來：睡覺把 `+0x06` 清成 0。
清「已用次數」＝ 過夜充能，說得通；清「上限」會讓道具永久失效，說不通。

所以 **`+0x05` 是上限、`+0x06` 是已用次數**。已在 `inventory.go` 更正。

這是 `rulebook/62`「找讀取端」的一個變形：**分不出兩個對稱欄位誰是誰的時候，
去找寫入端。** 讀取端只告訴你它們會被比較，寫入端才告訴你它們是什麼。

## 4b. 打獵（`1000:08af`–`0945`）

手冊：「在野外或在船上，每日一次出去找尋食物，能否找到須靠運氣。」

```
1000:0894  if 狀態(char+0x102) > 1 → 印訊息，不能打獵
1000:08bb  if 技能旗標(char+0xd0) == 0 → 印訊息，不會打獵
1000:08e2  char+0xef = 1                 ; 標記本日已打獵
1000:08e8  rnd(16)
1000:08f2  收穫 = rnd(16) − 6            ; 負數鉗成 0
1000:0906  收穫 == 0 → "The hunt was not succesful"
1000:092c  否則 → 糧食(party+0x9b) += 收穫，上限 255
```

**收穫 = max(0, rnd(16) − 6)** —— 值域 0–10，16 面裡 6 面空手（37.5%）。

兩個交叉印證：

- `char+0xd0` 是技能旗標陣列（`+0xc8` 起）的第 8 格，而**技能 8 就是「狩獵」**
  （`docs/re/21`）。實測起始隊伍只有遊俠 Menhir 這一格是 1，職業對得上。
- `char+0xef` 那個「本日已打獵」旗標**由睡覺清掉**（`2aed:0513`）。
  兩段程式合起來正好是手冊講的「每日一次」。

順帶確認兩個隊伍欄位：`party+0x9a` 是隊伍人數（睡覺與清旗標都拿它當迴圈上界）、
`party+0x9b` 是糧食份數（紮營 −1、打獵 +收穫）。

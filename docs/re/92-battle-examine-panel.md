# 92 — 戰鬥的 `?` 檢視，與兩個技能的閘門

`docs/manual-coverage.md` §7 把「戰鬥 `?` 檢視」列成第二個「解完沒接」——
`game.ActionExamine`（成本 0）早就定義了，卻**零呼叫端、沒綁鍵**，
而 `battleui.go` 的註解還寫著「熱鍵沿用原版（含 `?` 檢視）」。

那格不接，**戰術（技能 7）與怪物學識（技能 25）就永遠沒有效果**。

---

## 1. 從跳表找到函式

`docs/re/06` §已解出戰鬥動作跳表在 `138d:258f`，Examine ＝ case 10。
把表整張讀出來（`file = 0x138d × 16 − 0xC400 + off`）：

| case | 目標 | |
|---|---|---|
| 5 | `138d:23b3` | 攻擊 |
| … | | |
| **10** | **`138d:24e0`** | **檢視** |

case 10 的內容只有三行：

```
99b0  push [bp+6]                 ; 單位索引
99b3  call 07c5:1056              ; ＝ 17c5:1056 ＝ 0xc8a6（面板本體）
99b9  [bp-0x22] = 1               ; 「畫面要重畫」的旗標
```

**沒有扣行動點** —— 與 `ActionExamine` 的成本 0 對上。

> ⚠ 位址換算的坑：`docs/re/06` 寫的 `138d:xxxx` 是**真段**（`file = seg×16 − 0xC400`
> 直接用），而 case 10 裡 `call 07c5:1056` 的 `07c5` 是**指令裡的編碼值**，
> 要 `+0x1000` 才是真段。同一篇筆記裡兩種都有，換算前先看它從哪來
> （`tools/xref.py` 預設會加 `0x1000`，這裡要手動繞過）。

## 2. 面板逐行（`0xc8a6`）

```
c8c0  選單：Continue / Back / Quit             ds:0x0adb / 0x0ae4 / 0x0ae9，鍵 "CBQ"
c8db  游標移到單位的螢幕座標                   unit+0x4eb4 / +0x4eb6
c905  ds:0x5192 = 0xff → 重畫那一格 → 設回 0   ← **反白游標**
c958  名稱                                     遠指標表 ds:0x5194[單位]
c97b  狀態（+0x4ec4 != 0 才印）                ds:0x15ec[狀態]
c9c1    └ 1 < 狀態 < 5 時再接 "%s>%d" 帶 +0x4ecc   ← 束縛等級
ca4a  "%s:    %3d"   力量                      +0x4ec0
ca88  "%s:    %3d"   技巧                      +0x4ec6
cac6  "%s:    %3d"   速度                      +0x4eb8
cb04  "Armor: %3d pts."                        +0x4ebe
cb3a  武器名稱                                 +0x4ebc → 106a:000a 查名
cb7f  "HP: %3d  SP:%3d"   **只有槽位 > 11**    +0x4eba / +0x4ec2
cbd9  牠打算攻擊誰的名稱                       +0x4ed2 → ds:0x5194
cc06  再畫一次選單，等按鍵
```

`ds:0x5192 = 0xff` 這個反白機制**與 `L` 查看陷阱的白框是同一個**
（`docs/re/91` §1 的 `0x178b8`）。兩處獨立出現，可以當定案。

## 3. 兩個技能閘門是怎麼認出來的

面板裡有兩處條件式，讀的都是角色記錄的負偏移，而且**只有偏移不同**：

```
ca26  cmp byte es:[bx+si-0x63b], 0   → 0 就跳過整組屬性
cbb8  cmp byte es:[bx+si-0x64d], 0   → 0 就跳過「牠要打誰」那一行
```

兩者差 `0x12` ＝ **18**。技能旗標陣列從 `+0xc8` 起，一項一 byte，
而 `docs/re/21` §1 的 id 表裡：

```
怪物學識 = 25 → +0xc8 + 25 = 0xe1
戰術     =  7 → +0xc8 +  7 = 0xcf
0xe1 − 0xcf = 0x12 = 18            ← 完全吻合
```

所以：**`-0x63b` ＝ 怪物學識、`-0x64d` ＝ 戰術**。

這正好是手冊那兩句：

> 查看怪物時，除非隊伍中有人具備**怪物學識**，否則不會顯示怪物的屬性。
> 若隊伍中有角色具備**戰術**技巧，每隻怪物下方還會顯示牠可能攻擊的對象。

**手冊與機器碼獨立對上**，兩個閘門定案。

## 4. 手冊與 DOS 版不一致的一處

手冊寫「按 `->` 或 `<-` 可在角色與怪物之間前後切換」——
那是 **Apple II 版**的說法。DOS 版換成了選單：`Continue` / `Back` / `Quit`，
熱鍵 C / B / Q，字串與市集那組完全相同（`docs/re/52`）。

引擎兩種都收：C/B/Q 是原版鍵位，方向鍵是給現代玩家的方便。
**這是刻意的加法，不是判讀不同** —— 記在這裡免得下一輪有人「修正」它。

## 5. 沒讀的

- `+0x4ed4` 那個值（面板拿它與 `10`／`0xb`／`8` 比）的確切語意。
  引擎改用單位槽位（怪物 0–6、隊伍 7–11、召喚 12–14）做同樣的判斷，
  行為對得上手冊（召喚生物才顯示 HP／SP），但**不是逐位元組等價**。
- `ds:0x15ec` 那張狀態名稱表沒有逐筆讀出來，中文是照語意寫的。
- `106a:000a` 的武器查名沒讀 —— 引擎走 `StringPool.WeaponTypeNames()`，
  那張表與 `ITEMS.DAT` 前八筆同名（`gamedata/strings_test.go` 已釘）。

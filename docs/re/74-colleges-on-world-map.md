# 74 — 世界地圖上有 20 座學院，每座教一個技能

`docs/re/73` §4 只想補一件小事：tile `0x26` 對應哪個地點。
追下去卻是一整個沒被記載過的系統。

---

## 1. tile 分派只有四筆

```
19192  cmp ds:0x52f4, 0x2e  je  ┐
19199  cmp ds:0x52f4, 0x64  jne ┴→ call 278d:0098    ; 城鎮
191a7  cmp ds:0x52f4, 0x25  jne  → call 278d:0932    ; 神殿
191b3  cmp ds:0x52f4, 0x26  jne  → call 278d:11bd    ; ← 本篇
```

`docs/re/58` §2 記的觸發集合是 `{0x2e, 0x25, 0x26, 0x64, 0x5b}`，
但**`0x5b` 在這個分派裡沒有對應** —— 它會讓 `222f:0b0e` 回傳 `0x13`，
然後四個比較全部落空、什麼都不做。又一個「沒接」的東西。

## 2. `278d:11bd` ＝ 學院

```
1c698  al = party[+0xa8]              ; 設施參數
1c6a2  if (al != 0xff) 跳到 0x1c6ed   ; 已指定就直接用

       ; == 0xff：拿座標去查表
1c6af  cl = [bx + 0x342d]             ; X
1c6b7  cmp party[+0xa1]               ; 目前 X
1c6c3  al = [bx + 0x342e]             ; Y
       …

1c6f7  ax = [bp-2] × 4
1c700  push [bx + 0x5538]             ; ← 技能名表（docs/re/27 第 3 張）
1c709  push ds:0x3496                 ; "  The College of %s"
```

```
ds:0x3496 = "  The College of %s"
```

`ds:0x5538` 是 `docs/re/27` 解出的**技能名表（32 筆）**，
索引 ×4 是因為那是 far pointer 陣列。

## 3. `ds:0x342d` 是三元組表：(X, Y, 技能)

一開始當成 `(X, Y)` 配對讀，數字對不上任何東西。
**三個一組**才通 —— 第三欄是技能編號：

| 19 | 29 | 37 | 0 | 劍擊 |

**20 座學院**，教 16 種不同技能（劍術、空手道各有多座）。

值得注意的是**靈視系四個技能各有一座**（觀地／觀室／鑑物／讀心，#12–15），
與 `docs/re/69` §2 解出的動作 `0x0f`／`0x10`（觀室／鑑物）湊成一組 ——
那兩個動作是「隊上有人會就能用」，而技能要在這裡學。

> ⚠ 表的長度是依「#19 之後的第三欄若為 0 視為結束」讀的，
> 而 #19 的技能編號**本身就是 0**（劍擊）。所以「20 筆」有可能少算或多算 ——
> 要靠讀取端的迴圈邊界確認，還沒追。

## 4. 與城鎮學院的關係未定

`docs/re/19` §3 把學院列為**城鎮設施**之一（教技能、有學費表）。
本篇的學院是**世界地圖上獨立的 tile `0x26` 地點**。

兩者的關係有三種可能，目前分不出來：

1. 同一套：城鎮裡的「學院」入口也走 `278d:11bd`
2. 兩套並存：城鎮學院教多種技能、地圖學院各專精一種
3. `party+0xa8` 就是切換兩者的參數（`0xff` ＝ 走座標查表，否則城鎮指定）

第 3 種最像 —— 程式碼裡 `+0xa8 == 0xff` 才查座標表，而
`docs/re/73` §1 看到城鎮設施分派會先寫 `party+0xa8`。
**但沒有直接證據**，標為待確認。

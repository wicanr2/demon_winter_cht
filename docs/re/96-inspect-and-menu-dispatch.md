# 96 — `I) Inspect` 不在動作表裡；以及選單分派整條鏈的定案

`CONTEXT.md` §7 的 A2 只剩 `I` 一格。上一輪停在
「**選單指令碼 → 動作碼**中間還有一步沒讀到」（`docs/re/04` §3.1.1／3.1.2），
並且警告「任何『Inspect ＝ 動作碼 X』的結論都是猜的」。

那個警告是對的，但停手的位置差一點。**中間沒有多一步轉換 ——
少讀的是選單元件自己的最後一條指令。**

---

## 0. 結論先講

| | |
|---|---|
| 缺的那一步 | `FUN_2cdc_033d` 在「等輸入」模式回傳的是 **index + 4**，不是 index |
| 轉換表 | 在 `ds:0x217c`，**15 個 word**（一個選單項一格），不是先前讀到的 11 個 |
| `I` 為什麼對不上 | **它根本不回傳動作碼**：走 switch case 5，就地設 `ds:0x5c66 = 0x80` |
| `I` 做什麼 | 旗標讓繪圖常式把「有地城道具」的格子改畫成 tile `0x38`，維持一次重畫 |
| 順帶落地 | 動作 `0x06` ＝ Party info、`0x08` ＝ Save Game、`0x0d` ＝ Drop、`0x0e` ＝ Camp |

七格已由字串錨定獨立驗證過的動作碼（`docs/re/58` §4）**7/7 全中**。
兩張表的來源互不相干（動作表靠函式內字串錨定，轉換表是資料段位元組），
沒有共同的錯誤來源 —— 這是 `CONTEXT.md` §5「兩份互不相干的資料要對得上」那種證據。

## 1. 缺的那一步：選單元件回傳 index + 4

`FUN_2cdc_033d`（`2cdc:033d`，1488 bytes）的結尾：

```asm
2cdc:0725  CMP word ptr [BP + 0x12],0x1   ; param5 ＝ 呼叫模式
2cdc:0729  JZ  0x0731
2cdc:072b  CMP word ptr [BP + 0x12],0xa
2cdc:072f  JNZ 跳過
2cdc:0731  ADD AX,0x4                     ; ← 就是這一條
2cdc:0734  POP SI / MOV SP,BP / POP BP / RETF
```

主指令迴圈用 `param5 = 1` 呼叫（`222f:0d81`），所以**拿到的是 index + 4**。

這一條解釋了呼叫端兩個一直讀不通的地方：

```asm
222f:0d9c  MOV [BP-0x2],AX          ; AX ＝ index + 4
222f:0d9f  CMP AX,0xffff / JZ  …    ; 取消（沒加 4 的那條路）
222f:0da4  CMP AX,0x3    / JLE …    ; ← 取消／無效，不是「Walk…Camp 走另一條路」
222f:0da9  ADD AX,0xfffc            ; ← 還原成真正的 index，給游標記憶用
222f:0dac  MOV [0x4c84],AX
222f:0daf  MOV AX,[BP-0x2]          ; 重新載入 index+4
222f:0db2  SHL AX,1 / MOV BX,AX
222f:0db6  MOV AX,[BX + 0x2174]     ; ＝ ds:0x217c + index×2
```

`ADD AX,0xfffc` **不是**「算 index−4 當表索引」，是**把 +4 減回去**。
而 `[BX + 0x2174]` 配上 `BX = (index+4)×2`，實際位址就是 `0x217c + index×2` ——
表的真正起點是 `0x217c`，緊接在按鍵表 `0x216d`（15 bytes）後面。

`CMP AX,0x3 / JLE` 這一條先前被讀成「Walk／Party info／Save Game／Camp
不查表」。回傳值 ＝ index+4 之後，`≤ 3` 對應 index ≤ −1，**那是取消／無效**，
四個前排指令一樣走查表這條路。

## 2. 15 格轉換表（`ds:0x217c`，檔位移 `0x27c7c`）

先前只讀到 11 個 word 就停了，第 12–15 格（`0x2192`–`0x2199`）沒讀到 ——
而 `View room`／`View item`／`Quit` 正好在那裡。

四張表在資料段裡是連續排下來的，邊界因此可以互相驗證：

| 位址 | 長度 | 內容 |
|---|---|---|
| `0x2113` | 15 × 4 | 指令標籤的遠指標 |
| `0x214f` | 15 × 2 | 「這一項可不可選」旗標 |
| `0x216d` | 15 × 1 | 按鍵表 `WPSCLTDMEUIVXRQ` |
| `0x217c` | **15 × 2** | **本表** |
| `0x219a` | — | 字串本體（`Walk\0Party info\0…`）|

`0x217c + 15×2 = 0x219a` 剛好落在字串起點 —— **15 格，一格不多一格不少**。
用 11 格讀法的話 `0x2192`–`0x2199` 那四個 word 會變成沒人用的孤兒。

| idx | 鍵 | 指令 | 表值 | switch case | 回傳的動作碼 | 對照 `docs/re/58` |
|---|---|---|---|---|---|---|
| 0 | `W` | Walk | `0x04` | 4 | — 就地走一步 | — |
| 1 | `P` | Party info | `0x07` | 7 | `0x06` | 狀態列（`222f:1606`）|
| 2 | `S` | Save Game | `0x09` | 9 | `0x08` | 先前「未解」的 192 B |
| 3 | `C` | Camp | `0x0f` | 15 | `0x0e` | 先前**整格沒列** |
| 4 | `L` | Look | `0x08` | 8 | `0x07` | ✓ 陷阱 |
| 5 | `T` | Take | `0x0a` | 10 | `0x09` | ✓ `Take:` |
| 6 | `D` | Drop | `0x0e` | 14 | `0x0d` | 先前「被 0x09／0x0b 呼叫」|
| 7 | `M` | Move | `0x0c` | 12 | `0x0b` | ✓ `Move:` |
| 8 | `E` | Examine | `0x0b` | 11 | `0x0a` | ✓ |
| 9 | `U` | Use | `0x0d` | 13 | `0x0c` | ✓ |
| 10 | `I` | **Inspect** | `0x05` | **5** | **不回傳** | **不在表裡** |
| 11 | `V` | View room | `0x10` | 16 | `0x0f` | ✓ 觀室 |
| 12 | `X` | X)View item | `0x11` | 17 | `0x10` | ✓ 鑑物 |
| 13 | `R` | Read descr. | `0x06` | 6 | — 就地切模式 | — |
| 14 | `Q` | Quit | `0x12` | 18 | — 就地問 Y/N | — |

### 兩層 switch

`[bp-2]` ＝ 表值，`[bp-4]` ＝ 表值 − 1。**switch 判的是 `[bp-2]`，回傳的是 `[bp-4]`**：

```asm
222f:0df3  MOV AX,[BP-0x2]
222f:0df6  JMP 0x12f4
222f:12f4  CMP AX,0x13 / JNC 預設
222f:12fa  SHL BX,1 / JMP word ptr CS:[BX + 0x12ce]   ; 19 格內嵌跳表
```

跳表（`0x171be`，19 × 2 bytes）逐格：

| case | 目標 | 語意 |
|---|---|---|
| 0–3 | `222f:0df9` | 方向鍵：把 `[bp-2]` 寫進面向 `ds:0x4e32`，落入 case 4 |
| 4 | `222f:0dff` | 走一步（`W` 與方向鍵在這裡合流）|
| 5 | `222f:1274` | **`I` 探查** |
| 6 | `222f:1282` | `R` 切換敘述模式 |
| 7–17 | `222f:12c8` | `MOV AX,[BP-0x4]` → 函式尾 → **回傳動作碼** |
| 18 | `222f:12a8` | `Q` 離開（問 Y/N）|

**case 7–17 沒有任何一格改寫 `[bp-4]`** —— 11 格全部指向同一個位址。
所以「回傳的動作碼 ＝ case 編號 − 1」，值域 `0x06`–`0x10`，
剛好落在 21 格動作表的前段。

> `[bp-4]` 承載兩種語意這件事 `docs/re/04` §3.1.2 已經看出來了，
> 方向也對（「把兩條輸入路徑分開」）。差的只是回傳值那個 +4。

## 3. `I` 做什麼

case 5 的全部內容就三行：

```asm
222f:1274  MOV word ptr [0x5c66],0x80
222f:127a  MOV word ptr [BP-0x12],0xfffe    ; 迴圈狀態碼「重畫一次」
222f:127f  JMP 迴圈尾
```

`ds:0x5c66` 全檔**只有三個存取點**：

| 位址 | 動作 |
|---|---|
| `222f:0bf4` | 設 0（主迴圈每一圈，在繪圖之後）|
| `222f:1274` | 設 `0x80`（`I`）|
| `222f:14c7` | 讀（繪圖常式 `FUN_222f_1404`）|

讀取端在畫每一格之前插一段掃描：

```asm
222f:14c7  CMP word ptr [0x5c66],0x7f
222f:14cc  JLE 略過
222f:14ce  MOV [BP-2],0                     ; i = 0
222f:14d3  JMP 0x1515                       ; 先測終止符再進迴圈
222f:14d5  … es:[bx+si+0] == 這一格的 X ?
222f:14e6  … es:[bx+si+1] == 這一格的 Y ?
222f:14f1  … es:[bx+si+2] == party[+0xa3] ? ; 子地圖
222f:150b  MOV byte ptr ES:[BX + SI],0x38   ; ← 命中：把繪製緩衝區那一格寫成 0x38
222f:1511  ADD [BP-2],3
222f:1521  CMP AX,0xff / JNZ 繼續            ; 終止符
```

`ds:0x54e4` 是 `ITEMLOCB.DAT` 的緩衝區（`docs/re/95` §1 已驗證），
3 bytes 一筆 `(X, Y, 子地圖)`。

迴圈狀態碼 `-2` 讓主迴圈跳回 `222f:0b78`，**重跑一次繪圖**（`222f:0bdf`），
畫完在 `222f:0bf4` 把旗標清掉。所以 `I` 是**一次性覆蓋層**：
沒有技能門檻、沒有每日次數、不推進時間、不改任何持久狀態。

### 手冊獨立佐證

`docs/manual/part-3.md` §55：

> **I 探查周圍**：按「I」會自動掃描視野範圍內所有可見空間，找出地下城物品。
> 平時走動時通常看不到壁爐之類的東西，但按下「I」會在有物品的位置顯示地下城物品圖示。

oracle 第 3 級（手冊）與第 4 級（反組譯）獨立對上，逐字吻合，包含
「平時看不到」這個前提 —— 地城道具在地圖上本來就沒有自己的 tile。

> ⚠ `docs/manual-cht/01-transcript.md` 第 383 行把 `I` 寫成
> 「Inspect character（檢視人員）」。那是 1990 年台灣代理版的**誤譯**，
> 與英文手冊、執行檔都不符。照 `CONTEXT.md` §5 的注意事項，
> 翻譯本不是獨立來源。

## 4. 順帶落地的四格動作碼

21 格動作表（`cs:0x563`，檔位移 `0x16453`）裡的 stub 展開之後：

| 動作 | stub 呼叫 | 先前的狀態 | 現在 |
|---|---|---|---|
| `0x06` | `222f:1606` | 「狀態列重畫」 | **`P) Party info`** |
| `0x08` | `222f:1a94` | 「未解（192 B）」 | **`S) Save Game`** |
| `0x0d` | `222f:2da5` → `222f:2088(1)` | 「被 `0x09`／`0x0b` 呼叫的子常式」 | **`D) Drop`** |
| `0x0e` | `CALLF 0x1000:0000`（覆蓋段）| **整格沒列** | **`C) Camp`** |

`0x0d` 那一格的 stub 值得抄下來 —— 它同時解釋了 `It's too crowded here`
出現在哪裡，也補上了 `docs/re/69` §1 留的洞
（「參數 1（`Drop `）在這張分派表裡沒有對應的格子」）：

```asm
222f:041c  CALLF 222f:2da5        ; 列出腳下這一格有什麼，回傳件數
222f:0421  CMP AX,0x9
222f:0424  JZ  0x0435             ; 滿 9 件 → 印 ds:0x201a → 回傳 2
222f:0426  MOV AX,0x1 / PUSH AX
222f:042a  CALLF 222f:2088        ; ＝ 222f:2088(1) ＝ Drop
```

`0x08`（Save Game）那一格：把 `ds:0x5514`（`nSS.DAT` 緩衝區）與
`ds:0x1587` 兩份資料，配上 `[bx+0x551c]` 那張依子地圖索引的檔名遠指標表寫出去。
`docs/re/78` 的「遊戲中會把改動寫回 `nSS.DAT`」，寫出去的入口就是這裡。

## 5. 推翻的斷言

| 曾經寫過 | 真相 |
|---|---|
| `docs/re/04` §3.1：轉換表是 **11 個 word**、base `0x2174`、索引 `index` | **15 個 word**、起點 `0x217c`、索引 `index`（因為回傳值已經 +4）|
| `docs/re/04` §3.1：`ADD AX,0xfffc` 是「算 index−4」 | 是**把選單元件加上去的 +4 減回來** |
| `docs/re/04` §3.1：`CMP AX,3 / JLE` ＝「Walk…Camp 走另一條路，不查表」 | 是**取消／無效**。四個前排指令一樣查表 |
| `docs/re/04` §3.1.2：`Inspect` 可能是動作碼 `0x0d` → `222f:2da5` | **`I` 不回傳動作碼**。`0x0d` 是 `Drop` |
| `docs/re/58` §4：`0x0d` 是「被 `0x09`／`0x0b` 呼叫」的子常式 | 它**同時**是 `Drop` 那一格。`222f:2da5` 是共用常式，`0x0d` 是它的動作入口 |
| `docs/re/58` §4：`0x08` 未解 | `Save Game` |
| `docs/re/58` §4：表裡沒有 `0x0e` | 有，是 `Camp`（走覆蓋段的遠呼叫，所以字串錨定看不到）|
| `docs/re/69` §1：「參數 1（`Drop `）在這張分派表裡沒有對應的格子」 | 有，就是 `0x0d` |

## 6. 方法

**上一輪的停手是對的。** 三輪「推出一條看起來完美的映射 → 套到別的指令就壞」
之後停下來（`rulebook/41`），把已知的寫下來而不是把巧合寫成結論 ——
`222f:2da5` 那個「語意完美吻合」的答案，實際上是 `Drop` 的入口。
硬寫下去的症狀會是「按 `I` 跑去丟東西」，而且要玩到那一步才發現。

**這一輪能收掉，靠的是換方向而不是加力氣**（`rulebook/41`：撞牆時換的應是方法）：

1. 先讀**跳表本身**，而不是繼續猜 base。19 格裡有 11 格指向同一個位址
   這件事一眼就看得到，而它直接證明「回傳值 ＝ case 編號」，
   把動作碼的值域鎖死在 `0x06`–`0x10`。
2. 值域鎖死之後，**用已驗證的七格反推位址**（要讓 `Look` 得到 `0x07`，
   表值必須是 8，那一格必須在 `0x2184`），得到「差 8 ＝ 差 4 格」。
3. 差 4 格這個具體數字才讓人去讀選單元件的結尾，找到 `ADD AX,0x4`。

**先鎖值域再找公式**比「換 base 逐一試」快一個量級 ——
換 base 的做法試過三種、加減 1、兩種對應，共十幾組，最好的只中兩格；
而值域一鎖死，答案只剩一個。

另外一條：**資料表的邊界要用鄰居驗證**。`0x217c + 15×2 = 0x219a` 正好是字串起點，
四張表首尾相接、每張都是 15 筆 —— 11 筆的讀法會留下四個孤兒 word。
「讀到看起來夠用就停」是這一輪最貴的那個錯。

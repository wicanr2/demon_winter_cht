# 114 — 營地法術尾段與魔法物品充能

> 日期：2026-07-29
> 原版 oracle：`workplace/orig/demwin/DEMON.INT`
> SHA-256：`fc1df05513bfa0f1a38f95ce0fbe5e6ec390c8192b2f99b3b6118b3c23868ea5`
> 工具：既有 Ghidra 匯出＋IDA 9.4 複核；位址沿用本專案
> `segment:offset` 記法。

## 1. 問題

舊版 remake 已有戰鬥法術與營地火把，但營地的復活、解毒、照明、御風而行，
以及營地／戰鬥共用的魔法物品充能仍未串到玩家操作。本輪針對原版呼叫鏈逐段
核對，不用手冊敘述猜公式。

## 2. `1000:11e5`：營地效果尾段

可信來源：
`workplace/ghidra/export/decompiled/1000_11e5_FUN_1000_11e5.c`。

| effect | 行為 | 原版細節 |
|---:|---|---|
| 8 | 復活 | 只容許死亡目標；先後兩次 `Roll(100)` 取較小值，門檻 `SP*K/M`；成功寫 `status=0, HP=1` |
| 9 | 解毒 | 與 effect 8 共用成功率骨架，但目標前置條件不同 |
| 12 | 照明 | `light = clamp(SP*K/M, 1, 4)`，寫入隊伍 `+0xa7` |
| 17 | 御風而行 | 符印前送 `(28,50,map 34)`；符印後送 `(39,35,map 43)` |

因此 Magic Torch／Crystalight 的照明公式已由「合理推測」升級為靜態證據；
Wind Walk 也不是任意選目的地的傳送術。

## 3. `1000:2262`：營地 Use

營地選人與選道具後：

- 火把／提燈走直接光源路徑，用完清除；
- 魔法物品把槽位的 `Power` 與 `Effect` 傳給同一支
  `FUN_1000_11e5(..., mode=1)`；
- 效果無須目標時立即結算，需要角色目標時再選人；
- 道具強度代替角色投入 SP，角色 SP 不減少。

remake 對應：

- `internal/game.CampItemCast`
- `cmd/demonwinter/campitems.go`
- 照明與御風而行立即套用；復活、治療、解毒、解除、枯萎與屬性增減走選人畫面。

## 4. `1000:1902` → `138d:1e72`：四種充能

原版在合法使用後才呼叫 `FUN_138d_1e72`。`Total` 的值域同時表示充能模式：

| `Total` | 使用後行為 |
|---:|---|
| `Used == 255` | 每次把 `Total` 永久減一；降到零時銷毀 |
| `< 100` | `Used++`，是每日使用次數 |
| `== 200` | 每次使用必定銷毀 |
| `101..199` | `Roll(100) <= Total-100` 時銷毀 |

銷毀時清除道具型別；若原本已裝備，也一併解除裝備。remake 的單一實作是
`internal/game.UseItemCharge`，營地與戰鬥都走它，避免兩套充能規則漂移。

## 5. `17c5:18ab`：戰鬥 Use

`FUN_17c5_18ab` 先篩出可用魔法物品，讀取效果與強度，再走與施法相同的目標
選取／效果分派。取消目標不消耗行動點或充能；確認合法施放後才扣 3 AP 並呼叫
充能路徑。召喚與幻術也沿用戰場選點，而不是固定放在施術者旁邊。

remake 對應：

- `cmd/demonwinter/battleui.go` 的 `aoeCursor` 同時承接法術與物品；
- 道具不扣施術者 SP，`Power` 作為效果強度／召喚預算；
- 召喚先選生物，再以 I/J/K/M 或方向鍵選合法空格；
- `Battle.CanSummonAt` 檢查邊界、碰撞與地形。

## 6. 驗證

自動測試涵蓋：

- 四種充能模式與裝備銷毀；
- 營地魔法物品不扣角色 SP；
- 復活、解毒、照明與御風而行；
- 召喚欄位映射、槽位與玩家選點合法性；
- 戰鬥目標取消不提前提交（由共用游標狀態機保障）。

## 7. 保留未解

幻術召喚物「每回合可能消失」的確切機率仍未找到可信的原版指令證據。
目前不虛構百分比；這一點不能因召喚放置與充能已接好而誤標完成。

# 58 — 那 21 格不是「事件動作」，是每走一步的回傳碼分派

`CONTEXT.md` §7 的 worklist 把「事件動作分派表 21 格」列為關鍵路徑 A1。
動手第一件事是補 `docs/re/50` 留下的洞：**誰填選擇子 `[bp-0x16]`**。

答案在一行指令裡，而且順帶修正了整張表的定性。

---

## 1. 選擇子來自主迴圈的移動處理

```
16204  call 122f:0b0e          ; +0x1000 → 222f:0b0e
16209  mov  [bp-0x16],ax       ; ← 分派表的選擇子
1620c  mov  al,ds:0x50f0
1620f  les  bx,ds:0x4c76
16213  mov  es:[bx+0xa1],al    ; 把新的 X 寫回隊伍記錄
```

`222f:0b0e` 就是 `docs/re/04`／`docs/re/12` 那支主指令迴圈
（`docs/re/12` 修好跳表後反編譯從 6557 行降到 336 行）。

**所以這 21 格是「走一步之後發生了什麼」的分派，不是事件表的動作表。**
`docs/re/50` 叫它「事件動作」方向沒錯（事件確實從這裡回來），
但那個名字會讓人以為它是 `DATA*.TXT` 的欄位 —— 不是。

值域 6–26 也跟著有解釋：那是 `222f:0b0e` 的回傳碼值域。
`docs/re/51` 解出的「1/64 回傳 `0x17` ＝ 商隊」正是其中一格。

## 2. 回傳碼是怎麼產生的（`222f:0b0e` 尾段）

| 回傳 | 條件 | 附帶動作 |
|---|---|---|
| `0x16` | `party+0x9c == 0` | **遭遇倒數歸零** |
| `0x11` | 目的地 tile `& 0x7f` == `0x35` | —（`docs/re/05` 記的「硬阻擋」就是這個）|
| `0x13` | tile ∈ {`0x2e`,`0x25`,`0x26`,`0x64`,`0x5b`} | tile 存進 `ds:0x52f4`、寫座標 |
| `0x14` | 可通行性表 `[0x5500+tile] == 0xfd` | 寫座標 |
| `0x15` | **跨子地圖**：x==3／x==0x3c／y==3／y==0x3c | `+0xa3` ±1／±10，座標 wrap 到 4 或 `0x3b`，`+0xa9` 清 0 |
| `0x19` | 同上但**已在世界邊界**（`+0xa3` 的十位或個位到 1／7）| — |
| 事件表回傳 | tile == `0x11` 或 `0x53` → `FUN_222f_0a90()` > 0 | — |
| 劇情回傳 | 見 §3 → `FUN_222f_0619()` != 0 | — |
| — | 以上都不中 | **`+0x9c -= 1`**（遭遇倒數遞減）|

三件事跟著落定：

- **`0x15` 的動作是「什麼都不做」是對的** —— 換子地圖這件事在 `222f:0b0e`
  裡就做完了（改 `+0xa3`、wrap 座標），分派表那一格不需要再做事。
- **`0x19` ＝ 走出世界邊緣**，而動作 `0x19` 印的是
  *"Your crew refuses to sail any further…"*。兩邊獨立對上。
- **事件表確實透過這張表驅動** —— tile `0x11`／`0x53` 走 `FUN_222f_0a90`，
  它的回傳值直接變成分派選擇子。`docs/re/05` 卡住的「誰在什麼時候用什麼
  參數重新呼叫」，答案就是這條路。

## 3. 主線劇情旗標：`party+0x96`／`+0x97`／`+0x98`

`222f:0b0e` 裡有一段只在特定子地圖成立的檢查：

```c
uVar8 = party[+0xa3];                       // 子地圖 ID
bVar2 = party[+0x96];
bVar5 = (party[+0x96] < 0x80) || (party[+0x97] < 0x80) || (party[+0x98] < 0x80);

if ( (uVar8 == 0x37 && bVar2 < 0x80)
  || (uVar8 == 0x38 && Y < 10   && bVar2 < 0x80)
  || (uVar8 == 0x42 && party[+0x98] < 0x80)
  || (uVar8 == 0x38 && Y > 0x16 && party[+0x97] < 0x80)
  || (bVar5 && uVar8 == 0x38 && 0x20 < X && X < 0x37 && Y > 0x1e) ) {
    ds:0x15ca = 0x80;
    if (FUN_222f_0619() != 0) return 它;
}
```

**`+0x96`／`+0x97`／`+0x98` 是三個劇情旗標，bit7（`>= 0x80`）＝已完成。**
判斷式一律寫成 `< 0x80`（＝還沒完成才觸發）。

涉及的子地圖是 **`0x37`(55)、`0x38`(56)、`0x42`(66)**，
其中 `0x38` 依 Y 座標分成三段（北 `Y<10`、南 `Y>0x16`、中央那塊還要 X 在 33–54）。

這是目前找到的**第一條明確的主線推進機制**。
`CONTEXT.md` §7 的 A3（結局觸發時機未解）有了切入點：
先解 `FUN_222f_0619`（325 bytes），再回頭找誰把那三個 byte 設成 `>= 0x80`。

## 4. 21 格的語意（字串錨定）

> **編號是對的，別「訂正」它。**（2026-07-27 補）
>
> 我一度以為這張表的編號整體偏移了 6：跳表本體在檔位移 `0x16453`
> （`cs:0x563`），第 0 筆是 `222f:1606`，而下面這張表把它標成 `0x06`。
> 邊界檢查也寫著 `cmp ax, 0x15`（21 格，0–20），看起來就是 0-based。
>
> **但索引前面有一條 `sub ax, 6`**：
>
> ```
> 1647d  2d 06 00        sub ax, 6        ; ← 這一條
> 16480  3d 15 00        cmp ax, 0x15
> 16483  73 08           jae 0x1648d
> 16485  93              xchg bx, ax
> 16486  d1 e3           shl bx, 1
> 16488  2e ff a7 63 05  jmp cs:[bx+0x563]
> ```
>
> 所以**動作碼確實是 `0x06`–`0x1a`**，表索引才是 0–20。
>
> 我沒看到那條 `sub` 的原因值得記：跳表是**內嵌在程式碼裡的資料**
> （42 bytes 夾在 `jmp` 與這段之間），反組譯從表中間開始就會一路錯位 ——
> 我第一次讀到的是 `add al,0xb3` 那種垃圾，往後掃才對齊到 `3d 15 00`，
> 而 `2d 06 00` 剛好落在錯位的那一段裡。
>
> **教訓**：內嵌跳表附近的反組譯，在找到表的結尾之前對齊都是錯的。
> 要驗一個 switch 的 base，`cmp`／`shl`／`jmp` 三條之外**還要往前多看幾條**。
> 這次差一點就把一張正確的表「訂正」成錯的，而它被十幾份文件引用著。

## 5. `Take:` 與 `Move:` 是同一支的兩個實例

```
25be:0077 (Take:)          222f:3621 (Move:)
  call 1cdc:1727             call 1cdc:1727
  印 ds:0x278b "Take:"       印 ds:0x26bf "Move:"
  call 222f:2da5             call 222f:2da5
  call 222f:2e8b             call 222f:2e8b
  回傳值 < 0 → return 2      回傳值 < 0 → return 2
```

**逐指令相同，只差字串。** 兩者都轉呼叫 `222f:2da5`（動作 `0x0d`）——
那支回 9 時印 *It's too crowded here*，所以它是**選一個角色／目標**的共用常式。

也就是說這 21 格不是 21 個平行的動作，**有幾格是被其他格呼叫的子常式**
（`0x0a`→`0x0c`、`0x09`／`0x0b`→`0x0d`）。表的結構比 `docs/re/50` 當時看到的鬆。

## 6. 方法：字串錨定要驗證起點

第一次掃的時候沒檢查起點，抓到一批**指向字串中段**的巧合立即數：
`ipped`（equipped 的尾巴）、`the trap`、`d that skill today`、` died`。
其中 `You have used that skill today` 還一度被算到動作 `0x16` 頭上。

加一個條件就乾淨了：**該 offset 的前一個 byte 必須是 `\0`**。
16-bit 立即數在 65536 種可能裡撞進某個字串中段的機率不低，
而字串真正的起點一定接在前一條字串的終止符後面。

同一輪的另一個提醒：`docs/re/02` 早就寫過 `party+0xa6` 是怪物數，
`docs/re/12` 早就修好這支函式的跳表並留下 336 行可讀的反編譯 ——
**這一輪能快，是因為先去讀了那 336 行，不是從 asm 硬啃。**

## 7. 對 worklist 的影響

- **A1 的定性要改**：不是「事件表的動作」，是「移動回傳碼分派」。
  21 格已認出 12 格語意（原本約 5 格），其中 3 格是子常式而非獨立動作。
- **A2 不變但更具體**：引擎要補的是「走一步之後的世界事件」——
  取得、推移、陷阱、水池、換地圖、全隊死亡。
- **A3 有切入點了**：`party+0x96`／`+0x97`／`+0x98` 三個劇情旗標
  ＋ 子地圖 `0x37`／`0x38`／`0x42` ＋ `FUN_222f_0619`。

剩下未解的四格：`0x08`（192B）、`0x0c`／`0x12` 那一對的參數語意、
`0x0f`（87B）、`0x10`（87B）。

> **後續**（2026-07-27）：`0x0f`／`0x10` 是觀室／鑑物（`docs/re/93`），
> `0x0c`／`0x12` 的參數也解完了（`docs/re/69` §1、`docs/re/95` §3.10）。
> `0x08`（`222f:1a94`）讀了開頭：`子地圖 < 10` 時把 `ds:0x551c[子地圖−1]`
> 那 `0x1ff` bytes 寫出去 —— 那是 **`nSS.DAT` 的寫回**（`docs/re/78`），
> 不是一個玩家動作。

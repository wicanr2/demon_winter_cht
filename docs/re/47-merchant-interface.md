## 1. 全部的貨都標價 0

第一次跑起來，七件貨的開價一律是 0。

`MerchantPrice` 是乘法，`估價 = 底價 × 材質倍率`（`docs/re/44` §1），
所以只要材質倍率是 0，後面乘幾次都還是 0。往回查倍率表：

```
materialMultiplier = [0, 1, 2, 5, 20, 35, 50, 60, 75]
                      ↑ 類別 0 的倍率就是 0
```

而 `GenerateLoot` 從來沒寫過 `+0x0f`（材質類別）—— Go 的零值是 0，
剛好落在倍率 0 那一格。**不是估價公式錯，是掉寶生成器少填一個欄位。**

這個破洞在「只生貨、不標價」的時候完全看不出來：`docs/re/32`
那一輪的測試釘的是附魔、效果、詛咒，沒有一項會碰到 `+0x0f`。
價格是第一個讀這個欄位的消費者，一接上就把它照出來了。

> 這是 `rulebook/60` 的實例：**能區分對錯的訊號才有用**。
> 舊測試全綠，因為它們問的問題裡沒有一個的答案取決於 `+0x0f`。

### 暫時填 1，並且標明它是暫時的

原版填 `+0x0f` 的規則在 `1990:11b9`–`1228`。這一輪先暫填 1
（依據是兩份原版存檔裡每一件真道具都是 1，倍率 1 = 原價，保守的下界），
註解把「這是暫填、真規則在哪」寫在 `loot.go` 原地而不是某份 TODO 清單裡。

> **下一輪就把那一段讀完了**（`docs/re/48` §1），而且順帶發現整支生成器
> 有五處判讀偏了一格。暫填 1 已經拿掉，改成照原版擲。

一支等級 12 的商隊，畫面上的開價長這樣：

| 貨 | 開價 |
|---|---|
| 晨星鎚 +1 | 14 |
| 寶石 +4 | 1893 |
| 藥瓶 | 65 |
| 匕首 | 2 |
| 鱗甲 | 196 |
| 魔杖 | 26803 |

跨度四個數量級。**這不必然是錯的** —— 材質倍率本來就到 75 倍，
強度加價又是平方項（`docs/re/46` §1），高等級的魔杖賣天價完全講得通。
但目前**沒有任何一個數字跟原版對過**。

在 DOSBox 裡開同一支商隊比對之前，這一欄只能當「公式跑得動」的證據，
不能當「公式對了」的證據（`rulebook/65`）。

> 這張表本身也已經過時：`docs/re/48` 之後「寶石 +4」這種東西不會再出現
> （王冠以上沒有附魔），價格分布也整個換過。留著是因為**它就是發現
> 那個 bug 的線索** —— 寶石不該有附魔。

## 3. 介面的兩個判斷

**算不準的貨不賣。** `ItemValue` 會回報 `exact`；`+0x0a` 不為 0 的貨
在清單上顯示「說不出價」，按 Enter 也買不了。湊一個數字看起來比較完整，
但那是把「我們還沒讀懂」偽裝成「這東西就值這麼多」。

> **`docs/re/49` 把六項全解完之後這個狀態就拿掉了。** 它本來就是
> 公式缺一項時的自保，不是遊戲規則。

**進入鍵 `M` 是偵錯用的。** 原版什麼情況下會遇到商隊、規模與等級怎麼決定，
都還沒追（`docs/re/32` §4 的「遭遇觸發」）。與 `B 測試戰鬥`、`T 進入城鎮`
同一個性質：沒有這個鍵就沒辦法把畫面叫出來驗。

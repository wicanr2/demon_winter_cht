# 37 — 鑑定（紮營選單 Identify）

掉寶生成出來的東西是**未鑑定**的（`docs/re/30`）：效果與附魔都看不到。
要看清楚就得在營地花一天研究它。這一篇讀完 `1000:1e46`。

---

## 1. 流程

```
選人；取消 → 離開
狀態(char+0x102) >= 3 → 印訊息，重新選人
char[+0xed] != 0      → 印訊息，離開            ; 本日已研究過
畫道具清單，印 ds:0x34a "Item:"
選一格；10 → 離開
  重問直到：型別 != 0xff 且 槽[+0x10] != 1      ; 空格與已鑑定的都不能選
判斷會不會鑑定這一類（見 §2）→ 不會就印「你看不懂」，回頭再問
char[+0xed] = 1                                 ; ★ 擲骰之前就先記帳
機率 = 智力(char+0xf9) × 9 ÷ 2
rnd(100) < 機率 → 槽[+0x10] = 1，印 "Success!"
否則            → 印 "Failed!"
```

兩件事：

**成功率 = 智力 × 4.5。** 智力 22 就到 99%，起始角色（智力 10 上下）大約四成五。

**失敗也用掉一天。** `+0xed` 在擲骰**之前**就設起來了。那個旗標由睡覺清掉
（`2aed:0513`，與打獵的 `+0xef` 在同一個迴圈裡）—— 兩段程式合起來就是
「每人每天一次」。

## 2. 三種學識，各管一類

判定查的是角色記錄的三個 byte：

```
型別 < 13                     且 char[+0xde] == 0 → 不會
型別 == 14 / 24 / 25          且 char[+0xdf] == 0 → 不會
型別 == 13 或 15 <= 型別 < 24 且 char[+0xe0] == 0 → 不會
```

技能旗標陣列從 `+0xc8` 起算，所以這三個是**技能 22、23、24**。
翻開技能表（`docs/re/21`）：

| 技能 | 名稱 | 管哪些型別 |
|---|---|---|
| 22 | Weapon lore（武器學識）| 0–12（武器與護甲）|
| 23 | Potion lore（藥劑學識）| 14、24、25 |
| 24 | Item lore（物品學識）| 13、15–23 |

**三個範圍剛好把 0–25 切乾淨，一個不漏也不重疊。**

這是本專案少見的「兩邊各自解出來、對得上」：欄位位移是從這段程式碼推的，
技能名稱是從 `FILES.DTT` 的字串表切出來的（`docs/re/27`），
兩條獨立的線在「22/23/24 = 武器/藥劑/物品學識」交會。
如果技能表的切點錯了、或 `+0xc8` 的起點錯了，這裡就會湊出三個風馬牛不相及的技能。

順帶一提，技能 26 是 **View land（觀地）** —— 那正好也是紮營選單的一項
（`docs/re/33` §1 的 case 6）。那一項還沒讀。

## 3. 本專案的實作範圍

- `internal/assets/scenario`：`Character.IdentifiedToday`（`+0xed`）雙向
- `internal/game/identify.go`：`LoreSkillFor`／`IdentifyChance`／
  `CanIdentify`／`Identify`／`IdentifiableSlots`
- `internal/game/rest.go`：睡覺清掉 `IdentifiedToday`
- `cmd/demonwinter`：紮營選單按 `I`

介面上有一處刻意的偏離：**選道具的清單先把「看不懂」「已鑑定」標出來**。
原版是選下去才告訴你，但原版一天只能試一次 —— 讓人白白浪費一天不厚道。
規則層沒有放寬，`CanIdentify` 一樣會擋。

實機驗收（`workplace/dump/persist/52-camp-identify.png`）：
Wopple 的匕首標「已鑑定」，小斧與布甲標「看不懂」（起始角色沒有武器學識）——
與原版存檔裡那幾格的 `+0x10` 對得上。

**沒解的部分**：`char+0x102` 狀態值 2 是什麼（`< 3` 這個門檻把 0、1、2 放進來，
0 = 正常、1 = 中毒已知，2 未解）。

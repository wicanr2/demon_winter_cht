# 45 — 商隊售價，與四個軟浮點 entry point

`docs/re/44` 找到了估價常式，卻停在「後面那段浮點看不懂」。
這一篇把那段讀完 —— 靠的是**把 `310e` 那幾個 entry point 逐一點名**，
而不是猜。

---

## 1. 四個新命名的 entry point

`docs/re/14` §1 已經釘住六個：`0196`（常數→B）、`07a4`（32-bit 整數→A）、
`0588`（A×B）、`045e`（A÷B）、`07e2`（A→整數，截斷）、`0127`／`01b2`（載入／存回）。
另外兩個關鍵事實也在那裡：**`[0x482e]` 指向暫存器 A、`[0x4830]` 指向暫存器 B**。

有了那兩個指標，剩下的 entry point 開頭幾行就會自己招供：

| entry | 開頭在做什麼 | 結論 |
|---|---|---|
| `021e` | `pop ax/dx`（取回返回位址）→ `sub sp,8` → `es:bx = ss:sp` → 推回返回位址 → 跳 `01b2` | **把 A 存進堆疊上新開的 8 bytes**（暫存） |
| `0242` | `bx = sp + 8` → `lcall 01a5`（載入 `[es:bx]` 到 B）→ `lret $8` | **把那 8 bytes 載回 B 並釋放** |
| `02e4` | 同時讀 `[0x482e]` 與 `[0x4830]`，`cx = A.exp − B.exp` | **A ± B**（對階再加減）|
| `0732` | `di = [0x482e]`；`[di] = 0`；`[di-2] = 0x40b`；`test ax,ax` | **AX（16-bit 整數）→ A** |

`021e` / `0242` 是一對：**計算 Y 會蓋掉 A，所以先把 A 寄放在堆疊上，
算完再撈回 B**。看懂這一對，整段就通了。

## 2. 商隊售價

```
1d6d6  lcall 278d:1c1b(槽)     ; 估價（docs/re/44）
1d6e1  lcall 1d9f:0dd4         ; A = uniform()  ← 見下
1d6e6  bx = CS:0x35f2 (0.8); 0196 / 0588      ; A = u × 0.8
1d6f3  bx = CS:0x35ea (0.6); 0196 / 02e4      ; A = u × 0.8 ± 0.6
1d700  021e                    ; 把 A 寄放到堆疊
1d705  ax = 估價; 0732         ; A = 估價
1d70d  0242                    ; B = 剛才寄放的係數
1d712  0588                    ; A = 估價 × 係數
1d717  01b2 / 0127 / 07e2      ; 存回、載入、截斷成 32-bit
1d737  價格表[i] = dx:ax
```

**`1d9f:0dd4` 是均勻亂數。** 又是我們自己的文件早就寫好的
（`docs/re/14` §2）：

> `FUN_1d9f_0dd4 → FUN_30c2_0006`：整數 LCG 推進 + 立刻除以 2796203.0，
> **留在暫存器 A**

**`02e4` 是加不是減**，這一步不必再讀組合語言就能定：
若是減，係數 = `u × 0.8 − 0.6`，值域 `[−0.6, 0.2)` —— **會出現負數售價**。
加則是 `[0.6, 1.4)`。只有一個講得通。

於是：

```
售價 = trunc( 估價 × (uniform() × 0.8 + 0.6) )
```

**同一件東西在不同商隊手上，開價差可以到兩倍多**（0.6 倍到 1.4 倍）。
這就是為什麼商隊值得多看幾家 —— 不是議價技巧，是純運氣。

---

## 3. 本專案的實作範圍

- `internal/rng`：`RNG.Uniform()` —— 原版 `1d9f:0dd4` 留在暫存器 A 的那個小數
  （`Next() / 2796203.0`）。`Roll` 是它的整數等價版本，但這裡需要小數本身。
- `internal/game/price.go`：`MerchantPrice(r, 估價)`

**刻意用 `float64` 而不是有理數。** `Roll` 那邊之所以能改寫成整數運算，
是因為 `docs/re/14` 證明了在該值域內 `floor()` 不會跨界；這裡的量級大得多
（估價可以上萬、再乘一個係數），而且 0.8 與 0.6 在二進位裡都是無限小數。
用同一組 IEEE double、同一個運算順序，才逐位元對得上原版。

測試釘住兩件事：五千次抽樣落在 `[0.6, 1.4)` 且兩端都掃得到、
估價 0 不會憑空長出錢。

## 4. 還缺什麼

寫這一篇時還差**估價的第三項**（強度不為 0 時的加價）——
已經在 `docs/re/46` 讀完，購買介面在 `docs/re/47`。

剩下的缺口是估價的第四項（`槽+0x0a` 不為 0，`docs/re/46` §3）：
`ItemValue` 對這種貨回報 `exact = false`，商隊介面顯示「說不出價」也不賣。

# 55 — 附魔費用：從攻略反推出來的

`docs/re/54` §7 認出 `docs/walkthrough/part-5` 有完整的附魔價目表，
但結論是「要先把整條價格鏈補完才對得上」。

使用者說「反推就能得到價格」—— **對，而且不必等那條鏈。**
八種材質 × 十級 = **80 個資料點**，足夠直接解方程。

---

## 1. 兩維分開解

### 1.1 材質維：線性，一次全中

攻略 §(8) 給了「8 點強效賦能力量附魔到各材質」的八個價格：

```
10548  9993  9438  8883  8328  7772  7217  6662
```

差值一律 555（有一格 556 —— 捨入）。除得盡的比例是 **19 分之**：

```
cost(c) = base × (20 − c) / 19          c = 材質類別（1 = 一般）
```

`10548 × 18/19 = 9992.8 → 9993`、`× 12/19 = 6661.9 → 6662`……
八個全中。同一條套到 `+0→+1` 那一列（base 665）也八個全中 ——
**16 個點，零誤差**。

### 1.2 等級維：累積值一除就露出來

逐級費用看不出規律（`665, 1495, 2143, 2715…`，二階差還在跳），
但**累積**起來就清楚了：

```
F(10) / F(1) = 33327 / 665 = 50.11 = 10^1.7
```

逐點回推指數 `a = ln(F(n)/F(1)) / ln(n)`：

```
n= 2  1.6996     n= 5  1.6999     n= 8  1.6999
n= 3  1.6997     n= 6  1.6999     n= 9  1.6999
n= 4  1.6998     n= 7  1.6999     n=10  1.7000
```

**收斂到 1.7000。**

### 1.3 合起來

`665 = 35 × 19`，所以兩維併掉分母：

```
累積附魔費用  F(n, c) = 35 × (20 − c) × n^1.7
每一級的費用  cost(n, c) = F(n, c) − F(n−1, c)
```

拿攻略全表 80 個點驗：**誤差沒有一個超過 6**（逐級值差 ≤3）。
那個殘差正是攻略自己註明的那種捨入雜訊 ——
它的「總計」與「0→10」兩欄本來就差 2–3。

| | 類別 1（一般）|
|---|---|
| 預測 | 665 1496 2144 2715 3238 3728 4190 4631 5056 5466 |
| 實際 | 665 1495 2143 2715 3239 3725 4191 4630 5055 5466 |

## 2. 三個必須講清楚的保留

**(1) 這是從社群攻略反推的，不是從機器碼讀的。** 本專案的 oracle 優先序
把反編譯排在社群資料前面。這條公式的地位是**假說**，
要在原版找到附魔那支常式才算解出來 —— 而**我們連附魔在原版哪裡都還不知道**
（`docs/re/54` §7.1：城鎮設施八項裡沒有它，市集 12 個選項裡也沒有）。

**(2) `n^1.7` 對 1988 年的 16-bit 遊戲來說是可疑的東西。** 非整數次方要
`log`／`exp`，而我們目前在這個執行檔裡看到的只有整數次方
（`1990:0a83`，`docs/re/48` §3）。同樣能吻合 80 個點的還有
「**存一張十格的表，再乘материал係數**」—— 那在 1988 年合理得多。
**光靠攻略分不出這兩者**，因為它們的輸出一模一樣。
所以正確的說法是：*可觀察到的行為*是 `35 × (20−c) × n^1.7`，
*機制*未定。

**(3) 1.7 這個數字在別處出現過。** 估價的附魔項是
`trunc(1.7 × |附魔| × 350)`（`docs/re/49` §2）。

> ⚠ **這條線索後來被削弱了**（`docs/re/56` §5）：資料段裡確實有一個
> `1.7`（`1990:40f0`），但它是**戰鬥金幣的底數**，用法是 `1.7^n`
> —— 與這裡需要的 `n^1.7` 方向相反。估價那個 `1.7` 又是 push 立即數、
> 不在資料段。三個 1.7 不是同一件事。
>
> 而且 §2(2) 的疑慮**沒有解除**：全檔看到的次方都是整數指數
> （`1990:0a83`），沒有證據說這個引擎算得出非整數次方。

## 3. 方法本身值得記

這一輪真正的收穫不是公式，是**先分維再反推**這個順序：

- 逐級費用（兩維混在一起）看不出任何規律
- 固定等級、只看材質 → **線性**，一眼看出 555 與 19 分母
- 固定材質、改看**累積**而不是逐級 → 指數立刻掉出來

**逐級值是差分，差分會把冪次結構打散**；先積回去再看，
問題從「擬合十個沒規律的數」變成「量一個斜率」。

還有一點：**80 個點是奢侈。** 有這麼多點的時候，
「誤差全部 ≤6」本身就是很強的證據 —— 隨便湊一條式子不可能同時壓住 80 個點。
反過來說，如果只有兩三個點，同樣的擬合什麼都證明不了。

## 4. 本專案的實作範圍

**不實作。** 理由是 §2 的第 (1) 點：附魔在原版的哪裡都還沒找到，
接一個沒有呼叫端的服務等於自己設計遊戲。

這一篇的用途是：等找到那支常式，**先拿這條公式去對**，
對得上就省掉整段反推；對不上就知道是哪一維錯了。

# 24 — 隨機遭遇：七大地形對到 tile 值

這篇解掉專案裡掛最久的一項：**手冊的七大地形對應哪些 tile 值**。
先前四次嘗試都失敗（見 §6 的死路清單），這一輪換了方向才通。

位址換算沿用 `docs/re/00`。`222f` 段的檔位移基底是 `0x241f0`
（`222f:2a5b` = 檔位移 `0x2694b`）。

---

## 1. 結論：引擎沒有第二張地形表

**地形就是可通行性表的值。**

同一張 `FILES.DAT 0x040` 被讀兩次：移動時當「能不能走／要不要多算一步」，
遭遇時當「這是哪一種地形」。前面幾次找不到，是因為一直在找一張**不存在**的
「tile → 地形」對照表。

這與本專案在別處反覆看到的手法同源 —— CSR 式區間表、同一張表用兩個基底讀
（`docs/re/23` §1、`aispell.go`）。1980 年代的 640K 機器上，一個位元組能兼兩份差
就兼兩份差。

## 2. 三段查表（`FUN_222f_2a5b`）

```
222f:2a62  SI = Y×64 + X
222f:2a74  AL = 地圖[SI]                    ; tile 值
222f:2a7f  AL = [0x5500][tile]              ; ★ 可通行性表 → 地形類別
222f:2a82  [BP-1] = AL

222f:2b7b  rnd(8)
222f:2b8a  AX = 地形 × 8 + rnd(8)
222f:2b97  AL = [0x54fc][AX − 1]            ; ★ 地形的 8 個遭遇群組，挑一個
222f:2b9f  [BP-2] = AL                      ; 群組編號

222f:2bc5  SI = 群組 × 22
222f:2bda  AL = [0x550c][SI]                ; 群組最低等級
222f:2be9  AL = [0x550c][SI+1]              ; 群組最高等級
222f:2c50  AL = [0x550c][SI + 2 + 2×序號]   ; 怪物索引
222f:2c85  AL = [0x550c][SI + 3 + 2×序號]   ; 等級值
```

`[0x54fc]` 與 `[0x550c]` 是資源區指標（`docs/re/22` §1 的索引 4 與 8），
指向 `FILES.DAT 0x000`（64 bytes）與 `0x28E`（404 bytes）——
**那兩段原本都標「未知」，現在解開了**：

- `0x000`：**64 = 8 地形 × 8 群組槽位**
- `0x28E`：**18 個遭遇群組 × 22 bytes**（2 bytes 等級範圍 + 10 筆 × 2 bytes）

兩個尺寸各自把結構釘死，不需要靠統計猜。

### 觸發與數量

```
222f:080c  CMP [BX+0xa3],0x9 / JC 跳過      ; 子地圖編號 < 9 → 地城，不擲
222f:0814  CMP [0x52d4],0x0  / JNZ 跳過     ; 船上不擲
222f:081b  rnd_raw() & 0x3f == 0x34         ; 1/64
...
222f:2bf5  rnd(7)
222f:2c01  隻數 = 8 − rnd(7)                ; 1–7 隻
222f:2c1c  序號 = rnd(10) − 1
```

### 等級檢查

```
222f:2ca8  難度 − 1 > 這筆的等級 → 跳過
222f:2cb1  難度 + 1 < 這筆的等級 → 跳過
```

**`難度 − 1 <= 等級 <= 難度 + 1`，對每一筆都成立。** 遭遇因此會跟著隊伍變強：
難度 1 遇骷髏，難度 9 遇元素。

等級值 `>= 100` 的那種另有兩條規則（`222f:2c8e`／`2c9e`）：只有前兩隻抽得到，
而且一旦抽中就**鎖定那一格**，剩下每一隻都是同一種。沼澤那一組十筆全是這種
—— 所以出來的一定是清一色的鬼火群或鬼墳族群，不會混雜。

### 「Kudzu 樹叢」沒有自己的類別

八個類別裡，六個對上手冊、兩個是地城地板 —— **剩不下位置給 Kudzu**。

手冊寫 Kudzu 會遇到「類人族、探險者、昆蟲及龍」，而那四樣剛好是平原那一組的
子集（平原掛 6/4/5/1/3/8/9/12）。合理推測是 kudzu 的 tile 併進了平原類別，
遭遇上不做區分。**這是個否定結論，不是還沒查完。**

### 證據等級

只有**山丘是直接驗證**（移動成本，原版程式碼寫死那兩個 tile）。其餘六個是
「遭遇群組內容 + 圖塊外觀 + 世界地圖佔比」三路佐證的**推定** ——
`DEMON.INT` 與資料檔裡都沒有地形名稱字串（搜過 `Plain`/`Forest`/`Swamp`/`Hill`/
`Tundra`/`Kudzu`/`Desert`，零命中），所以拿不到直接證據。

不過沼澤與沙漠那兩條特別強：手冊點名的四隻怪（鬼火、鬼墳族、苦修僧、蜥蜴人）
各自只出現在那一個地形掛的群組裡，而手冊寫的時候不可能看得到這份資料表。

## 5. 為什麼前四次沒解出來

前四次分別試過：可通行性分組（放棄得太早）、`FILES.DAT 0x0A8`（那是視線遮蔽表）、
掃一張 102 格的 0–6 表（不存在）、`MONSTER.DAT` 欄位（沒有地形欄）。

**第一次其實已經摸到答案了** —— 當時記的是「可通行性表把 102 個 tile 分成 11 組，
**組別本身不等於地形種類**」。那句話正好講反：組別**就是**地形種類。
會下那個結論，是因為看到 `0xfe` 一組有 19 格、城鎮的 `0x2e`／`0x64` 混在裡面，
覺得太雜 —— 但 `0xfe` 是不可通行那一側，本來就不參與地形分類；
走得到的 0–7 那八組每組都很乾淨。

第五次改用 `rulebook/62`「找讀取端」才通：不要再對資料做統計，去找**誰讀它**。
`FUN_222f_2a5b` 的第三行就把答案寫在臉上。

還有一條岔路值得記：任務單裡寫「從 `DS:0x52f4` 的 tile 值追隨機遭遇路徑」，
並列了 16 個存取點。**那是錯的線索** —— `0x52f4` 是一個到處被重用的暫存字，
在事件文字解析裡當迴圈計數器、在移動裡才暫存 tile。照著它追會一直繞。

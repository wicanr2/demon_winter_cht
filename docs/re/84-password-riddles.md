# 84 — 兩道密語謎題（16 格表 case 10／11）

`docs/re/83` 把那張 16 格表接上了 `nSS.DAT` 類別 5，但當時只實作 case 14。
本篇把兩道密語謎題（case 10、11）逐指令讀完並接進引擎 ——
它們是**全遊戲僅有的自由文字輸入**，其餘互動全部是選單。

答案是**明文存在資料段裡**的：`VOID` 在 `ds:0x2c7b`、`JESRIC` 在 `ds:0x2d08`。
那個年代沒有人會為了作弊去反組譯一片 5.25 吋磁片；會的人早就買了攻略。

---

## 1. case 10：幽靈司祭（`0x1a2d7`，地圖 5 的 (11,20)）

```c
if (map[0x48b] == 0) return 3;              // 已經解過了，這一格沒反應
0xd9f:27f5();  ds:0x4c7a = 0x28;  1cdc:1727();
印 "A spectral priest utters a chant:"
印 "'Power, Divinity, Spirit...' and"
印 "awaits the final word of the spell"
ds:0x4c82 = 5;
讀字串(buf, 0x11);                          // 上限 17 bytes
if (stricmp(buf, "VOID") != 0) {
    印 "The priest fades away into mist"   // ← 答錯
} else {
    15be:1694(8);                           // 音效
    map[0x48b] = 0;                         // ← 把牆打開
    122f:28d0(5, 1);
}
```

**答對沒有任何台詞**，只有音效與開牆。答錯才有那句「司祭化成霧氣散去」。
`docs/re/65` §3 把那句列在 case 10 底下沒說是哪一支，這裡定案。

### `0x48b` 這個常數值得停下來看

原版把要打開的那一格寫成**線性索引常數** `0x48b`。三件事同時成立才對得上：

| 檢查 | 結果 |
|---|---|
| `0x48b` 換算 `y*64 + x` | **(11, 18)** |
| `MAP5.MAP` 在 (11,18) 的 tile | **`0x0d`** |
| 可通行表在 tile `0x0d` 的值（`docs/re/22` §2）| **`0xff` ＝ 牆** |

而觸發格是 (11,20) —— **正南兩格，同一欄**。
寫進去的 `0` 在可通行表是 4，不是 `0xff`，所以走得過去。

三份互相獨立的產物（反組譯的常數、地圖檔的實際位元組、可通行性表）
指向同一個結論。這比「讀起來合理」強一級，所以釘成測試
（`internal/assets/world/riddledoor_test.go`）—— 座標公式寫反、
地圖檔頭處理錯掉，都會讓 `0x48b` 落在別的地方，
而遊戲裡的症狀是「答對了但牆沒開」或「在地圖別處挖了個洞」，兩種都沒有錯誤訊息。

> **牆只開在記憶體裡。** 地圖緩衝區不進存檔（`nSS.DAT` 才是），
> 所以離開地城再進來，牆會回到原狀。看起來像 bug，
> 但那是 1988 年的行為 —— 照抄，不要「順手修掉」。

## 2. case 11：馬利馮神殿的門房（`0x1a393`，地圖 4 的 (59,39)）

```c
印 "A voice from nowhere speaks: 'Only"
印 "those who worship Malifon may enter"
印 "this temple. What is thy name?' "
讀字串(buf, 7);                             // 上限 7 bytes ＝ JESRIC + NUL
if (stricmp(buf, "JESRIC") != 0) {
    印 "You are not known to this temple."
    印 " Leave at once."
    party+0xa2 = 0x26;                      // ← Y = 38
} else {
    印 "You may enter."
}
```

**沒有任何持久旗標** —— 答錯可以再試，這一題不會鎖死。

`party+0xa2` 是隊伍 Y（`docs/re/83` §1 的 `0x0e1db` 那組已經確認）。
觸發格在 Y=39，答錯推回 **38** —— 就是把你趕出門一步，不是傳送。
又一次「常數落在觸發格旁邊」的自我驗證。

輸入上限 7 恰好是 `JESRIC`（6 字）加結尾 NUL。
**上限比答案短的話這一題永遠答不出來**，所以移植時這個數字不能亂調
（已釘成測試）。

## 3. 比對是 `stricmp`，不是 `strcmp`

兩題都走 `0x2025:000f`，而兩個呼叫端的行為都是「相等回 0」。
從字串常數是全大寫、而攻略上寫的也是全大寫來看，很容易實作成
大小寫敏感的 `==` —— 然後測試也照抄大寫，於是「打小寫過不了關」
這件事永遠不會被發現，直到玩家打了 `void`。

已釘成測試：`VOID`／`void`／`Void`／` void ` 都要算對。

## 4. 順帶記下的未解

- `ds:0x4c82 = 5`（case 10 讀輸入前設，case 11 沒設）。讀入上限是 0x11 不是 5，
  所以它不是長度限制 —— 推測是輸入欄的顯示寬度，未確認。
- `0xd9f:27f5`／`1cdc:1727`／`15be:1694(8)` 三支的確切語意
  （開框、清畫面、音效編號 8）都只是從上下文推的。
- 兩題都不改 `nSS.DAT`，所以那一格會反覆觸發。case 10 靠 `map[0x48b]`
  自己當旗標，case 11 根本沒有旗標。

## 5. 引擎接上的範圍

`internal/game/riddle.go`（題目資料 + 判定）、`cmd/demonwinter/riddleui.go`（畫面）。
`-riddle=10|11` 可直接叫出來。

**題目翻成中文，輸入欄留 ASCII** —— 答案是原版寫死的明文，
中文化不能動，否則玩家照攻略打字會打不進去。

16 格表目前接上 10、11、14 三個 case；其餘 12 個會明確顯示「還沒接」。

# 28 — 船隻陣列（碼頭的最後一塊）

`docs/re/19` §4 把買船與修船的**價格公式**解完了，卻在船隻記錄的格式上停住：
「只知道是全域 struct 裡 10 格 × 6 bytes、船體值在該記錄 `+0x25`」。
碼頭因此一直只能報價 —— 沒有記錄格式就放不了船。

這一輪把讀取端與**寫入端**都讀完，六個欄位全部定案。

---

## 1. 陣列在哪

`ds:0x4c76` 指向隊伍 struct，也就是 `PARTY.DAT` 的 trailer。
船隻陣列在 **trailer `+0x22`，10 格 × 6 bytes**（佔到 `+0x59`）。

修船的搜尋迴圈（`2aed:112f`）把兩件事一起講清楚了：

```
112f  si = i * 6                        ; shl/add/shl → i*2+i=3i，再 *2
1140  al = es:[bx+si+0x22]              ; ship.X
1147  cl = es:[bx+0xa1]                 ; party.X
1151  ax = ship.X − party.X
1154  call abs()
115a  cmp ax,2 / jge 跳過                ; |ΔX| < 2
1170  al = es:[bx+si+0x23]              ; ship.Y ——「+1」就是 Y
...   同樣的 |ΔY| < 2
118f  記下 i
1198  cmp i,0xa / jl 回圈                ; 10 格
119e  沒找到 → "You don't have a boat to repair!"
```

`i*6` 定下 stride、`+0x22` 定下基底、`+0x23` 定下 Y —— 一段程式碼給三個答案。

---

## 2. 六個欄位

寫入端（`2aed:13d6`–`144d`，放新船那一段）把剩下的欄位一次講完：

```
13e0  ship[+0] = party.X(+0xa1) + dx
1401  ship[+1] = party.Y(+0xa2) + dy
141d  ship[+2] = party.MapID(+0xa3)      ← 子地圖編號
1432  ship[+3] = 0x4b (75)               ← 船體滿值
1448  ship[+4] = 2                       ← 固定常數，語意未解
      ship[+5] 從沒被寫過
```

| 位移 | 欄位 | 依據 |
|---|---|---|
| `+0` | X 座標 | 讀取端比對 party.X、寫入端寫 party.X + dx |
| `+1` | Y 座標 | 同上 |
| `+2` | 子地圖編號 | 寫入端寫 `party+0xa3`；佔位檢查（`1393`）也拿它跟 `party+0xa3` 比 |
| `+3` | 船體值。**0 = 這一格是空的** | 修船讀它算費用（`11d8`）、找空格用 `cmpb $0, +0x25`（`13cc`）|
| `+4` | 原版一律寫 2，**語意未解** | 兩份原版存檔的兩艘船也都是 2 |
| `+5` | 從沒被寫過，兩份存檔都是 0 | — |

> **「這一格有沒有船」看的是船體值，不是座標。** 座標 (0,0) 是合法位置，
> 拿它當空槽標記會誤判。原版用的就是船體值。

驗證：原版 `PARTY.DAT` 依這個格式解出**兩艘船**——

```
格 0: X=39 Y=21 圖=44 船體=56/75
格 9: X=13 Y=51 圖= 1 船體=67/75
```

圖 44 是世界子地圖（欄 4 列 4）、圖 1 是 `MAP1.MAP`，兩個都是合法編號；
兩個船體值都在 0–75 之間。**六個欄位全部落在合理值域**，這是格式判對的旁證。

---

## 3. 放船的規則（`2aed:10a5` → `2aed:1301`）

碼頭確認買船後，依序試四個方向 —— **西、東、北、南**：

```
10a5  place(−1, 0, cost)
10c3  place( 1, 0, cost)
10d3  place( 0,−1, cost)
10ea  place( 0, 1, cost)
1101  四個都失敗 → "The docks are full."
```

`place()`（`2aed:1301`）做三件事：

```
1308  idx = (party.Y + dy) << 6 + party.X + dx      ; 地圖一列 64 格
132f  tile = [0x4c94][idx]
1337  tile != 0x14 且 != 0x62 → 回 0                 ; ★ 必須是海面
134e  掃 10 格：X、Y、子地圖三者全同 → 回 0            ; 那一格已經有船
13bb  掃 10 格：找 船體 == 0 的空格
      沒有 → "You already have 10 ships."
13d6  寫入六個欄位（見 §2）
148a  隊伍金幣 −= 費用（32-bit SUB/SBB）              ; ★ 放成功才扣錢
1498  "Your ship and crew are ready."
```

三個順帶的收穫：

- **`0x14` 與 `0x62` 兩個 tile 都當海面**。這是「tile `0x62` 是海不是牆」的
  又一個獨立佐證 —— 放船的判定明明白白把兩個值並列。
- **錢在成功放船之後才扣**。放不下不收費。
- 「碼頭滿了」與「你已經有 10 艘船了」是**兩句不同的話**，對應兩種不同的失敗。

---

## 4. 副產品：金幣是 4 bytes，不是 3

`148a` 那兩行是扣款：

```asm
sub  word es:[bx+0x0a], ax
sbb  word es:[bx+0x0c], dx
```

`SUB`／`SBB` 成對、跨 `+0x0a` 與 `+0x0c` 兩個 word —— **金幣是 32-bit**。

`docs/re/19` §2 早就這樣列了，但 `internal/assets/scenario/save.go` 一直把它
標成「長度未知，兩份存檔的第 4 個 byte 都是 0，分不出 3 還是 4」，
只讀 3 bytes。**分不出來就去找讀寫端** —— 又是同一條教訓。已改成 4 bytes
（`ValueCap` 的封頂不變，數值仍在 24 bit 內）。

---

## 5. 船不是「你的」

原版**沒有記載歸屬**：修船只看腳邊有沒有船（§1 的 3×3 判定），
買船只是往海上多放一艘。世界一開始就有兩艘（原版存檔的第 0 與第 9 格），
任何人走到旁邊都能修。

## 6. 本專案的實作範圍

- `internal/assets/scenario/ship.go`：記錄的解碼與編碼（存檔已能雙向）
- `internal/game/ship.go`：`FindShipNear`／`BuyShip`／`RepairShip`
- `cmd/demonwinter`：碼頭畫面的 `B` 買船、`R` 修船

**一處刻意偏離原版**：修船的搜尋迴圈原版對 10 格一律讀座標，
不跳過空格。空格的 (0,0) 在隊伍走到地圖角落時會被判成「腳邊有船」，
接著把船體修成 75 —— 憑空生出一艘船。那是疏漏不是玩法，本作跳過空格。

**沒做**：搭船航行本身（上船、在海上移動、下船）。那是移動系統的一部分，
與碼頭無關，還沒讀。`+0x04` 那個固定值 2 的語意也還沒解。

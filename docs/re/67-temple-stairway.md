# 67 — 神殿後面的樓梯

`docs/re/66` §4 在神殿那張 9 格跳表裡撞到一句沒被記載過的話：

```
ds:0x324c  "The priest shows you to"
ds:0x3264  "a stairway in the back."
```

`docs/re/19`（神殿三項服務）與 `docs/re/29`（改宗）都沒提過它。
這一篇把去向讀出來。

---

## 1. 它是一道傳送門

```
1c04a   關掉輸入、清畫面
1c05a   印 "The priest shows you to"
1c067   印 "a stairway in the back."
1c081   party[+0xa1] = 0x16      ; X = 22
1c08b   party[+0xa2] = 0x15      ; Y = 21
1c095   party[+0xa3] = 0x01      ; 子地圖 1
1c09f   party[+0xa9] = 0         ; 清掉（語意未定）
1c0a8   retf
```

**直接寫座標，不檢查可通行性、不推進時間** —— 與 `docs/re/05` 的
`TeleportTo` 同一種寫法。

---

## 2. 目的地是起始地城

子地圖 `1` 就是 `MAP1.MAP`。而**起始存檔的隊伍就在子地圖 1**：

```
起始存檔  +0xa1 X = 9   +0xa2 Y = 32   +0xa3 子地圖 = 1
樓梯目的地      X = 22        Y = 21              1
```

同一張地圖的不同角落。所以這道樓梯是**從城鎮回到起始地城的捷徑**，
不是通往新區域 —— 這個判讀比「神殿藏著隱藏關卡」保守，
但符合座標證據。

> ⚠ 目的地 `(22, 21)` 那一格是什麼還沒查（要解 `MAP1.MAP` 對應位置的 tile）。
> 「捷徑」是依座標推的，不是從敘述讀的。

---

## 3. 觸發條件：部分解開

### 選擇子直接是選單回傳值

```
1bfe1  push ds:0x3159    ; 三筆 far ptr → 選項文字
1bfe7  push ds:0x3172
1bfe2  push ds:0x316d    ; ← "DPC"
1bff0  call 1cdc:033d    ; 通用選單常式，回傳存 [bp-6]
1c00d  if ([bp-6] == 8 && ds:0x5d48 == 0) 回選單   ; 改宗的閘門
1c01a  ax = [bp-6]
1c0ce  sub ax,2 / cmp ax,9 / jmp cs:[bx+0xbeb]
```

有效的 case 只有**偶數**（2、4、6、8、10 → case 索引 0、2、4、6、8），
奇數全部落到 `jae` 的預設分支。

| 選單回傳 | case | 目標 |
|---|---|---|
| 6 | 4 | `0x1c020` → `278d:0f38` ＝ **改宗**（`docs/re/29` 那支）|
| 8 | 6 | 有閘門 `ds:0x5d48 != 0` |
| **10** | **8** | `0x1c04a` ＝ **樓梯** |

### ⚠ 更正：神殿選單只有三個熱鍵

`ds:0x316d` ＝ **`DPC`** —— Donate／Pray／Convert，就是
`docs/re/19` §3 記的那三項。

所以**本篇原本寫「這道樓梯是第四項服務、那份清單需要補」是錯的** ——
樓梯不在 D/P/C 這張選單裡。選單常式 `1cdc:033d` 只認那三個熱鍵，
回傳值 10 不可能由它們產生。

**樓梯的觸發來源因此仍未定**：要解 `1cdc:033d` 才知道它在什麼情況下
回傳 10（可能有熱鍵以外的路徑，或某個條件成立時直接跳過選單）。

# 32 — 商隊遭遇

`docs/re/30` §5 認出掉寶生成器有兩個呼叫端，第二個當時只認出字串：

> `0x1d6b0` | `"You see a group of"` `" merchants"`、`"They show you"`
> `"their wares..."` | **商隊遭遇**（未讀）

這一篇把生成那一半讀完。價格那一半後來在 `docs/re/44`／`45`／`46` 解出來，
遭遇畫面也接上了（`docs/re/47`）；還沒解的只剩**遭遇觸發**（見 §4）。

---

## 1. 開場訊息

```
1d58c  印 "You see a group of"
1d599  idx = [0x3612 + 規模×2]              ; 規模 → 形容詞編號
1d5a0  印 [0x3632 + idx×4]                  ; 形容詞（遠指標）
1d5ba  印 " merchants"
1d5c7  印 "You may: Greet"
1d5d4  印 "      or Ignore"
```

規模在 `0x1d562` 算出後鉗在 9（`cmp 9 / jle`）。
`ds:0x3612` 的對照表是 `[0, 1, 2, 2, 3, 4, 5, 5, 6, 6]` ——
**七個形容詞蓋十種規模**：

| 規模 | 形容詞 |
|---|---|
| 0 | ragged looking |
| 1 | poor looking |
| 2, 3 | travelling |
| 4 | adventuring |
| 5 | well dressed |
| 6, 7 | upper class |
| 8, 9 | wealthy |

> **遠指標的段值要 +0x1000 才解得開。** `ds:0x3632` 存的是
> `(offset, segment)`，段值 `0x21f0` 直接套 `seg*16 − 0xC400` 會落到程式碼區。
> 這份 dump 的段值有 +0x1000 的偏移（與 `CALLF 0xN000:xxxx` 代表
> `0xN0000 + xxxx` 是同一件事），補上就對了。踩過一次才發現。

## 2. Greet / Ignore

```
1d5e1  menu(2 個選項)                        ; 選項字串是同一張表的第 7、8 項
1d5ff  回傳 0xffff → 重問
1d60e  回傳 10 → 直接離開                     ; Ignore
1d619  [0x4c7c]++                            ; 用途不明的計數器（掉寶那邊也有）
1d61d  印 "They show you" / "their wares..."
```

## 3. 貨從哪來

```
1d63c  機率 = rnd(120) − 80                  ; 負的鉗成 0
1d656  件數 = rnd(4) + 6                     ; 7–10 件
1d666  for i := 0; i < 件數; i++ {
1d66e    槽 = [0x514e] + i×17                ; 17 bytes 一件 —— 就是道具槽格式
1d6a0    gen(等級, 槽, 機率, 模式 1)
```

> ⚠ **那個機率不是「詛咒機率」，本節原本讀錯了。** 生成器在商隊模式下
> 拿它擲中的貨**跳過第一道效果門檻**，附魔不取負、效果不被擋、
> 驅邪成功率也不寫 —— 商隊那條路一件詛咒品都生不出來（`docs/re/48` §5）。
> 值域 0–40、超過一半擲到 0 這兩件事仍然成立，只是意思相反。

商隊與市集的差別：

| | 市集 | 商隊 |
|---|---|---|
| 貨從哪來 | `ITEMS.DAT` 的 30 種基本款 | 掉寶生成器 |
| 有沒有效果 | **沒有**（效果是掉寶時長的）| 可能有 |
| 鑑定 | 已鑑定 | 生成時未鑑定，但**列出來給你看的時候會標成已鑑定**（`docs/re/44` §2）|
| 詛咒 | 不會 | **也不會**（`docs/re/48` §5）|

模式 1 那條路（`1990:122d`）只把結果寫進全域 `ds:0x4e2e`，商隊在呼叫前後
各碰一次，逐件記在自己的陣列裡。戰鬥掉落走模式 0，用的是寫死的
`rnd(10) == 10`，而且**只有那一條會真的把東西變壞**。

## 4. 沒解的部分

| 項目 | 卡在哪 |
|---|---|
| 價格 | 解出來了：`trunc(估價 × (uniform() × 0.8 + 0.6))`（`docs/re/45`），估價本身見 `docs/re/44`／`46`。只剩「`+0x0a` 不為 0」那一小段未解，那種貨介面上顯示「說不出價」也不賣 |
| 購買介面 | 做好了，見 `docs/re/47` |
| 材質類別 `+0x0f` | 解出來了，見 `docs/re/48` §1 |
| **遭遇觸發** | 什麼情況下會遇到商隊、規模與等級怎麼來，都沒追。現在靠偵錯鍵 `M` 叫出畫面 |

寫這一輪的時候「價格沒解就不做介面」是對的判斷：硬湊一個
「底價 × 某個係數」等於自己發明規則，與「反編當 oracle」相衝突。
價格解出來之後這個限制就消失了。

## 5. 本專案的實作範圍

`internal/game/merchant.go`：`MerchantAdjective`（含十種規模的對照表）、
`MerchantEffectChance`、`MerchantWareCount`、`RollMerchant`。

測試釘住：形容詞對照、那個機率的值域與「超過一半擲到 0」、
件數 7–10、生成當下未鑑定（列出來時會標成已鑑定，見 `docs/re/44` §2）、
**商隊的貨一件負附魔都沒有、也沒有驅邪成功率**。

遭遇畫面與購買在 `docs/re/47`。

# 43 — 敬拜（紮營選單 Worship）＋ 神祇法術表

紮營選單的最後一項。規則在 `docs/re/42` §4 已經讀完，卡的是一張表：
`[0x4cc4]` 那 11 個 word 在哪裡。這一篇把它找出來，十四項就全接上了。

---

## 1. 用指標鏈把表的位置逼出來

`[0x4cc4]` 是執行期指標，不能直接在檔案裡找。但它是**資源競技場**
（`docs/re/22`）那條指標鏈上的一環，而競技場是「一塊一塊接著切」的：

```
[0x4e28] = [0x5510] + 0x3c
[0x5300] = [0x4e28] + 0x1ae
[0x4cc4] = [0x5300] + 0x1a4
[0x51d4] = [0x4cc4] + 0x16
```

每一段的長度都對得上已知的表：

| 段 | 長度 | 是什麼 |
|---|---|---|
| `[0x4e28]` → `[0x5300]` | `0x1ae` = 430 | **43 個法術 × 10 bytes** |
| `[0x5300]` → `[0x4cc4]` | `0x1a4` = 420 | **30 件道具 × 14 bytes** |
| `[0x4cc4]` → `[0x51d4]` | `0x16` = 22 | **11 個 word** |

三段長度全部命中已知數字，這條鏈就自己把自己釘死了。剩下的是找起點：
`[0x4e28]` 是法術表，而 `gamedata` 早就把它定位在 `FILES.DAT + 0x45e`，
反推 `[0x5510] = 0x45e − 0x3c = 0x422` —— **正好是種族上限表的位移**
（`offRaceMax = 0x422`，早就驗證過的）。起點對上，整條鏈就都對上了。

於是：

```
神祇法術表 = FILES.DAT + 0x422 + 0x3c + 0x1ae + 0x1a4 = 0x7ae
```

翻開來看：

```
0000 0025 0017 0013 0022 000c 0001 000d 0025 0022 ffff
   0   37   23   19   34   12    1   13   37   34    −1
```

**十一個值，十個落在法術表的範圍內（0–42），最後一個是 −1。**
`docs/re/29` 早就記過第 11 位神祇（`DeityAncient`）是特殊的那一位 ——
現在知道特殊在哪：**祂不賜法術**。

> 這是「**用長度反推位置**」的一次乾淨示範。指標本身查不到，
> 但每一段的長度都是已知資料結構的大小，鏈條一節一節扣下來，
> 位置就是唯一解。不必動態除錯。

## 2. 規則

```
選人；狀態 >= 2 → 訊息
技能 15（薩滿）與 16（司祭）都沒有 → 「你不會」
char[+0xf1] != 0 → 「今天做過了」
char[+0xf1] = 1                          ; 擲骰之前先記帳
deity = char[+0xf0] − 1
spellID = 神祇法術表[deity]
rnd(100) > char[+0xeb] 或 spellID == −1 → 失敗
成功：
  char[+0xeb] −= 5
  spellID == −2 → spellID = rnd(11) + 0x1a      ; 27–37
  FUN_1000_11e5(誰, 300, spellID, 3)            ; ★ 力度固定 300
```

三件事：

**力度固定 300。** 一般施法的力度是玩家投入的那幾點法力；300 是完全不同的
量級。實測（`-deity 1`，Onizeh 賜法術 0 = 傷害型）打出 **24 點** ——
神祇出手就是壓倒性的。

**成功率與神殿祈禱共用同一個 `+0xeb`，遞減也一樣是 −5**（`docs/re/19` §3.3）。
營地敬拜與戰鬥中呼喚神祇吃的是同一條額度，用完就沒了。

**`−2`（隨機挑 27–37）這條路跑不到。** 表裡沒有任何一位神祇用這個值。
程式碼有分支、資料沒用到 —— 照實實作並註明。

## 3. 本專案的實作範圍

- `internal/assets/gamedata`：`offDeitySpell = 0x7ae`、`NumDeities = 11`、
  `Tables.DeitySpell(deity)`（1-based，−1 = 不賜法術）
- `internal/assets/scenario`：`Character.WorshipedToday`（`+0xf1`）雙向
- `internal/game/worship.go`：`CanWorship`／`Worship`／`WorshipPower`
- `internal/game/rest.go`：睡覺清掉三個每日旗標（鑑定／敬拜／驅邪）
- `cmd/demonwinter`：紮營選單按 `W`；偵錯旗標 `-deity`

**一處刻意的偏離**：本專案讓玩家選法術落在誰身上。原版沒有這一步
（`FUN_1000_11e5` 自己決定目標，那一段沒讀）。等目標選擇的邏輯解出來再對齊。

實機驗收（`workplace/dump/persist/59-camp-worship.png`，`-give-skill 16 -deity 1`）：
「Onizeh 聽見了 Wopple 的祈求，降下烈焰之柱／Wopple 受到 24／祈禱成功率降為 15%」
—— 20 → 15 的 −5 與力度 300 的傷害量級都對得上。
沒有信仰或不懂祈求的人在清單上直接標出原因。

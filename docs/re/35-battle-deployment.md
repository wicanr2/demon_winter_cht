# 35 — 開戰時的擺位

`docs/re/34` 解開 3×3 陣型格之後留了一句「佈陣讀出來了但沒接，因為座標對不上」。
這一篇把擺位規則讀完，接上了 —— 也把「座標對不上」那一段講清楚是怎麼回事。

---

## 1. 單位陣列的形狀

先補一個 `docs/re/20` 的欄位表沒寫的東西：**單位結構的間距是 38 bytes（0x26）**，
陣列起點 `0x4eb4`。三處各自算出同一個 `slot × 0x26`（`0x76c3`、`0x7d71`、
`0x7d95`），對得起來。

**玩家單位從槽位 7 開始。** 證據不是猜的：佈陣那一段寫的是 `[0x4fbe + 38m]`，
而 `0x4fbe − 0x4eb4 = 0x10a = 266 = 38 × 7`，`0x4fc0`（+2）是 Y、
`0x4fd4`（+0x16）是精靈圖 —— 三個欄位位移同時對上，不是巧合。
建立玩家單位的迴圈也直接寫著 `for (slot = 7; slot < 人數 + 7; slot++)`。

所以整張槽位圖是：怪物 0–6、玩家 7–11、召喚 12–14（召喚那三格見 `docs/re/20`）。

## 2. 隊伍：陣型原樣攤開

```
c600  for row := −1; row <= 1; row++ {
c608    for col := −1; col <= 1; col++ {
c615      成員 = 陣型格[格號++]
c621      == 0xff → 跳過                        ; 空格
c634      char[+0x102] >= 5（死亡）→ 跳過
c643      圖塊 = 0x14 + 面向×2
c68f      地圖[row×64 + col + 0x34d] = 圖塊
c6ba      單位[7+成員].X = col + 0x0d
c6c4      單位[7+成員].Y = row + 0x0d
```

**`0x34d` = 845 = 13×64 + 13** —— 中心就是 (13, 13)。陣型格怎麼排，
隊伍就怎麼站，一格對一格。

沒被放進陣型的人**不會上場**（掃九格、只擺格子裡有的人）。

---

## 3. 怪物：貼著你的臉散落

```c
do {
  x = rnd(5) + 隊伍中心X − 3;          // −2 .. +2
  y = rnd(5) + 隊伍中心Y − 3;
} while (地圖[y×0x40 + x] != *(char*)0x51d8);
地圖[y×0x40 + x] = 精靈圖;              // ★ 擺完就蓋上去
單位[槽].X = x;  單位[槽].Y = y;
```

三件事值得記：

**一、`[0x51d8]` 是「空地」的定義，取樣自 `地圖[0x34d]`** —— 也就是隊伍
腳下那一格。拿隊伍站的地方當「可站」的標準，省掉一張可通行性表。

**二、佔位表就是地圖本身。** 迴圈沒有另外檢查「這格有人嗎」，
因為每擺好一個單位就把牠的圖塊蓋進地圖 —— 那一格的值從此不再等於空地值，
下一隻自然擲不中。一個資料結構同時當地形與佔位用，是這個年代的典型手法。

**三、原版沒有重擲上限。** 中心 ±2 全被佔滿或全是別的地形時，
那個 `do { } while` 就轉不出來了。實際上不會發生（怪物數量遠少於 25 格），
但本專案還是加了上限，擲不出來就少放一隻。

**開場是一團混戰，不是兩軍列隊對峙。** 怪物一開始就在你身邊兩格內。

## 4. 座標系：對得上的部分與對不上的部分

相對幾何本專案照抄：隊伍 3×3、怪物 ±2、共用同一個中心 (13, 13)。

> ⚠ **本節下半段已由 `docs/re/36` 解開並取代。** 戰場是 15×15、座標 (6,6)–(20,20)、
> 中心 (13,13)，本專案現在**沿用原版的絕對座標**，不再有原點落差。
> 下面那張「互相不相容」的表留著當紀錄 —— 第三條（`0x172f4` 的 9 stride 緩衝）
> 根本不是戰場，那是誤接。

~~**對不上的是絕對座標**，而且這一段還沒解乾淨。~~ 已知的三件事當時互相不相容：

| 觀察 | 出處 |
|---|---|
| 單位座標是 **64 stride** 的緩衝索引（`地圖[y×0x40 + x]`），中心 (13,13) | 佈陣、怪物散佈、呼吸吐息 |
| 畫面是一個 **9×9 視窗**，左上角 = 中心 − 4，而且**跟著行動單位捲動**（`[0x50f0] += sign(單位X − [0x50f0])`）| `FUN_222f_1404` 的呼叫端 |
| 戰場地形另有一塊 **9 stride** 的緩衝（`[0x514e]`），由 `0x172f4` 從大地圖切一塊 (9−2k)² 貼進 (k, k) | `docs/re/22`、`battleterrain.go` |

那個「5 stride」的算法（`地圖[x×5 + y×0x140 + 0x34d]`）現在也說得通了：
一個世界 tile 攤成 5×5，所以跨一個區塊就是 5 格、跨一列區塊就是 5×64 = 0x140。
它在數的是**區塊**，不是格子。

`internal/game/battlefield.go` 那句「9×9 是戰場邊界，已從原版確認」是錯的，
已訂正 —— 9×9 是視窗，戰場是 15×15。

# 56 — 戰鬥獎勵：從「grep 常數而不是 grep 結果」找到的

`docs/re/55` 從攻略反推出附魔費用，但卡在一個懷疑：
`n^1.7` 對 1988 年的 16-bit 遊戲來說要 log／exp，太重了。

使用者說：**「當年的數字可能都是用公式從某個基數算出來的，
所以找不到跟遊戲或攻略一樣的數字是有可能的。」**

那句話直接改變了搜尋策略：**不要 grep 結果，要 grep 常數。**

---

## 1. 一次命中

把幾個懷疑的浮點常數當 IEEE double 掃全檔：

```
1.7   33 33 33 33 33 33 fb 3f  →  0x115f0
2.6   cd cc cc cc cc cc 04 40  →  0x115e0
1.4 / 1.2 / 0.05 / 19.0 / 35.0 →  沒有
```

**`1.7` 就在 `2.6` 旁邊 16 bytes**（`1990:40f0` 與 `1990:40e0`）——
同一個常數池。而 `2.6` 是掉落價格上限的底數（`docs/re/48` §3）。

找不到的那幾個也有意義：`1.4`／`1.2` 是**用四個立即數 push 上堆疊**的
（`docs/re/49` §1），所以檔案裡沒有連續 8 bytes。
**常數在不在資料段，本身就是「怎麼用」的線索。**

順著 `mov bx,0x40f0`（只有一處，`0xe2ed`）就到了戰鬥勝利的結算。

## 2. 經驗值（完整，已實作）

```
0xc187   總經驗 += 單位[+0x24]            ; 每殺一隻累加
0xe21e   ds:0x52d0 = 總經驗 ÷ 隊伍[+0x9a]  ; 3016:000a 有號 32-bit 除法
0xe264   if 角色[+0x102] >= 2 → 跳過       ; 束縛或死亡拿不到
0xe273   角色[+0xc4..c7] += ds:0x52d0
0xe289   封頂 0x00FFFFFF
```

三件事跟著出來：

- 訊息 `Exp per chr: %ld` 的 **per chr 是真的除過的** —— 總經驗除以隊伍人數。
- **分母是全隊人數，不是拿得到的人數。** 有人被束縛或死亡時，
  那一份不會分給活著的人，**直接消失**。
- 分界在 `>= 2`：戰鬥狀態是單一列舉值（0 正常／1 中毒／2–4 束縛／5 死亡，
  `docs/re/26`），所以**中毒照樣拿經驗**，切在「還能自己行動」那條線上。

**本專案原本完全沒有發放戰鬥經驗值** —— `Character.Experience` 只有讀
（升級檢查、神殿捐獻、角色卡）沒有加。打怪不給經驗，核心成長線是斷的。
這一輪接上了。

## 3. 金幣（式子讀出來了，但輸入欄位講不通）

```
for i := 0; i < 隊伍[+0xa6]; i++ {
    X = 單位[i] + 0x1a
    金幣 += pow(1.7, X) + rnd(pow(2.1, X)) + 3
}
```

兩個底數都在同一個常數池（`0x40f0` = 1.7、`0x40e8` = 2.1），
次方走的是 `1990:0a83`（整數指數，`docs/re/48` §3 命名過的那一支）。

**但 `單位+0x1a` 依 `docs/re/20` §214 是「附魔加成」**，
拿它當金幣的指數講不通（大多數怪物是 0，算出來每隻 5 金）。三種可能：

1. `docs/re/20` 對**怪物單位**的那一欄判讀不適用（玩家單位才是附魔）
2. 迴圈邊界 `隊伍[+0xa6]` 不是怪物數
3. 怪物在那一欄放的是別的東西（等級？寶藏等級？）

**沒有證據裁決，所以不實作。** 式子先記在這裡，等 `+0xa6` 與怪物側的
`+0x1a` 有定論再接。

## 4. 踩到的坑：printf 的參數順序

第一次讀的時候，我把那個 Σ 當成經驗值 —— 因為它就在
`Exp per chr: %ld    Gold: %ld` 前面被 push。

**C 的參數是右到左推的**：最後 push 的才是第一個 `%ld`。
實際順序是 `push Σ` → `push ds:0x52d0` → `push 格式字串`，
所以 **`ds:0x52d0` 才是 Exp，Σ 是 Gold**。

差一步就會把整條經驗值公式接錯。看到 printf 就要停下來倒著數。

## 5. 順帶：`docs/re/55` 的第三個線索被削弱了

`docs/re/55` §2(3) 說「1.7 在估價的附魔項也出現過，可能是同一組常數」。

現在知道資料段那個 `1.7` 是**戰鬥金幣的底數**，而且用法是 `1.7^n`
（1.7 當底、n 當指數），與附魔費用需要的 `n^1.7`（n 當底、1.7 當指數）
**方向相反**。估價那個 `1.7` 又是 push 立即數、不在資料段。

所以「三個 1.7 是同一件事」這條線索**不成立**。
`docs/re/55` 的 `n^1.7` 仍然只是擬合得很好的假說，
而且「這個引擎算不算得出非整數次方」的疑慮**沒有被解除** ——
目前全檔看到的次方都是整數指數。

## 2. `inc` 與 `dec` 成對就是證據

掃全部 30 處存取，關鍵是這三處：

```
0x0c611  inc  ds:0x52d4
0x0fb58  dec  ds:0x52d4
0x16d4e  dec  ds:0x52d4
```

**二元開關不需要 `inc`／`dec`** —— 那是計數器的操作。
配上大量的 `cmp 0`（八處）與兩處 `寫 imm = 0`，形狀完全是：

```
進一層 → inc
出一層 → dec
「是否在最外層」→ cmp 0
強制回到最外層 → 寫 0
```

**所以 `docs/re/22` 的「子地圖巢狀深度」是對的**，
`docs/re/04` §103 標的「未定案」可以結案。

它之所以在很多地方**看起來**像二元開關，是因為那些地方問的是
「是不是在大地圖」（`== 0`）—— 對深度計數器問這個問題完全合理。

> 這是「同一個欄位在不同地方被用成不同粒度」的例子：
> 有的地方只關心 0／非 0，有的地方真的在加減。
> 只看前者會得出「二元開關」的結論。

## 3. 順帶把 `docs/re/75` 的一處講清楚

`docs/re/75` §2 對 `0x189ce` 只寫「地城裡某狀態成立時延後 10 步」。
現在那個狀態有名字了：

```
189bb  if (ds:0x52d4 != 0 && party[+0xa3] < 9) {
189ce      party[+0x9c] = 10        ; 延後 10 步
       }
```

**＝「在室內（巢狀深度 > 0）且子地圖 < 9」→ 遭遇倒數設 10。**

與 `docs/re/24` §58 的「船上不擲」是同一個變數的同一種用法 ——
不在大地圖上時，遭遇規則會被改掉或跳過。

## 4. 教訓：新開 worklist 項目之前先 grep

`docs/re/75` §4 寫「新增：`ds:0x52d4` 的語意」時，答案已經在五篇筆記裡。
`grep -rn 52d4 docs/` 三十秒就查到。

這與 `CONTEXT.md` §6 記的「動手挖之前先查手上已有的」是同一條，
但這次的形式不同：**不是「不知道就去挖」，而是「順手開一個 worklist 項目」**。
開項目的成本感覺很低，所以跳過了查證 —— 結果那一項本來就不存在。

**worklist 上多一項假的未解，比少一項真的未解更糟**：
它會讓下一輪的人（或下一個 session 的自己）去追一個已經有答案的東西。

順帶：這一輪差點踩另一個坑。`CONTEXT.md` 的「已被推翻的斷言」裡記著
「`0x52f4` 是到處被重用的暫存字，把暫存變數當專用欄位去追會一直繞」。
`0x52d4` 只差一個字元、也有三十處存取 —— 很容易套用同一個結論。
但它**不是**暫存字，是有明確語意的深度計數器。**相鄰的位址不代表同類。**

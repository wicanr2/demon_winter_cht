# 52 — 市集與商隊是同一支常式，而商隊有七個選項

`docs/re/50` §1 發現商隊常式（`278d:1fd1`）開頭就分岔：`mode == 1` 是商隊，
`mode == 0` 是別的東西。這一篇把 `mode == 0` 讀出來 ——
順便發現**本專案的商隊畫面只做了原版七個選項裡的兩個**（讀完之後補上了 Haggle）。

---

## 1. 兩個模式是兩個畫面

```
1d925  ax = mode × 4
1d92e  印 [0x362a + ax] 那個遠指標指到的標題
```

| mode | 標題 | 選項數 |
|---|---|---|
| 0 | `    Marketplace` | 12 |
| 1 | `    Merchants` | 7 |

選項字串在兩張遠指標表（`ds:0x3670`／`ds:0x36c6`），
熱鍵則是緊接在後的一個字串 —— 長度剛好等於選項數，可以互相驗：

```
mode 0  PSCBHI12345Q   ; 12 個
mode 1  PVCBHIQ        ; 7 個
```

而函式開頭 `[bp-0x34] = 12`、`mode == 1` 時 `+= −5 → 7`（`1d4d1`）——
**第三個獨立的來源指向同樣的數字**。

| # | mode 0（市集）| mode 1（商隊）|
|---|---|---|
| 0 | Purchase | Purchase |
| 1 | Sell | **View mind** |
| 2 | Continue | Continue |
| 3 | Back | Back |
| 4 | **Haggle** | **Haggle** |
| 5 | Identify | **Inspect** |
| 6–10 | 五個角色槽 | — |
| 11 | Quit | Quit |

---

## 2. 分派表有 14 個 case，不是 12

同樣掃 `2e ff a7` 找到 `0x1e077`，跳表在 `278d:2b83`，`cmp ax,0x0e` → 14 個。

12 個是市集的選項，多出來的兩個正是商隊換掉的那兩項：

| case | 位址 | 是誰 |
|---|---|---|
| 4 | `0x1dc38` | Haggle（**兩個模式共用同一段程式**）|
| 12 | `0x1df5b` | View mind（商隊）|
| 13 | `0x1dd38` | Inspect（商隊）|
| 6–10 | `0x1dbcf` | 五個角色槽指向同一段 |

**Haggle 共用**這件事有實用價值：市集的議價（`docs/re/19` §7）與商隊的議價
是同一條規則，不必分開解。

---

## 3. 議價的三條分支

每一件貨各自有一個議價計數器 `ds:0x6054 + i×2`，開畫面時 31 格全部清 0
（`1d52e`–`1d549`）。

```
1dc3d  if rnd(100) < 10 × 計數器:
           印 "You have insulted" / "the merchant"
           計數器 = 1000                      ; 這件貨等於報廢
1dc9c  else if rnd(100) < 15 × 計數器:
           印 "The merchant stands firm"      ; 沒降價，計數器不動
1dcf2  else:
           計數器++                           ; 成功，下一次更難
```

三件事跟著出來：

- **第一次議價一定成功**（計數器 0 → 兩道門檻都是 0）。
- **越議越危險**：成功一次之後，翻臉機率 10%、僵持 15%；再一次是 20% / 30%。
  第五次成功之後翻臉機率就到 50%。
- 翻臉的代價是**那一件貨報廢**（計數器 1000，之後每次都落在第一條）。
  不是整支商隊翻臉，是那一件。

成功那條只做了 `計數器++` 與重畫 —— 價格是**顯示的時候**拿計數器重算的
（`0x1dac5`–`0x1db4b`）：

```
n = 計數器；n == 0xffff → 0；n > 99 → n − 100
要價 = max(2, 開價 − trunc(開價 × n × 0.06))
```

**每成功一次打掉開價的 6%，下限 2 金。** `n > 99 → −100` 是「僵持過一次」
的標記：`HaggleUnmoved` 會 `+100`，折扣級數不變但下次 `×10` 必定超過
`rnd(100)` 的上限 —— **僵持一次就等於死路，再議必定翻臉**。

> ⚠ **這條規則早就在本專案的 `internal/game/economy.go` 裡了**（市集那邊
> `docs/re/19` 就解完了，連 `> 99 → −100` 與下限 2 都在）。上一版本文寫
> 「還沒讀」是**沒查自己的實作**。同一個坑在 `docs/re/45` 也踩過一次
> （`1d9f:0dd4` 的身分 `docs/re/14` 早就寫好了）—— 動手前先 grep 自己的
> 程式碼與文件，成本比重讀組合語言低一個數量級。

貨單上還有兩個狀態字串（`0x1da7e` 的分支）：

| 計數器 | 顯示 | 意思 |
|---|---|---|
| 1000 | `Inslt ` | 翻臉了，這件不賣 |
| 1001 | ` LIE  ` | **謊報** —— 應該是 View mind 的產物 |

## 4. View mind 是一次性的

```
1df5b  if [bp-0x14] == 0 → 什麼都不做
1df69  if [bp-0x14] == 1 → 印 "Only usable once"
1df7f  [bp-0x14] = 1                          ; 用掉
```

`[bp-0x14]` 是這一支商隊的「已經看過了」旗標。**看什麼還沒讀**
（`1df84` 之後那段迴圈）。名字加上它跟 Haggle 並列，合理的猜測是
「看穿商人心裡的底價」—— 但那是猜測，沒有證據，不寫進實作。

---

## 5. 對本專案的意思

`docs/re/47` 說「商隊購買介面做好了」。**那句話要收窄**：
做好的是 Purchase 與離開，原版還有 View mind、Continue、Back、Haggle、Inspect。

- **Continue／Back** 是貨單翻頁。本專案一次列完 7–10 件（640×400 放得下），
  這兩項在我們這裡沒有對應物 —— 不是缺漏，是版面不同。
- **Haggle 接上了。** 規則與市集共用，`economy.go` 的 `Haggle`／`HagglePrice`
  直接拿來用；差別只有初值 —— **商隊一律從 0 開始**（`0x1d52e` 清 31 格），
  不吃市集那個「隊伍裡有人會說服就給初值」的加成。
- **Inspect／View mind** 完全沒讀。

所以商隊畫面的正確狀態是「**能買、能殺價，還少 View mind 與 Inspect**」。

---

## 6. 這一輪的方法

三個獨立來源互相驗選項數（熱鍵字串長度、遠指標表長度、`[bp-0x34]` 的
`12 − 5`）—— 任何一個讀錯，三者就對不起來。這種**冗餘交叉驗證**
比「反編譯看起來是這樣」硬得多，而且成本幾乎是零。

找跳表的手法與 `docs/re/50` §1.1 一樣：掃 `2e ff a7`。用第二次就順了。

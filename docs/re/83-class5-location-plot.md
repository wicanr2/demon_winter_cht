# 83 — 類別 5 就是那張 16 格表：地點劇情事件（含艾瑞戈爾整段對話樹）

`docs/re/65` §4 留下一個未解：**「`ds:0x52f6` 這個事件狀態變數誰在設」**。

答案不在任何「事件狀態機」裡 —— `ds:0x52f6` 是 `nSS.DAT` 查表函式的**輸出參數**，
而它輸出的值就是特殊格 attr 的低 5 bit。所以：

> **`nSS.DAT` 類別 5 的記錄 = 地點劇情事件，它的「值」就是那張 16 格表的 case 編號。**

`docs/re/77`（格式）與 `docs/re/65`（分派表）這兩篇一直是分開的，
中間差的就是這一句。接上之後，主線劇情的**觸發座標全部落地**。

---

## 1. 為什麼 `ds:0x52f6` 看起來像個孤兒

`docs/re/65` §2 說內層選擇子是 `ds:0x52f6`，然後找不到誰設它 —— 因為找法反了。
掃全檔對 `ds:0x52f6` 的寫入有七處，其中六處長得一模一樣：

```
0x0e1db  al = es:[bx+0xa1] ; ds:0x52f4 = ax     ; 隊伍 X
0x0e1e5  al = es:[bx+0xa2] ; ds:0x52f6 = ax     ; 隊伍 Y
0x0e1ef  call 222f:1321                          ; ← 查表
0x0e1f4  les bx, ds:0x52f8                       ; ← 用結果
```

`0x0f69b`、`0x1698f`、`0x1784b`、`0x190c2`、`0x19eea` 五處同型，
來源不同（隊伍座標、`ds:0x50f0/0x50ee`、區域變數）但形狀一致：
**先填一組 (X, Y)，再呼叫 `222f:1321`。**

第七處 `0x172c0` 在 `222f:1321` **自己**裡面（類別 4 的傳送續跳）。

所以 `ds:0x52f4`／`ds:0x52f6` 是一組 **in/out 參數**：
進去時是座標，出來時是查表結果。`docs/re/77` §3 早就把 out 那半邊寫對了，
只是沒有人把它跟 `docs/re/65` 的 case 編號接起來。

> **`docs/re/65` §2 說「`ds:0x52f4` 是 tile 暫存（`docs/re/58`）」，那是誤導。**
> 它在這條路徑上是查表座標與序號輸出。`docs/re/24` §… 說它是「到處被重用的暫存字」
> 也只對了一半 —— 它確實被多處重用，但在 `222f:1321` 的呼叫序列裡語意是固定的。

### 查表函式 `222f:1321`（`0x17211`）的完整介面

```
in:   ds:0x52f4 = X,  ds:0x52f6 = Y,  ds:0x5514 = nSS.DAT 緩衝區遠指標
out:  ret       = 類別（類別 4 時是垃圾值，呼叫端改看 ds:0x5c62）
      ds:0x5c62 = 類別
      ds:0x52f8/0x52fa = 命中記錄的遠指標
      ds:0x52f4 = 序號（類別 1／2 為 1-based，其餘 0-based）
      ds:0x52f6 = attr & 0x1f            ← 本篇的重點
      類別 4 另外把 ds:0x52f4/0x52f6 覆寫成傳送目的座標
沒命中：ret = 0xff，其餘輸出不動
```

### 類別怎麼分派（`FUN_25be_0263` ＝ `0x19a43`）

```
0x19a4b   cmp ds:0x5c62, 3 ; je  ┐
0x19a52   cmp ds:0x5c62, 6 ; je  ┴→ 陷阱（"A trap!" @ ds:0x29e4）
0x19f15   cmp ds:0x5c62, 5 ; jne → 預設：讀 DATA*.TXT 顯示房間文字（docs/re/22）
0x19f1f   若參數 != 0 → 印 "Something you cannot" / "identify lies before you."
0x19f4f   ds:0x15ce = 0x80
0x19f55   ax = ds:0x52f6                  ← 選擇子
0x1a5eb   cmp ax, 0x10 ; jae 預設
0x1a5f3   jmp cs:[bx*2 + 0xdeb]           ← docs/re/65 那張 16 格表
```

`cmp ds:0x5c62, 5` 這一行就是連結點。它是**指令層級的證據**，不是推論。

## 2. 資料層的反證：15 個值，跨五張地圖零碰撞

從 `ALL_SS.DAT`（母本，未被遊玩污染）把五張子地圖的類別 5 記錄全部攤開：

| 地圖 | 類別 5 的值 |
|---|---|
| 1 | 1, 2, 3, 12, 14 |
| 2 | 6, 8, 9 |
| 3 | 4, 5 |
| 4 | 7, 11, 13 |
| 5 | 10, 15 |

**聯集恰好是 1–15，每個值只出現在一張地圖，一次碰撞都沒有。**

這是可以被資料打死的預測：如果「值」只是某種區域旗標或狀態碼，
五張獨立的地圖各自編號，撞號幾乎必然。15 個值分佈在 5 張地圖而全域唯一，
只有一種解釋 —— 它是**全域的事件編號**。而 16 格表剛好 case 0 是預設（不用），
真正有內容的正是 case 1–15。

### 幾何再驗一次

`docs/re/65` §3 那張表的 case 語意是從**字串**認出來的。
座標分佈是從**資料**來的。兩邊獨立，形狀卻對得上：

| case | 語意（來自字串） | 座標（來自 `ALL_SS.DAT`） |
|---|---|---|
| 1 | `You hear the whirring of massive machinery` | 地圖 1 (15,38)、(23,38) —— 走廊兩端 |
| 2 | `Your party has been crushed by the walls.` | 地圖 1 (16..20, 36..40) 共 12 格 —— **夾在 case 1 兩端之間的整段走廊** |
| 3 | `Do you approach?` | 地圖 1 (23,27)(23,31)(33,27)(33,31) —— 矩形四角 |
| 5 | `The tombstones shift before you` | 地圖 3 (20,60)(24,58)(28,60) —— 三塊墓碑 |
| 14 | 檢查 `party+0xbe` → 艾瑞戈爾 | 地圖 1 **(60,1) 單獨一格** |
| 15 | `A crimson forcefield bars your entry to the Circle of Light` | 地圖 5 (10,50)(11,49)(11,51)(12,50) —— **繞著 (11,50) 的四格十字** |

case 1 + case 2 是一條壓牆走廊：兩端聽到機械聲，中間整段會把人壓死。
case 15 是四個入口格圍住中心一格 —— 光之環的門本來就該長這樣。

**兩條互相獨立的證據鏈（反組譯的字串 vs 資料的幾何）指向同一個結論，
比任何一條單獨成立都強。**

### 順帶記兩件資料上的怪事

- 地圖 1 有**兩筆完全相同**的記錄 `case12@(26,8)`。查表是線性掃描先中先回，
  所以第二筆永遠碰不到。移植時照抄即可，不要「順手去重」——
  去重會改變類別 1／2 的序號計數（`0x172df` 對每一筆都加），
  而那個序號是 `DATA*.TXT` 的索引。
- **出貨資料裡沒有類別 0、6、7。** 五張地圖只出現 1、2、3、4、5。
  但程式碼對類別 6 有處理（跟 3 一起走陷阱路徑），對類別 0 也有
  （`docs/re/22`：走預設路徑讀 `DATA*.TXT`）。
  留著程式路徑、資料不用，是原版自己的狀態，不是判讀錯誤。

## 3. case 14：艾瑞戈爾（`FUN_25be_1ae2` ＝ `0x1b2c2`）

`docs/re/82` 解出 `25be:19d1(page, mode)`，mode 0 是 `EREGORE.TXT`。
這支函式從頭到尾就是在叫它 —— **十次，正好對上 `EREGORE.TXT` 的 10 頁**。

### 入口閘門（`0x1a54b`）

```
if (party+0xbe != 0) return 3;      ; 談過就不再談
call 25be:1ae2
```

### 對話樹

```
19d1(0xffff, 0)                     載入 EREGORE.TXT

if (party+0x99 == 1) {              ← 第二階段（見下）
    party+0x99 = 0
    party+0xbe = 1                  latch，之後入口閘門直接回 3
    19d1(9, 0)                      頁 9
    return 0
}

19d1(0, 0)                          頁 0：開場
ans = 等 1..2
  1 → 19d1(1, 0)  頁 1               → 收尾
  2 ↓
19d1(2, 0)                          頁 2
ans = 等 1..3
  2 → 19d1(3, 0)  頁 3               → 收尾
  3 → 19d1(4, 0)  頁 4               → 收尾
  1 ↓
19d1(5, 0)                          頁 5
ans = 等 1..3
  3 → 19d1(6, 0)  頁 6               → 收尾
  1 →                                 → 收尾
  2 ↓
19d1(7, 0) ; 19d1(8, 0) ; 19d1(9, 0)   頁 7、8、9
party+0xbe = 1                      latch
return 0
```

三層選擇、七條出口。頁 9 是兩條路徑共用的結局段
（一次談成走 7→8→9；沒談成的話下次見面直接跳頁 9）。

### 收尾那一段做了什麼（`0x1b482`）

```
party+0xa6 = 3
party+0x16 = 0x39 ; +0x17 = 0x38 ; +0x18 = 0x61
call 222f:2cf2(party+0xa1 − 1, party+0xa2 − 1)
party+0x99 = 1
call 07c5:000d(0)
```

`+0xa6` 是怪物 ID 陣列 `+0x16` 的長度（`docs/re/02` §…、`docs/re/57`）。
所以這幾行是**擺一場三隻怪的戰鬥**：ID 0x39、0x38、0x61，
位置在隊伍座標的左上一格。**談崩就開打。**

然後 `party+0x99 = 1` —— 這就是兩階段的來源：
第一次見面沒談成 → 打一架 → `+0x99` 立起來；
下次再踩 (60,1) → 走 `+0x99 == 1` 那條 → 直接播頁 9 並 latch。

### `party+0x99` 全檔只有三處存取

`tools/fieldscan.py 0x99` → `0x1b2dd`（比較）、`0x1b2e5`（清 0）、`0x1b4ca`（設 1）。
**三處全在這支函式裡。** 它是艾瑞戈爾專用的一格狀態，不是通用旗標。

> 這裡順便修掉一個我自己犯過的錯：`docs/re/81` 記過「找不到寫入就懷疑工具有盲點」。
> `+0x99` 這次是**用同一支 fieldscan 一次就找齊**的 ——
> 工具沒有盲點的時候，找不到就是還沒找對地方。

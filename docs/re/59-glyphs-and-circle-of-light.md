# 59 — 主線骨幹：三個緋紅符印與光之環

`docs/re/58` 找到 `party+0x96`／`+0x97`／`+0x98` 三個劇情旗標，
但當時掃不到任何寫入點。這一篇把整條鏈補完 ——
**這是本專案第一次拿到「怎麼破關」的機制。**

---

## 1. 掃不到寫入點，是因為漏了一種定址

`+0x96` 用 `[bx+disp16]`（ModRM rm=7）掃只有兩處，都是讀。
補掃 `[bx+si+disp16]`（**rm=0**）立刻命中：

```
06b4c  26 80 b8 96 00 00     cmp  BYTE PTR es:[bx+si+0x96],0x0
06bb8  26 c6 80 96 00 80     mov  BYTE PTR es:[bx+si+0x96],0x80
```

`si` 是變數，**三個旗標共用同一段程式碼** —— 所以 `+0x97` 在整份執行檔裡
一次寫入都沒有，它是 `+0x96 + 1` 算出來的。

> 教訓：掃 `[bx+disp16]` 不等於掃完 disp16。
> 8086 的 mod=10 有八種 rm，只掃 rm=7 會漏掉所有「基底 + 索引」的寫法，
> 而**陣列式的欄位（旗標組、槽位）恰恰都用那種寫法**。

## 2. 解符印的完整流程（`0x6afe`–`0x6bbe`）

```
6afe   si = Y×64 + X
6b0c   les bx, ds:0x4c94              ; 地圖 tile 陣列
6b10   cmp es:[bx+si], 0x63           ; 腳下的 tile 是符印嗎？
6b14   je  繼續                        ; 否 → "I see no glyph!"

6b2e   al = party[+0xa3]              ; 子地圖 ID
6b35   ax -= 0x37                     ; − 55
6b3c   if (ax == 0x0b) ax = 2         ; 子地圖 66 特判
6b47   si = ax                        ; 索引 0／1／2

6b4b   cmp es:[bx+si+0x96], 0         ; 這個符印還在嗎？
6b51   je  繼續                        ; 否 → "It is already inactive"

6b7b   si = 施法者索引 × 0x104
6b87   al = 角色[+0xff]               ; 目前法力值
6b8e   ax -= 50                       ; ← 扣 50 點
6b91   角色[+0xff] = al

6b97   印 "In a flash of power the magic"
6ba4   印 "of the glyph is destroyed."
6bb8   es:[bx+si+0x96] = 0x80         ; ← 旗標設為完成
```

### 子地圖 → 旗標的映射

| 子地圖 | 十進位 | `− 55` | 特判 | 索引 | 旗標 |
|---|---|---|---|---|---|
| `0x37` | 55 | 0 | — | 0 | `+0x96` |
| `0x38` | 56 | 1 | — | 1 | `+0x97` |
| `0x42` | 66 | 11 | → 2 | 2 | `+0x98` |

與 `docs/re/58` §3 從 `222f:0b0e` 那邊讀到的三個子地圖**完全一致**，
兩段互不相干的程式碼給出同一組對應。

## 3. 三個都解完才進得去光之環

```
1a565  les bx, ds:0x4c76
1a569  cmp es:[bx+0x96],0  → je  擋下
1a571  cmp es:[bx+0x97],0  → je  擋下
1a579  cmp es:[bx+0x98],0  → jne 放行（0x1a5c5）
1a581  擋下：印 ds:0x2e40
```

```
ds:0x2e40 = "A crimson forcefield bars your entry to the Circle of Light"
```

被擋下時還會把玩家推開：`if (party[+0xa1] == 0x0b) party[+0xa2] = 0x36 − (面向×2 + 2)`。

> ⚠ 注意這裡比的是 **`!= 0`**，而 `222f:0b0e` 的傷害判定比的是 **`< 0x80`**。
> 兩處門檻不同 —— 目前的存檔三個都是 `0`，解完是 `0x80`，
> 中間值在觀察到的資料裡不存在，所以**兩種寫法在實務上等價**。
> 但不能因此說旗標是布林：`0x80` 這個值本身說明作者留了低 7 bit。

## 4. 攻略獨立佐證（三方閉合）

`docs/walkthrough/part-4.md` §113–115：

> 解咒法術每次花費 **50 點法力值**……航向世界的**東南角**，會找到馬利馮的火山。
> 火山周圍延伸出**三塊狹長陸地**，每一塊的盡頭都有一個符印。
> **符印還在的時候在附近走動會傷害隊伍**，所以要盡快趕到每個符印上**紮營**，然後**施展解咒**。

逐條對上：

| 攻略 | 反組譯 |
|---|---|
| 50 點法力 | `6b8e  ax -= 50`（角色 `+0xff`）|
| 東南角 | 子地圖 55／56／66 —— 7×7 網格的 `col5–6 × row5–6` |
| 三塊狹長陸地 | `0x38` 在 `222f:0b0e` 依 Y 分三段（北 `Y<10`、南 `Y>0x16`、中央 `X` 33–54）|
| 符印還在就傷害隊伍 | `FUN_222f_0619`（旗標 `< 0x80` 才呼叫，字串含 `died`）|
| 走到符印上 | `cmp es:[bx+si],0x63` —— 腳下 tile 必須是 `0x63` |
| 紮營施法 | 觸發它的是 **UNCURSE／IMPRISON 專屬選單**（`docs/re/60`）。~~紮營施法路徑 `docs/re/42`~~ —— 那是錯的推測，`[bp+0x8]` 的簽名紮營各項都一樣，分不出是哪一個 |

而 `translations/glossary.md` §209 早就從 `TOWN.TXT` 記下
「**三個緋紅符印（three crimson Glyphs）**，使人靠近即腐化」——
與 `crimson forcefield` 同一個形容詞。**三個獨立來源指向同一件事。**

> 又一次驗證「先查手上已有的」：譯名表裡那一行是幾週前為了裁決
> glyph／rune 的譯法寫的，當時完全不知道它是主線關鍵。

## 6. 還沒解的部分

- **禁錮與終局**：見 `docs/re/60`（本篇的續篇，完整破關路徑）。
- **`FUN_222f_0619`**（`0x16509`，325 bytes）：符印還在時「在附近走動會傷害隊伍」
  的實作。字串裡有 ` died`。傷害量與判定範圍未讀。
- **光之環裡面**：`0x1a5c5` 放行後只是 `return 3`，真正的內容在分派表下游；
  同一個函式裡還有一張 16 格跳表（`0x1a5f3`，`CONTEXT.md` §7 的 B7 之一）。
- **`WIN.TXT` 的觸發**：仍未解。光之環進得去 ≠ 破得了關。
- **符印 tile `0x63`**：可通行性表 `ds:0x5500` 對它的值還沒查，
  也還沒確認 `MAP*.MAP` 裡實際有幾個 `0x63`。

## 7. 對 remake 的意義

在這之前，本專案有一個能走、能打、能買賣、能升級的世界，
**但沒有任何「破關」的路徑** —— 因為不知道主線是什麼機制。

現在知道了：**三個符印 → 解咒 → 光之環**。這是第一條可實作的主線鏈，
而且它需要的每一塊本專案都已經有了（紮營施法、法力扣除、子地圖 ID、
tile 查詢、trailer 欄位讀寫）。缺的只是把 `+0x96`–`+0x98` 接進存檔結構
與解咒法術的效果。

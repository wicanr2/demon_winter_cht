# 116 — 怪物近戰走位：原版候選路線與 remake 接線

日期：2026-07-30
工具：IDA Pro 9.4 官方版匯出、原始 16-bit 指令複核
輸入：`DEMON.INT`
SHA-256：`fc1df05513bfa0f1a38f95ce0fbe5e6ec390c8192b2f99b3b6118b3c23868ea5`

## 問題與舊狀態

`cmd/demonwinter/battleui.go` 的舊註解明說：近戰走位是 remake 補充，原版分支
尚未讀。實作只比較 `|dx|`／`|dy|`，選差距較大的軸；正面有隊友或牆時，
`Battle.Step` 失敗便結束行動。這會讓原版能繞過的障礙物卡住怪物。

規則層其實已有 `Battle.FirstStepToward` 的確定性最短路實作與隊友繞路測試，
但沒有任何正式呼叫端。這是另一個「實作存在、產品路徑沒接」的缺口。

## IDA 證據

位址同時列執行期段位址與 IDA 線性位址：

| 段位址 | IDA | 證據 |
|---|---:|---|
| `138d:03f5` | `sub_13CC5` | 怪物 AI 主決策；噴吐、施法後進近戰 |
| `1990:0002` | `sub_19902` | 共用的轉向、移動、相鄰攻擊核心 |
| `1990:0554` | `sub_19E54` | 由攻擊者與記憶目標建立候選路線 |
| `1990:06ed` | `sub_1A0ED` | 測試下一格是否等於戰場空地值，必要時換候選方向 |
| `1990:07cd` | `sub_1A1CD` | 比較候選段長並寫入 `DS:5210` 路線緩衝 |

`sub_13CC5` 從怪物單位 `+0x1e` 取出記憶目標槽位，驗證目標仍在場上且陣營
為玩家側；無效才用 `Roll(15)-1` 重挑，並把新槽位寫回 `+0x1e`。有效後呼叫
`sub_19902(attacker)`。回傳 3 時重新選目標，證明近戰核心可能因路線／目標狀態
要求上層重試，不是固定朝一個座標走一步。

`sub_19902` 的關鍵行為：

1. 呼叫 `sub_19E54(attacker, rememberedTarget)`。
2. `DS:5210` 起的資料以 `0xff` 結束；每組是「方向、連續步數」，最多讀三組。
3. 方向與單位 `+0x14` 不同時，寫回面向並扣 `DS:5190` 一點。
4. 前進時查 `DS:15da/15d2` 的 X/Y 方向增量，更新地形緩衝與單位座標，
   並扣兩點。
5. 行動點至少 3 時掃四個相鄰格；遇到玩家側單位才呼叫共同攻擊核心
   `sub_15EAA`，成功後扣三點。

所以「原版有障礙物感知的候選路線」是已證實；現行最大座標差直走不等價。

## remake 映射

正式呼叫端現在改為：

1. `AITarget` 維持原版的記憶目標與死亡後重挑。
2. `stepToward` 只提供同長路線的偏好方向。
3. `Battle.FirstStepToward` 依 `BattleTerrain.Walkable` 與 `UnitAt` 做廣度優先
   搜尋，目標是抵達敵人相鄰格。
4. `monsterTurn` 再使用既有 `TurnTo`／`Step`／`ResolveAttack`；1／2／3 點成本
   不變。

測試覆蓋：

- 直線路徑；
- L 形同長路徑依偏好穩定選擇；
- 正面隊友阻擋時繞路；
- 正面不可走 terrain 時繞路；
- 四面封死時不聲稱有路。

## 信心與剩餘差異

- **已證實**：原版不是最大差距單軸直走；它會建立障礙物感知候選路線，
  且轉向／移動／攻擊成本是 1／2／3。
- **已驗證 remake 行為**：會繞牆與隊友、抵達目標相鄰格，且結果可重播。
- **強證據、非逐步相同**：remake 用完整最短路搜尋；原版只比較固定數量的
  分段候選。兩者在同長多路可走時的 tie-break 尚未做 DOSBox 動態逐步對拍。

這個差異不改命中、傷害、目標記憶、行動點或勝負規則；若未來要求逐步錄影
完全一致，再以相同戰場與 RNG 對拍同長岔路，不把本輪結果誇成逐指令移植。

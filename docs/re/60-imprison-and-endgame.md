# 60 — 禁錮與終局：完整的破關路徑

`docs/re/59` 解出符印的解除機制，但把觸發它的東西誤標成「紮營施法路徑」。
掃完整支函式的字串，真相更清楚 —— **那是一個主線專屬的選單。**

---

## 1. 主線專屬選單：UNCURSE / IMPRISON / EXIT

嚴格字串錨定掃 `0x6700`–`0x6d00`：

```
0x6749  「%c) %s」                       ← 選單列
0x68e4  「9) Exit」
0x6a14  「UNCURSE 」
0x6a1f  「IMPRISON」
0x6a2a  「EXIT」
0x6aef  「That requires 50 SP!」
0x6b1b  「I see no glyph!」
0x6b54  「It is already inactive」
0x6b97  「In a flash of power the magic」
0x6ba4  「of the glyph is destroyed.」
0x6bda  「That requires 100 SP!」
0x6c18  「The spell fizzles...」
```

**這兩個法術不在 `FILES.DTT` 的 43 筆法術表裡。**
43 筆從 `COLUMN OF FIRE` 到 `THE END`，沒有 `UNCURSE` 也沒有 `IMPRISON`。
> ⚠ 「走自己的選單」不精確 —— 它們走的是**同一支通用施法選單的另一組選項**
> （`docs/re/61` §3），不是另一個函式。

> `docs/re/59` §4 寫「紮營施法路徑（`docs/re/42`）」是**錯的**，已更正。
> 當時的依據只有「`[bp+0x8]` 是角色索引」，那個簽名紮營選單各項都一樣，
> 分不出是哪一個 —— 又一次「分不出兩者的證據不是證據」。

攻略的說法逐字對上：

> 「解咒法術每次花費 **50 點法力值**，**禁錮**本身則要花 **100 點**……
> 你也湊不出處理 3 個符印再加上施展禁錮所需的 **150 點法力值**」

`50 × ?` 加 `100` —— 攻略講的 150 是「還剩一個符印 + 禁錮」的情境。

## 2. IMPRISON 的完整判定（`0x6bc5`–`0x6c2b`）

```
6bc5   si = 施法者索引 × 0x104
6bd1   cmp 角色[+0xff], 0x64        ; 目前法力 >= 100？
6bd7   jae 繼續                      ; 否 → "That requires 100 SP!"

6bfb   ax -= 100                     ; 扣 100 點法力
6bfe   角色[+0xff] = al

6c07   cmp party[+0xa3], 5           ; 子地圖 == 5？
6c0d   je  成功
6c0f   cmp party[+0xa2], 6           ; Y <= 6？
6c15   jbe 成功
       → "The spell fizzles..."      ; 地點不對，法力照扣

6c26:  call 1cdc:2254                ; 音效
6c2b:  call 0000:3575                ; ← 重定位補的遠呼叫
```

三件事值得記：

- **地點不對也照扣 100 點法力。** 判定順序是「先扣再檢查地點」，
  在錯的地方施放會白白損失 —— 這與攻略叮嚀「先備份 `PARTY.DAT`」呼應。
- **成功條件是子地圖 `5` 或 `Y <= 6`**（或的關係，不是且）。
  子地圖 5 **小於 10**，依 `docs/re/24` 的規則那是**地城**，不是戶外。
- ~~`call 0000:3575` 目標由載入器填，靜態看不到~~ —— **這句錯了**。
  segment 欄留白給重定位，但 **offset 是連結期就定死的**：`0000:3575` ＝ `1000:3575`
  ＝ `0x07175` ＝ **結局函式**（`docs/re/61`）。`docs/re/50` 的動作 `0x0e` 同理。

## 3. 結局文字檔在一張遠指標表裡

```
ds:0x2f3e  42 2f f0 21          → 遠指標
ds:0x2f42  "T2C.TXT"
ds:0x2f4c  "CYPHER.SHP"
ds:0x2f6b  "EREGORE.TXT"
ds:0x2f77  "WIN.TXT"
ds:0x2f7f  "T.TXT"
ds:0x2f86  ← 25 筆城鎮座標表（docs/re/19 已解）
```

四個檔名**沒有任何直接引用** —— 它們透過前面那張遠指標表被索引存取，
所以掃 offset 掃不到。這與 `unit+0x24`、`party+0x97` 是同一類空洞：
**索引式存取會讓常數消失。**

`WIN.TXT` 的實際觸發點仍未定位。合理推測是 `0x6c2b` 那個重定位遠呼叫，
但**沒有證據**，不能寫成結論。

## 4. 完整的破關路徑（目前所知）

```
① 三個緋紅符印              docs/re/59
   世界東南角，子地圖 55／56／66
   走到 tile 0x63 上 → UNCURSE（50 SP）
   → party[+0x96 + (子地圖−55)] = 0x80
   符印還在時在附近走動會被 FUN_222f_0619 傷害

② 光之環的門                docs/re/59 §3
   三個旗標都非 0 才放行
   否則 "A crimson forcefield bars your entry to the Circle of Light"
   並把玩家推開

③ 禁錮                      本篇
   在子地圖 5（地城）或 Y <= 6 處 → IMPRISON（100 SP）
   → call 0000:3575（重定位，推測是結局）
```

**這是本專案第一次有一條從頭到尾的主線。** 三段各自都有反組譯依據，
①② 還有攻略獨立佐證。

## 5. 誠實的保留

| 項目 | 狀態 |
|---|---|
| ~~`0x6c2b` 的 `call 0000:3575` 指向哪~~ | **已解**：`0x07175`，字串 `CONGRATULATIONS! You have won Demon's Winter.`（`docs/re/61` §2）|
| `WIN.TXT` 的載入點 | 未定位，但**已不影響結論** —— 結局文字寫死在資料段 `ds:0x066a`，不是從 `WIN.TXT` 讀的 |
| `FUN_222f_0619` 的傷害實作 | 未讀（325 bytes）|
| 光之環**裡面**有什麼 | `0x1a5c5` 放行後只 `return 3`，下游還有 16 格跳表（`0x1a5f3`）|
| UNCURSE／IMPRISON 選單**從哪裡叫出來** | 部分解開：它是**通用施法選單** `1000:2a53` 的另一組選項（熱鍵 U/I/E），不是獨立函式。**切換條件**仍未讀到（`docs/re/61` §3、§5）|
| `EREGORE.TXT`／`T2C.TXT`／`T.TXT` 的時機 | 未解 |

**「破關路徑已知」不等於「破得了關」** —— 上面六項至少要再解掉
「選單怎麼叫出來」與「`3575` 是什麼」，才談得上實裝一條可玩通的主線。

## 6. 對 remake 的意義

引擎要補的東西現在很具體：

1. 存檔加 `+0x96`–`+0x98` 三個 byte（`scenario.Save`）
2. tile `0x63` 的語意（符印）
3. UNCURSE／IMPRISON 選單 + 兩個動作的判定（含「地點不對照扣法力」）
4. 光之環的門（三旗標檢查 + 推開玩家）
5. `FUN_222f_0619` 的符印傷害

前四項需要的機制本專案都已具備。第 5 項要先讀完那 325 bytes。

# 93 — 兩個靈視技能：觀室能做，鑑物做不了

`docs/re/69` §2 把動作 `0x0f`／`0x10` 定位成觀室與鑑物，但只讀到入口
（掃全隊有沒有人會技能 27／28）就停了。這一篇把兩支讀完。

結論分兩半：**觀室可以現在就接，鑑物不行** —— 它要的東西還不存在。

---

## 1. 觀室 View Room（`0x0f` ＝ `222f:30dc` ＝ `0x18fcc`）

```
18fdf  掃全隊：任一角色 [+0xe3] != 0 → 有人會        ; 技能 27
1900b  沒人會 → return 2                            ; **什麼訊息都不印**
19027  if (trailer[+0xad] == 3) {
19034      印 "Your psychic powers are weak"
19041      等按鍵;  return 2
       }
19059  trailer[+0xad]++                             ; ← 用掉一次
1905e  x, y = 隊伍座標
       for step = 0; step < 3; step++ {             ; ← 只看三格
19072      x += ΔX[facing];  y += ΔY[facing]
19087      if (x == -1 || y == -1 || x == 0x40 || y == 0x40) break
190b3      if (map[y*64 + x] != 0x11) continue      ; 只有事件閘門 tile
190b9      ds:0x52f4 = x; ds:0x52f6 = y; call 222f:1321
190ca      if (ds:0x5c62 == 0) continue             ; 類別 0 跳過
190d4      if (ds:0x5c62 == 4) continue             ; 類別 4（傳送）跳過
190e3      call 25be:0263(1)                        ; ← **peek 模式**
190ed      return
       }
19101  印 "You see nothing";  等按鍵;  return 2
```

### peek 模式就是手冊那句話

`25be:0263` 是事件消費者，也就是**踩到格子時跑的那一支**。它的參數在
陷阱那條分支被檢查：

```
19a4b  if (ds:0x5c62 != 3 && != 6) goto 文字路徑
19a62  if ([bp+6] != 0) { 印 "A trap!"; 等按鍵; return 2 }   ← 到此為止
```

走路觸發時 `param = 0`，陷阱會真的擲點、扣血、改寫；
觀室傳 `param = 1`，**只印一行 `A trap!` 就返回**。

手冊：「用觀室技巧也能看到陷阱，**但不會標記為『已注意』**。」
—— 對上了，而且比手冊更精確：不只不標記，連傷害都不會發生。

非陷阱的類別（1／2 的事件文字、5 的地點劇情）在 peek 模式下**照常完整顯示**，
因為那個旗標只擋陷阱那一支。

## 2. 鑑物 View Items（`0x10` ＝ `222f:34d2` ＝ `0x193c2`）

```
193d5  掃全隊：任一角色 [+0xe4] != 0 → 有人會        ; 技能 28
19401  沒人會 → return 2
19422  if (trailer[+0xae] == 3) { 印 "Your psychic powers are weak"; 收尾 }
1943e  trailer[+0xae]++
19443  if (Roll(3) == 2) { 印 "Fails"; 收尾 }        ; ← 1/3 失敗
19462  印 "View item:"
19479  call 222f:2da5                               ; 選一個目標（動作 0x0d）
1947f  call 222f:2e8b
19488  結果 < 0 → 離開
1949b  les bx, ds:0x55c8[結果]                      ; ← 遠指標表
1949f  if (*bx == 0) 印 "You can discern nothing"
       else sprintf("An image of %s", bx) → 印，再印 "comes to you"
```

`222f:2da5` 是 `Take:`／`Move:` 共用的那支「選一個目標」（`docs/re/58` §5）。

> ⚠ 這裡原本寫「`ds:0x55c8` 是**地城道具的敘述指標表**」，講得像一張新表。
> **訂正**（`docs/re/94` §4.2）：`0x55c8 − 0x55b8 = 4 筆`，它就是 `docs/re/27` §2
> 第 6 張「場景／物件互動文字」陣列（303 筆，`FILES.DTT` 索引 164–466）
> **偏移 4 筆之後**的位置。不是新表，那批字串本專案早就抽得出來。

**所以鑑物是地城道具系統的一部分。** 引擎現在連地城道具都沒有
（`CONTEXT.md` §7 的 A2），接上去只會得到一個空選單。
這一項的**前置是 A2，不是它自己** —— 記在這裡，免得下一輪又把它排進
「只差接線」那一類。

> **2026-07-27 補**：A2 做完了，這一項因此解封並已實作
> （`internal/game/viewitem.go`＋`X` 鍵）。當時那句「前置是 A2」是對的 ——
> 從標記到解封中間隔了十幾輪，而**沒有這句話的話，中間任何一輪都可能
> 有人去接它然後得到一個空選單**，再花時間查為什麼。

## 3. 兩處與別處不一致的細節

**觀室比的是沒遮罩的 tile。** `0x190b3` 是 `cmp byte es:[bx+si], 0x11`，
而走路觸發（`docs/re/05`）與 `L` 查看陷阱（`docs/re/91`）都先 `& 0x7f`。
差別只在最高位被設起來的格子：那種格子走上去會觸發、觀室卻看不到。
**引擎照別處遮罩**，不模擬這個不一致 —— 它更像疏漏而不是設計。

**觀室不管有沒有看到都扣一次。** `inc` 在掃描之前（`0x19059`），
所以對著空走廊用一次也是一次。

## 4. 手冊說一天一次，執行檔說三次

手冊「觀室」與「鑑物」兩節都寫「這項技能每天只能使用一次」。
機器碼兩處都是 `cmp …, 3`：

| | 計數 | 上限 |
|---|---|---|
| 觀地（`docs/re/38`）| `+0xac` | 旗標，**確實是一天一次** |
| 觀室 | `+0xad` | **3** |
| 鑑物 | `+0xae` | **3** |

三個都由睡覺清 0（`0x1ef68`–`0x1ef7c`，緊接在把水池額度設成 7 之後）。

手冊講的是 Apple II 版，這裡移植的是 DOS 版的執行檔 —— 引擎照執行檔。
**待 DOSBox 實跑複核**（連按三次 `V` 看第四次會不會被拒），
列進 `CONTEXT.md` §7 的 C 區。

# 100 — 墓碑、鐘、旅人的床：A7 剩下三格字串已知的 case

`docs/re/65` §3 對 case 5／12／13 只抄了字串：

| case | 字串 | 當時的判讀 |
|---|---|---|
| 5 | `The tombstones` / `shift before you` | 「墓碑移動」|
| 12 | `Do you wish to ring the bell?` / `Nothing happens.` / `The sound of angels crying…` | 「鐘」|
| 13 | `Do you wish to sleep here?` / `She bids you farewell…` | 「NPC 過夜」|

三個判讀方向都對，但**字串完全沒說出機制**。讀完函式之後：
一座每次都重排的墓碑迷宮、一口只在夜裡有用的鐘、
一張唯一功能是把時鐘撥到入夜的床 —— 而後兩者是**同一條設計的兩端**。

---

## 0. 結論先講

| | |
|---|---|
| case 5 | **墓園重排**：從 `MAP3.MAP` 重讀 → 隨機把 30 格墓碑變成擋路石 → 三格強制留通 |
| case 12 | **鐘**：`hour >= 24` 才有效，開的是**大半張地圖外**的一道門 (21,59) |
| case 13 | **旅人的床**：`hour <= 24` 才問，睡完把時辰設成 **25** —— 不回血、不換日 |
| 兩者相扣 | 床把時間撥到入夜，鐘才敲得響。門檻是同一個 `0x18` ＝ 24，方向相反 |
| 順帶 | 這一對比較**佐證了 worklist C8**：時辰上限若是 23，鐘那條分支就是死碼 |

## 1. case 5 —— 墓園每次都重排（`25be:0989` ＝ `0x1a169`）

```
1a169  清文字框
1a16e  印 "The tombstones"
1a17b  印 "shift before you"
1a188  do { 122f:28d0(3, 0) } while (回傳 != 0)     ; ← 從 MAP3.MAP **重讀**
       n = 1
loop:
1a1a6  x = Roll(11) + 19                            ; Roll 是 1 起算 → 20..30
1a1b6  y = Roll(6)  + 56                            ;                → 57..62
1a1d7  if (map[y×64 + x] != 0x56) goto loop          ; 不是墓碑就重擲
1a1ee  map[y×64 + x] = 0x54                          ; 變成擋路石
1a1f2  n++;  if (n <= 30) goto loop                  ; ⇒ 成功 30 次

1a1fd  map[0xf1d] = 0x56       ; (29,60)
1a207  map[0xe58] = 0x56       ; (24,57)
1a211  map[0xf54] = 0x56       ; (20,61)
1a21b  重畫；return 2
```

`122f:28d0` ＝ `0x187c0` 就是 `docs/re/95` §3.9 那支存／載地圖的常式，
第二個參數 0 是載入。第一個參數是**寫死的 3**，不是「目前這張圖」。

### 1.1 方向與直覺相反：`0x56` 是可以走的

查可通行性表（`FILES.DAT` 偏移 `0x40`）：

| tile | raw | 擋路 |
|---|---|---|
| `0x56` | `0x06` | **否**（可以走）|
| `0x54` | `0xff` | **是** |
| `0x11` | `0xfe` | 否（事件格）|

所以這個事件是「**長出 30 塊擋路石**」，不是「移走 30 塊墓碑」。
先查表才敢寫，否則整段邏輯會反過來。

> 實跑的畫面直接印證了 `0x56` 是墓碑：那個圖塊就是一塊墓石
> （`workplace/dump/tomb/shift.png`）。

### 1.2 三格強制留通是「不會被當場封死」的保證

原版寫的是**線性索引**，換算 `index = y×64 + x`
（與壓牆那邊 `ES:[BX + SI + 0x10]` 同一套：緩衝區第 0 格就是 tile (0,0)，
**沒有 `MAP*.MAP` 檔頭那一個 byte**）：

| 索引 | 座標 | 對應的入口 | 方位 |
|---|---|---|---|
| `0xf1d` | (29,60) | (28,60) | 東邊一格 |
| `0xe58` | (24,57) | (24,58) | 北邊一格 |
| `0xf54` | (20,61) | (20,60) | 南邊一格 |

三格各對一個入口的**相鄰格**，而且三格都落在隨機範圍內 ——
所以寫回去的意義是：**不管亂數怎麼擲，踩進入口之後至少有一步可以走。**
順序也重要：**排在長石頭之後**，所以就算被挑中也會被蓋回來。

### 1.3 只改記憶體，不寫回檔案

與壓牆走廊（case 1／2）同一個路數。重排的第一步就是從檔案重讀，
上一次的迷宮因此消失 —— 要是寫回去，墓園會被第一次的隨機結果鎖死。

引擎的重讀走 `world.LoadByID` 的三段優先序（存檔目錄 → 原版資料目錄），
理由與 case 1 相同：玩家推開過的家具不該被這一步還原。

## 2. case 12 —— 鐘只在夜裡有用（`25be:0c5f` ＝ `0x1a43f`）

```
1a44f  印 "Do you wish to ring the bell?"
1a45c  ans = 1000:b566()                  ; 是非題
1a461  if (ans != 1) return 2
1a46e  if (party[+0x9f] >= 0x18) goto 開門  ; ← +0x9f ＝ **時辰**
1a480  印 "Nothing happens." ; return 2

開門:
1a499  印 "The sound of angels crying opens up from the heavens
        and then everything is silent again"
1a4aa  map[0xed5] = 0x39                   ; ← (21,59)：0x3a（擋）→ 0x39（通）
1a4b0  重畫；return 2
```

`+0x9f` 就是 `save.go` 的 `hourOffset`。`JNC` 是無符號 `>=`，門檻 24。

`0xed5 = 3797 = 59×64 + 21` → **(21,59)，同一張地圖 1**。
鐘在 (26,8)，門在 (21,59) —— **隔了大半張地圖**。玩家看不到門打開，
只會聽到那句天使的哭聲。

實機確認過那道門本來是擋著的：從 (21,62) 往北走三步，
第三步停在 (21,60) 並印「前方無法通行」。

### 2.1 `1SS.DAT` 有一筆重複記錄

地圖 1 的類別 5 清單裡 **(26,8) 出現兩次**（偏移 150 與 156，attr 都是 `0xac`）。
查表取第一筆，所以第二筆是死資料。

而地圖上 `0x11` 其實有兩格：(26,8) 與 (27,8)。(27,8) 有自己的記錄，
是**類別 2**（偏移 147）—— 所以那不是「重複記錄該指向 (27,8) 才對」，
兩格本來就是不同的東西。**重複就只是重複。**

## 3. case 13 —— 旅人的床只負責撥時鐘（`25be:0cd8` ＝ `0x1a4b8`）

```
1a4bc  if (party[+0x9f] > 0x18) return 2        ; 太晚了 → **連問都不問**
1a4d7  印 "Do you wish to sleep here?"
1a4e8  ans = 1000:b566()
1a4ed  if (ans == 0) { 印 "She bids you farewell and adds
                          'May the Ancients protect you...'"; return 2 }
1a505  印 "You sleep"
       for i := 0; i < 3; i++ { 等一下; 印 "." }   ; "You sleep..."
1a542  party[+0x9f] = 0x19                       ; ← 時辰 ＝ 25
1a548  return 2
```

**只有那一行 `= 25`。** 不回血、不回法力、不換日、不清步數 ——
與紮營睡覺（`Clock.WakeAt`：擲 `Roll(6)` 落在清晨、日 +1、回復）
是**兩套完全不同的機制**，不要合併。

`JBE` 是無符號 `<=`，所以剛好 24 時的話「既能睡也能敲」——
兩個門檻都含等於，照抄，不要挑一邊改成嚴格不等。

## 4. 兩個 case 拼起來是一條設計

| | 條件 | 效果 |
|---|---|---|
| 床（地圖 4 的 (21,57)）| `hour <= 24` | 時辰 → 25 |
| 鐘（地圖 1 的 (26,8)）| `hour >= 24` | 遠處那道門開 |

白天找那位旅人睡一覺 → 時間跳到入夜 → 這時鐘才敲得響。
兩者在不同地圖，但時辰不會因為換地圖重設，而時辰 25 之後還有
25→37 共十幾個時辰可以趕路（每 10 步一個時辰）。

### 4.1 順帶佐證 worklist C8：一天真的不只 23 小時

C8 記著「時間 wrap 值 `38/35/23` 對不上手冊的一天 26 小時，
疑似當年把十六進位當十進位讀」。

這一輪多一個**程式碼自己給的證據**：時辰上限如果是 23，
`hour >= 24` 這條分支永遠到不了，那句「天使的哭聲」就是死碼，
而且 case 13 把時辰設成 25 也會立刻變成非法值。
`hourWrap = 38`（時辰 1–37）才講得通。

> 這不是「證明 26 小時是錯的」，只是把「上限 ≥ 25」釘了下來。
> C8 真正的疑問（38 還是 26）仍然開著。

## 5. 實機驗收

| 場景 | 軌跡 |
|---|---|
| 墓園（地圖 3，從 (18,60) 往東踩 (20,60)）| 「墓園：重排，長出 30 塊擋路石」→ 訊息「墓碑在你面前挪動了起來」|
| 留通格（三個不同 `-seed`）| 重排後往南走 → **三次都走得進 (20,61)** |
| 再踩一次入口 | 又重排一次（先從檔案重讀，所以不會累積）|
| 鐘 `-hour=13` | 「什麼事都沒發生。」|
| 鐘 `-hour=25` | 「(21,59) 的門開了」＋ 天使的哭聲 |
| 門的對照組 `-hour=25` 但沒敲鐘 | 從 (21,62) 往北，第三步「前方無法通行」|
| 床 `-hour=13` 按 Y | 「睡到 25 時」，狀態列 **25 時 17 日**（日期沒動）|
| 床 `-hour=13` 按 N | 「她向你道別…」|
| 床 `-hour=30` | **連問都不問**（「已經太晚了」）|

## 6. 對 worklist 的影響

- **A7 只剩 case 6／7／8／9**。那四個連字串都還沒讀（6 與 9 各 8 bytes
  是轉呼叫），而它們是送道具跳表 param 5／6 的呼叫端（`docs/re/99` §2）。
- 是非題那一頁抽成 `confirmScreen`（`cmd/demonwinter/confirmui.go`），
  case 12／13 共用 —— 原版也共用同一支 `1000:b566`。
- **C8 補一條證據**（§4.1）：時辰上限 ≥ 25。

# 104 — A8 的題目本身是錯的：一次性與否寫在類別編號裡

worklist 的 A8 寫成一件分類工作：

> `nSS.DAT` 的 `Consume`／`Advance` —— 判定哪些事件是一次性的。
> 這是**分類工作不是實作工作**，兩支常式都現成。

實際上五個檔案 105 筆類別 1／2 記錄**一筆都不用判**。
一次性與否是**類別編號本身**，而引擎缺的是一道觸發閘門，不是一張分類表。

---

## 0. 結論先講

| | |
|---|---|
| 類別 1 | **一次性**。值 0 時自動播一次，`MarkVisited` 之後值變 1，從此完全沒有反應 |
| 類別 2 | **可重讀**。同樣自動播一次；之後站上去會武裝「重讀」，按 `R` 可以再看 |
| 閘門位置 | `FUN_222f_0a90`（`docs/re/05` §1.5 早就完整反編譯了，只是沒人讀出這一層）|
| 重讀倒數 | `ds:0x4e2e`，值 0／1／2 |
| `R` 是什麼 | 主選單第 13 項 `R) Read descr.`，移動迴圈 switch case 6（`222f:1282`）|
| 寫回動作 | 類別 1／2 **都是 `MarkVisited`**，兩者都不會 `Consume` |
| `Consume` 的四處 | 戰鬥結算兩處、陷阱解除一處、`25be:06fc` 一處 —— 都不在事件文字這條路上 |

---

## 1. 閘門

```c
// FUN_222f_0a90
0x52f4/0x52f6 ← 玩家座標
FUN_222f_1321()                      // 掃 nSS.DAT，命中就填 0x5c62=類別、0x52f6=值
local_4 = 0xfffd;                    // 預設：無事件
if (0x5c62 != 0 && (0x5c62 != 1 || 0x52f6 == 0)) {
    if (0x4e2e == 2)      { 0x4e2e--; local_4 = 0x12; }        // 重讀
    else if (0x5c62 == 2 && 0x52f6 != 0) { 0x4e2e = 1; }       // 武裝
    else if (0x5c62 == 4) { 傳送; local_4 = 0xffff; }
    else                  { local_4 = 0x12; }                  // 一般觸發
}
```

三處合起來才看得懂：

| 位置 | 做的事 |
|---|---|
| `222f:0c0c` | 移動迴圈每一次指令：`0x4e2e == 1` 就減一 |
| `222f:0c17` | 接著查腳下這一格，命中 tile 值就呼叫上面那支 |
| `222f:1282` | `R) Read descr.`：`0x4e2e != 1` 直接回無事件；否則設成 2 再查一次 |

所以：

- **類別 1**：進入條件是「值 == 0」。第一次踩到播完 → `MarkVisited` → 值 1 →
  之後連 if 都進不去。**倒數從沒被武裝過，`R` 也讀不回來。**
- **類別 2**：值 1 之後不自動播，改成把倒數設成 1。玩家按 `R` → 倒數 2 →
  下一次查表第一條就中，`0x12` 觸發。讀完倒數減回 1，可以連按。

## 2. 為什麼可以確定「類別 2 真的會被標記」

`25be:0e23` 那處 `MarkVisited` 前面有 `cmp ds:0x5c62,1`，只吃類別 1；
另一處 `25be:11c9` 沒有類別檢查。光讀指令會懷疑類別 2 到底會不會被標記 ——
如果不會，值就永遠是 0，那條「值 != 0」的分支就是死碼。

**出貨資料把這個問題關掉了。** `nSS.DAT` 是存檔，而出貨的那一份是
壓片前有人玩過一段的狀態（`docs/re/78` §2）：

| 檔案 | 已造訪的類別 1 | 已造訪的類別 2 |
|---|---|---|
| `1SS.DAT` | 7 | **9** |
| `2SS.DAT` | 5 | **3** |
| `3SS.DAT` | 0 | 0 |
| `4SS.DAT` | 0 | 0 |
| `5SS.DAT` | 0 | 0 |

那位 1988 年的玩家只走過地圖 1 與 2，而他在**類別 2 的格子上留下了 12 個
值 1**。分支不是死的。釘在 `TestShippedDataHasVisitedClassTwo`。

> 順帶解開一個沒人問過的差異：遊戲載入的是 `ALL_SS.DAT`（母本，
> **35 筆類別 1／2 的值全是 0**），`nSS.DAT` 才是那份玩過的存檔。
> 兩者並存不是重複，是「母本 vs 存檔」。

## 3. 原版截圖裡的第三個證據

`workplace/dosbox/shots/03-ega-ingame.png`：主選單那 14 項裡，
**`Read descr.` 被畫成網點**（其餘項目是實心紅底）。那一格就是
`0x4e2e != 1` 的視覺呈現 —— 沒有東西可重讀時，選項本身是灰的。

反組譯、出貨資料、原版畫面三邊一致。

## 4. 引擎這一側原本缺什麼

`checkEvent` 的 `TriggerLookup` 分支查到記錄就直接播、播完 `MarkVisited`，
**沒有任何一處看「值」**。後果：

- 類別 1 的一次性事件每次踩過都重播一次
- 類別 2 的重讀機制整個不存在，`R` 鍵也沒有

補上 `internal/game/eventgate.go`（純規則）＋ `cmd/demonwinter/readdescr.go`
（`R` 與武裝）。有一處刻意的偏差寫在程式裡：原版**每一次指令**都會重查
腳下這一格，本專案的事件檢查只掛在「走成功」那一條，所以另外補一支
`armReread`，撞牆或走出子地圖時只跑閘門的武裝分支、永遠不觸發事件。

順帶修掉一個一直存在的錯：`a.lastTile` 原本存 `Walk` 的回傳值，
**撞牆時那是擋路的那一格**，不是腳下這一格 —— 狀態列的「地形」會印錯，
`R` 也會查錯格子。改成 `World.TileUnder`。

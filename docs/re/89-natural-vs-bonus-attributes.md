# 89 — `+0xe8`／`+0xe9` 不是未解欄位，是天生屬性（並更正 `docs/re/88` §3）

`docs/re/88` §3 把建角程式的兩處欄位複製標成「語意未解」：

> `[+0xe8] = [+0xf8]`、`[+0xe9] = [+0xfb]` ——
> 四個位移在 `save.go` 都不在已命名的清單裡。……**不命名、不猜**。

**那句話錯了。四個都早就命名過。**

---

## 1. 為什麼 grep 找不到

`save.go` 的屬性位移全部是**相對於 `expOffset`（`0xc4`）**的：

```go
attrStrengthNaturalOffset = 0x24
attrSkillNaturalOffset    = 0x25
attrMaxSPNaturalOffset    = 0x26
attrSpeedBonusOffset      = 0x33
attrStrengthBonusOffset   = 0x34
attrSkillBonusOffset      = 0x37
```

所以 `0xe8` 這個數字**在整份 `save.go` 裡一次都沒出現過** ——
它是 `0xc4 + 0x24` 算出來的。我拿 `0xe8` 去 grep，理所當然落空，
然後把「grep 不到」讀成「沒人命名過」。

| 記錄位移 | 算式 | 欄位 |
|---|---|---|
| `+0xe8` | `0xc4 + 0x24` | **力量（天生）** |
| `+0xe9` | `0xc4 + 0x25` | **技巧（天生）** |
| `+0xea` | `0xc4 + 0x26` | 法力上限（天生）|
| `+0xf3` | `0xc4 + 0x2f` | 速度（天生）|
| `+0xf8` | `0xc4 + 0x34` | **力量（含裝備加成）** |
| `+0xfb` | `0xc4 + 0x37` | **技巧（含裝備加成）** |

> 這是**同一種錯的第三次**（前兩次：`tools/route.py` 的地圖檔頭偏移、
> Python 那邊的道具槽步長 16 vs 17）。三次的形狀一樣：
> **在別的地方重算一次布局，然後相信自己算的。**
> 而這一次更糟 —— 我不是算錯，是**拿字面值去搜一個算出來的值**，
> 落空之後下了「未解」的結論。
>
> `rulebook/62` 的第一條就是「**搜尋落空 ≠ 不存在**」。踩到了。

## 2. 那兩處複製在做什麼

建角（`0x14d95`–`0x14db4`）：

```
力量(天生) ← 力量(含加成)
技巧(天生) ← 技巧(含加成)
```

擲點的結果先落在「含加成」那一組，建角再把它抄回「天生」——
新角色身上沒有裝備，兩組本來就該相等。

反方向也存在（`0x057e2`、`0x06137`）：

```
力量(含加成) ← 力量(天生)
技巧(含加成) ← 技巧(天生)
```

那是「重算含加成值」的起點（先歸零成天生值，再疊裝備效果）。

還有 `0x1f6b7`／`0x1f6ca`／`0x1f6dd`：`inc +0xf7`／`+0xf8`／`+0xfb` ——
一個 switch 各自 `inc` 一個「含加成」欄位，形狀像**升級時加屬性點**。
（`+0xf7` ＝ `0xc4 + 0x33` ＝ 速度（含加成）的前一格，未逐一確認，先不斷言。）

## 3. 順著這條線抓到的 bug：存檔裡的角色會換人

引擎的規則層只用**天生值**（`game.Character.Traits`），裝備效果在使用時
現算（`ArmorRating`、武器骰）。所以「含加成」那四個 byte
**規則層從來不讀**。

問題是 `ApplyTo` 也**從來不寫**它們 —— 於是它們留著載入時的舊值。
對從存檔載入的角色來說，那是它自己的值，沒事。
**對新建的角色來說，那是出貨存檔那五個人的值。**

拿 `-newgame` 建好五個角色、存檔、逐位元組看：

```
角色0: 天生(力,技,速)=(10, 8,13)   含加成=(13,13,12)   ← 13/13/12 是出貨角色 0 的數字
角色1: 天生(力,技,速)=( 3, 7, 8)   含加成=(12,13,15)   ← 出貨角色 1 的
```

名冊上顯示的是自己擲的點（規則層用天生值），**存檔裡的另一半是別人的**。
重讀存檔之後，任何讀「含加成」欄位的地方就換人了 ——
而畫面上完全看不出來。

> 這是 `-newgame` 抓到的第二個「只有真的開新遊戲才會暴露」的 bug
>（第一個是十把匕首，`docs/playtest/07`）。共同點：
> **從存檔載入的路徑上，每個 byte 都是有效資料，所以缺口不會顯現。**

### 修法

`game.Character` 補一組 `TraitsWithBonus`（力量／技巧／速度／法力上限），
`FromSave` 讀、`ApplyTo` 寫 —— 讓那句註解自己要求的對稱成立：

> FromSave 多讀一個欄位，這裡就要多寫一個，否則那個欄位會在存檔時悄悄退回舊值。

`Finish()` 把它同步成天生值（新角色沒裝備，就是原版 `0x14d95` 做的事）。

**沒有動一般的遊玩路徑**：引擎不模擬「裝備加屬性」，
所以對已載入的角色照舊保留原值，不拿天生值去蓋掉它 ——
那會把存檔裡真有的裝備加成靜靜丟掉。

驗過：五個新角色的天生與含加成三欄全部一致，
非巫師的天生法力上限是 0（`initialSP` 只有巫師非 0）。

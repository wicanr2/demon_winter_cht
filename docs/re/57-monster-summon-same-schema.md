# 57 — 怪物表與召喚表是同一套 schema

`docs/re/56` 讀出了戰鬥金幣的式子，卻卡在輸入欄位：

```
金幣 += 1.7^X + Roll(2.1^X) + 3      X = 單位[+0x1a]
```

`docs/re/20` §214 說 `unit+0x1a` 是**附魔加成**。拿它當金幣的指數講不通 ——
玩家武器沒附魔就是 0，算出來每隻 5 金。當時列了三個可能，沒有證據裁決。

這一篇把它解掉了，順帶推翻四處判讀。

---

## 1. 先排除兩個可能

**「迴圈邊界不是怪物數」——`docs/re/02` 早就寫了。** `party+0xa6` 是
`MONSTER.DAT` 索引陣列（`+0x16`）的長度，兩個完全獨立的函式
（`FUN_25be_0e77` 與 `FUN_17c5_000d`）用同一組 offset 扮演同一角色。
`docs/re/16` §150 也這樣用。**又是一次「先查手上已有的」該省下的功夫。**

**「迴圈索引的是怪物 ID 陣列」——不是。** `0xe2d0` 的位址算式是
`i×8 + i` → `×2` → `+i` → `×2`＝**`i×38`**，加 `0x4ece`。
stride 38、base `0x4eb4` 是戰鬥單位陣列（`docs/re/20`），不會錯。

所以剩下的只有一種：**怪物在 `+0x1a` 放的不是附魔。**

---

## 2. 掃寫入點，掃出一個空洞

`ds:0x4ece` 全檔 9 處，只有兩處是寫：

| 位址 | 誰 | 寫什麼 |
|---|---|---|
| `0xab21` | 召喚生物 | `ds:0x51d4` 表的第 8 個 word |
| `0xc345` | 玩家角色 | 裝備 slot（17 bytes/格）的 `+0x1a` **−10** |

**怪物建立段（`0xc060`–`0xc1b2`，`+0x20` 寫立即數 1 ＝ 怪物陣營）
根本沒有寫 `+0x1a`。** 而且 `ds:0x4ed8`（`unit+0x24`，擊殺經驗值）
**全檔只出現一次，還是個讀**（`0xc182`）。

怪物的速度、力量、技巧、HP、SP、經驗值、level 全都不是在主段填的 ——
搬移那一段還沒找到（見 §6）。但要判 `+0x1a` 的語意，不必先找到它。

## 3. 兩張表同構：96 個數值零誤差

`docs/re/20` §2 的召喚生物表是 12 筆 × 11 個 signed word。
`docs/formats/game-data-tables.md` §2 的 `MONSTER.DAT` 是 99 筆 × 11 個數值欄位。

**同樣是 11 欄。而且 12 隻召喚生物在 `MONSTER.DAT` 裡都有同名怪物。**

**八個欄位（速度、力量、技巧、HP、攻擊型別、w5、w6、w8）逐筆完全相同 ——
96 個數值零誤差。** 這種吻合不可能是巧合：兩張表用的是同一套欄位定義。

不同的三欄也講得通：

- **第 8 欄**：怪物是擊殺經驗值，召喚版存的是另一個數（在召喚流程被讀成成本，
  但實際上是死欄位，見 §4）
- **SP**：召喚版一律**低於**怪物版（火元素 28 vs 50）—— 召喚出來的是弱化版
- **特殊**：只有冰元素不同（4 vs 7）

### 結論

**`unit+0x1a` 對怪物 = `MONSTER.DAT` 的 level（1–10）。**

金幣的量級隨之落定：

| level | `1.7^lv` | `Roll(2.1^lv)` | 一隻的金幣 |
|---|---|---|---|
| 1 | 1 | 1–2 | **5–6** |
| 5 | 14 | 1–40 | **18–57** |
| 10 | 201 | 1–1667 | **205–1871** |

這對 1988 年的 CRPG 完全合理，而「每隻固定 5 金」不合理。

## 4. 推翻的四處判讀

### 4.1 `MONSTER.DAT` 第 7 欄不是「每回合攻擊次數」，是**護甲點數**

原本的依據是「戰士序列 `1,2,3,4,4,4,5,6,6` 隨等級遞增」——
但護甲隨等級變好同樣遞增，這條依據分不出兩者。

同構表指出它對應召喚表的 w6，而 w6 **搬進 `unit+0x0a`**（`0xaae7`）。
`unit+0x0a` 的用途有兩個直接證據：

```
ds:0x0b15 = 'Armor: %3d pts.'      ← 0xcb04 push [bx+0x4ebe] 進去印
0x9f4d     sub [bp-0x10],ax        ← 從命中值裡減掉
```

**印出來就叫 Armor。** 攻擊次數不會被拿去做減法，也不會印成 pts.。

### 4.2 `unit+0x0a` 不是「護甲索引」，是**護甲點數**

`docs/re/20` §214 寫「護甲索引，來源＝角色 `+0x101`」。
玩家建立段（`0xc43e`–`0xc468`）會把槽位索引換算成點數再寫回 `unit+0x0a`，
`%3d pts.` 也說明它是點數不是索引。

> ⚠ **本節原本的機制描述是誤讀，已訂正。** 原文寫「**逐件裝備累加**：
> 檢查 `+0xe6` 旗標，成立就 `[bp-0x2] += 2`」——那個檢查**只跑一次、
> 不在任何迴圈裡**（角色只有一件護甲），而 `+0xe6` 是**技能旗標第 30 格**
> （`0xc8 + 30`，硬化皮膚），不是裝備旗標。真正的算式是
> `表[型別 − 7] + 附魔`，再視硬化皮膚 `+2`；表在 `31f0:16c5`。
> 見 `docs/re/103` §2 與 §4。

### 4.3 召喚表 w5 不是「未解的遭遇型別清單」，是 **sprite index**

`docs/re/20` §7 把 w5 列為未解（只知道它寫進全域 `ds:0x5210`）。
同構表顯示它 = `MONSTER.DAT` 的 `sprite_index`，而那一欄是**已驗證**的
（同種系怪物共用同一個值）。逐筆對照直接看得出來：
棕熊 7 ＝ 熊系 sprite 7、幼龍 27 ＝ 龍系 sprite 27。

`ds:0x5210` 的身分也跟著解開：那是**槽位 → sprite 的對照陣列**。
召喚寫第 0 格（`0xaac1`），怪物建立段逐槽寫（`0xbd1f`），
畫圖時逐槽讀（`0xb9ce`、`0xba03`）。

### 4.4 召喚表 w7 不是「成本欄位」，是**經驗值欄位**

`docs/re/20` §2 標它「實務上是死欄位」——**方向對，理由錯**。
它不是「為召喚設計卻沒用到的成本」，它是**經驗值欄位**，
只是召喚生物不會給玩家經驗，所以在召喚流程裡沒有讀取端。

對怪物它就是 `unit+0x24`（`docs/re/56` 的總經驗來源）。

`tools/screenshot.sh workplace/dump/persist/73-battle-gold.png KEYS=Return -battle -battle-win`

## 7. 本專案的實作範圍

`internal/game/loot.go`：`BattleGold`、`intPow`（`1990:0a83` 的整數次方，
`LootPriceCap` 也改用同一支）。
`cmd/demonwinter/battleui.go`：`awardGold`，勝利結算接在經驗之後。

金幣進隊伍錢包（存檔 `+0x0a`，4 bytes）—— 那個 offset 本專案早就解出來了
（`save.go` 的 `goldOffset = 0x0a`），與 `0xe380` 的 `add es:[bx+0xa],ax`
完全對上，封頂也同樣是 `0x00FFFFFF`。

測試釘住：各等級的區間、逐隻累加而非取平均、沒有怪物就沒有金幣、
以及**等級越高金幣越多**（讀錯欄位就會失去單調性）。

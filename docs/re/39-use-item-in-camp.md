# 39 — 在營地用道具（紮營選單 Use）

`1000:2262`。這一篇有兩個收穫：**點火把的機制**（`docs/re/26` §5 記的缺口），
以及**訂正一條「沒實作」的假記錄**。

---

## 1. 兩條完全不同的路

```
選人（重問直到狀態 <= 1）；取消 → 回 3
組字串「名字:」並印
畫道具清單，印 ds:0x3ce "Use item:"
迴圈 {
  slot = 選格；10 → 回 3
  base = 角色 + slot×0x11        ; 槽本身從 base+0x0c 開始
  if 槽型別 == 0x1a 或 0x1b → 跳出迴圈（走光源那條）
  if 槽型別 < 0xfe 且 [base+0x14] != 0 且 [base+0x11] != [base+0x12] {
      載入效果 [base+0x13]
      [0x4cc8] = 道具名稱指標
      cast = FUN_1000_11e5(誰, [base+0x14], [base+0x13], 1)
      回 (cast == 1) ? 0 : 3
  }
  否則重問
}
; 光源那條：
槽型別 = 0xff                     ; 用掉即消失
party[+0xa7] = (型別 == 0x1b) ? 3 : 2
印 ds:0x3d8 "Done!"
```

---

## 2. 收穫一：點火把

**型別 26 是火把、27 是提燈**（`ITEMS.DAT` 的型別名表第 26、27 項就是
`torch` 與 `lantern`）。用掉就消失，並把 `party+0xa7`（光源等級）
設成 **2（火把）／ 3（提燈）**。提燈亮一級。

`docs/re/26` §5 記過一句：「本專案還沒有點火把／照明術這些會改動光源的機制，
所以整場維持初值」。**機制就在這裡。** 紮營會把光源重設成 1（`2aed:040c`），
點一支火把回到 2，提燈 3 —— 三個數字湊成一組完整的光源循環。

---

## 3. 收穫二：訂正「兩條沒實作的過濾條件」

`internal/game/item.go` 原本寫著：

> 原版還有兩條過濾條件沒有實作：`usable_flag == 0` 與「兩個充能欄位相等」。
> 那兩個欄位在 17 bytes 的存檔槽裡沒有定位到（反組譯的 `0x11`/`0x12`
> 超出槽長，應該是載入後的記憶體結構）。

**錯了。** `+0x11`／`+0x12` 是相對**角色記錄 + 槽×17** 算的，
而槽本身從 `+0x0c` 才開始 —— 減掉 `0x0c` 就是 `+0x05`／`+0x06`，
也就是次數上限與已用次數。同理 `+0x13` = `+0x07`（效果）、
`+0x14` = `+0x08`（強度）。

這一段把四個欄位並排寫出來，一看就清楚。所謂「沒實作的兩條」其實是
**`強度 != 0`** 與 **`上限 != 已用`** —— `InventorySlot.Usable()` 早就實作了。

> **教訓**：位移是相對誰算的，要跟著它的基底走。少了那一步，
> 一個已經解出來的欄位會被誤判成「還沒定位到的記憶體結構」，
> 然後在文件裡留一條永遠不會有人去查的假缺口。
> 這是 `rulebook/63`「不要相信過時的標記」的另一面：**標記寫下的當下就可能是錯的。**

## 4. 本專案的實作範圍

`internal/game/useitem.go`：`ItemTypeTorch`／`ItemTypeLantern`／
`LightSourceLevel`／`CanUseInCamp`／`UseInCamp`。
`cmd/demonwinter`：紮營選單按 `U`。

**只走得通光源那一條。** 有效果的道具要走施法路徑，而本專案的施法目前
離不開 `Battle`（`applySpell` 需要戰場）—— 那條路要等「戰鬥外施法」做出來。
選單上照實標：光源標「點起來，光源 N」、有效果的標「戰鬥中才能用」、
平凡裝備標「用不了」。

實機驗收（`workplace/dump/persist/54-camp-use.png`，`-give-item 26,0,0,0`）：
清單上火把標「（點起來，光源 2）」，其餘三件標「（用不了）」；
按下去之後訊息是「Wopple 點起了火把（光源 2）」，那一格清空。

**沒解的部分**：`FUN_1000_11e5` 的第四個參數（Use 傳 1、Worship 傳 3）是什麼。

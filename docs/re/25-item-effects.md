# 25 — 道具效果：索引欄位與生成表

解掉 `CONTEXT.md` 掛著的「**道具效果索引欄位未定位**（選了不會有效果）」。

位址換算沿用 `docs/re/00`。

## 1. 效果索引就在道具槽裡

道具槽是 17 bytes，起點在角色記錄 `+0x0c`
（`17c5:1956` 的 `ADD AX,0xc`，配合 `17c5:1944` 的 `SHL AX,4 / ADD AX,DX` ＝ ×17）。

使用道具的主體是 `FUN_17c5_18ab`。過濾與取值都在同一段：

```
17c5:1969  LES BX,[BP-0x26]                     ; 道具槽指標
17c5:196c  AL = ES:[BX]      / CMP AX,0xfe / JGE 跳過   ; 空槽
17c5:1976  CMP byte ES:[BX+0x8],0x0 / JZ  跳過          ; ★ 強度 0 → 不可用
17c5:197d  AL = ES:[BX+0x5]
17c5:1981  CMP AL,ES:[BX+0x6]       / JZ  跳過          ; ★ 次數用完 → 不可用
...
17c5:19dd  AL = ES:[BX+0x7]  → 效果索引
17c5:19e6  AL = ES:[BX+0x8]  → 效果強度
17c5:19ef  PUSH 效果索引 / CALLF 0x1000:114f
```

兩處「跳過」都跳到 `17c5:19cc`，那裡 `JMP` 回選單迴圈頭 `17c5:1913` 重選。

補進道具槽佈局：

| 位移 | 內容 |
|---|---|
| `+0x00` | 道具型別＝`ITEMS.DAT` 索引，`0xFF` 空槽 |
| `+0x05` | 已用次數 |
| `+0x06` | 總次數（與 `+0x05` 相等＝用完）|
| `+0x07` | **效果索引** |
| `+0x08` | **效果強度**，同時當「可不可用」旗標 |
| `+0x09`–`+0x0c` | 武器特效 A／B 與各自的條件旗標（既有結論）|
| `+0x0e` | 附魔加成（+10 偏移）|
| `+0x10` | 已鑑定旗標 |

## 2. 道具與法術共用同一張效果表

`FUN_1000_114f` 就是法術用的那個載入函式（`docs/re/09` §4.1）：

```
1000:1156  AX = 索引 ×2
1000:115e  AX ×= 4                     → 索引×8
1000:116a  [0x4cc8] = 遠指標 [0x4ccc + 索引×8]      ; 訊息字串 A
1000:1182  [0x4e24] = 遠指標 [0x4ccc + 索引×8 + 4]  ; 訊息字串 B
1000:11a6  LES BX,[0x4e28]                          ; 效果記錄表
1000:11aa  [0x4e2c] = ES:[BX + 索引×10 + 0]
1000:11ba  [0x4e2e] = ES:[BX + 索引×10 + 2]
1000:11ca  [0x4e30] = ES:[BX + 索引×10 + 4]
           [0x4e32] = … + 6
```

**一張表、一個載入函式、一個索引空間** —— 所以道具的 `+0x07` 與法術 id 是
同一個東西。`+0x07 = 7` 就等於施放 7 號法術（STRENGTH）的效果，強度用 `+0x08`
取代「投入多少法力」。

順帶記下：每個索引還帶**兩個遠字串指標**（`0x4ccc + 索引×8` 與 `+4`）。
那是效果的兩句訊息（施放時／命中時），本作目前用法術名稱代替，還沒接上。

### 原版起始存檔一件可用道具都沒有

dump 過 `PARTY.DAT`：五名角色全部 10 格的 `+0x05`–`+0x08` 都是 0。
照上面的規則，**原版開局按 Use 是空選單**，要拿到有效果的道具才選得到東西。

> ⚠ 本專案原本有一條測試斷言「真實存檔至少列得出一件，否則過濾規則太嚴」。
> **那個預期是錯的**，它釘住的是還沒解出 `+0x08` 時的不完整規則。已改成反向斷言。

## 3. 效果是掉寶時生成的（`ITEMS.DAT` 四個未解欄位的答案）

`ITEMS.DAT` 每筆有四個一直標「語意未確認」的數字（`Unknown1`–`4`，
Python 參考實作叫 `f3`–`f6`），值域 0–17，而且**同一大類內部完全相同**
（武器全是 `0,10,8,9`、護甲全是 `12,7,7,7`）。

生成端在 `FUN_1990_????`（`1990:1390`–`1990:149e`）：

```
1990:1390ish  把那四個欄位讀進 SS:[BP-0x1a]、[BP-0x18]、[BP-0x16]、[BP-0x14]
1990:13ab     強度 = rnd(等級×2) + 2                → 寫進 +0x08
1990:13bc     if 第一個欄位 == 0 → 0x13e3
1990:13c2       否則：類別 = rnd(17)，與另外三個欄位比對、重複就重擲
1990:13e3     從四個欄位裡隨機挑一個 → 類別
1990:13fa     類別 −= 1
1990:13fd     BX = 類別 × 6
1990:140a     count  = [BX + 0x1941]
1990:1411     rnd(count)
1990:142a     效果索引 = [類別×6 + rnd(count) + 0x1941]
1990:1491     寫進 +0x07
```

也就是**兩層擲點**：先決定「效果類別」，再從該類別的候選裡挑一個效果索引。

`DS:0x1941`（檔位移 `0x27441`）是 17 列 × 6 bytes 的候選表，
格式 `[候選數, e1 … e5]`：

| 類別 | 候選效果索引 |
|---|---|
| 0 | 2, 10, 14 |
| 1 | 1, 6, 19 |
| 2 | 12, 15, 21 |
| 3 | 7, 20 |
| 4 | 0, 4, 31, 32 |
| 5 | 13, 16 |
| 6 | 3, 8, 9, 18, 22 |
| 7 | 37 |
| 8 | 33, 39 |
| 9 | 30, 29, 28 |
| 10 | 5, 11, 17 |
| 11 | 35, 36 |
| 12 | 34, 41 |
| 13 | 40, 23 |
| 14 | 24, 25 |
| 15 | 26 |
| 16 | 27 |

效果索引值域 0–41，**正好落在法術表的 0–42 之內** —— 又一次印證 §2 的
「同一個索引空間」。第 17 列開始就是字串資料（`Use the arrow keys!`
一類），所以表就是 17 列，不多不少。

### ~~還沒釐清的一角~~ → 已解，見 `docs/re/30`

本節原本寫「第一個欄位為 0 時走『從四個欄位挑一個』那條路……挑到 0 減 1
會得到 −1，索引到表外」。**分支方向讀反了**：`13c0` 是 `jne`，
**不等於 0 才**走「挑一個」。

正確的規則是兩種用法：`f[0] != 0` 時四個是**候選清單**、
`f[0] == 0` 時另外三個是**排除清單**（`rnd(17)` 撞到就重擲）。
兩條路都保證非零，減一之後永遠落在 0–16。

掉寶生成已完整解出並實作（附魔、兩道效果門檻、強度與最低法力的配對重擲、
三種充能種類），見 `docs/re/30`。

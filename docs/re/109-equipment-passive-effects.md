# 裝備常駐效果：`+09/+0A` 與 `+0B/+0C`

> 狀態：**已證實並接入 remake**（2026-07-29）。
> Oracle：`DEMON.INT` SHA-256 與其他逆向文件相同；IDA 9.4 listing
> `workplace/ida/DEMON.INT.asm`。
> 主要常式：`sub_11959`、`sub_11CBF`、`sub_18248`。

## 1. 結論

裝備槽的兩組欄位不是「0x15 才啟用下一 byte」的布林條件：

| 槽位移 | 語意 |
|---|---|
| `+09/+0B` | 裝備常駐效果類型 A／B |
| `+0A/+0C` | 對應效果值，原始 byte = 實際增減量 + 10 |

已確認類型：

| 類型 | 作用 |
|---:|---|
| `11h` | 最大法力 |
| `12h` | 速度 |
| `13h` | 力量 |
| `14h` | 技巧 |
| `15h` | 武器戰鬥特效 |

`11h`–`14h` 修改角色的「含裝備加成」欄位；`15h` 不進該常式，
而是在建立戰鬥單位時寫入武器特效。低於 `11h` 的代碼會動技能旗標，
其中 6、7 經特殊映射後落在角色 `+EB/+EC`。

## 2. IDA 證據

### 2.1 換裝先還原天生值

`sub_11959` 在重新套用裝備前明確執行：

```text
+F7 <- +F3  速度（含加成 <- 天生）
+F8 <- +E8  力量（含加成 <- 天生）
+FB <- +E9  技巧（含加成 <- 天生）
+FE <- +EA  MaxSP（含加成 <- 天生）
```

接著對仍裝備的武器／護甲各呼叫一次 `sub_11CBF`。所以換武器不是把新值
疊在舊值上，而是從天生值重建兩件裝備的總效果。

### 2.2 `sub_11CBF` 的完整分派

該常式以步長 2 掃槽位移 `+09/+0A`、`+0B/+0C`：

1. 值 byte 為 0 就跳過。
2. 類型 `>=15h` 跳過。
3. `11h` 指向角色 `+FE`。
4. `12h` 指向 `+F7`。
5. `13h` 指向 `+F8`。
6. 其餘的 `14h` 指向 `+FB`。
7. 寫入 `目前值 + 原始值 - 10`，每一組效果後鉗在 `3..255`。

這不是依攻略猜名稱：四次 `cmp` 後各自建立目標欄位指標，消費端直接證明類型。

低代碼的指令映射也能逐條照錄：

| 原始類型 | `+C8` 後的索引 | 寫入位置 |
|---:|---:|---|
| 0–4 | 6–10 | 技能旗標 6–10 |
| 5 | `19h` | 技能旗標 25 |
| 6–7 | `23h`–`24h` | 角色 `+EB/+EC`（祈禱機率／束縛等級） |
| 8–`10h` | 原值 | 技能旗標 8–16 |

目標 byte 已是 1 時保留，否則寫 2。換裝入口先把 31 個技能旗標中原值為 2
的清成 0，再重套目前武器與護甲；`+EB/+EC` 不在這個清除迴圈內。remake
忠實實作這個不對稱，但沒有替低代碼猜測玩家可見名稱。

### 2.3 `15h` 的獨立消費端

`sub_18248` 建立玩家戰鬥單位時，已先取得裝備武器槽。由於角色 inventory
從 `+0C` 開始，指令讀取的角色偏移 `+15/+16`、`+17/+18` 正是槽內
`+09/+0A`、`+0B/+0C`：

```text
18753  cmp slot[+09], 15h
1875A  unit[+1C] = slot[+0A] - 10
1877C  cmp slot[+0B], 15h
18783  unit[+1C] = slot[+0C] - 10
```

因此 `15h` 是武器戰鬥效果類型，而不是所有效果共同的 enable flag。

## 3. 兵器庫的獨立資料錨點

加穆爾神殿兵器庫釘頭鎚的建立碼寫：

```text
slot[+09] = 12h
slot[+0A] = 0Ch
```

依上述消費端即為速度 `12 − 10 = +2`，精確吻合攻略的
「釘頭鎚，恆常：速度 +2」。這是執行檔的類型分派與攻略成品描述互相獨立的
交叉驗證，不再是 C13 原先只有一筆資料的推測。

## 4. Remake 實作

- `scenario.InventorySlot` 將舊名 `CondA/CondB` 改成
  `EffectTypeA/EffectTypeB`，原始值欄也明確命名。
- `Character.RecomputeEquipmentBonuses` 從天生值重建，再按武器、護甲及
  A/B 順序逐組套用和鉗制。
- 換裝、驅邪脫裝、消耗裝備與升級走同一重建入口；載入／存檔保留原版
  已持久化的有效值與旗標，避免合法但非典型存檔被讀寫邊界擅自正規化。
- `CombatUnit` 使用已維護的有效速度、力量、技巧與 MaxSP；`15h` 仍走既有
  `WeaponEffect` 傷害路徑。
- 低代碼依指令映射重建技能旗標 2；類型 6／7 精確落在
  `PrayChance/BindLevel`，且照原版不隨一般技能清除迴圈復原。
- 升級增加的是天生 MaxSP，重建後才重新套用裝備，避免換裝吃掉升級成果。

## 5. 驗證

- parser 測試：`15h` 兩組武器效果、`12h` 正負值合計。
- 規則測試：武器與護甲四種加成合併、換武器移除舊效果、負值、
  `CombatUnit` 使用有效值、存檔同時保留天生與含加成欄位。
- 兵器庫釘頭鎚測試：`12h/0Ch` 解析為速度 +2。
- 低代碼測試：0／5／6／7 的特殊映射、已學技能不覆寫、換裝重建。
- `go test ./internal/assets/scenario ./internal/game`：通過。

## 6. 保留的語意未知

錨點；尤其類型 6／7 為何把 `+EB/+EC` 設成 2，不從欄位名稱反推設計意圖。
未知的是名稱與目的，不是 runtime 行為。

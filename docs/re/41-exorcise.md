# 41 — 驅邪（紮營選單 Xorcise）

**這不是戰鬥裡的「驅散不死」。** 名字很像，做的事完全不同：
Xorcise 是**把身上被詛咒的裝備弄下來**。

`1000:1959`。這一篇的收穫比選項本身大 —— 它順帶說清楚了**詛咒到底做了什麼**，
還替四對屬性欄位做了第二次獨立確認。

---

## 1. 流程

```
選施術者；狀態 >= 2 → 訊息，重問
技能 15（薩滿）與 16（司祭）都沒有 → 「你不會」
char[+0xf2] != 0 → 「今天做過了」
選對象（FUN_1000_053c(1)，模式 1）
畫對象的道具清單，印「名字:」+ ds:0x32c "Exorsize item:"
選一格；10 → 離開
  ★ 重問直到那一格 == 對象的護甲槽(+0x101) 或 武器槽(+0x100)
施術者[+0xf2] = 1                       ; 擲骰之前先記帳
rnd(100) > 槽[+0x0d] → "Fails"
否則 "Success!"：
  for i in 0..30: if char[+0xc8+i] == 2 → 設 0
  char[+0xf7] = char[+0xf3]
  char[+0xf8] = char[+0xe8]
  char[+0xfb] = char[+0xe9]
  char[+0xfe] = char[+0xea]
  武器槽 == 這一格 → 武器槽 = 0xff，另一件若在則 FUN_1000_1cbf(對象, 護甲槽)
  護甲槽 == 這一格 → 護甲槽 = 0xff，另一件若在則 FUN_1000_1cbf(對象, 武器槽)
```

**只能對「正穿戴著」的東西驅邪。** 選單會一直重問，直到你挑中對方的武器格
或護甲格 —— 放在包包裡的詛咒物碰不到。這條限制本身就在說：
**詛咒是「穿上去才發作」的。**

---

## 2. 收穫一：`+0x0d` 是驅邪成功率

道具槽的 `+0x0d` 一直躺在 `inventory.go` 的「語意未解」那一排。
這裡是它唯一的讀取端：`rnd(100) > 它` 就失敗，所以**值越大越好驅**。

原版起始存檔十件裝備的 `+0x0d` **全部是 0** —— 沒有詛咒物，
一件也驅不動。與「附魔全是 +0」是同一組現象的兩面。

嚴格說它是「好驅程度」不是「抗性」，命名時要小心方向。

---

## 3. 收穫二：技能旗標不是布林

```
for i in 0..30: if char[+0xc8+i] == 2 → 設 0
```

技能旗標陣列有**第三種值**：

| 值 | 意義 |
|---|---|
| 0 | 沒學過 |
| 1 | 已學 |
| **2** | **學過，但被詛咒封住** |

驅邪成功就把所有 2 清成 0。注意是清成 **0 不是 1** —— 詛咒解開之後
那項技能**沒有還回來**，只是不再佔著位置。夠狠。

> **這是一個會被存檔悄悄吃掉的細節。** 本專案原本把旗標讀成
> `on == 1` 的布林，寫回去只寫 0／1 —— 值 2 的技能存一次檔就變成 0，
> **詛咒自動解除**。已改成 `Skills` + `CursedSkills` 兩個陣列，
> 寫回時還原成 2。測試釘住這條往返。

---

## 4. 收穫三：四對屬性欄位的第二次確認

```
char[+0xf7] = char[+0xf3]
char[+0xf8] = char[+0xe8]
char[+0xfb] = char[+0xe9]
char[+0xfe] = char[+0xea]
```

拿 `save.go` 的定義對照（相對 `expOffset` = `0xc4`）：

| 目標 | = | 來源 | 對應欄位 |
|---|---|---|---|
| `+0xf7` = `+0x33` | ← | `+0xf3` = `+0x2f` | 速度（含加成 ← 天生）|
| `+0xf8` = `+0x34` | ← | `+0xe8` = `+0x24` | 力量（含加成 ← 天生）|
| `+0xfb` = `+0x37` | ← | `+0xe9` = `+0x25` | 技巧（含加成 ← 天生）|
| `+0xfe` = `+0x3a` | ← | `+0xea` = `+0x26` | 法力上限（含加成 ← 天生）|

**四對一一對應，一個不差。** 那幾對「天生 vs 含加成」原本是靠欄位間距與
數值比對推出來的（`docs/formats/game-data-tables.md` §1.4），
這裡是完全獨立的第二個來源 —— 驅邪要把加成還原，就得知道加成的原始值在哪。

順帶也說清楚**詛咒的第二種效果**：它會動那四個含加成欄位。
所以一件詛咒裝備可以同時：附魔為負、封住技能、壓低四項屬性。

## 5. 本專案的實作範圍

- `internal/assets/scenario`：`InventorySlot.ExorciseResist`（`+0x0d`）、
  `Character.ExorcisedToday`（`+0xf2`），兩個都雙向
- `internal/game/character.go`：`CursedSkills`（旗標值 2）與往返還原
- `internal/game/exorcise.go`：`CanExorcise`／`Exorcise`／`CursedSkillList`
- `cmd/demonwinter`：紮營選單按 `X`，三層選單（施術者 → 對象 → 身上的裝備）

**沒實作**：§4 那四個含加成欄位的還原。本專案的 `game.Character` 只帶天生值，
含加成的那一份沒有模型 —— 補這一條要先把「裝備加成」整套做出來，
不是驅邪這一項的事。`FUN_1000_1cbf`（脫下一件之後重算另一件的加成）同理。

實機驗收（`workplace/dump/persist/56-camp-exorcise.png`，`-give-skill 15`）：
三層選單走得通，Wopple 對自己的匕首驅邪，訊息是
「驅不動匕首（成功率 0%）」—— 那件的 `+0x0d` 確實是 0。

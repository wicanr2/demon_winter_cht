# 53 — View mind，以及那個追了三篇的旗標

`docs/re/52` 把商隊七個選項讀到只剩 View mind。這一篇讀完它 ——
順便解掉一個從 `docs/re/32` 起、被誤讀過一次、又被標為「用途未解」兩輪的旗標。

---

## 1. 那個旗標的三段身世

| 出處 | 當時的結論 |
|---|---|
| `docs/re/32` | `rnd(120) − 80` 是**詛咒機率** |
| `docs/re/48` §5 | 不是詛咒。生成器裡它只做一件事：**跳過第一道效果門檻**。商隊把它逐件記在自己的陣列（`ds:0x4e2e` 進出一次），**後續拿它做什麼沒讀** |
| 本文 | 那個陣列的唯一讀取端是 **View mind**。旗標的意思是**這一件商人在說謊** |

`0x1dfa8` 讀的正是 `ss:[bp-0x32 + i×2]` —— 與 `0x1d6c4` 寫入的是同一個陣列。
**寫入端與讀取端對上，這條線就閉合了。**

---

## 2. View mind 本體

```
1df5b  if [bp-0x14] == 0 → 什麼都不做
1df69  if [bp-0x14] == 1 → 印 "Only usable once"   ; 一支商隊只能用一次
1df7f  [bp-0x14] = 1
       for i := 0; 貨[i].型別 != 0xff; i++ {
1df90      if rnd(3) >= 3 → 跳過                    ; 1/3 看不出來
1dfa8      if 說謊旗標[i] != 0:
1dfb1          議價計數器[i] = 1001                  ; 貨單上那一格改印 " LIE "
1dfb7          揭穿數++
       }
```

三件事：

- **一支商隊只能讀一次心。**
- **只揭穿真的在說謊的貨** —— 沒說謊的怎麼讀都不會被標。
- 每一件說謊的貨**各有 2/3 機率**被揭穿；讀一次不代表全揭穿，
  但也沒有第二次機會。

議價計數器 1001 這個值與翻臉的 1000 只差 1，而顯示端
（`0x1da7e`）先比 1000 印 `Inslt `、再比 1001 印 ` LIE  ` ——
**兩個狀態共用同一個欄位，價格那一欄整個被字取代**。

---

## 3. 說謊的貨還買不買得到？沒讀

被標成 1001 之後：

- 議價會立刻翻臉（`rnd(100) < 10 × 1001` 恆真）→ 計數器變 1000。
- 購買那一支對 1001 怎麼處理**沒追**。

本專案的選擇是**標出來、不賣**（「他報的價是假的，你不買了」）。
理由：價格那一欄在原版已經被 ` LIE ` 取代，畫面上根本沒有數字可以照著付；
在沒讀的情況下，讓玩家用一個不存在的價格成交比擋下來更失真。

---

## 4. 「說謊」在機制上是什麼，仍然開放

已經確定的只有兩端：

- **生成端**：擲中的貨跳過第一道效果門檻（`docs/re/48` §5）。
- **商隊端**：那一件被 View mind 標成 ` LIE `。

中間那條「為什麼跳過門檻＝說謊」沒有證據。看得出來的關聯是：
商隊列貨時把每一件都標成已鑑定（`docs/re/44` §2），估價因此把
附帶法術的強度算進去 —— 一件被「多滾一輪」的貨，開價與它實際的價值
未必對得上。**但那是推論，不寫進實作。**

## 5. 本專案的實作範圍

- `internal/game/merchant.go`：`MerchantWare.Lying`（原本叫 `Guaranteed`）、
  `MerchantWare.Exposed`、`ViewMind(r, m)`；買到揭穿過的貨會被擋下。
- `cmd/demonwinter/merchantui.go`：`V` 鍵，一支商隊只能用一次。

測試釘住：只有說謊的貨會被揭穿、揭穿率落在 2/3 附近（400 支商隊抽樣）。

**加了偵錯旗標 `-merchant-lies N`。** 說謊機率是三層機率疊起來的
（超過一半的商隊擲到 0、每件貨再各自中、View mind 又只有 2/3 揭得穿），
不指定就幾乎截不到那一格 —— 試了十個 seed 都是「你讀不出什麼」。
**驗不到的東西等於沒驗**，與其賭運氣不如加一個標明是偵錯的入口。

畫面實測 `workplace/dump/persist/70-merchant-viewmind.png`：
「你看穿了 1 件貨的假話」，藥瓶那一列的價格變成「謊報」。

# 63 — 每步 HP 變動：符印傷害與巨魔再生是同一支

`docs/re/62` §5 把 `FUN_222f_0619`（符印還在時的傷害）列為主線唯一還缺的機制。
讀完那 325 bytes 才發現：**它同時是巨魔天生能力「再生」的實作。**

---

## 1. 一個迴圈，兩條路

```c
ds:0x15cc = 0x80;
changed = false;  dead = 0;

for (i = 0; i < party[+0x9a]; i++) {
    rec = 角色[i];
    if (rec[+0x102] == 5) {                       // 已死亡
        dead++;
    }
    else if (ds:0x15ca < 0x7f && ds:0x15ca != 1) {
        if (rec[+0xf5] == 4 && rec[+0xfd] < rec[+0xfc]) {   // 巨魔且沒滿血
            rec[+0xfd]++;                          // ← 再生
            changed = true;
        }
    }
    else if (ds:0x15ca > 0x7f || rec[+0xf5] != 4) {
        changed = true;
        rec[+0xfd]--;                              // ← 流血
        if (rec[+0xfd] == 0) {
            dead++;
            rec[+0x102] = 5;                       // 死亡
            ...印訊息、重畫
            changed = false;
        }
    }
}
```

`ds:0x15ca` 是模式旗標，全檔只有三處寫：

| 位址 | 值 | 情境 |
|---|---|---|
| `0x164d5` | `0` | 一般行走（`222f:0b0e` 裡）|
| `0x16c0d` | `0x80` | **符印區**（`docs/re/58` §3 那段檢查的最後一行）|
| `0x1acd1` | `0x80` | HP 被設成 0 之後，借這支結算死亡 |

所以：

- **模式 `0`** → 巨魔 HP +1，其他種族不動 ＝ **「再生」天生能力**
- **模式 `0x80`** → 全隊 HP −1 ＝ **符印傷害**

### 巨魔在符印區不免疫

第二條的條件是 `ds:0x15ca > 0x7f || 不是巨魔`。
`0x80 > 0x7f` 直接成立，**種族判斷被 `||` 短路掉**。

也就是說巨魔平常會慢慢回血，但走進符印區照樣一步掉一點 ——
兩條路在同一個 if-else 鏈裡互斥，不會一邊再生一邊流血。
這是讀對**鏈的順序**才看得出來的，拆成兩個獨立判斷就會弄錯。

### 值 `1` 那條路走不到

再生的條件多了一個 `&& ds:0x15ca != 1`，但**全檔沒有任何地方寫 1**。
那是留給沒做完的第三種模式，本專案不模擬。

## 2. 這解釋了「再生」天生能力

`docs/re/54` §5 解出四個種族天生能力（偽技能 31–34），
其中 **31 ＝ Regeneration ＝ 巨魔**，當時只知道名字，不知道效果在哪。

現在知道了：**它不是一個獨立的效果，就是這支每步 tick 的模式 0 分支。**
種族欄 `+0xf5 == 4` 寫死在裡面，沒有走技能表。

順帶對上 `CONTEXT.md` 的種族表（`4` ＝ 巨魔）與
`docs/re/21` 的種族修正 —— 三處一致。

## 3. 本專案的實作

`internal/game/steptick.go`：`StepHPTick(party, mode)`、`GlyphDrainMode(flags, subMap)`。
`cmd/demonwinter/main.go`：`stepHPTick()` 接在 `MoveOK` 之後、事件檢查之前。

### 一處刻意放寬的差異

原版判定符印傷害的條件更細 —— `docs/re/58` §3 的那段依 Y 座標
把子地圖 `0x38` 分成三段（北 `Y<10`、南 `Y>0x16`、中央還要 `X` 在 33–54）。

**本專案用「整張子地圖」**：只要在 55／56／66 且該符印還沒解，就流血。
**範圍比原版大**。等那三段的邊界確認過再收窄 ——
現在收窄的風險是把「該流血的地方」漏掉，那比多流血更難發現。

## 4. 實機（對照組）

```bash
# 符印還在
tools/screenshot.sh 75-glyph-drain.png KEYS=Return,Left,Left,Left -map=55 -x=47 -y=22
# 先解掉符印再走同樣三步
tools/screenshot.sh 76-glyph-cleared.png \
  KEYS=Return,r,c,Return,Down×11,Return,Escape,Left,Left,Left \
  -map=55 -x=47 -y=22 -sp=120
```

| 截圖 | 結果 |
|---|---|
| `75-glyph-drain.png` | 走三步 → **「符印的力量侵蝕著隊伍」** |
| `76-glyph-cleared.png` | 解掉符印後走同樣三步 → **沒有訊息** |

兩張圖的差別只有中間那次 UNCURSE。**這是對照組，不是單張截圖**——
單看第一張只能證明「有東西在扣血」，兩張並排才證明「扣血的原因是符印」。

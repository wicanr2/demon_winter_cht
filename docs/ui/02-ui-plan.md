# 畫面改版計畫

承 [`01-ui-assessment.md`](01-ui-assessment.md) 的量測與問題清單，加上四個重製版的做法調查，
與已經定案的四條約束，收成一份可以照著做的順序。

## 1. 定案的約束

| # | 約束 | 來源 |
|---|---|---|
| C1 | **保留原版骨架，重做觀感。** 目標是「一看就是 1988 年的 SSI，可是很舒服」 | 使用者，2026-07-28 |
| C2 | **素材（sprite／tileset）維持原版不動。** 只改 UI 外框、配色、字型、排版 | 使用者，2026-07-28 |
| C3 | 畫布可以放大；但量測顯示原版世界視窗就是 288×252，放大換不到更多地圖，**先維持 640×400** | 使用者授權＋`01` §3.2 的量測 |
| C4 | 中文一律點陣字，不用向量字 | 專案既有前提（`internal/assets/cjk`）|

C2 直接決定了參考對象。四個重製版裡：

- **冰城傳奇三部曲（2018）**把全部素材重畫成手繪石框與羊皮卷 —— **C2 排除這條路**。
  它的長期抱怨也正是「像素圖與高解析介面互相打架」，重畫得不徹底就會混搭得很怪。
- **Wasteland Remastered（2020）**是 1988 年的 DOS 遊戲，原版就是「上方視窗＋左下隊伍表
  ＋右下捲動訊息」，**與冬之魔同代同結構**。它的做法是版面與字元格一格不動、
  內容層維持等寬點陣感，只把**裝飾層**（面板外框、底紋、鍵帽、色調）換掉。
  **這是本專案的主要參考。**
- **Wizardry: Proving Grounds（2024）**的價值在兩個具體元件：把原始介面做成
  可放大可關閉的常駐小窗（一致好評），以及選項頁「選中列的值方塊整塊填實心配黑字」
  ——那就是把原版的反白重新配色，不是換掉機制。
- **Gold Box Companion**（SSI 家族唯一可參考的）走另一個極端：原畫面一像素不改，
  資訊疊在外面。最低風險也最不好看，本專案不採，但它提醒了一件事：
  **需要的資訊可以放到旁邊，不一定要改原本那一塊。**

分界線因此畫在**裝飾 vs 內容**：外框、底色、色調、鍵帽可以重做；
圖塊、人物、地形、字元格一律不動。

## 2. 四個重製版的共通做法

1. 版面骨架原位保留，只換材質。
2. 實心色塊改成**有厚度的外框 + 內容區獨立底色**。沒有人用「加粗雙線」解決問題。
3. 配色收斂成一個色相加一個強調色，**背景一律不是純黑**（灰石紋、帶色偏的近黑加暗角）。
4. 多出來的畫布拿去做框與裝飾，**不是等比例放大 UI**。
5. 懷舊視覺做成**可切換的功能**。Wizardry 做了，好評；冰城傳奇沒做，玩家至今在要。
   成本差距很小，值得從一開始就把「UI 皮膚可換」寫進版面層。

第 3 條與 `01` §3.5 的 EGA 配色表相容 —— 那張表已經把顏色分了工，
差的只是背景從純黑換成帶色偏的近黑。

## 3. 已完成

### 3.1 英數字模（`01` 的 P7）

原本：中文倚天 16×15 畫 1 倍（1×1 像素），英數 CGA `ASC.FNT` 8×8 放大 2 倍（2×2 像素）。
同一行兩種像素密度，看起來一粗一細。

追下去發現**問題比密度更深一層**：原版的兩套 ASCII 字模都是**粗筆畫的顯示體**。
`ASC.FNE` 的 `A` 直筆有 4 px 寬，倚天漢字是 1–2 px。就算把 `ASC.FNE` 以 1 倍畫上去
（密度對了、而且那才是原版 EGA 模式實際在用的字），**筆畫重量還是差一倍**。

倚天自己有全形英數（`Ａ` = Big5 `A2CF`），2 px 筆畫、16×15、與漢字同一套設計，
**而且寬度一樣是 16 —— 版面完全不動**，`PadCells` 系列的欄位對齊一行都不用改
（`01` §P7 擔心的連鎖改動全部免掉）。

做成 `-ascii` 三選一：

| 值 | 英數來源 | 用途 |
|---|---|---|
| `eten`（預設）| 倚天全形英數 | 與漢字同重量，混排一致 |
| `ega` | 原版 `ASC.FNE`（16×14）| 要對照原版 EGA 長相時用 |
| `cga` | 原版 `ASC.FNT`（8×8 ×2）| 原版 CGA 模式的真實樣子 |

對照圖：`workplace/dump/ux/font-eten.png`／`font-ega.png`／`font-cga.png`（同一張角色卡）。

順帶修正一條既有的錯：`NewMixedFont` 原本寫死「必須是 CGA 8×8」，
現在改成**判「放大後的寬度是否等於 `CellWidthASC`」**。排版格寬是全專案的共用前提，
讓尺寸不合的字模靜默通過，症狀會是十幾個畫面「有點不齊」而不是一個看得見的錯誤。

## 4. 待辦，依建議順序

順序的邏輯：先把「玩家看不到該看的」補回來，再處理「看得到但看起來不對」，
最後才動互動方式。細節見 `01` §3.1／§3.2 的 A1–A10 與 B1–B8。

| 階段 | 內容 | 為什麼排在這 | 風險 |
|---|---|---|---|
| 0 | 固定 `workplace/dump/ux/` 的截圖流程，每階段跑同一組畫面 | 版面錯誤（溢出、重疊、對齊）**測試看不到**，只有截圖比對抓得到 | 低 |
| 1 | A1 偵錯欄下架 ＋ A2 抬頭列（金幣／糧食／時辰）＋ A3 右上常駐隊伍表 | 這三件是同一次改動的三面：偵錯欄挪走，空出來的位置正好給隊伍表。做完立刻拿回最重要的資訊 | 低 |
| 2 | A4 地圖／戰場加雙線白框 ＋ A5 拿掉戰場格線 ＋ A6 EGA 配色分工 ＋ A7/A8 欄位對齊 | 框不只是好看：現在**視野內縮的邊界讀不出來**，黑格子和背景同色 | 中 |
| 3 | B1／B2 版面常數重排 ＋ B5 訊息移到地圖框正下方 | 字模已經定案且格寬沒變，可以直接排版面，不會排兩次 | 中高 |
| 4 | B3／B4 紅底選單元件，取代鍵位提示塊 | 新元件，要同時接四個畫面的輸入流程 | 中 |
| 5 | B6 城鎮重用地圖視窗 ＋ B7 段落行距 ＋ B8 標點壓縮 | B8 動到前進量，必須與 `WrapMixed` 同源 | 中 |
| 6 | 戰場單位改用 `DEMON.SHE` 的人形圖塊（`01` P10）＋ `GOT.FNE` 落點 | 敵人對到哪些圖塊索引還沒查 | 中 |

> `01` 的原順序把字型換裝排在階段 3；那一項已經做完（§3.1），
> 而且因為格寬沒變，後面的版面重排不必等它，順序因此往前收了一階。

## 5. 從調查帶回來、要寫進上面各階段的注意事項

**（1）中文比英文短，會把原版面板撐出空洞。**
原版那塊紅底選單的寬度（176 px ＝ 11 格）是照最長英文標籤裁的，
14 項換成中文每項只剩 2–4 字，照抄寬度會得到一塊很空的紅色色塊。
冰城傳奇的解法可以借：**寬度不動，改成左對齊項目 + 右側放快捷鍵徽章或狀態**，
把空白填成資訊而不是縮窄面板。→ 影響 B3。

**（2）首字母熱鍵在中文化之後消失。**
`L)ook`、`R)ead descr.` 這套建立在英文單字上。三個重製版的替代做法分別是
黃色首字母（冰城）、鍵帽徽章（Wizardry／Wasteland）、數字編號（Wasteland 的彈出選單）。
**鍵位本身一定要保留**（改掉會讓既有攻略與 `docs/re` 的對照失效），
只換顯示方式，建議用鍵帽徽章：`[R] 重讀`。→ 影響 B3／B4。

**（3)「不可用項目畫成網點」不要換成單純調暗。**
網點是原版的機制表達（`01` 量到該列黑:紅 ≈ 59:41），而且它本身就是
`R) Read descr.` 那條規則的畫面證據（`docs/re/104` §3）。
建議網點與降透明度兩者並存，網點當可切換的復古樣式。→ 影響 B3。

**（4）背景不要留純黑。**
四個案例無一例外。在 C2（素材不動）之下可行的做法是**在圖塊層以外**鋪一層
極低對比的底紋或暗角 —— 那是 UI 層不是素材層，不違反 C2。→ 影響 A6。

**（5）EGA 高飽和不能整組降下來，只能分區。**
紅底選單、白色雙線框是辨識度來源。切法：大面積色塊降明度與飽和度，
小面積保留原始 EGA 純色當強調。→ 影響 A6，`01` §3.5 那張表照這條校一次。

**（6）不要把訊息文字「整理乾淨」。**
Wizardry 2024 最實質的批評是戰鬥訊息被簡化成「命中＋數字」，
丟掉了原版 swings／thrusts／claws／bites 的動詞變化。
中文化時這個風險更高，譯者傾向統一句式。**原版訊息的變化度當成要保存的資產。**
→ 影響翻譯流程，不只 UI。

**（7）雙模式不是免費的。**
ScummVM 的 Ultima VI enhanced mode 預設兩倍解析度，結果過場只填半個畫面。
若要做「原味／現代」雙視覺模式，**兩套必須共用同一組邏輯座標**。
現階段的低成本做法是把顏色與框樣式收進一個 theme 結構，不要散在各個 `draw*` 裡。
→ 影響階段 2 的實作方式。

**（8）像素密度太高會讓畫面不可讀。**
SKALD（2024）用 C64 調色盤重做現代 CRPG UI，失敗處是像素畫太密，
玩家得一直按 highlight 鍵才知道哪裡可以互動。我們的圖塊不動（C2），
但**新加的裝飾（底紋、暗角、框上的紋理）要克制**，不要把可互動的東西藏進裝飾裡。

# 畫面評估：現況 vs 原版

> **後續**：改版方向、定案的約束（含「素材維持原版不動」）與實作順序收在
> [`02-ui-plan.md`](02-ui-plan.md)。本篇的 §P7（字型密度）**已處理**，
> 而且解法與這裡寫的兩條都不同 —— 追下去發現原版兩套 ASCII 字模都是
> 粗筆畫顯示體，密度對齊之後筆畫重量還是差一倍；改用倚天自己的全形英數，
> 格寬不變、`PadCells` 系列一行都不用改。見 `02` §3.1。

比對素材：`workplace/dosbox/shots/*.png`（DOSBox 實跑，EGA `mode 10h`，640×350，
在 1024×768 視窗裡以 1:1 貼在左上角，所以截圖上的像素座標就是原版座標）
與 `workplace/dump/ux/*.png`（remake，640×400 邏輯畫布，nearest 放大 2 倍後
貼在 1600×900 視窗的 (160,33)）。文中原版尺寸都是從截圖量出來的，量法附在該條後面。

## 1. 逐項對照

| 元素 | 原版 | remake | 落差 |

| 畫布 | 640×350，文字格 16 寬 × 14 列距（隊伍列 y=0/14/28/42/56 量得），等於 40 欄 × 25 列 | 640×400，文字格 16×16，40 欄 × 25 列 | 縱向多 50 px，但沒有被用掉 |
| 常駐抬頭 | 第 0 列全寬：`Gold: 65  Pro: 8`（金幣、糧秣） | 無 | 金幣與糧食在 remake 的世界畫面上完全看不到（`a.gold()` 有資料，只是沒畫） |

## 2. 問題清單

依「先修哪個玩家感受最大」排序。

### P1　隊伍狀態不在畫面上

**看到什麼**：`01-world.png` 右欄從上到下是時辰、步數、內縮、座標、地形、深度、圖塊檔名，
接著九行鍵位提示。沒有金幣、沒有糧食、沒有任何一個人的生命或法力。
原版把這些放在最顯眼的兩塊：第 0 列的 `Gold/Pro`、右上角的五人表。

**為什麼是問題**：這是一款會餓死人、會沒錢住店、會在野外被打殘的遊戲。
玩家的決策（要不要紮營、要不要回城、還能不能再打一場）全靠這三個數字。
現在要按 `P` 才看得到，而 `P` 會把整個右欄換掉，等於用「看不到別的」換「看得到血量」。

**影響**：世界地圖、地城、城鎮。戰鬥畫面右欄有 HP，但那是臨時表不是常駐表。

### P2　偵錯欄位與開發註記出現在正式畫面

**看到什麼**：
- 狀態欄五行裡有四行是偵錯資訊：`步數 1`、`內縮 3`、`座標 9,32`、`地形 0`、`深度 0`、`圖塊 DEMON.SHE`（`cmd/demonwinter/main.go:1291-1294`）。
- 鍵位提示最後一行直接寫著 `偵錯 B F1 F3 F4`（`main.go:1321`）。
- 營地畫面（`05-camp.png`）最下面一行是 `※ 原版紮營選單的 14 項已全部接上（見 docs/re/33）`（`cmd/demonwinter/campui.go:362`）。
- 試玩紀錄裡還有 `（地點劇情 3 還沒接，見 docs/re/65）` 這種寫給自己看的訊息會直接進訊息列。

**為什麼是問題**：`圖塊 DEMON.SHE` 和 `docs/re/33` 對玩家沒有意義，卻佔著版面最上面、
字最大的位置。它們也讓畫面「像個工具」而不像遊戲——這條和 P5 的第一眼焦點是同一件事的兩面。

**影響**：世界地圖、地城、營地，以及所有會經過 `a.message` 的畫面。

### P3　選單被換成了鍵位說明

**看到什麼**：原版的世界選單是 15 列紅底清單，游標反白，不能用的項目蓋網點。
remake 換成右欄九行白字提示，一行擠兩到三個「字母＋動作」。

**為什麼是問題**：
1. 玩家要自己把「字母」和「動作」配對，而不是移游標選一項。
2. 「現在能不能做」這個訊息消失了。原版靠網點告訴你「讀說明」現在不能按；
   remake 全部一樣亮，按下去才知道不行。戰鬥指令那邊有做（付不起的加括號），
   世界與營地沒有，同一個概念在專案裡有兩套表現。
3. 提示塊隨功能長大。`drawStatus` 的註解已經記到「一鍵一行會溢出畫面」，
   於是改成一行塞三個——那是版面在推著資訊走，不是資訊在決定版面。

**影響**：世界地圖、營地、城鎮、戰鬥（戰鬥是底部橫排提示）。

### P4　沒有面板邊框，元素浮在純黑上

**看到什麼**：整個 remake 只有事件文字框有一條 1 px 黃線。地圖、狀態欄、選單、
角色卡、名冊都直接畫在黑底上。

**為什麼是問題**：除了「不像 1988 年的 SSI」以外，有一個實際的可讀性後果——
**視野內縮的邊界看不出來**。`drawWorld` 在光照不足時不畫外圈格子（留黑），
原版因為有框，玩家看得到「框裡有一圈是黑的」；remake 沒有框，
黑格子和畫布背景是同一個顏色，看起來只是「那邊沒東西」。
同理，地圖區到底有多大，玩家要靠猜。

**影響**：世界地圖（尤其地城與夜間）、戰場、所有選單畫面。

### P5　第一眼焦點落在最不重要的東西上

現在依「亮度 × 面積」排序，畫面上最搶眼的依序是：鍵位提示塊（九行白字，約 344×144）、
偵錯數字（五行，含 2 倍放大的粗數字）、地圖（288×252，但大部分是黑的）。

應該的順序是：地圖 → 隊伍狀態 → 目前可以做什麼（選單）→ 訊息 → 其他。
原版靠三件事達成：地圖有白框圈住、隊伍表在右上角、選單是唯一一塊有色塊背景的東西。
remake 三件都沒有，於是「哪裡才是主體」只能靠玩家自己判斷。

**影響**：全部畫面。

### P6　畫布下緣長期空著

量測（非黑像素的最下緣，換算成邏輯座標）：

| 畫面 | 內容底部 | 空白 |
|---|---|---|
| `01-world` | y≈258 | 下方 142 px（35%） |
| `05-camp` | y≈186 | 下方 214 px（53%） |
| `06-sheet` | y≈218 | 下方 182 px（45%） |
| `04-spell` | y≈130 | 下方 270 px（67%） |
| `08-roster` | y≈361 | 下方 39 px |

只有事件框出現時（`02-event`）畫布才填到底。也就是說 640×400 這個尺寸是為了
「文字框展開時剛好塞得下」而定的，其餘時間有三分之一以上是空的。
`04-spell`、`05-camp` 這類選單畫面更接近「一張純文字的 terminal 輸出貼在左上角」。

**影響**：世界地圖、營地、施法、角色卡、換裝。

### P7　字型密度不一致（已定案，這裡只記連帶影響）

換成 8×16 的 ASCII 點陣、1 倍繪製之後，有三處要一起改：

1. **`textlayout.CellWidthASC` 會從 16 變成 8**，於是
   `PadCells` / `PadCellsLeft` / `TruncateCells` 的前提（「本專案所有字元的排版格寬相同，
   所以格就等於 rune」）不再成立。這三支目前是用 rune 數在補空白的，
   一旦半形出現，所有含英數的欄位（隊伍表、戰鬥單位表、角色卡）都會歪。
   對應改法是把它們改成以像素為單位補到定寬，或加一個 `PadPixels`。
   `layout.StatusCells` 同理，它現在是 `可用寬 / CellWidthCJK`。
2. **右欄會多出空間**。目前 21 格（344 px）的限制是被全形英數撐出來的；
   `Wopple 24/24 29/29` 這種字串半形化以後只剩約一半寬，右欄放得下真正的隊伍表。
3. **`MixedFont.Draw` 裡 `asciiScale = 2` 與 `WrapMixed` 的寬度計算要同時改**，
   兩邊不同步會出現「排版說塞得下、畫出來超出框」。`cjktextbox.go` 的註解已經點過這個風險。

另外記一筆備選：`internal/ui/text.go` 的 `LoadEGAFont` 已經能解 `ASC.FNE`（EGA 版 16×14、
1 bpp、可指定前景色），那正是原版 EGA 模式實際在用的那套字，也是 1×1 像素。
如果 8×16 的字模來源還沒定，先接 `ASC.FNE` 可以立刻解掉粗細不一，
而且不動 `CellWidthASC=16`，上面第 1 點的連鎖改動全部免掉；代價是英數維持全形寬，
右欄不會變寬。兩條路都行，差別在「要不要現在付欄寬重算的成本」。

### P8　中文排版的細節

- **行距是 0**。`CellHeight = 16`、倚天字模墨高 15，所以段落文字上下只隔 1 px。
  表格這樣沒問題，`02-event` 的敘事段落就明顯太擠。
- **全形標點佔滿一整格**。`02-event` 的「私人藏書室。遠處的牆邊」，句號後面出現
  接近一格的空白洞。標點的字面本來就只佔半格，點陣排版要靠壓縮前進量處理。
- **數字欄沒有右靠**。`06-sheet` 的 `生命 24／ 24`、`08-roster` 的 `法力 29／ 29`，
  斜線前後各有一個非預期的空格；同一畫面裡「經驗 1074 ／ 1100」又是另一種間距。
- **全形半形混用不一致**。同一個畫面同時出現全形「／」與半形 `/`（`03-battle` 是 `11／11`
  但寫法上是 `%3d/%-3d`，被全形寬度拉開的），還有全形「：」與半形冒號並存。
- **括號讓清單縮排歪掉**。`07-equip` 的空欄位寫成「（空）」＝三個全形字，
  比「小斧」多一格，於是六列空欄整齊地往右凸出來，看起來像是另一層階層。

**影響**：事件文字框、角色卡、名冊、換裝、戰鬥單位表。

### P9　顏色只剩白色

remake 目前的顏色分工是：白＝全部、黃＝文字框邊與行動者框、`#404040`＝戰場格線。
`#404040` 不在 EGA 16 色裡（最接近的是 `#555555`），這一點會在「整個畫面是不是同一套色」
上被看出來。原版同一張畫面就用了白、淺灰、紅、黑、黃、綠、淺洋紅六七種，
而且每種都有固定意義。顏色是這個年代的 UI 最便宜的分層手段，現在完全沒用。

### P10　戰場

- **格線是原版沒有的**（`mv-03-afterattack.png`、`q14-01-final.png` 都沒有格線），
  而它現在是畫面上最密的圖形，把地形圖塊切碎。
- **單位是文字**（「怪→」「我←」）。`game.PartyGlyph` 的註解已經查清楚原版是
  「把圖塊索引寫進繪製緩衝區」，`DEMON.SHE` 那 102 格裡就有人形；
  也就是說用圖塊畫單位是走原版的路，缺的只是敵人要對到哪些索引。
- **敵我不分色**：右欄的表把「獸人／蜘蛛／巨鼠／1 級法師」和「Wopple／Stumpy／Podgon」
  排在同一串，全白。原版靠位置分（敵人只在遭遇時列出，我方永遠在右上）與圖塊分。
- **「第 1 回合」出現兩次**：抬頭一次（`戰鬥　第 1 回合`），戰鬥紀錄第一行又一次。

### P11　其他一次性的東西

- `04-spell` 的「最低法力」欄標題右緣在 x≈350，底下的數值右緣在 x≈381，差兩格沒對齊。
- `05-camp` 的指令列一列放的項目數不固定（第一列 1 項、第四列 2 項、第五列 3 項），
  左邊的字母欄看起來像一直行清單，右邊卻不是。
- `08-roster` 每人四行、行間無分隔，五個人 20 行連在一起。
- 事件框的「－ 完 －」固定畫在第 6 行，內容只有一行時它離內文有四行空白。

## 3. 改版方向

### 3.1 不動骨架就能做的

| # | 做什麼 | 具體改哪裡 |
|---|---|---|
| A1 | 偵錯欄位改成需要時才顯示 | `drawStatus` 的 `步數／內縮／座標／地形／深度／圖塊` 六個欄位與 `偵錯 B F1 F3 F4` 那行，收進一個 `-debug` 旗標或 F12 疊層；`campui` 那行 `※ …（見 docs/re/33）` 直接刪 |
| A2 | 把金幣、糧食、時辰放到第 0 列全寬抬頭 | 新增一支 `drawTopBar`，內容 `金幣 65　糧食 8　13時 17日 紅玉月`，畫在 y=0，全部畫面共用 |
| A3 | 右上角補常駐隊伍表 | 五列，`序號／名字／生命／法力`，數值右靠；世界、地城、營地、戰鬥都畫。等於把 `drawRoster` 縮成一個常駐精簡版 |
| A4 | 地圖／戰場加雙線白框 | 沿用 `ui.StrokeRect` 畫兩圈（外圈 1 px、內圈 2 px、間距 1 px），框內留 4 px；框大小要用 `tileMetrics()` 回來的實際格高算，不要用 `layout.MapHeight`（EGA 是 252 不是 288，`drawBattlefield` 的註解已經踩過一次） |
| A5 | 拿掉戰場格線 | `drawBattlefield` 裡那圈 `StrokeRect(..., gridColor)` 移除；瞄準模式（`a.aoe != nil`）時才畫，顏色改 `#555555` |
| A6 | 顏色分工 | 見 §3.5 的對照表；同時把 `gridColor` 從 `#404040` 換成 EGA 色 |
| A7 | 數值欄一律右靠 | `06-sheet`、`08-roster`、戰鬥單位表全部改用 `PadCellsLeft`；`／` 統一成半形 `/`；全形冒號只用在中文句子裡 |
| A8 | 「（空）」改成「—」 | `07-equip` 空欄位用一個全形破折號，欄寬就與其他列一致 |
| A9 | 事件框的翻頁提示改成右下角 | `DrawMixedTextBox` 裡 hint 的 x 改成靠右、顏色改淺灰；y 改成「最後一行下面一行」而不是固定第 6 行 |
| A10 | 戰鬥抬頭去重 | 抬頭保留 `第 N 回合`，戰鬥紀錄不要再輸出回合行 |

A1–A3 是同一次改動的三面：把偵錯欄挪走，空出來的位置正好給隊伍表。

### 3.2 要動版面常數／畫布尺寸的

**畫布維持 640×400。** 量測顯示原版世界視窗就是 288×252（＝9×9 × 32×28），
與戰場尺寸一致，所以放大畫布不會換來更多地圖，只會換來邊距。
真正的問題是 640×400 目前只用了上面三分之二，把版面重排就填得滿。

### 3.4 哥德花體 `GOT.FNE` 的取捨

中文沒有對應的花體，硬造一套 16×16 的中文花體不划算（要造的字量在千字級，
而且 16×16 的格子放不下花體的裝飾筆畫，做出來只會糊）。三個可行的處理：

1. **`GOT.FNE` 只留給本來就是英文的地方**：標題畫面的 `DEMON'S WINTER`、
   製作群、角色的英文名（玩家自己輸入的，本來就是 ASCII）、章節分隔。
   這樣花體出現的位置正好是原版最強調的那幾處，而且不需要任何中文對應。
2. **中文的「標題感」改用原版自己的另一套手法**：反白（白底黑字）與紅底黑字。
   主選單的游標列就是反白（量測：`02-ega-mainmenu.png` 那一列是純白塊配黑字），
   紅底選單則是另一種。用色塊而不是字體來表示層級，這是同一個年代、同一個作品裡
   就有的語彙，不算另外發明。
3. **加一級字重就好**：中文標題用「同一套倚天字模、外擴 1 px 描邊」做成偽粗體。
   16×16 的字外擴 1 px 還讀得出來（比 12×12 安全），成本是一支 shader 或
   四次偏移繪製。這條可以晚點再決定，不擋前面的工作。

建議先做 1 + 2，把 3 當備案。要注意 `GOT.FNE` 是 16×14，畫在 16×16 的格子裡
上下各留 1 px，與中文同列時基線要對齊（沿用 `MixedFont.Draw` 現有的置中算式）。

## 4. 建議的實作順序

| 階段 | 內容 | 風險 |
|---|---|---|
| 0 | 先把 `workplace/dump/ux/` 的截圖流程固定下來，每階段跑一次同一組畫面 | 低。這類版面錯誤（溢出、重疊、對齊）測試看不到，只有截圖比對抓得到——`tileMetrics` 那次就是三個畫面壞了兩個而測試全綠 |
| 1 | A1（偵錯欄下架）＋ A2（抬頭列）＋ A3（隊伍表） | 低。只動 `drawStatus`，不碰版面常數。做完立刻拿回最重要的資訊 |
| 2 | A4（框）＋ A5（拿掉格線）＋ A6（配色）＋ A7/A8（欄位對齊） | 中。框的尺寸一定要走 `tileMetrics()`；EGA/CGA 兩種素材都要各截一張驗 |
| 3 | P7 的字型換裝（8×16 或先接 `ASC.FNE`）＋ `PadCells` 系列改成像素對齊 | **最高**。它會動到每一個有欄位的畫面。做法上建議先補一組「固定欄寬字串」的單元測試（給定輸入，斷言像素寬），再換字型；否則歪掉的欄位會散在十幾個檔案裡，而且看起來只是「有點不齊」不像壞掉 |
| 4 | B1／B2（版面常數重排）＋ B5（訊息移到左下） | 中高。`layout` 的測試會擋住「版面等式不閉合」，但擋不住「畫出來很醜」；每動一個常數就重截一次 |
| 5 | B3／B4（紅底選單元件，取代鍵位提示） | 中。這是新元件，但它同時要接四個畫面的輸入流程（世界／營地／城鎮／戰鬥）。輸入順序的錯誤只有實跑抓得到，上下兩個方向與每一種按鍵都要各送一次 |
| 6 | B6（城鎮重用地圖視窗）＋ B7/B8（行距、標點壓縮） | 中。B8 動到前進量，一定要和 `WrapMixed` 的寬度計算同源，否則會回到「排版說塞得下、畫出來超框」 |
| 7 | 戰場單位改圖塊（P10）＋ `GOT.FNE`（3.4） | 中。敵人要對到 `DEMON.SHE` 的哪些索引還沒查；查不出來之前先用我方人形＋顏色區分，別退回文字 |

順序的邏輯是：先把「玩家看不到該看的」補回來（階段 1），再處理「看得到但看起來不對」
（2、3），最後才動互動方式（5）。階段 3 排在版面重排之前，是因為字寬一改欄位就要重算，
先排版面再改字型等於排兩次。

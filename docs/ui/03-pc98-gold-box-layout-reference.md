# PC-98 Golden Box 日文版面參考

> 目的：用真正將西洋 CRPG 日文化的同代作品，檢查《冬之魔》繁中介面的
> 640×400 畫布、16×15 倚天字與資訊分區是否合理。這是**版面參考**，
> 不是遊戲規則或美術素材的 oracle。

## 1. 核心案例與系列交叉檢查

使用者指定的《克萊恩英豪》與《幽靈騎士》分別對應：

| 台灣常見譯名 | 原名 | PC-98 日文版 |
|---|---|---|
| 克萊恩英豪 | *Champions of Krynn* | Opera House 移植、Pony Canyon 發行，1992-10-21 |
| 幽靈騎士 | *Death Knights of Krynn* | Opera House 移植、Pony Canyon 發行，1993-08-20 |

兩作都是 SSI Golden Box 引擎、由同一團隊移植成全日文 PC-98 版，與
《冬之魔》同屬「美式隊伍制 CRPG 如何容納 CJK 文字」的直接案例。
它們比一般 PC-98 JRPG 更適合回答本專案的排版問題。

為避免只看兩款 Krynn 作品而誤把單一移植批次的做法當成通則，另以四款
Forgotten Realms 系列作交叉檢查：

| 作品 | PC-98 公開圖庫涵蓋的可比畫面 |
|---|---|
| *Pool of Radiance* | 建角、對話、城鎮、automap、營地、遭遇與戰鬥 |
| *Curse of the Azure Bonds* | 日文長文、隊伍狀態、城鎮、目標資訊與戰鬥 |
| *Secret of the Silver Blades* | 對話、寶物、探索、automap、商店與大規模戰鬥 |
| *Pools of Darkness* | 港口、室內／城市、商店、對話、世界地圖與室內外戰鬥 |

這六款橫跨 Forgotten Realms 與 Dragonlance，且畫面種類互補。它們共同證明的
才列為系列規律；個別作品的框飾、題頭色與插畫比例只當視覺靈感。

## 2. 量測結果

### 2.1 字級與文字容量

| 項目 | PC-98 Krynn 兩作 | 《冬之魔》目前 | 判定 |
|---|---:|---:|---|
| 邏輯畫布 | 640×400 | 640×400 | 同尺度 |
| CJK 字格 | 約 16×16 | 倚天字模 16×15，置於 16×16 格 | 同尺度 |
| 敘事正文寬度 | 約 608 px／38 全形格 | 38 格 | 直接吻合 |
| 固定表格行距 | 約 16 px | 16 px | 直接吻合 |
| 長文行距 | 約 16 px | 20 px | 《冬之魔》刻意較鬆，保留 |
| 一頁正文 | 截圖常見 3 行；框可容納更多 | 5 行 | 容量合理 |

最重要的結論不是「PC-98 也很像 DOS」，而是移植團隊真的以
**16×16 CJK 全形格作為 640×400 介面的基本單位**。因此本專案採用倚天
16×15 原尺寸、16×16 排版格及 38 格正文，並非任意放大。

### 2.2 畫面分區

探索與戰鬥畫面反覆使用三層：

1. **主內容區**：地圖、插畫或戰場，占上方及左側最大面積。
2. **情境資訊區**：敘事時是帶框正文；戰鬥時右欄顯示目標名稱、HP、AC、
   武器等資料。資訊不疊在圖像上。
3. **全域命令列**：最底一條獨立黑底區，列出當下可用動作或
   「滑鼠點擊／Return」提示，不與敘事正文混在同一框。

《冬之魔》目前的「上方抬頭＋左側地圖／戰場＋右側隊伍表＋左下訊息」
與這個資訊架構相容。PC-98 案例進一步支持以下原則：

- 常駐數值留在固定欄位，不能只在 debug 訊息或彈窗出現。
- 情境訊息與可操作命令分層，避免玩家分不清哪一行是敘述、哪一行能按。
- 長文可以占整個主內容寬度，不必強迫塞進窄右欄。
- 戰鬥右欄應只顯示當前單位／目標的高價值資料，不重複整份隊伍表。

### 2.3 顏色與字重

兩作以**綠字表示遊戲內容／可用命令、白字表示系統提示或目前選取**；
青色英文題頭另成一級。黑底上沒有陰影與抗鋸齒，日文仍是清楚的單色點陣。

可帶回《冬之魔》的不是固定色碼，而是角色分工：

- 正文、一般數值：theme 的文字主色。
- 目前選取、輸入提示：高亮色。
- 區段題頭：第二強調色。
- 危險、負值、敵方：警告色。
- disabled：保留既有網點語意，不只降低亮度。

倚天預設橫向加粗一像素比 PC-98 日文字模更重；繁體漢字筆畫也更密。
所以正文繼續用 20 px 行距，不為了表面一致硬壓回 16 px。固定表格與短命令列
才使用 16 px 行距。

### 2.4 六款系列畫面的共同語法

擴大樣本後，最穩定的不是某一套框線，而是下列資訊優先順序：

1. 探索、對話、商店和戰鬥可以重組主內容區，但隊伍狀態始終留在可預期位置。
2. 戰鬥畫面把戰場留給空間判讀，當前單位／目標數值集中在側欄，戰報與命令
   放在另一區；不以漂浮提示覆蓋棋盤。
3. 日文敘事採短段落、明確換頁提示。即使畫布容得下，也不把正文壓成滿屏小字。
4. 商店、營地、建角等高資訊量畫面改用整齊表列；探索 HUD 的裝飾不妨礙欄位對齊。
5. 同一套引擎可容納城鎮插畫、第一人稱探索、automap 與俯視戰場，因此
   《冬之魔》Modern EGA 應統一框、色彩角色與字級，而非把所有狀態硬套同一格版面。

對《冬之魔》最直接的新裁決是：世界／地城、一般戰鬥與海戰應共享資訊層級，
但允許各自保留適合玩法的主視窗比例。這比追求三種模式外框逐像素一致更接近
PC-98 Gold Box 的成熟做法。

## 3. 對目前中文規劃的裁決

### 保留

- 640×400 邏輯畫布。
- 倚天 16×15 字模置於 16×16 格。
- 38 格中文正文寬度與五行分頁。
- 固定表格 16 px 行距、長文 20 px 行距。
- 上方內容、右側狀態、下方訊息／命令的骨架。
- 中文標點 12 px 前進量；日文截圖不能推翻繁中禁則與標點壓縮。

### 補強

- 底部或訊息框中的「敘事」與「現在可按的命令」要用框、底色或固定位置分開。
- 戰鬥右欄優先顯示目前單位、目標、HP／SP／防護與武器；不堆疊低價值重複資訊。
- 抬頭、正文、選取、警告要有穩定的 theme 色彩角色，EGA／CGA／Modern EGA
  切換時只換色值，不換資訊語意。
- 表格標題與數值欄共用固定格線；全形英數沿用倚天，以免字重重新分裂。

### 不照抄

- 不複製 Golden Box 的寶石框、龍槍標誌、角色圖示或其他受版權保護素材。
- 不把《冬之魔》的探索／海戰操作改成 Golden Box 指令。
- 不因 PC-98 正文行距較密，就犧牲繁體漢字的可讀性。
- 不把 PC-98 的 16 色調色盤當成 DOS《冬之魔》的還原依據；它只可作
  Modern EGA 的低飽和配色參考。

## 4. 可驗收規格

後續 UI 截圖抽樣至少檢查：

1. 640×400 原生畫面下，正文每行最多 38 格，無半字與框外溢出。
2. 連續五行繁中長文仍可辨識，不因粗體與 16 px 行距黏成一片。
3. 世界、地城、戰鬥三種狀態都能一眼分出主內容、常駐狀態、情境訊息與命令。
4. EGA／CGA／Modern EGA 三主題中，相同資訊角色使用一致語意。
5. F8 切換只改 theme，不改斷行、欄寬、選取項目或遊戲狀態。

# Android／Web 版未來規劃

狀態：未實作，列為桌面版第一版之後的未來工作。

## 目標

讓沒有桌上型電腦環境的新世代玩家也能接觸《冬之魔》，同時維持三個邊界：

1. 遊戲規則、亂數、存檔格式與桌面版一致。
2. 公開發行不夾帶原版資料或倚天字型；玩家必須匯入合法副本。
3. 行動／瀏覽器介面可以更方便，但不暗改戰鬥、航海、謎題與故事旗標。

目前採用的 Ebitengine 官方支援 Android 與瀏覽器 WebAssembly，因此不需要另寫一套
遊戲規則引擎；真正工作量集中在素材匯入、持久儲存、觸控操作、音訊生命週期與平台
驗收。技術依據見
[`Ebitengine Mobile`](https://ebitengine.org/en/documents/mobile.html)及
[`Ebitengine WebAssembly`](https://ebitengine.org/en/documents/webassembly.html)。

## 共用前置工作

- 把平台檔案系統、存檔、素材匯入與離開事件收斂到明確介面，遊戲核心不得直接假設
  桌面路徑或鍵盤存在。
- 建立「資料包匯入精靈」：檢查必要檔名、雜湊或結構，拒絕缺漏與不相容資料；錯誤
  訊息使用繁中 JSON。
- 將 `F1`、`F6`、`F7`、`F8`、`F10` 與探索命令映射為可重綁的語意動作；鍵盤仍保留，
  觸控只呼叫相同動作。
- 以同一固定種子與 `tools/playthrough.sh` 路徑建立桌面、Android、Web 的跨平台
  狀態雜湊比對。
- 三主題都測試不同螢幕比例；遊戲邏輯畫布與碰撞不因縮放改變。

## Web 版：先做可安裝的離線試玩

### W0：編譯尖峰

- 建立 `GOOS=js GOARCH=wasm` 的最小建置，盤點目前依賴中不支援瀏覽器的檔案與音訊路徑。
- 第一版只使用使用者當次匯入的資料，不把原版素材放在伺服器或快取清單。
- 必須由「開始遊戲」手勢啟動音訊，處理瀏覽器對 `AudioContext` 的限制。

### W1：瀏覽器儲存與復原

- 將玩家匯入的資料包與存檔放入瀏覽器持久儲存；啟動時明示資料只留在本機瀏覽器。
- 提供存檔匯出／匯入，避免清除網站資料後永遠失去進度。
- 關閉分頁無法保證非同步寫入完成，因此重要節點與固定間隔主動存檔，不只依賴離開事件。

### W2：漸進式網頁應用與驗收

- 加入漸進式網頁應用（PWA）外殼、離線啟動、橫向全螢幕與桌面安裝。
- 驗收 Chrome、Firefox、Safari、Edge 的鍵盤、觸控、音訊恢復、資料匯入與存檔。
- 公開主機只部署引擎、remake 自製素材與授權文件；持續整合以 deny-list 掃描成品。

## Android 版：原生外殼加觸控介面

### A0：Android `.aar` 尖峰

- 依官方 `ebitenmobile bind` 流程建立 Android 原生外殼，先驗證啟動、暫停、恢復、
  音訊焦點與自動存檔。
- 以系統文件選擇器讓玩家匯入合法資料包；不要求廣泛儲存權限。

### A1：為 CRPG 設計的觸控層

- 左側方向區支援點按與長按；右側命令區使用分組頁籤與兩欄卡片，避免按鈕擠在一起。
- `F1` 對應固定的說明按鈕；主題、配樂與操作模式放入快速設定，不佔用戰鬥畫面。
- 地城精準移動與海戰相對轉舵要有不同觸控提示；不得用類比搖桿模糊方向。
- 觸控目標、字級與安全區要涵蓋小手機、平板、圓角及螢幕切口。

### A2：封裝與裝置驗收

- 先提供可側載測試包，再決定是否上架；簽章金鑰不得進入儲存庫。
- 至少抽樣一台低階手機、一台主流手機與一台平板；測試背景切換、來電中斷、
  藍牙鍵盤、長時間遊玩、耗電與記憶體壓力。
- 發行包同樣只含乾淨引擎與 remake 自製素材；完整原版資料永不上 GitHub 或商店。

## 建議順序與完成定義

1. 先做 Web W0，最快揭露核心中的桌面假設。
2. 完成共用平台介面後並行 W1 與 Android A0。
3. 觸控命令版面在 Web 手機瀏覽器先快速迭代，再落到 Android 原生外殼。
4. Web 通過跨瀏覽器 A6 抽樣後，才稱為公開測試版。
5. Android 通過真機中斷／復原與完整資料 deny-list 後，才產生對外測試包。

任一平台的「完成」都必須包含：可匯入合法資料、可從頭建立隊伍、可保存與恢復、
F1 說明完整、EGA／CGA／Modern Icon 可切換、配樂可關閉，以及固定種子 A6 代表路徑
與至少一個後期高風險場景的狀態一致性證據。

# 10 — 世界只有一格：邊界換圖解完了，但沒有呼叫端

A6（全程試玩破關）一直被當成「量級很大的體力活」。真的去排路線才發現
它根本還跑不起來 —— **世界地圖的邊界換圖沒有接上**，新遊戲那張子地圖
走到邊就再也過不去，另外 20 張一張都到不了。

---

## 1. 症狀是「世界只有一格」，而畫面上完全正常

`internal/assets/world/grid.go` 的 `CrossEdge` 早就照 `DEMON.INT`
0x16fec–0x17114 實作好，單元測試也齊（換圖四向 ＋ 世界邊緣擋住 ＋
不在邊界上的情形）。`docs/re/58` §2 連兩個回傳碼都列進表裡：

| 回傳 | 條件 | 附帶動作 |
|---|---|---|
| `0x15` | 跨子地圖：x==3／x==0x3c／y==3／y==0x3c | `+0xa3` ±1／±10、座標 wrap 到 4 或 `0x3b`、`+0xa9` 清 0 |
| `0x19` | 同上但已在世界邊界（欄或列到 1／7）| 印字串 |

`grep -rn CrossEdge --include=*.go .` 的結果是**三行，全在它自己的檔案裡**。

沒有呼叫端的後果不是報錯，是走到第 3／60 格時撞牆 —— 而撞牆本來就是
走地圖時最常見的事。**四輪試玩沒有一次撞到這個洞**，因為那幾輪都用
`-map` 直接跳到目標子地圖，跳過了唯一會用到這段程式碼的路徑。

> 這與 `docs/re/98` 的光之環門是同一類：**待辦清單把它們排成好幾列，
> 實際上是同一個消費端沒在做事。** 差別是那一次接得太寬（少了座標比對），
> 這一次是根本沒接。

`docs/re/64` §3 寫 `-glyphs` 旗標「非有不可，不然每次驗禁錮都要先跑完
整段主線」。那句話沒錯但不完整：**當時就算願意跑，也跑不到。**

## 2. 原版的兩個分支，逐指令

```
16fe1  cmpb $0xa, es:0xa3(%bx)      ; 地城（編號 < 10）整段跳過
16fe7  jae  16fec
16fe9  jmp  17117                   ; → 直接提交候選座標

16fec  cmpw $0x3, -0xa(%bp)         ; 候選 X == 3？（往西）
16ff2  mov  es:0xa3(%bx),%al
16ffd  idiv %cx                     ; cx=10 → ax=欄、dx=列
16fff  cmp  $0x1,%ax                ; 欄 == 1 → 世界西緣
17004  mov  0x50f0,%ax  →  -0xa(%bp)   ; X 從全域還原
1700a  mov  0x50ee,%ax  →  -0xc(%bp)   ; Y 從全域還原
17010  mov  $0x19,%ax; jmp 16a45       ; 回傳 0x19
17016  add  $0xfff6,%ax → es:0xa3(%bx) ; 否則 map_id −= 10
17025  movw $0x3b,0x50f0                ; X ← 59
1702b  movb $0x0,es:0xa9(%bx)           ; nSS 快取旗標清 0
17031  mov  $0x15,%ax; jmp 16a45        ; 回傳 0x15
```

其餘三向（`0x17037` 往南、`0x17082` 往北、`0x170cd` 往東）形狀完全一樣。
`0x17117` 是共同的收尾：把候選座標寫回 `0x50f0`／`0x50ee`。

兩件事因此定案：

- **`0x50f0` 是 X、`0x50ee` 是 Y。** 往西那一支把 `0x50f0` 設成 59，
  往南那一支把 `0x50ee` 設成 4 —— 各自對上 wrap 的那一軸。
- **走到世界邊緣是「這一步不存在」，不是「停在邊界格上」。**
  擋住的那一支把**兩軸都從全域還原**。這一點要照做：停在邊界格上的話
  下一步又觸發一次判定，玩家會看到訊息連發。

動作 `0x19` 印的是 *"Your crew refuses to sail any further…"*
（`docs/re/50` 動作表）。措辭假設玩家在船上 —— 世界邊緣那一圈是海，
走著到不了（§4 量到的結果支持這個讀法）。原版沒有分「在船上／沒在船上」，
`cmd/demonwinter/worldedge.go` 也不分。

## 3. 接上之後：實機驗證

```
tools/screenshot.sh … KEYS=Return,Right,Right -map=34 -x=59 -y=50 -trace=…
   6  野外  ( 5,50) 地圖44
```

從子地圖 34 的 (59,50) 往東兩步：第一步踩到 X==60 → 換到 **44**、X wrap 到 4；
第二步走到 (5,50)。`34 + 10 = 44` 對上「X 方向動十位數」。

反向的對照組也驗了：34 的 (28,59) 往南 → 「前方無法通行」。
邊界那一格是海，**走著過不去** —— 原版的可通行性檢查在分派之前
（`docs/spec/04-movement.md` 第 8 步 vs 第 10 步），所以這是對的行為，
不是漏接。

世界邊緣那一支（`0x19`）**沒有實機驗到**：21 張子地圖裡欄與列都到 6，
沒有欄 7／列 7 的圖，而欄 1／列 1 的三張（12、13、21…）外緣那一圈是海，
走著到不了。它要在船上才驗得到，留給 A6 的航海段。

## 4. 順帶把路線工具擴成跨子地圖

`dwroute` 原本只在單張圖裡找路，問不出「走不走得到 55」。
新增三個旗標：

```
dwroute -world       -from 34:28,50 -to 55:47,22   # 跨子地圖，自己換圖
dwroute -world-reach -from 34:28,50                # 走得到哪幾張
dwroute -world-reach -from 34:28,50 -sailing       # 有船的話到得了哪裡
```

判定沿用引擎自己那幾支：可通行性用 `gamedata.Tables.Passability`、
換圖用 `world.CrossEdge`、海面用 `game.IsOcean`、出口用 `EXITS.DAT`
加 `docs/re/85` 的 `0xfd` 判別式。**規劃用的判定與遊戲用的判定是同一份。**

三個刻意的取捨：

1. **出口是強制的，不是選項。** 踩到出口格就被送走（引擎 `checkExit`），
   所以規劃時不能把出口格當普通路面走過去 —— 那樣排出來的路線實跑會斷。
2. **落點不檢查可通行性。** 原版換圖直接寫座標，不查落點。照做。
3. **`-sailing` 是上界不是可行路線。** 它假設全程在船上，沒模擬上船
   （要走到船停的那一格）與下船。它回答的是「就算有船，到得了嗎」。

## 5. 量出來的三件事

### 5.1 沒有船，主線走不完

從新遊戲的 34:(28,50) 出發：

| 模式 | 走得到 | 內容 |
|---|---|---|
| 只算陸路 | **4 張** | 34、44、地城 1、地城 2 |
| 含航海 | **23 張** | 上面加 21 張世界子地圖與地城 3／4／5 |

**買船不是選配，是主線必經。** 手冊把船寫成一種交通工具，而量出來的
結果是「沒有它連東南角都到不了」。

### 5.2 破關地點在 220 步外

含航海的最短距離：

| 目標 | 步數 | 主線用途 |
|---|---|---|
| 子地圖 55 | 98 | 第一個符印 |
| 子地圖 56 | 154 | 第二個符印 |
| 子地圖 66 | 210 | 第三個符印 |
| **地圖 5** | **220** | **光之環 → 禁錮 → 破關** |

三個符印在 98／154／210，破關在 220 —— 順序與距離自然吻合，
不必另外排優先序。這也解釋了為什麼 `-glyphs` 當初非有不可。

### 5.3 41／51／52 進不去（未解）

21 張子地圖裡有三張，含航海也走不到：

- 網格上 **41／51／52 自成一個孤島**（往東的 61、往北的 40／50、
  往南的 42／53 都不存在，欄 1 那一側是世界邊緣）。
- `EXITS.DAT` 只有一筆通往這個群：`(40,59) → 51:(45,8)`，
  而 (40,59) 在**地圖 2**。
- 地圖 2 從外面進得去的兩個入口是 `2:(10,45)`（來自 34）與 `2:(2,19)`
  （來自 22）。**兩個都走不到 (40,59)**，含航海也走不到。
- `2SS.DAT` 的類別 4（傳送）**是 0 筆**，所以不是靠傳送格接的。

三張圖上有城鎮一座、神殿兩座、學院六座 —— 不像廢棄內容。
**沒有結論**：可能是劇情傳送（冥河擺渡人那一類）、可能是還沒接的機制、
也可能原版就進不去。要查的話從「地圖 2 那個區塊還有什麼入口」開始，
別從「是不是廢棄內容」開始 —— 那是猜。

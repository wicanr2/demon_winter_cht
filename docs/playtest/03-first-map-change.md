# 03 — 走出地城：換地圖接上了

`docs/playtest/02` 的結論是「下一個障礙不是戰鬥了，是換地圖」。這一篇就是它。

---

## 1. 缺的不是解碼，是呼叫端

`EXITS.DAT` 兩個月前就解好了（`docs/re/78` §6），啟動時也載進來了。
**但沒有任何地方查過它。**

這是最難發現的一類洞：解碼有測試護著、測試全綠、文件寫得完整 ——
只有「誰在用它」是空的。症狀是玩家走到樓梯上什麼都不會發生，
沒有錯誤、沒有訊息，看起來就像那一格本來沒事。

`CONTEXT.md` §7 A2 一直把它列在「動作層還沒接」裡，但列表上的字
不會告訴你**它有多接近可用**。

## 2. 第一版的觸發條件是錯的

照 `docs/re/05` §3 實作了「tile 遮罩後 == `0x11` 或 `0x53`」——
然後拿資料一對就穿了：走得到的出口候選，來源 tile 是
`0x24`／`0x13`／`0x00`，**一個 `0x11` 都沒有**。

> ⚠ **這裡原本寫「從起點走得到的五個出口」，那個數字是錯的。**
> 當時用的 `tools/route.py` 沒有套 `0xfd` 判別式，把別的地圖的出口
> 也列進來了。**從起點走得到的出口只有一個**（(22,21)）——
> 見 `docs/playtest/05` §1。結論（tile 閘門不成立）不受影響：
> 那一個出口的 tile 是 `0x24`，照樣不是 `0x11`。

真正的條件是**可通行表值 == `0xfd`**，而答案本來就在 `docs/re/58` 的
分派表裡（動作 `0x14`）。完整經過與那條可被資料打死的驗證寫在 `docs/re/85`。

> 值得記的是**怎麼發現的**：不是重讀反組譯，是**先算「哪些出口走得到」**，
> 再看那些格子的 tile 是什麼。實作逼出了一個資料查詢，
> 而那個查詢立刻推翻了文件。
>
> 如果照錯的條件寫完就收工，測試會全綠（沒有測試涵蓋觸發條件），
> 而遊戲裡的樓梯全部是死的。

## 3. 實跑：從地城走到地面

零捷徑（只有 `-autofight`），從原版出貨存檔開始：

```
  26  野外  (20,23) 地圖1  訊息="有陷阱！"  文字框
  ...
  33  野外  (22,20) 地圖1
  34  換地圖 → 34 (55,8)
  35  野外  (55, 8) 地圖34  訊息="進入地圖 34 的 (55,8)"
```

26 步走到 (22,21)，換到地圖 34 的 (55,8)。截圖確認畫面從地城的
石牆換成了世界地圖的山地地形。

**順帶驗到兩件不是這一輪做的事：**

- 第 26 步的「有陷阱！」是 `nSS.DAT` 類別 3 的路徑（`docs/re/83` 接的），
  第一次在真實走路中觸發。
- 地圖 34 來自 `SUM.MAP` 的段，不是獨立檔案 —— 換圖的兩個來源都走通了。

## 4. 一個沒有靠運氣的安全性

出口的落點自己也可能是出口 tile（實測有：三筆記錄都通往圖 34 的 (55,8)，
而那一格 tile 是 `0x24`，可通行表值正是 `0xfd`）。

會不會一落地就再觸發一次、無限換圖？不會 ——
**因為檢查點掛在「移動成功之後」，而換地圖用的是傳送不是移動。**

這不是運氣，是原版把檢查放在移動迴圈裡的必然結果。
但值得寫下來：如果哪天有人「順手」把 `checkExit` 移到每幀檢查，
它會變成無限迴圈，而且症狀是畫面瘋狂閃爍，不會有人聯想到這一段。

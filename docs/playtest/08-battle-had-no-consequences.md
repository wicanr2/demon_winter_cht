# 08 — 戰鬥一直沒有後果

這一輪要做的是 `docs/re/58` §4 的動作 `0x18`（全隊死亡）。
接的時候發現：**那個動作永遠不會成立，因為戰鬥的傷害從來沒有回到隊伍身上。**

---

## 1. 動作 `0x18`：全隊死亡

原版那支很短（`25be:000c`）：印四行字，回傳 −1。

```
A cold breeze
chills the air...
...all characters
have died.
```

**11 個呼叫端**散在戰鬥結算、飢餓／中毒推進、事件處理那幾條路上 ——
也就是**任何一條會扣血的路都要檢查一次**，不是只有戰鬥。

在這之前，引擎只在戰鬥結算裡印一行「隊伍全滅」的紀錄，然後回世界地圖。
一支全員陣亡的隊伍照樣可以走路、紮營、進城，而畫面上沒有任何異常。

## 2. 接的時候才發現：傷害根本沒寫回去

引擎把角色複製成 `Unit` 上場，傷害只寫在 `Unit` 上。
搜 `writeBackFromUnit` 的呼叫端 —— **只有一個，在營地施法那裡。**

所以：

- 打完一場慘勝回到地圖，**全隊滿血**。
- 打輸了每個人也還是滿血 → `PartyWiped` 永遠 false → **死亡畫面永遠不出現**。

**戰鬥完全沒有後果。**

### 為什麼四輪試玩沒看出來

三個條件疊在一起：

1. **戰鬥畫面上的血量是對的** —— 那是 `Unit` 的值。單看戰鬥截圖沒問題。
2. **軌跡只記位置與畫面**，不記血量。走完一段路的軌跡看起來完全正常。
3. 要看出來得在戰鬥**前後各看一次隊伍名冊** —— 而驗收從來沒這樣做過。

> 這是移植架構自己引入的缺口。原版沒有「複製一份上場」這回事 ——
> 角色記錄就是戰鬥用的那份資料（`docs/re/20`），所以它不會有這個問題，
> 也不需要對應的程式碼。**照原版逐指令對，是對不出這種 bug 的。**

### 修法

`game.WriteBackParty(members, units)`，在戰鬥結算時呼叫一次。

配對用**槽位**不用名字：三段槽位不相交（怪物 0–6、隊伍 7–11、召喚 12–14），
而按名字找（`u2c` 那種）遇到同名角色會配錯 —— 遊戲允許同名，建角不查重複。

**判別式不看 `Side`**：被魅惑的隊員 `Side` 會變成 `SideCharmedPlayer`，
用 `Side == SidePlayer` 篩會把他的傷害漏掉。槽位不會變。

## 3. 血量進軌跡

加一欄。理由就是上面第 2 點 —— 這一整類 bug 之所以隱形，
是因為軌跡裡沒有隊伍狀態。

實跑（`-battle -autofight`）：

```
   6  戰鬥  ( 9,32) 地圖1  第4回合  血24/21/25/26/15
   7  戰鬥  ( 9,32) 地圖1  第4回合  血21/21/25/26/15   ← 結算寫回
   8  野外  ( 9,32) 地圖1           血21/21/25/26/15   ← 帶著傷回到地圖
```

修之前第 8 行會是 `24`。

換硬一點的怪再跑一次：`血0/13/15/0/0` —— 三個人死了，而且死了就是死了。

## 4. 順手修掉自己上一輪弄壞的東西

跑試玩一直失敗，log 是：

```
載入地圖：SUM.MAP 沒有子地圖 1，可用的是 [12 13 2 21 ...]
```

**上一輪的 regression。** 我把 `-map` 的預設改成「用存檔的 MapID」，
而出貨存檔的 MapID 是 `1` —— 送進 `loadMapArg` 之後被當成
`SUM.MAP` 的段編號查，而地圖 1 是獨立檔案 `MAP1.MAP`。

`mapchange.go` 那份 `loadMapByID` **有** 1／3／5 的特例，`loadMapArg` 沒有。
**同一條規則兩份實作，我改了預設值卻只驗了其中一條路**
（`-newgame` 的 MapID 34 剛好在 `SUM.MAP` 裡）。

而且不只兩份 —— `cmd/dwroute` 也自己抄了第三份。

修法：合成一份 `world.LoadByID`，三個呼叫端都用它，附測試
（獨立檔案的 1／3／5 加 `SUM.MAP` 的每一段都要載得到）。

> 這是「同一件事只留一份實作」在這個 repo 裡的**第四次**教訓
>（前三次：`route.py` 的檔頭偏移、Python 的道具槽步長、`0xe8` 的字面值 grep）。
> 前三次的代價是誤判；這一次的代價是**上一輪 push 出去的東西啟動就壞**。

## 5. 還有一個工具缺陷

外層 `timeout` 砍掉 `playthrough.sh` 時，`docker run --rm` 的容器**會活下來**
（砍的是 shell，不是容器）。三個孤兒容器同時跑，互相搶 CPU，
於是後續每一次試玩都慢到像卡住 —— 而 log 上什麼都看不到。

加 `--name` + `trap cleanup EXIT INT TERM`。

## 6. 死亡畫面驗過了

要截到那張圖得先真的打到全滅。做法沒有捷徑：先打一場硬仗
（`-battle-monsters 60,61,62,63`）把隊伍打成 `0/13/15/0/0`、存檔，
**再從那份存檔開一場同樣的硬仗** —— 兩個殘血的人撐不過兩回合。

```
   4  戰鬥  ( 9,32) 地圖1  第2回合  血0/13/15/0/0
   5  全隊死亡
```

存檔往返也順便驗到了：第一輪存出去的 `PARTY.DAT` 血量是 `[0,13,15,0,0]`，
第二輪讀回來一樣。

畫面：一陣冷風／讓空氣凝結……／……全隊／都死了。＋（按任意鍵離開）

### 順手補一個軌跡的洞

第一次跑出來，全隊死亡之後軌跡寫的是「野外」——
`screenName()` 少了 `a.death` 那一格。**軌跡與 `Update` 的分派順序不一致，
軌跡就在說謊**，而這一輪要抓的就是這個狀態。

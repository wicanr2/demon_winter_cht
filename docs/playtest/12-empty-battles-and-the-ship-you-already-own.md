# 12 — 每一場遭遇都是空的，還有那艘一開始就有的船

`docs/playtest/11` 把 A6 第一段跑完了，但留下一個沒解釋的數字：
**200 步、四場戰鬥，金幣／血量／法力／糧食四個值一個都沒動。**

追下去是本輪第三個「解完但沒有呼叫端」，而且比前兩個嚴重 ——
**從新遊戲開始的隊伍永遠打不了仗。**

---

## 1. 症狀：仗打完什麼都沒發生

軌跡長這樣：

```
  22  野外   (33,42) 地圖34  血13/11/7/6/11
  23  戰鬥   (34,42) 地圖34  第1回合  血13/11/7/6/11
  24  野外   (34,42) 地圖34  血13/11/7/6/11
```

一回合就結束、沒有傷害。而勝利本來要給金幣（每隻怪
`1.7^等級 + Roll(2.1^等級) + 3`，1 級怪 5–6 枚，`docs/re/56` §3）——
金幣停在 75。

三個候選解釋：勝利沒給錢、怪物立刻逃走、或者**這場仗根本沒有我方單位**。

## 2. 原因：陣型九格全是 `0xff`

`startBattle` 照陣型佈陣：

```go
x, y, ok := game.DeployPartyAt(a.save.Formation, i)
if !ok {
    continue // 陣型裡沒有他就不上場
}
```

那個 `continue` 是對的，而且是**刻意的**：十間試煉室就是靠「把陣型清空、
只填回符合職業的人」做出單挑（`docs/re/101` §2），加保險會讓五個人全上場。

問題在另一頭 —— `ApplyNewGame` 把九格全部寫成 `0xff`（照原版
`0x14984` 的迴圈），而**建角沒有把人放回去**。於是：

- 每一場隨機遭遇都只有怪物、沒有我方單位
- 一回合就結束，沒有傷害也沒有戰利品
- 畫面上完全正常，軌跡也完全正常 —— 只是四個數字都不動

`startBattle` 的註解甚至寫著「入隊會找第一個空格、**建角與新遊戲都會把人
放進陣型**，所以『不在陣型裡』只會是刻意的」。那句話是錯的。

### 原版做了，而且我們早就記下來了

`docs/re/34` §3：

```
15089  for i := 0; i < 9; i++ {
15090    if party[i] == 0xff { party[i] = party[+0x9a]; break }   ; 新人的編號就是舊人數
       }
```

就在人數 `+0x9a` 遞增（`0x15109`）的前一步。

`internal/game/formation.go` 的 `AddMember` **就是這段的實作**，
連註解都標了 `0x15089`，單元測試也有 —— 而 `grep -rn AddMember` 的結果
是三行，全在它自己的檔案裡。**又一個零呼叫端。**

> 三個一起看（`CrossEdge`、`AddMember`，加上 `docs/re/98` 的光之環門）：
> 這一類缺口的共同形狀是**「函式有、測試有、文件有，就是沒有人叫它」**。
> 它不會出現在任何待辦清單上，因為每一份清單都是照「解了沒」列的。
> 抓得到它的只有實跑，而且要**看狀態不只看畫面** ——
> 這三次都是靠軌跡裡的數字，不是截圖。

修法一行：建角確認槽位時，不在陣型裡就放進第一個空格。
判斷「已經在裡面就不再加」是為了 `F1`（覆寫既有槽位，每次都加會把同一個人
塞進好幾格）。

## 3. 修完之後：仗是真的，隊伍也真的會死

同一條路線、同一個 seed 重跑：

```
  23  戰鬥   (34,42) 地圖34  第1回合  血13/11/7/6/11
  24  戰鬥   (34,42) 地圖34  第2回合  ...
 113  戰鬥   (15,11) 地圖44  第2回合  血13/8/0/6/0
 118  全隊死亡
 119  死亡   (15,11) 地圖44  血0/0/0/0/0
```

**五個 1 級角色徒手走 100 步，在子地圖 44 被打光。** 這不是 bug ——
攻略第一句就是「往北走到海濱鎮，先把裝備買齊。我會建議每個人先買一把匕首，
再買一件布甲給其中一名角色」。空手上路本來就會死。

所以 `docs/playtest/11` 的第一段路線（101 步直奔新格里昂）順序是錯的：
**買裝備要排在走長路之前。**

## 4. 順帶：那艘一開始就有的船

`docs/playtest/10` §5.1 寫「買船不是選配，是主線必經」，量測沒錯
（陸路只到 4 張子地圖），但**結論下得太快** —— 新遊戲就給了一艘船：

```go
// 起始那艘船（`0x14956`–`0x1497a` 寫的是船隻陣列第 9 格）
NewGameShipSlot  = 9
NewGameShipX     = 13
NewGameShipY     = 51
NewGameShipMapID = 1
NewGameShipHull  = 67   // 不是滿值 75 —— 一開始就是一艘半舊的船
```

那艘船在**地圖 1 的 (13,51)**。

> **2026-07-28 訂正：下面「開局 36 步可拿船」的結論不成立。**
> `EXITS.DAT` 的確有 `(25,48) → 1:(20,48)`，但來源座標沒有 FromMap；
> 必須再由來源格的 passability `0xfd` 判斷它屬於哪張圖。逐圖掃描後，
> `(25,48)` 被**子地圖 64**認領，不是起點所在的 34。實跑從 34 走到
> `(25,48)` 也只會留在原地圖。以下表格保留作為錯誤推論的紀錄，
> 不再當成玩家路線。

| 步驟 | 座標 | 步數 |
|---|---|---|
| 起點 | 34:(28,50) | — |
| 走到地圖 1 的入口 | 34:(25,48) | **5** |
| 換圖落點 | 1:(20,48) | — |
| 走到船邊的陸地 | 1:(13,52) | **31** |
| 往北一步上船 | 1:(13,51) | 1 |

(13,51) 的 tile 是 `0x41`，三面鄰居是 `0x62` ＝ `tileOceanB` ——
**它是停在水上的船格**，所以路線規劃器問「走不走得到 (13,51)」永遠是否，
要問的是「走不走得到旁邊那格陸地」。這一格從九個地圖 1 的入口裡
只有 **(20,48)** 與 **(6,41)** 那兩個進得去。

> 找它花了幾輪，因為第一個問法是錯的：拿船的座標直接餵給 `-to`。
> **船停在水上，而水在可通行表裡是擋住的** —— 上船是靠 `Boardable`
> 這個例外，不是靠可通行性。要問的是它的鄰居。

原本據此推論「買船是備案」也一併撤回。靜態可達性顯示新遊戲陸路只到
34／2／44／1；能落到船所在連通區的 `(20,48)` 入口來自子地圖 64，
另一個 `(6,41)` 則由地圖 1 內部的 `(45,1)` 傳送而來。起始船可能是
中後段由地城另一區取得的船，不能再當作開場捷徑。

⚠ **還沒驗的一段**：那艘船停在地圖 1 的水域，而地圖 1 不是世界子地圖
（編號 < 11），邊界換圖對它不適用。從那片水域怎麼開到世界地圖上 ——
要靠某個海路走得到的出口格，還沒查。這是 A6 下一段的第一個問題。

## 5. 買裝備那一段：腳本的第二類坑

改成照攻略走（先到海濱鎮買裝備）之後，市集本身一次就通了：
游標開在匕首（2 金），`B` 五次 → 75 金變 65 金，訊息
「a 買下匕首，付 2 金（剩 65）」。布甲是道具表第 8 項（0–7 是八種武器）。

分裝備與裝上就沒那麼順，踩到三個坑：

**（1）踏進城鎮那一步不能用 `rep`。** `rep` 每一步之後都會 `settle`，
而 `settle` 的白名單只有「野外」，其餘一律送 Escape ——
剛進城就被踢出來，`m` 於是落到世界地圖上變成「推開家具」。
軌跡連續兩行「進入海濱鎮」「離開海濱鎮」就是這個。

**（2）收方游標預設指向「下一個人」**（`p.target = (p.member+1) % len`），
不是第一個人。給第二個人要 0 次 Down。

**（3）交出之後那一格會變空，剩下的不會往前補。** 所以第 k 次要選第 k 格；
一直選第 0 格的話第二次就撞到「這一格是空的」。

**（4）裝上成功之後畫面會自己關回紮營選單**（`c.equipMember, c.equipSlot = -1, -1`），
**不要再送 Escape**。多送的那一下會把紮營收掉，接下來的方向鍵直接走到世界地圖上，
而 `key s` 在紮營選單裡是**睡覺**不是存檔 —— 於是截圖看得到「a 換上匕首」，
存檔裡卻什麼都沒裝上。

**（5）每一段都要先關掉標題畫面。** 從存檔接續一樣會先進標題，
第一個按鍵會被它吃掉。

> **教訓：跨模態選單的長腳本不要一次寫完。** 拆成三段、每段結尾存檔、
> 下一段從存檔接續，錯的時候才不會連鎖。而且**`PARTY.DAT` 本身就是比截圖
> 更確定的驗收訊號**：金幣、背包型別、裝備格全在裡面，一行 python 就讀得出來，
> 不必判讀畫面。
>
> ```
> 金幣 60　陣型 [0,1,2,3,4,255,255,255,255]
> a 背包 [255,255,255,255,0,8,…] 武器格 4 護甲格 5
> b 背包 [0,255,…]               武器格 0 護甲格 255
> ```

拆完之後三段一次通：`a6-leg1.txt`（建角 ＋ 買）、`a6-leg2-share.txt`（分裝備）、
`a6-leg3-equip.txt`（裝上）。五個人各一把匕首、a 多一件布甲護甲 1，
與攻略的第一句完全一致。

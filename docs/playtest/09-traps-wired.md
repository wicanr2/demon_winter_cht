## 2. 實跑：從出貨存檔走 35 步去踩一格陷阱

`cmd/dwroute` 找路 → `tools/playthrough.sh -autofight -seed 7` 驅動。
路上真的踩到兩個毒針、打了一場仗，然後走到 (12,17) 按 `L`：

```
  27  陷阱 Poison needle hits
  28  野外 (20,23) 訊息="毒針射中了\nPodgom 受到傷害 2"   血24/21/23/26/15
  37  陷阱 Poison needle hits
  38  野外 (19,17) 訊息="毒針射中了\nMenhir 受到傷害 1"   血24/21/23/26/14
  51  查看陷阱：1 個（已注意）
  53  陷阱 A pool!
  54  野外 (11,17) 訊息="即使再小心\n還是觸動了陷阱\n一池水！
       \nWopple 受到傷害 2 ×3\n受到傷害 1\n受到傷害 0\n受到傷害 1
       \nWopple游了出來"                                  血16/21/23/26/14
```

三件事同時驗到：

- **血真的會掉**，而且掉進存檔（`24 → 23 → 16`，軌跡逐行可查）。
- **水池是一輪一輪擲的**：六輪 `2,2,2,1,0,1` 才游出來 ——
  手冊「每回合有 33% 機率脫困」。**傷害 0 出現了**，
  那是 `Roll(3)−1` 的合法結果，不是 bug。
- **類別 6 走的是另一條**：先印「即使再小心／還是觸動了陷阱」
  才進陷阱本體 —— 那 50% 的迴避這次沒擲中。

截圖：`03-look-found.png` 白框畫在隊伍框左邊那一格（面向西、距離 1）；
`04-trap-fired.png` 六行傷害之後**下面照樣跳出房間敘述** ——
原版印完陷阱訊息還是會走文字路徑，`springTrap` 回 `false` 是對的。

## 3. 出貨資料裡就有一格「已注意」的陷阱

`internal/assets/scenario/specialtiles.go` 的註解寫著：

> 類別 6 …**出貨資料裡一筆都沒有** —— 程式路徑留著、資料沒用到。

**錯的。** `1SS.DAT` 的 `(11,17)` 就是一筆，而且就是這一輪踩到的那口水池。

推起來很順：`nSS.DAT` 是存檔（`docs/re/78`），出貨的 `PARTY.DAT`
又是一份玩過的存檔（`docs/re/87`）—— 那一格是 **1988 年那位玩家
自己按 `L` 標下來的陷阱**，跟著母片一起出貨了三十八年。

釘成 `TestShippedDataHasANoticedTrap`。

## 4. 一個方法上的提醒（又踩了同一個坑）

為了找「哪裡有陷阱」，我先寫了一段 python 自己切 `nSS.DAT` 的 3-byte 記錄。
它列出來的類別 3 座標是 `(12,38)`、`(58,21)`… **一個都沒對**：
實跑踩到的是 `(20,23)` 與 `(19,17)`。

那段 python 是**第二份實作**，而它漂掉了。
唯一沒漂的是類別 6 那一筆 —— 純屬運氣。

正確的做法是後來做的：用專案自己的 `ParseSpecialTiles` 寫一條測試。
**這是同一個 session 內第五次踩「一條規則只留一份實作」**
（前四次：`route.py` 的檔頭偏移、Python 的道具槽步長、`0xe8` 的字面值 grep、
三份 id→map）。這次代價很小，因為結論沒有寫進文件就先被實跑推翻了 ——
但如果我當時拿那些座標去寫「陷阱分布」的筆記，就會多一份看起來很合理的假資料。

## 5. 沒驗到的

- **解除陷阱那一條沒有實機驗**：隊伍裡沒有盜賊，也沒有給技能的偵錯旗標。
  單元測試蓋了（`TestLookForTrapsWithDisarmClearsTheTile`），實機還沒有。
- **`L` 的 25% 分支沒有實機驗**：這支隊伍剛好也沒有察覺陷阱技能，
  但那一格是類別 6、擲中了才顯示 —— 也就是說 25% 這條**實際上有跑到**，
  只是沒有辦法從單一次結果分辨它和 100% 的差別。
- **陷阱打死人時「全隊各掉 1 點」那條**（`25be:145c` → `222f:0619` 模式 `0x80`）
  照反組譯實作了，但**沒有用 DOSBox 複核**。讀起來很怪，列進 `CONTEXT.md` §7 C 區。
- 起手那一下 `key l` 被標題畫面吃掉了（`01-look-none.png` 拍到的是標題剛關掉之後）。
  腳本層的問題，不影響結論 —— 真正的 `L` 在第 51 行。

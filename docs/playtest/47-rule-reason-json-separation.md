# 47 — 規則層原因文字 JSON 分離與檢查器補強

日期：2026-07-30

## 問題

先前 `dwstrings uicheck` 只掃 `cmd/demonwinter`，因此雖然畫面程式沒有硬編
中文，`internal/game` 回傳的 `Reason` 仍直接帶著玩家文案，例如「金幣不夠」、
「這一格是空的」。介面把它原樣顯示，實際上仍讓引擎規則與繁中文案耦合。

另有一個檢查器缺陷：掃描器能列出硬編字串數量，卻沒有把數量加入失敗條件，
所以即使 `-list` 顯示 23 條，命令仍回報通過。

## 修正

- 規則層 `Reason` 現在只回傳 `reason.*` 穩定 key。
- 需要角色名稱或數值的訊息以 `ReasonArgs` 傳遞；規則層不負責組句。
- 介面統一由 `app.reasonText` 查 `ui.json` 並套入參數。
- F8 主題名稱、切換提示與海戰玩家船名稱一併移入 JSON。
- 城鎮設施只回傳既有 `town.menu.label_*` key。
- 戰鬥動作在規則測試中只保存英文穩定識別字，不再保存未使用的中文名稱。
- `uicheck` 同時掃 `cmd/demonwinter` 與 `internal/game`，且任何硬編玩家中文
  都會讓命令以失敗結束。

## 驗證

強化後的檢查結果：

```text
介面文案：已遷 836 條（其中 135 條 key 是算出來的）／目錄 836 條／還硬編 0 條
介面文案檢查通過
```

規則測試另外釘住動態資料邊界：收件人名稱、獵人名稱與治療對象名稱必須位於
`ReasonArgs`，不得重新串成文案。`internal/game` 與 Xvfb 下
`cmd/demonwinter` 測試均通過。

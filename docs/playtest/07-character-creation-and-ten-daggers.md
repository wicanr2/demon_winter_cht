# 07 — 建角接進新遊戲，順手抓到「十把匕首」

`docs/re/87` 把新遊戲的**起點**修正了，但 `-newgame` 當時只設隊伍共用欄位 ——
五個角色還是出貨存檔那五個。這一篇把最後一段接上。

---

## 1. 強制建滿五個

原版的建角在遊戲外（`Character Utilities`），玩家必須先造好隊伍
才有存檔可以載。本作沒有那支獨立程式，所以做成**新遊戲開場的強制流程**：
五個槽位都建過才走得動。

為什麼要強制而不是「可以跳過」：不強制的話玩家會拿著**別人玩過的角色**
從正確的起點開始 —— 而**畫面上看不出那五個人不是自己建的**。

兩道保險：

- 建角畫面的 ESC 在強制流程裡不關畫面（退到底只會提示還剩幾個）。
  五個沒建完就沒有隊伍，關掉只會讓玩家卡在一個沒有隊伍的世界地圖上。
- `Update` 裡加一道：`a.create == nil && newGamePending()` 就開回來。
  任何一條把 `a.create` 設成 nil 的路徑都會讓玩家帶著半套隊伍溜出去。

流程驗證（軌跡）：

```
   3  建角  (28,50) 地圖34
   4  建角  … 訊息="a 已加入隊伍第 1 位"
   ...
   8  野外  (28,50) 地圖34  訊息="隊伍組好了。按 S 存檔。"
```

五個角色照順序建滿，然後才放行。名冊上是五個 1 級角色、一族一個。

---

## 2. 抓到的 bug：新角色帶著十把匕首

第一次跑完看名冊，五個人的武器欄都寫**匕首**，護甲 0。
一支剛建好的隊伍不該有武器。

原因很短：`scenario.InventorySlot` 的**零值是 `Type == 0`**，
而 `0` 是「匕首」這個道具型別。空槽的值是 **`0xff`**（`scenario.SlotEmpty`）。
`Finish()` 建 `Character{...}` 時沒動 `Inventory`，於是十格全是匕首。

`weaponLabel` 本身是對的 —— 它在 `w.Empty()` 時回「徒手」。
問題是那一格**不是空的**，它是一把匕首。

### 為什麼躲過了所有先前的驗收

**因為在這一輪之前，沒有任何路徑會產生「零值的背包」。**

從存檔載入的角色，十格都是檔案裡的真資料 —— 零值永遠不會出現。
`F1` 雖然一直能用，但它是覆寫既有槽位，而測試與截圖驗收看的都是
「擲點對不對、職業對不對」，沒有人看武器欄。

> 這是**真正開新遊戲**才會暴露的那一類 bug：
> 它不在任何既有測試的路徑上，也不在任何既有截圖的畫面裡。
> 而它對玩家很顯眼 —— 第一次打開名冊就看到五把不存在的匕首。

修法：`Finish()` 明確把十格設成 `SlotEmpty`，並把裝備索引設成 −1。
釘成測試（`TestFinishClearsInventory`），斷言連 `ArmorRating()` 也是 0。

## 4. 已經比對完了（`docs/re/88`）

原本這一節寫「還沒與原版逐欄比對，現在的實作是推論不是驗證」。
**已經驗完**：角色記錄的基底是 `ds:0x4c7e`（步長 `0x104`），
建角對它做四件事 ——

| 位址 | 動作 |
|---|---|
| `0x14dc5` | 等級 ＝ 1 |
| `0x150d1` | 迴圈十次清空背包（`Type = 0xff`）|
| `0x150ed`／`0x150ff` | 裝備武器／護甲槽 ＝ `0xff` |
| `0x15109` | trailer 的人數 +1 |

所以本篇的修法方向是對的，但**當時的理由不完整** ——
我只推了「零值 `Type == 0` 是匕首」，而兩個裝備槽索引是靠「合理」補的。
現在兩者都有指令依據。順帶補上「人數隨建角遞增」（原本留著出貨的 5，
剛好對但那是巧合）。

仍未實作：`+0xe8 = [+0xf8]`、`+0xe9 = [+0xfb]` 兩處欄位複製，語意未解。

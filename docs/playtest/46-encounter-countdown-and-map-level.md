# 46 — 遭遇倒數、出口難度來源與存檔欄位收尾

日期：2026-07-30

## 結論

這一輪關掉兩個「後期研究已解、執行期仍沿用早期近似」的落差：

1. 新遊戲遭遇倒數是 `Roll(5)+0x0e`，本專案的 `Roll` 為 1-based，
   所以正確值域是 **15–19**，不是 14–18。
2. 遭遇難度不是隊伍最高等級。進圖時原版以存檔 `+0xaf` 初始化
   `ds:0x5c60`；踩 `EXITS.DAT` 出口時，第六欄會寫回 `+0xaf`。
   劇情階段 `+0xb9 == 2`（冬之魔已降臨）再加 2，上限 10。

同輪移除 `SaveGame.Unknown9C`：它和已命名的 `EncounterCountdown` 指向同一個
`+0x9c`，雙重欄位會讓載入／寫回順序掩蓋錯誤，並不是兩份資料。

## 實作邊界

- `EXITS.DAT` 第六欄改名 `MerchantBase`，換圖成功後才寫回存檔；換圖失敗
  不得先改動狀態。
- 商隊規模與野外遭遇沿用同一份地圖基準，符合原版共用 `ds:0x5c60` 的證據。
- 只有劇情階段恰為 2 時加值；其他階段不自行推論。
- 損壞／人工存檔的 0 基準在 remake 端鉗成 1，避免遭遇表無界重擲；
  這是失敗即關閉（fail-closed）保護，不改正常原版資料。

以及新遊戲倒數的 15／19 端點。
